## 📦 Assignment Operators

```text
=     simple assignment
+=    add and assign
-=    subtract and assign
*=    multiply and assign
/=    divide and assign
%=    modulus and assign
&=    bitwise AND assign
|=    bitwise OR assign
^=    bitwise XOR assign
//=   floor divide assign
**=   exponentiate assign
```

> ⚠️ **Note**: Python does **NOT** have `>>>=` (unsigned right shift) because it lacks fixed-width integers.

### 1. Simple & Chained Assignment

<Code lang="python" title="Chained assignment works differently than Java" code={`
# ✅ Valid: Chained assignment
a = b = c = d = 20  
print(a, b, c, d)  # 20 20 20 20

# ✅ Valid: Chained at declaration (unlike Java!)
# In Python, variables are created when assigned.
x = y = z = 0 
`} />

<Aside type="caution">
**Mutable Trap**: Chained assignment with mutable objects (lists/dicts) creates **references to the same object**.
```python
a = b = []
a.append(1)
print(b)  # [1] 😱 b changed too!

# ✅ Fix: Assign separately
a, b = [], []
```
</Aside>

### 2. Compound Assignment — No Hidden Casts!

<Code lang="python" title="Compound operators are straightforward" code={`
x = 10
x += 5   # x = 15
x -= 3   # x = 12
x *= 2   # x = 24
x /= 4   # x = 6.0 (Division always returns float in Python 3!)
x //= 2  # x = 3.0 (Floor division)
x **= 2  # x = 9.0 (Exponentiation)
`} />

#### 🔬 Why Python is Simpler than Java

In Java, `b += 1` works for bytes because of an implicit cast. In Python, there are no primitive types like `byte` or `short`. Everything is an `int` (arbitrary precision).

<Code lang="python" title="No narrowing casts needed" code={`
# Python ints grow automatically
val = 10
val += 10**100  # ✅ Works perfectly! No overflow.

# Division trap:
x = 10
x /= 2  
print(type(x))  # <class 'float'> ✅
# If you want int, use floor division:
x //= 2         # <class 'int'>
`} />

<Aside type="danger">
**Golden Rule**: `/=` always converts to `float`. Use `//=` if you want to stay an integer.
</Aside>

## 🔄 Conditional (Ternary) Operator

```text
value_if_true if condition else value_if_false
```

> 🇵🇾 **Python Syntax Flip**: Unlike Java (`condition ? true : false`), Python puts the condition in the middle. This reads like English: *"Give me A if X is true, else B."*

<Code lang="python" title="Basic ternary usage" code={`
a, b = 10, 20
max_val = a if a > b else b  # 20 ✅

# Nested ternary (parentheses recommended for readability):
x = 5
result = "positive" if x > 0 else ("negative" if x < 0 else "zero")
print(result)  # "positive"
`} />

### ⚠️ Type Flexibility

Python is dynamically typed, so the two outcomes don't need to be the same type (though it's bad practice).

<Code lang="python" title="Dynamic types in ternary" code={`
# ⚠️ Valid but confusing:
val = 10 if True else "hello" 

# ✅ Preferred: Keep types consistent
count = 1 if exists else 0
`} />

## 🏗️ Object Creation — No `new` Keyword!

> Python does **NOT** use the `new` operator. You simply call the class constructor like a function.

<Code lang="python" title="Object creation examples" code={`
# String
s = "Hello"           # Literal (preferred)
s2 = str("Hello")     # Constructor

# List
arr = [1, 2, 3]       # Literal (preferred)
arr2 = list()         # Constructor

# Custom Class
class Student:
    def __init__(self, name):
        self.name = name

st = Student("Alice")  # ✅ No 'new' keyword!

# What happens internally:
# 1. __new__ allocates memory
# 2. __init__ initializes attributes
# 3. Returns reference
`} />

<Aside type="note">
**Garbage Collection**: Like Java, Python uses automatic Garbage Collection (reference counting + generational GC). No `delete` needed.
</Aside>

## 📚 Sequence Access Operator `[]`

> Used for accessing elements in lists, tuples, strings, and dicts.

<Code lang="python" title="Indexing and Slicing" code={`
# List access
arr = [10, 20, 30]
print(arr[0])   # 10
arr[1] = 99     # Modify

# Negative Indexing (Python Superpower!)
print(arr[-1])  # 30 (Last element) ✅

# Slicing [start:stop:step]
print(arr[0:2]) # [10, 99]

# Dict access
d = {"key": "val"}
print(d["key"]) # "val"

# ❌ Bounds Checking:
# print(arr[10]) # 💥 IndexError: list index out of range
`} />

<Aside type="tip">
**Pythonic Safety**: Instead of checking length, use `try/except` or default values:
```python
# Safe dict access
val = d.get("missing_key", "default") 

# Safe list access
try:
    val = arr[10]
except IndexError:
    val = None
```
</Aside>

## 📊 Operator Precedence Table (Highest → Lowest)

```text
+------------+--------------------------------------+-----------------------------------+----------------+
| Precedence | Operators                            | Description                       | Associativity  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 1          | ()                                   | Parentheses                       | N/A            |
+------------+--------------------------------------+-----------------------------------+----------------+
| 2          | **                                   | Exponentiation                    | Right-to-left  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 3          | +x, -x, ~x                           | Unary plus, minus, NOT            | Right-to-left  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 4          | *, /, //, %                          | Multiplication, Division, Mod     | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 5          | +, -                                 | Addition, Subtraction             | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 6          | <<, >>                               | Shifts                            | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 7          | &                                    | Bitwise AND                       | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 8          | ^                                    | Bitwise XOR                       | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 9          | |                                    | Bitwise OR                        | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 10         | in, not in, is, is not,              | Membership, Identity              | Left-to-right  |
|            | <, <=, >, >=, !=, ==                 | Comparisons                       |                |
+------------+--------------------------------------+-----------------------------------+----------------+
| 11         | not                                  | Boolean NOT                       | Right-to-left  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 12         | and                                  | Boolean AND                       | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 13         | or                                   | Boolean OR                        | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 14         | if – else                            | Conditional expression            | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 15         | =, +=, -=, ...                       | Assignment                        | Right-to-left  |
+------------+--------------------------------------+-----------------------------------+----------------+
```

<Code lang="python" title="Precedence in action" code={`
# ** has higher precedence than *
result = 2 * 3 ** 2  # 2 * 9 = 18 (NOT 36!)

# Comparison chaining (Python Exclusive!)
x = 5
if 1 < x < 10:       # Equivalent to (1 < x) and (x < 10)
    print("InRange") ✅

# Logical vs Bitwise
# 'and' has lower precedence than '=='
if x == 5 and y == 10: ... # Evaluates as (x==5) and (y==10) ✅
`} />

## 🧪 Operand Evaluation Order — Left to Right Always!

> Just like Java, Python evaluates operands **left-to-right**, regardless of operator precedence.

<Code lang="python" title="Left-to-right operand evaluation" code={`
def trace(name):
    print(f"Evaluating {name}")
    return 1

# Expression: trace('A') + trace('B') * trace('C')
# Precedence: * happens before +
# Evaluation Order: A, then B, then C

result = trace('A') + trace('B') * trace('C')

# Output:
# Evaluating A
# Evaluating B
# Evaluating C
# Result: 1 + 1 * 1 = 2
`} />

<Aside type="tip">
**Interview Gold**: Precedence determines **grouping** (who binds to whom), but evaluation order determines **side effects** (which function runs first).
</Aside>

## 1️⃣ Simple Assignment `=`

### Basic Forms

```python
x = 42                      # simple
x = y = z = 0               # chained — all bind to SAME object
a, b = 1, 2                 # tuple unpacking
a, b = b, a                 # swap — no temp variable
first, *rest = [1,2,3,4]    # extended unpacking
*init, last = [1,2,3,4]
a, *mid, z = [1,2,3,4,5]
```

### 🔬 Bytecode — What `=` Produces

```python
import dis

def f():
    x = 42

dis.dis(f)
# LOAD_CONST   42          ← push PyLongObject(42) onto eval stack
# STORE_FAST   'x'         ← pop from stack, write to fast locals array
```

```python
# Module level:
x = 42
# LOAD_CONST   42
# STORE_NAME   'x'         ← writes to module __dict__

# Inside function:
def f():
    x = 42
# STORE_FAST   'x'         ← writes to C array (faster than dict)
```

```
Opcode by scope:
┌────────────────┬───────────────┬────────────────────────────┐
│ Scope          │ Store opcode  │ Storage                    │
├────────────────┼───────────────┼────────────────────────────┤
│ Local          │ STORE_FAST    │ C array (index lookup)     │
│ Global/Module  │ STORE_NAME    │ dict (hash lookup)         │
│ Closure cell   │ STORE_DEREF   │ PyCell on heap             │
│ Class body     │ STORE_NAME    │ class __dict__             │
└────────────────┴───────────────┴────────────────────────────┘
```

### 🔬 Chained Assignment Internals

```python
x = y = z = 0
```

```
Bytecode:
  LOAD_CONST   0
  DUP_TOP             ← duplicate top of stack
  STORE_FAST   z
  DUP_TOP
  STORE_FAST   y
  STORE_FAST   x

Result:
  x ──▶ PyLongObject(0)
  y ──▶ PyLongObject(0)    ← ALL point to SAME object
  z ──▶ PyLongObject(0)
```

```python
# Safe for immutables (int, str, float):
x = y = z = 0
x += 1        # x rebinds to new object — y, z unaffected

# DANGEROUS for mutables:
a = b = c = []        # all three → same list
a.append(1)
print(b)              # [1]  ← b changed!
print(c)              # [1]  ← c changed!
```

---

### 🔬 Tuple Unpacking Internals

```python
a, b = 1, 2
```

```
Bytecode:
  LOAD_CONST   (1, 2)      ← builds tuple on stack
  UNPACK_SEQUENCE  2       ← unpacks: pushes 2 then 1 (reverse order)
  STORE_FAST   a           ← stores 1
  STORE_FAST   b           ← stores 2
```

```python
# Swap:
a, b = b, a

Bytecode:
  LOAD_FAST    b
  LOAD_FAST    a           ← both loaded BEFORE any store
  STORE_FAST   a
  STORE_FAST   b
  ← no temp variable, no tuple created, done on eval stack
```

## 2️⃣ Augmented Assignment `+=`, `-=`, etc.

### The Critical Rule — Mutable vs Immutable

```python
# IMMUTABLE (int, str, float, tuple):
x = 5
x += 3
# x = x.__add__(3) → new PyLongObject(8)
# x rebound to new object
# id(x) CHANGES

# MUTABLE (list, dict, set):
lst = [1, 2]
lst += [3]
# lst.__iadd__([3]) → modifies in-place
# lst still points to same PyListObject
# id(lst) UNCHANGED
```

```
Augmented assignment dispatch:
  x += y

  1. Try x.__iadd__(y)       ← in-place (mutable types)
     if NotImplemented →
  2. Try x = x.__add__(y)    ← creates new object (immutable types)
     if NotImplemented →
  3. Try y.__radd__(x)       ← reflected
  4. TypeError
```

### All Augmented Forms

```python
x = 10

x += 3      # 13   — __iadd__ or __add__
x -= 3      # 10   — __isub__ or __sub__
x *= 3      # 30   — __imul__ or __mul__
x /= 3      # 10.0 — __itruediv__ (ALWAYS float)
x //= 3     # 3    — __ifloordiv__
x %= 3      # 0    — __imod__
x **= 3     # 0    — __ipow__

x = 0b1100
x &= 0b1010 # 0b1000  — __iand__
x |= 0b0011 # 0b1011  — __ior__
x ^= 0b1111 # 0b0100  — __ixor__
x <<= 2     # 0b010000 — __ilshift__
x >>= 1     # 0b01000  — __irshift__
```

### 🔬 Bytecode — Augmented Assignment

```python
import dis

def f():
    x = 5
    x += 3

dis.dis(f)
# LOAD_FAST    x
# LOAD_CONST   3
# BINARY_OP    +=      ← tries __iadd__ first
# STORE_FAST   x       ← rebinds regardless
```

## 3️⃣ Walrus Operator `:=` — Assignment Expression (3.8+)

### What It Is

```python
# Regular assignment — STATEMENT (can't be used inside expression):
x = 10           # statement only

# Walrus — EXPRESSION (returns the value, can be used inline):
y := 10          # 💥 SyntaxError alone — must be inside expression

(y := 10)        # ✅ — assigns AND returns 10
print(y := 10)   # prints 10, y = 10
```

```
Walrus = assignment that ALSO evaluates to the assigned value.
It's an expression, not a statement.
```

### Real Use Cases

```python
# 1. while loop with sentinel:
import sys

# BEFORE walrus (verbose):
line = sys.stdin.readline()
while line:
    process(line)
    line = sys.stdin.readline()

# WITH walrus (clean):
while line := sys.stdin.readline():
    process(line)
```

```python
# 2. Avoid double evaluation:
import re

# BEFORE:
match = re.search(r"\d+", text)
if match:
    print(match.group())

# WITH walrus:
if match := re.search(r"\d+", text):
    print(match.group())
```

```python
# 3. Filter with computed value (avoid recomputing):
results = [
    processed
    for raw in data
    if (processed := expensive_transform(raw)) is not None
]
# expensive_transform called ONCE per item
# result reused in both filter and collection
```

```python
# 4. Chunked reading:
import io

buf = io.BytesIO(b"hello world this is data")
while chunk := buf.read(4):
    print(chunk)
# b'hell'
# b'o wo'
# b'rld '
# b'this'
# b' is '
# b'data'
```

### 🔬 Walrus Scope Rules

```python
# Walrus leaks to ENCLOSING function scope — by design:
results = [y := x + 1 for x in range(5)]
print(y)    # 5  ← last value leaks out of comprehension

# Regular loop variable — also leaks in Python 3:
for x in range(5):
    pass
print(x)    # 4  ← leaks too

# But comprehension variable does NOT leak:
[z for z in range(5)]
print(z)    # NameError — z is scoped to comprehension
            # walrus := is the exception to this rule
```

```python
# Walrus CANNOT be used at module/class level without parens:
walrus := 10     # SyntaxError
(walrus := 10)   # ✅
```

```python
# One RHS, multiple targets:

# Different from:
a, b, c = [], [], []    # three separate lists
```

```python
# Augmented assignment on subscript and attribute:
```

### 🔬 Augmented Assignment on Subscript — Internals

```python
lst[i] += x

# Desugars to:
lst[i] = lst[i] + x

# Bytecode:
# LOAD_FAST     lst
# LOAD_FAST     i
# DUP_TOP_TWO              ← duplicate lst and i (for STORE later)
# BINARY_SUBSCR            ← execute lst[i] (calls __getitem__)
# LOAD_FAST     x
# BINARY_OP     +=         ← compute new value
# ROT_THREE
# STORE_SUBSCR             ← execute lst[i] = result (calls __setitem__)
```

## 🔬 DSA Connection

```python
# Two-pointer swap — no temp:
arr = [3, 1, 4, 1, 5]
l, r = 0, len(arr) - 1
while l < r:
    arr[l], arr[r] = arr[r], arr[l]   # tuple unpack swap
    l += 1
    r -= 1

# Fibonacci — tuple assignment avoids temp:
a, b = 0, 1
for _ in range(10):
    a, b = b, a + b    # both RHS evaluated BEFORE any assignment
    print(a)

# Running max with walrus:
data = [3, 1, 4, 1, 5, 9, 2, 6]
if (m := max(data)) > 5:
    print(f"Max {m} exceeds threshold")

# Sliding window — augmented assignment:
window_sum = sum(arr[:k])
for i in range(k, len(arr)):
    window_sum += arr[i]        # O(1) update
    window_sum -= arr[i - k]    # instead of O(k) re-sum
```

## 🚀 Real-World Production Patterns

### Pattern 1 — Config with Augmented Assignment

```python
# Building request headers incrementally:
headers = {"Content-Type": "application/json"}
headers |= {"Authorization": f"Bearer {token}"}   # dict |= (3.9+)
headers |= {"X-Request-ID": str(uuid4())}

# Same as:
headers.update({...})  # older style
```

### Pattern 2 — Walrus in Data Pipeline

```python
# Process stream until empty:
def process_queue(queue):
    while item := queue.get_nowait_or_none():
        if (result := transform(item)) is not None:
            output.append(result)
```

### Pattern 3 — Chained Augmented for Counters

```python
# Word frequency — augmented on dict:
freq = {}
for word in text.split():
    freq[word] = freq.get(word, 0)
    freq[word] += 1

# Better — defaultdict:
from collections import defaultdict
freq = defaultdict(int)
for word in text.split():
    freq[word] += 1    # augmented on defaultdict — clean
```

## 💀 Interview Trap 2 — `+=` on Tuple Mutates but Raises

```python
t = ([1, 2], [3, 4])

t[0] += [5]
# 💥 TypeError: 'tuple' object does not support item assignment
# BUT:
print(t)
# ([1, 2, 5], [3, 4])  ← MUTATION HAPPENED despite the error!
```

```
What happened:
  1. t[0].__iadd__([5]) → SUCCEEDS → list mutated in-place
  2. t[0] = result      → FAILS    → tuple is immutable → TypeError
  3. Both happen. Exception raised AFTER mutation.
  4. t[0] is now [1, 2, 5] but TypeError was also raised.

This is one of the most dangerous silent bugs in Python.
Try/except around it hides the partial mutation.
```

## 💀 Interview Trap 4 — Augmented Assignment Creates Local

```python
count = 0

def increment():
    count += 1    # 💥 UnboundLocalError

# Why?
# Compiler sees 'count += 1' → 'count = count + 1'
# Assignment to 'count' inside function → marks count as LOCAL
# LOAD_FAST 'count' before STORE_FAST → count not yet set → error

# Fix:
def increment():
    global count
    count += 1
```
