## 🔀 Type Conversion in Python

> **Python does not have "casting" operators** like `(int)x`. Instead, it uses **constructor functions** (`int()`, `float()`, `str()`) to convert values.  
> Because Python is **dynamically typed**, variables don't have fixed types — only objects do.

```text
Type Conversion in Python
│
├── Numeric Conversion
│   ├── int(x)    → Integer (truncates floats)
│   ├── float(x)  → Floating point
│   └── complex(x)→ Complex number
│
├── String Conversion
│   ├── str(x)    → String representation
│   └── repr(x)   → Developer-friendly string
│
├── Boolean Conversion
│   └── bool(x)   → True/False (based on truthiness)
│
├── Sequence Conversion
│   ├── list(x)   → List
│   ├── tuple(x)  → Tuple
│   ├── set(x)    → Set
│   └── dict(x)   → Dictionary
│
└── No "Narrowing" or "Widening"
    ├── No data loss from overflow (arbitrary precision ints)
    ├── No explicit syntax like (int)x
    └── TypeError if conversion is impossible
```

<Aside type="success">
🎯 **Python Advantage**: No silent overflow, no bit-truncation surprises, and no `ClassCastException`. If a conversion fails, you get a clear `ValueError` or `TypeError` immediately.
</Aside>

## 🔼 Implicit Conversion (Coercion)

Python automatically converts types in **mixed arithmetic expressions** to preserve precision.

### 🧭 Implicit Hierarchy

```text
int → float → complex
```

*   `int` + `float` → `float`
*   `float` + `complex` → `complex`
*   `bool` is a subclass of `int` (`True`=1, `False`=0)

<Code lang="python" title="Numeric coercion examples" code={`
# int + float → float
result = 5 + 2.5      # 7.5 (float) ✅

# bool acts as int
result = True + 1     # 2 (int) ✅
result = False * 10   # 0 (int) ✅

# Division always returns float (Python 3)
result = 10 / 2       # 5.0 (float) ✅

# No implicit string conversion!
# result = "Age: " + 25  # ❌ TypeError: can only concatenate str to str
`} />

<Aside type="note">
**Key Insight**: Unlike Java, Python **never** implicitly converts numbers to strings. You must use `str()` explicitly. This prevents accidental concatenation bugs.
</Aside>

## 🔽 Explicit Conversion (Constructor Functions)

To change types, you call the type constructor. This is **not** a cast operator; it creates a **new object** of the target type.

### 1️⃣ Numeric Conversions

| Function | Input Example | Output | Notes |
|----------|---------------|--------|-------|
| `int(x)` | `int(9.99)` | `9` | Truncates toward zero (like Java cast) |
| `int(x)` | `int("10")` | `10` | Parses string |
| `float(x)` | `float(10)` | `10.0` | Adds decimal |
| `float(x)` | `float("3.14")` | `3.14` | Parses string |
| `complex(x)` | `complex(1, 2)` | `(1+2j)` | Real + Imaginary |

<Code lang="python" title="Int and Float conversion" code={`
# Float → Int (Truncation, NOT Rounding)
print(int(9.99))   # 9  ✅ (Same as Java (int)9.99)
print(int(-9.99))  # -9 ✅ (Truncates toward zero)

# String → Int/Float
print(int("100"))   # 100 ✅
print(float("3.14")) # 3.14 ✅

# ❌ Invalid conversions raise ValueError
try:
    int("abc")
except ValueError:
    print("Cannot convert 'abc' to int!")

# Base conversion for int()
print(int("1010", 2))  # 10 (Binary to Decimal) ✅
print(int("FF", 16))   # 255 (Hex to Decimal) ✅
`} />

<Aside type="caution">
**Warning**: `int()` **truncates** decimals, it does **not** round.
```python
int(9.99)  # 9
# To round, use round():
round(9.99)  # 10
```
</Aside>

### 2️⃣ String Conversions

| Function | Input Example | Output | Notes |
|----------|---------------|--------|-------|
| `str(x)` | `str(10)` | `"10"` | Human-readable |
| `repr(x)` | `repr(10)` | `"10"` | Unambiguous (for devs) |
| `str(x)` | `str([1,2])` | `"[1, 2]"` | Works on any object |

<Code lang="python" title="String conversion" code={`
# Number → String
s = str(100)       # "100"
s = str(3.14)      # "3.14"

# List → String
s = str([1, 2, 3]) # "[1, 2, 3]"

# Object → String
class Dog:
    def __str__(self): return "Woof"
    def __repr__(self): return "Dog()"

d = Dog()
print(str(d))  # "Woof"
print(repr(d)) # "Dog()"
`} />

### 3️⃣ Boolean Conversions (Truthiness)

`bool(x)` returns `True` or `False` based on Python's **truthiness** rules.

*   **Falsy**: `None`, `False`, `0`, `0.0`, `""`, `[]`, `{}`, `set()`
*   **Truthy**: Everything else

<Code lang="python" title="Boolean conversion" code={`
print(bool(1))       # True
print(bool(0))       # False
print(bool("Hello")) # True
print(bool(""))      # False
print(bool([]))      # False
print(bool(None))    # False

# Useful for checking empty containers:
if bool(my_list):    # Same as: if my_list:
    print("Not empty")
`} />

## 🧠 Mental Model First

```
Python has NO casting operator like C/Java.
  C:      (int) 3.14     → truncates float to int
  Java:   (int) 3.14     → same
  Python: int(3.14)      → constructor call, not a cast

Every "cast" in Python is:
  1. A call to a TYPE CONSTRUCTOR
  2. Which creates a BRAND NEW OBJECT
  3. Of the target type
  4. The original object is UNCHANGED

x = 3.14
y = int(x)      # new PyLongObject created
                # x still points to PyFloatObject(3.14)
                # y points to PyLongObject(3)
```

```
TWO KINDS OF CONVERSION:
┌─────────────────────────────────────────────────────────┐
│  IMPLICIT (Coercion)  │  Python does it automatically  │
│    int + float        │  → int promoted to float        │
│    bool in arithmetic │  → True=1, False=0              │
├───────────────────────┼─────────────────────────────────┤
│  EXPLICIT (Casting)   │  You call the constructor       │
│    int("42")          │  → 42                           │
│    str(42)            │  → "42"                         │
│    float("3.14")      │  → 3.14                         │
└───────────────────────┴─────────────────────────────────┘
```

## 1️⃣ `int()` — To Integer

```python
int(3.9)          # 3       ← TRUNCATES toward zero (not floor)
int(-3.9)         # -3      ← toward zero, NOT -4
int(True)         # 1
int(False)        # 0
int("42")         # 42
int("  42  ")     # 42      ← strips whitespace
int("-17")        # -17
int("0b1010", 2)  # 10      ← binary string
int("0xFF",  16)  # 255     ← hex string
int("77",     8)  # 63      ← octal string
int("FF",    16)  # 255     ← no prefix needed when base given
```

```python
# What fails:
int(3+4j)         # TypeError: can't convert complex to int
int("3.14")       # ValueError: invalid literal for int() with base 10
int("12 34")      # ValueError: spaces inside number
int("")           # ValueError: empty string
int(None)         # TypeError
```

### 🔬 Internals — `__int__` and `__index__`

```python
# int() calls __int__ first, then __index__, then __trunc__:

class MyNum:
    def __int__(self):
        return 42

int(MyNum())    # 42

# __index__ — for types that are losslessly int-like:
class Color:
    def __index__(self):   # used in slicing, bin(), hex(), oct()
        return 0xFF0000

import sys
c = Color()
int(c)          # 16711680
bin(c)          # '0b111111110000000000000000'
[1,2,3][c]      # used as list index — requires __index__
```

```
int() dispatch order:
  1. Already int?      → return same object (fast path, no copy)
  2. Has __int__?      → call it
  3. Has __index__?    → call it
  4. Has __trunc__?    → call it (deprecated path)
  5. str/bytes input?  → parse with given base
  6. Nothing works?    → TypeError
```

### 🔬 `str()` vs `repr()`

```python
# str() calls __str__ → human-readable
# repr() calls __repr__ → developer/unambiguous

class Point:
    def __str__(self):    return f"({self.x}, {self.y})"
    def __repr__(self):   return f"Point({self.x}, {self.y})"

p = Point()
str(p)    # "(1, 2)"         ← for end users
repr(p)   # "Point(1, 2)"   ← for developers, eval()-safe ideally
```

```
str() dispatch:
  1. Has __str__?  → call it
  2. Fallback to __repr__
  3. Default: "<ClassName object at 0xADDRESS>"
```

## 🔬 Implicit Coercion — When Python Does It For You

```python
# Numeric promotion:
1 + 1.0         # 2.0    int coerced to float
True + 1        # 2      bool coerced to int
True + 1.0      # 2.0    bool → float

# No coercion across unrelated types:
"1" + 1         # TypeError: str + int — Python REFUSES implicit cast
[1] + (1,)      # TypeError: list + tuple — REFUSES
```

```
Promotion chain (automatic):
  bool → int → float → complex
  Each step is lossless in this direction.
  Reverse is NEVER automatic — always explicit.
```

## 🔬 `__int__`, `__float__`, `__str__` Protocol

```python
# Any class can define casting behavior:
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def __int__(self):
        return int(self.celsius)

    def __float__(self):
        return float(self.celsius)

    def __str__(self):
        return f"{self.celsius}°C"

    def __bool__(self):
        return self.celsius != 0

t = Temperature(36.6)
int(t)      # 36
float(t)    # 36.6
str(t)      # "36.6°C"
bool(t)     # True
```

chr(65)                 # 'A'

# Digit char to int:
int('7')                # 7
ord('7') - ord('0')     # 7   ← bit-level alternative

# list(map(int, ...)) — parse digit array:
list(map(int, "12345"))         # [1, 2, 3, 4, 5]
list(map(int, "12345".split())) # [1, 2, 3, 4, 5] — same here
[int(c) for c in "12345"]      # [1, 2, 3, 4, 5]

# Number to digit list:
[int(d) for d in str(12345)]    # [1, 2, 3, 4, 5]

## 🚀 Real-World Production Patterns

### Pattern 1 — Safe Casting With Validation

```python
# Never naked cast user input:
def parse_port(raw: str) -> int:
    try:
        port = int(raw)
    except (ValueError, TypeError):
        raise ValueError(f"Invalid port: {raw!r}")
    if not (1 <= port <= 65535):
        raise ValueError(f"Port out of range: {port}")
    return port
```

### Pattern 2 — Encoding Pipeline

```python
# str → bytes → network:
def send_message(sock, message: str):
    data = message.encode("utf-8")      # str → bytes
    length = len(data).to_bytes(4, "big")  # int → bytes (4-byte header)
    sock.sendall(length + data)

# network → bytes → str:
def recv_message(sock) -> str:
    raw_len = sock.recv(4)
    length = int.from_bytes(raw_len, "big")  # bytes → int
    data = sock.recv(length)
    return data.decode("utf-8")              # bytes → str
```

## 💀 Interview Trap 1 — `int()` Truncates, Not Rounds

```python

import math

math.floor(-3.9) # -4   ← toward -∞

math.trunc(3.9)  # 3
math.trunc(-3.9) # -3
```

## 💀 Interview Trap 3 — `float` Precision Lost in `int` Round-Trip
