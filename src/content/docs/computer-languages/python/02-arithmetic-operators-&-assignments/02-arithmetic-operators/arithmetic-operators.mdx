## 🔢 Rule 1: No Type Promotion — Dynamic Typing FTW

> Python uses **dynamic typing** — no compile-time type promotion rules.  
> Operations return the "natural" result type.

### 📊 Python vs Java: Type Behavior Comparison

| Operation | Java Result Type | Python Result Type | Why Python Wins |
|-----------|-----------------|-------------------|----------------|
| `byte + byte` | `int` (needs cast back) | `int` (no cast needed) | ✅ No narrowing cast traps |
| `char + char` | `int` (Unicode sum) | `TypeError` (can't add str) | ✅ Prevents accidental Unicode math |
| `int / int` | `int` (truncates!) | `float` (true division) | ✅ No surprise truncation |
| `int + float` | `float` | `float` | ✅ Same, but no declaration needed |
| `Integer.MAX_VALUE + 1` | `-2147483648` (overflow!) | `2147483648` (arbitrary precision) | ✅ 🎉 No silent overflow! |

<Code lang="python" title="Character arithmetic — Python prevents accidents" code={`
# Java: 'a' + 'b' → 195 (Unicode sum) — easy bug!
# Python: explicit conversion required — safer!

# ❌ This fails (and should!):
# result = 'a' + 'b'  # TypeError: can only concatenate str (not "str") to str

# ✅ Explicit Unicode math (if you really need it):
result = ord('a') + ord('b')  # 97 + 98 = 195 ✅
char_result = chr(result)      # 'Ç' (Unicode 195)

# ✅ String concatenation (the common case):
text = 'a' + 'b'  # "ab" ✅ — clear intent
`} />

<Aside type="tip">
**MUST KNOW**: Python's `+` is **type-sensitive**:
- `int + int` → `int` ✅
- `str + str` → `str` ✅  
- `int + str` → `TypeError` ✅ (forces explicit conversion)
- `list + list` → `list` (concatenation) ✅

This prevents the "accidental Unicode math" bug common in Java!
</Aside>

## 🔥 Rule 2: Division — `/` vs `//` (The Critical Distinction) ⭐

### 🟢 True Division `/` — Always Returns Float

```python
# Python 3: / is TRUE division — NEVER truncates!
10 / 3    →  3.3333333333333335  # float ✅
7  / 2    →  3.5                 # float ✅
-7 / 2    → -3.5                 # float ✅ (not truncated!)

# Even int / int returns float:
print(type(10 / 2))  # <class 'float'> ✅
```

### 🟡 Floor Division `//` — Truncates Toward NEGATIVE INFINITY

```python
# // is FLOOR division — rounds DOWN (toward -∞)
10 // 3    →  3    # floor(3.33) = 3 ✅
7  // 2    →  3    # floor(3.5)  = 3 ✅
-7 // 2    → -4    # floor(-3.5) = -4 ✅ (NOT -3!)

# Why floor (not truncation)? Mathematically consistent with modulo!
```

<Code lang="python" title="Floor vs truncation visualized" code={`
import math

# Java-style truncation (toward zero):
def trunc_div(a, b):
    return int(a / b)  # Convert float to int = truncate toward zero

# Python floor division (toward -∞):
def floor_div(a, b):
    return a // b

# Compare for negative numbers:
print(trunc_div(-7, 2))  # -3 (Java behavior)
print(floor_div(-7, 2))  # -4 (Python // behavior)
print(math.floor(-7 / 2))  # -4 (confirms floor)

# When to use which:
# ✅ Use // for: array indexing, loop counters, integer algorithms
# ✅ Use /  for: averages, ratios, any calculation needing precision
`} />

### 🔵 Division by Zero — Same as Java for Floats

## 🔬 Rule 3: Modulo (%) — Mathematically Correct Sign Rule

### 🎯 Python's Modulo: Sign Follows DIVISOR (Right Operand)

```python
# Java: sign follows DIVIDEND (left) — can be surprising
# Python: sign follows DIVISOR (right) — mathematically consistent!

# Positive divisor → positive result:
 7 %  3  →  1   ✅
-7 %  3  →  2   ✅ (because -7 = -3×3 + 2)

# Negative divisor → negative result:  
 7 % -3  → -2   ✅ (because 7 = -3×(-3) + (-2))
-7 % -3  → -1   ✅

# Memory rule: result has same sign as DIVISOR (right side)
```

### 🔗 Floor Division + Modulo Invariant

```python
# Python guarantees: (a // b) * b + (a % b) == a  (always!)

# Example with negative numbers:
a, b = -7, 3
quotient = a // b   # -4 (floor division)
remainder = a % b   #  2 (modulo)

# Verify invariant:
check = quotient * b + remainder  # (-4)*3 + 2 = -12 + 2 = -10 ❌ wait...
# Actually: (-4)*3 + 2 = -12 + 2 = -10 ≠ -7

# Let me recalculate:
# -7 // 3 = -3 (floor of -2.33 is -3, not -4!)
# -7 % 3 = 2 (because -7 = 3×(-3) + 2 → -9 + 2 = -7 ✅)
# Check: (-3)*3 + 2 = -9 + 2 = -7 ✅

print(-7 // 3)   # -3
print(-7 % 3)    # 2
print((-7 // 3) * 3 + (-7 % 3))  # -7 ✅ invariant holds!
```

<Code lang="python" title="Modulo use cases — Pythonic patterns" code={`

def is_even(n): return n % 2 == 0
def is_odd(n): return n % 2 != 0  # ✅ Better than == 1

print(is_odd(-3))   # True ✅ (because -3 % 2 = 1 in Python... wait)

# Actually: -3 % 2 = 1 in Python (divisor 2 is positive)
# So -3 % 2 == 1 → is_odd(-3) using == 1 would work in Python!
# But != 0 is still clearer and works in all languages.

# ✅ Cyclic indexing (circular buffer):

index = -1
print(arr[index % len(arr)])  # arr[2] = 'c' ✅ wraps negative to end

# ✅ Hash table indexing (always non-negative):
def hash_index(key, table_size):
    return hash(key) % table_size  # Result always 0 to table_size-1 ✅
`} />

<Aside type="success">
🎯 **Python Modulo Advantage**: The invariant `(a // b) * b + (a % b) == a` **always holds**, even for negatives. This makes cyclic arithmetic and hash functions more predictable!
</Aside>
