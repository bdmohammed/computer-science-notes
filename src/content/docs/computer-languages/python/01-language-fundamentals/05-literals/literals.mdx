A **Literal** is a fixed value assigned directly in source code.

- ✔ Represents constant data
- ✔ Written directly in code
- ✔ Python infers type dynamically at runtime

<Code lang="python" title="What a literal looks like" code={`
x = 10           # 10    → integer literal
d = 10.5         # 10.5  → floating-point literal
b = True         # True  → boolean literal (capitalized!)
z = [1, 2, 3]   # [1,2,3]→ list literal  ← WARNING: NOT compile-time
`} />

```
          SOURCE CODE
               │
        ┌──────▼──────┐
        │  Tokenizer  │  ← recognizes literal tokens
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │     AST     │  ← Constant(value=42) node
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │  Bytecode   │  ← LOAD_CONST  (pulled from co_consts)
        └─────────────┘
```

> Integer, float, string, bytes, bool, None literals → stored in `co_consts` of the code object at compile time. List/dict/set literals → bytecode **constructs them at runtime** every call.

| Literal | Example | Notes |
|---------|---------|-------|
| Integer | `10`, `0x1F`, `0b101`, `0o10` | Unlimited precision (no overflow) |

| Boolean | `True`, `False` | Capitalized, singleton objects |

| String | `"Hello"`, `'Hi'`, `"""Multi"""` | Immutable, Unicode by default |
| None | `None` | Singleton for "no value" (like Java `null`) |

## 1️⃣ Integer Literals

Whole numbers. **Unlimited precision** — no `int`/`long` split like Java.

### Number Systems
| System      | Base | Prefix      | Allowed Values | Example  | Value |
| ----------- | ---- | ----------- | -------------- | -------- | ----- |
| Decimal     | 10   | none        | `0-9`          | `10`     | 10    |
| Octal       | 8    | `0o` / `0O` | `0-7`          | `0o10`   | 8     |
| Hexadecimal | 16   | `0x` / `0X` | `0-9`, `A-F`   | `0x10`   | 16    |
| Binary      | 2    | `0b` / `0B` | `0-1`          | `0b1010` | 10    |

### All Forms
```python
# Decimal (base 10)
x = 1_000_000       # underscores for readability (3.6+)
x = 255

# Binary (base 2)
x = 0b1111_0000     # → 240

# Octal (base 8)
x = 0o17            # → 15

# Hexadecimal (base 16)
x = 0xFF            # → 255
x = 0xDEAD_BEEF     # → 3735928559
```

### 🔬 Internals — Compile-Time Constant Folding

```python
import dis

def foo():
    return 2 * 1024 * 1024

dis.dis(foo)
# LOAD_CONST   2097152   ← compiler folded 2*1024*1024 at compile time
# RETURN_VALUE
```

> CPython's **peephole optimizer** (now `ast_optimizer`) folds constant expressions involving literals. `2 * 1024 * 1024` never executes at runtime — result already in `co_consts`.

### Underscore Rules
```python
1_000_000     # ✅
_1000         # ✅ (but this is an identifier, not a literal)
1__000        # ❌ SyntaxError — consecutive underscores
1_            # ❌ SyntaxError — trailing underscore
0x_FF         # ❌ SyntaxError — after prefix
```

<Aside type="note">
Python **is case-insensitive** for literal prefixes too — `0xFF`, `0Xff`, `0xff` all work identically.
</Aside>

# Super Short Mental Trick
If you see a prefix, it's not decimal:  
- `0o` → octal  
- `0x` → hexadecimal  
- `0b` → binary  

> ⚠️ **Python vs Java**: Python uses `0o` for octal (not just `0`), preventing accidental octal interpretation!

## Decimal
```text
123 = 1×10² + 2×10¹ + 3×10⁰ = 123
```

## Binary
```text
0b1010 = 1×2³ + 0×2² + 1×2¹ + 0×2⁰ = 10
```

## Octal
```text
0o10 = 1×8¹ + 0×8⁰ = 8
```

## Hexadecimal
```text
0x10 = 1×16¹ + 0×16⁰ = 16
```

## 2️⃣ Floating Point Literals

- Real numbers (decimals). Default type is **`float`** (IEEE 754 double-precision).
- **No suffix needed** — Python doesn't distinguish `float`/`double`.

<Code lang="python" title="✅ Valid"
code={`
d  = 10.5           # float literal
d2 = 10.5           # no 'd' suffix needed
f  = 10.5           # no 'f' suffix — all floats are double-precision
big   = 1.5e10      # scientific notation → 15000000000.0
small = 1.5e-3      # scientific notation → 0.0015
hex_float = 0x1.2p3 # ✅ Hex float (Python 3.6+): 1.125 × 2³ = 9.0
.5              # → 0.5   (leading dot allowed)
5.              # → 5.0   (trailing dot allowed)
1_000.000_001   # underscores allowed
`} />

### 🔬 What the compiler stores

```python
import dis

def foo():
    return 3.14

dis.dis(foo)
# LOAD_CONST  3.14   ← IEEE 754 double stored in co_consts
```

```python
# 3.14 in co_consts is stored as C double — already has precision error baked in
import struct
struct.pack('d', 3.14).hex()
# '1f85eb51b81e0940'  ← actual bits stored
```

<Code lang="python" title="❌ Invalid"
code={`
# No compile-time type errors for float assignment!
# But watch for precision issues:
f = 10.5  # ✅ Valid — but it's a float, not a "double"
`} />

<Aside type="tip">
**Memory trick:** *"Python floats are fearless — no suffix stress."*  
- Integral literals auto-convert to float in expressions:
```python
d = 123.456         # ✅ valid
d = 0o123.456       # ❌ SyntaxError: octal not allowed in float literals
d = 0x123           # ✅ integer literal → auto-converted to float in float context
d = 0xBeef          # ✅ → 48879.0
```
</Aside>

<Aside type="danger">
**Never use `float` for money** — same precision issues as Java:
```python
print(0.1 + 0.2)  # 0.30000000000000004 😱
# Use Decimal for financial calculations:
from decimal import Decimal
print(Decimal('0.1') + Decimal('0.2'))  # 0.3 ✅
```
</Aside>

## 3️⃣ Character & String Literals

> 🚨 **Python has no `char` type** — single characters are just length-1 strings.

### String Forms (covers Java's char + String)

<Code lang="python" title="All valid string/char forms" code={`
c1 = 'A'           # Single-quoted string (length 1)
c2 = chr(97)       # Convert Unicode code point → 'a'
c3 = '\u0041'      # Unicode escape → 'A'
c4 = '\n'          # Escape sequence → newline

# Python also supports:
s1 = "Hello"       # Double quotes
s2 = '''Multi
line'''            # Triple-quoted (no escaping needed)
s3 = f"Value: {42}" # f-string (Python 3.6+)
`} />

<Code lang="python" title="✅ Valid"
code={`
ch  = 'A'
ch2 = chr(65)          # → 'A'
ch3 = '\u0041'         # Unicode → 'A'
ch4 = '\ubeef'         # valid Unicode escape
ch5 = '\u0061'         # → 'a'
# No hex literal direct assignment to "char" — use chr():
ch6 = chr(0xFace)      # ✅ if within valid Unicode range (0–0x10FFFF)
`} />

<Code lang="python" title="❌ Invalid / Gotchas"
code={`
ch = "A"          # ✅ Valid! But it's a str, not a "char"
ch = a            # NameError: 'a' not defined (unless variable exists)
ch = 'ab'         # ✅ Valid! But it's a 2-char string, not single char
ch = ''           # ✅ Valid! Empty string (unlike Java char)
ch = chr(65536)   # ✅ Valid! Python supports full Unicode (not limited to 0–65535)
ch = \u0062       # SyntaxError: missing quotes
ch = '\iface'     # DeprecationWarning / SyntaxError: invalid escape
`} />

## 4️⃣ String Literals & Text Blocks

Sequence of characters, enclosed in **single `' '`, double `" "`, or triple `''' '''` / `""" """` quotes**.

- Immutable — same as Java
- Unicode by default (Python 3)
- **f-strings** for interpolation (Python 3.6+)

<Code lang="python" title="String basics" code={`
# Regular
s = "hello"
s = 'hello'

# Raw string — backslashes NOT processed
r = r"C:\Users\name"    # ✅ → C:\Users\name
r = "C:\Users\name"     # ⚠️  \U, \n processed → broken path on Windows

# Bytes literal
b = b"hello"            # bytes object, not str

# Concatenation
result = "Hello" + "World"  # "HelloWorld"

# f-strings (Python's superpower 🔥)
name = "Alice"
age = 25
info = f"{name} is {age} years old"  # "Alice is 25 years old"

# Number + String = String (explicit conversion needed)
mixed  = str(10) + "20"   # "1020"
mixed2 = "10" + str(20)   # "1020"
# Or use f-string: f"{10}{20}" → "1020"
`} />

### Multi-line Strings (Python's Text Blocks)

<Code lang="python" title="Triple-quoted strings — clean & readable" code={`
json = """
{
    "name": "Alice",
    "age": 25
}

html = '''

# Strip leading whitespace with textwrap.dedent if needed:

### Escape Sequences

| Escape | Meaning |
|--------|---------|
| `\n` | newline |
| `\t` | tab |

| `\'` `\"` | literal quote |

### 🔬 String Literal Concatenation — Compile-Time

```python
s = "hello" " " "world"    # adjacent string literals → merged at compile time
# → "hello world"  (single str object in co_consts)

# Useful for long strings without \ or +:
query = (
    "SELECT * FROM users "
    "WHERE active = true "
    "ORDER BY created_at"
)
```

```python
import dis

def foo():
    return "hello" " " "world"

dis.dis(foo)
# LOAD_CONST  'hello world'   ← already merged, single constant
```

> This is **not** string concatenation at runtime. The tokenizer merges adjacent string literals before AST is even built.

### 🔬 f-string Internals (3.12 changed this)

```python
name = "Ali"
f"Hello {name}!"
```

**Before Python 3.12:**
```
compiled to:  "Hello " + str(name) + "!"
bytecode:     FORMAT_VALUE + BUILD_STRING opcodes
```

**Python 3.12+:**
```
new LOAD_FAST_AND_CLEAR + CALL_INTRINSIC_1
f-strings now use a dedicated parser → faster, fewer allocations
```

```python
# f-strings allow expressions, not just names
f"{2 + 2}"              # "4"
f"{obj.method()}"       # method called at runtime
f"{value:.2f}"          # format spec
f"{value!r}"            # calls repr()
f"{'hi':>10}"           # "        hi"

# Nested f-strings (3.12+)
f"{'nested' if True else 'nope'}"
```

### 💀 f-string Trap — Lazy Evaluation at Call Site

```python
import logging

# WRONG — always evaluates the f-string, even if DEBUG logs are disabled
logging.debug(f"Processing {expensive_function()}")

# CORRECT — lazy: only evaluates if DEBUG is enabled
logging.debug("Processing %s", expensive_function())
```

> In prod with `INFO` level logging, the first version calls `expensive_function()` **every time** even though the log is never written. Real perf bug in high-frequency code paths.

## 5️⃣ Boolean Literals

Only **two values** allowed: `True` or `False` (**capitalized!**).

<Code lang="python" title="Boolean literals" code={`
flag = True
done = False

# ✅ Pythonic idiom — truthiness checks
if is_active:      # not: if is_active == True
    pass
if not is_empty:   # not: if is_empty == False
    pass

# ✅ Python treats many values as "truthy" / "falsy"
if 1:              # ✅ True (non-zero numbers are truthy)
    pass
if 0:              # ❌ False (zero is falsy)
    pass
if "hello":        # ✅ True (non-empty string)
    pass
if "":             # ❌ False (empty string)
    pass
if []:             # ❌ False (empty list)
    pass`} />

> `True` and `False` are **keywords** (since Python 3, can't be reassigned) AND literals. Stored as `PyBoolObject` which subclasses `PyLongObject`.

```python
# Compiled as constants:
import dis
def foo(): return True
dis.dis(foo)
# LOAD_CONST  True   ← in co_consts
```

<Aside type="caution">
`"True"` (with quotes) is a **string**, not a boolean.  
`true` or `TRUE` → `NameError`. Python is **case-sensitive** for `True`/`False`.
</Aside>

## 6️⃣ None Literal

Represents the **absence of a value** (Python's `null`).

<Code lang="python" title="None usage" code={`
s   = None      # ✅ reference type
arr = None      # ✅ list/array reference

# Python doesn't have primitive vs reference distinction
x = None        # ✅ Valid — any variable can be None
b = None        # ✅ Valid

# But operations may fail at runtime:
# x + 1  # TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

# Use type hints + Optional for clarity (Python 3.5+):
from typing import Optional
def find_user(id: int) -> Optional[str]:
    return None  # or return "Alice"
`} />

> Singleton. One `PyObject` for entire process lifetime. Always use `is None`, never `== None`.

```python
import dis
def foo(): return None
dis.dis(foo)
# RETURN_CONST  None   ← special opcode in 3.12, was LOAD_CONST before
```

<Aside type="danger">
**Common runtime crash in Python:**
```python
s = None
len(s)   # 💥 TypeError: object of type 'NoneType' has no len()
```
Always check for `None` before calling methods:
```python
if s is not None:
    print(len(s))
# Or use: print(len(s) if s else 0)
```
</Aside>

## 8️⃣ Collection Literals — NOT Compile-Time Constants

```python
[1, 2, 3]     # list literal
(1, 2, 3)     # tuple literal
{1, 2, 3}     # set literal
{"a": 1}      # dict literal
```

### 🔬 What bytecode actually does

```python
import dis

def foo():
    return [1, 2, 3]

dis.dis(foo)
# LOAD_CONST   1
# LOAD_CONST   2
# LOAD_CONST   3
# BUILD_LIST   3        ← constructs new list at RUNTIME every call
# RETURN_VALUE
```

```python
def bar():
    return (1, 2, 3)    # tuple of constants

dis.dis(bar)
# LOAD_CONST   (1, 2, 3)  ← ENTIRE TUPLE stored as single constant ✅
# RETURN_VALUE
```

```
┌─────────────────────────────────────────────────────────┐
│           COMPILE-TIME vs RUNTIME                       │
│                                                         │
│  int/float/str/bytes/bool/None  →  co_consts (compile) │
│  tuple of constants             →  co_consts (compile) │
│  list  [...]                    →  BUILD_LIST (runtime) │
│  dict  {...}                    →  BUILD_MAP  (runtime) │
│  set   {...}                    →  BUILD_SET  (runtime) │
└─────────────────────────────────────────────────────────┘
```

> This is why using a `tuple` as a constant lookup is faster than a `list` — the tuple is one `LOAD_CONST`, the list is N pushes + `BUILD_LIST`.

```python
# Real perf difference in tight loops:
# Slow — list rebuilt every iteration
for x in range(1_000_000):
    if x % 2 in [0, 2, 4]:   # BUILD_LIST every iteration
        pass

# Fast — tuple loaded from co_consts once
for x in range(1_000_000):
    if x % 2 in (0, 2, 4):   # LOAD_CONST once
        pass
```

## 🔬 `co_consts` — Where Literals Live

```python
def foo():
    x = 42
    y = "hello"
    z = 3.14
    return (x, y, z)

print(foo.__code__.co_consts)
# (None, 42, 'hello', 3.14)
#  ↑
#  None always included (implicit return value)
```

> Every literal in a function body is deduplicated and stored in `co_consts` tuple on the `PyCodeObject`. The bytecode instruction `LOAD_CONST i` just indexes into this tuple — O(1), no hashing, no lookup.

## 🔬 Literal Type Compatibility (Python vs Java)

| Concept | Java | Python |
|---------|------|--------|
| Type checking | Compile-time (static) | Runtime (dynamic) |
| Integer overflow | Possible (`int` → `long`) | **Never** (unlimited precision) |
| Float suffix | `f`/`d` required for `float` | No suffix needed |
| Char vs String | Distinct types | No `char` — all are `str` |
| Null safety | `null` only for references | `None` for any variable |
| Octal prefix | `0` (error-prone) | `0o` (explicit, safer) |

<Code lang="python" title="Python's dynamic flexibility" code={`
# No compile-time range checks:
b = 130          # ✅ Valid — no "byte" type; use int
# But if you need byte-range validation, check manually:
if not (-128 <= b <= 127):
    raise ValueError("Out of byte range")

# Float assignment — no suffix drama:
f = 10.5         # ✅ Just works

# Type hints are optional (for tooling, not enforcement):
from typing import Union
x: Union[int, float] = 10  # Hint only — runtime accepts anything
`} />

"hello"         # str (immutable, Unicode)
None            # null equivalent

# Number bases:
0b1010          # binary → 10
0o17            # octal  → 15  
0xFF            # hex    → 255

# Readability:
1_000_000       # underscore separator (PEP 515)

# Strings:
f"{x}"          # f-string interpolation
r"\path"        # raw string (ignore escapes)
"""multi"""     # triple-quoted (text blocks)

# Gotchas:
# - No char type → use str of length 1
# - No type suffixes (f, d, L)
# - Octal = 0o (not 0)
# - None checks: use 'is', not '=='
```
</Aside>
```

```python
# Same value, same literal → CPython may or may not intern
a = 256
b = 256
a is b      # True  ← small int cache

a = 257
b = 257
a is b      # True  ← in same code block, compiler deduplicates co_consts!

# But:
def f(): return 257
def g(): return 257
f() is g()  # False ← different code objects, different co_consts
```

```python
# Float literals — never cached
a = 3.14
b = 3.14
a is b      # True  ← same code block, same co_consts slot
            # False ← across functions/modules
```

> The deduplication of literals in `co_consts` is a **per-code-object** optimization. Never rely on `is` for comparing literal values across function boundaries.

## 💀 Interview Trap — Raw String Edge Case

```python
r"hello\"        # ❌ SyntaxError — raw string cannot end with odd number of backslashes
r"hello\\"       # ✅ → 'hello\\'  (two chars: \ and \)
r"hello\"world"  # ✅ → 'hello\\"world' — backslash doesn't escape quote in raw
                 #     but it DOES prevent the quote from ending the string
```

> Raw strings process backslash as literal `\` **except** it still affects quote termination. A raw string ending in `\` is always a `SyntaxError`. This trips up regex writers.

## 🔄 Key Conversion Summary

| Java Concept | Python Equivalent | Notes |
|--------------|-----------------|-------|
| `int x = 10;` | `x = 10` | No type declaration needed |
| `long l = 10L;` | `l = 10` | No `L` suffix — ints auto-scale |
| `float f = 10.5f;` | `f = 10.5` | No `f` suffix needed |
| `boolean b = true;` | `b = True` | Capitalized keywords |
| `char c = 'A';` | `c = 'A'` | Returns `str` of length 1 |
| `String s = "Hi";` | `s = "Hi"` | Same syntax, more features |
| `null` | `None` | Singleton, use `is None` to check |
| `010` (octal) | `0o10` | Explicit prefix prevents bugs |
| Underscores | `1_000_000` | Same PEP 515 support ✅ |
| Text blocks | `"""..."""` | Triple quotes, no `"` prefix needed |
| Unicode `\uXXXX` | `\uXXXX` | Same escape syntax ✅ |

> 🚀 **Pro Tip**: Python's dynamic typing removes most compile-time literal traps, but introduces runtime gotchas. Always write tests for edge cases!
