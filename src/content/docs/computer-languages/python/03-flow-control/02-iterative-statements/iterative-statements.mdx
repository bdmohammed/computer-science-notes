## for Loop 

> In Python, `for` is actually a **"for-each"** loop. It iterates over any **iterable** object (lists, strings, dicts, ranges, files).

---

### 🔑 Syntax & Execution Flow

```python
for item in iterable:
    # body

for x in [1, 2, 3]:         print(x)
for c in "hello":           print(c)
for k in {"a":1,"b":2}:     print(k)     # keys only
for i in range(5):          print(i)
```

```
for flow:
     get iterable
            │
            ▼
     get iterator
            │
            ▼
  ┌───────────────────┐
  │   next(iterator)  │◄────────────┐
  └────────┬──────────┘             │
           │                        │
    ┌──────┴──────┐                 │
 StopIteration   item               │
    │             │                 │
    ▼             ▼                 │
exit loop   execute body────────────┘
```

<Code lang="python" title="Basic for loop" code={`
# Iterating over a list
fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit)  
# apple
# banana
# cherry
`} />

### 🔬 What `for` Actually Does Internally

```python
for x in iterable:
    body

# EXACTLY equivalent to:
_iter = iter(iterable)        # calls iterable.__iter__()
while True:
    try:
        x = next(_iter)       # calls _iter.__next__()
    except StopIteration:
        break
    body
```

```
ITERATOR PROTOCOL:
┌─────────────────────────────────────────────────────────┐
│  __iter__()   → returns iterator object                 │
│  __next__()   → returns next value OR raises            │
│                 StopIteration when exhausted            │
└─────────────────────────────────────────────────────────┘

Anything implementing both is ITERABLE.
list, str, dict, set, tuple, range, generator, file → all iterable.
int, float, bool → NOT iterable (no __iter__).
```

### 🔬 The Power of `range()`

Since Python doesn't have C-style `for (i=0; i<n; i++)`, we use `range()` to generate sequences of numbers.

| Function | Sequence Generated | Use Case |
|----------|--------------------|----------|
| `range(n)` | `0, 1, ..., n-1` | Simple count |
| `range(start, stop)` | `start, ..., stop-1` | Custom start |
| `range(start, stop, step)` | `start, start+step, ...` | Steps/Skipping |

<Code lang="python" title="Range examples" code={`
# 0 to 4
for i in range(5):
    print(i, end=" ")  # 0 1 2 3 4

# 2 to 9
for i in range(2, 10):
    print(i, end=" ")  # 2 3 4 5 6 7 8 9

# Even numbers 0 to 10
for i in range(0, 11, 2):
    print(i, end=" ")  # 0 2 4 6 8 10

# Reverse loop (Java: for(int i=5; i>0; i--))
for i in range(5, 0, -1):
    print(i, end=" ")  # 5 4 3 2 1
`} />

---

### 🔬 `range` Is Lazy — Not a List

```python
r = range(10)
type(r)             # <class 'range'>
import sys
sys.getsizeof(r)    # 48 bytes — FIXED regardless of size!
sys.getsizeof(range(10_000_000))  # still 48 bytes

# range stores only (start, stop, step) — computes on demand
# O(1) space regardless of size
# O(1) membership test: 5 in range(10) — math, not scan
```

## 🔄 The `while` Loop

> Use when the number of iterations is **unknown** and depends on a condition.

### 🔑 Syntax

```python
while condition:
    # body
```

<Code lang="python" title="Basic while loop" code={`
// Condition checked BEFORE body — may never execute
count = 0
while count < 5:
    print(count, end=" ")
    count += 1  # ⚠️ Must update variable manually!
# Output: 0 1 2 3 4

// Zero iterations — condition false from start
x = 10
while x < 5:
    print("never")    // never executes
}

// Infinite loop — common server pattern
while True:
    Request req = server.accept();
    handle(req);
    // exits only via break, return, or exception
}
`} />

```
while flow:
  ┌─────────────────────────┐
  │  evaluate condition      │◄────────────────┐
  └────────────┬────────────┘                  │
               │                               │
        ┌──────┴──────┐                        │
      false          true                      │
        │              │                       │
        ▼         execute body─────────────────┘
   exit loop
```

---

### ⚠️ while Loop — Key Rules

1. **Condition coerces to boolean** — truthy/falsy rules apply
2. **Braces optional** for single non-declarative statement
3. **No unreachable code errors** — infinite loops are runtime issues

<Code lang="python" title="Truthy/Falsy in while" code={`
// ✅ Valid: Non-zero numbers are truthy
x = 1;
while (x):
    print("runs");  // Infinite loop! 1 is truthy.
    x = 0;  // Stop condition


// ❌ Trap: 0 is falsy
y = 0;
while (y):
    print("won't run");  // Skipped!
`} />

<Code lang="python" title="Braces rules" code={`
// ✅ Valid: single statement, no braces
while (true):
    print("hello");  // infinite loop

// ⚠️ Dangerous: only first line is part of loop
while (true):
    print("hello")
    print("always prints");  // NOT part of loop!

// ❌ Invalid: declarative statement without braces
while (true):
    x = 10  // ❌ Error: Lexical declaration cannot appear in a single-statement context

// ✅ Fix: use braces
while (true):
    print("hello")
`} />

### 🔬 Unreachable Code in while — Same Rules as for

<Card title="Condition always true → infinite loop" icon="error">

</Card>

<Card title="Condition always false → loop unreachable" icon="error">


    ```python
        print("hi");            // ✅ Compiles fine! Never reached at runtime.
    ```
</Card>

## 🔬 Iterator Protocol — Custom Iterable

```python
class CountDown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):     # makes it iterable
        self.current = self.start
        return self         # returns iterator (itself)

    def __next__(self):     # makes it an iterator
        if self.current <= 0:
            raise StopIteration
        val = self.current
        self.current -= 1
        return val

for n in CountDown(5):
    print(n)
# 5, 4, 3, 2, 1
```

```
┌───────────────────────────────────────────────────────┐
│  ITERABLE    has __iter__ → returns iterator         │
│  ITERATOR    has __iter__ + __next__                 │
│  All iterators are iterable (return self from iter) │
│  Not all iterables are iterators (list returns new) │
└───────────────────────────────────────────────────────┘
```

```python
# List is iterable but NOT an iterator:
lst = [1, 2, 3]
iter(lst)           # creates new list_iterator object
next(lst)           # TypeError: list is not an iterator

it = iter(lst)      # now it is an iterator
next(it)            # 1
next(it)            # 2
```

## 💀 Interview Traps

<Card title="Trap 1: `for` Loop Variable Scoping" icon="caution">
    ```python
        for x in range(5):
            pass

        print(x)    # 4  ← x leaks into enclosing scope — always last value

        # Inside function — same:
        def f():
            for x in range(5):
                pass
            print(x)   # 4  ← still accessible

        # BUT — if loop never runs:
        def g():
            for x in []:    # empty iterable
                pass
            print(x)        # NameError — x never bound
    ```
</Card>

<Card title="Trap 2: Modifying List While Iterating" icon="caution">
    ```python
        lst = [1, 2, 3, 4, 5]
        for x in lst:
            if x % 2 == 0:
                lst.remove(x)   # 💀 skips elements!

        print(lst)   # [1, 3, 5]? NO → [1, 3, 5] sometimes but...

        lst = [2, 4, 6]
        for x in lst:
            if x % 2 == 0:
                lst.remove(x)
        print(lst)   # [4]  ← 4 SKIPPED

        # Iterator holds internal index counter.
        # remove() shifts elements left.
        # Counter advances past unvisited elements.

        # Index: 0  → lst=[2,4,6], x=2, remove 2 → lst=[4,6]
        # Index: 1  → lst=[4,6],   x=6, remove 6 → lst=[4]
        # Index: 2  → len=1, stop

        # 4 was NEVER visited.

        # Fix — iterate copy:
        for x in lst[:]:
            if x % 2 == 0:
                lst.remove(x)

        # Better — list comprehension:
        lst = [x for x in lst if x % 2 != 0]
    ```
</Card>

<Card title="Trap 3: `for` Loop Variable Captured in Lambda/Closure" icon="caution">
    ```python
        funcs = [lambda: x for x in range(5)]
        [f() for f in funcs]
        # [4, 4, 4, 4, 4]  ← all return 4 (last value of x)

        # All lambdas capture x by REFERENCE (same closure cell).
        # After loop, x = 4. All lambdas see x = 4.

        # Fix — capture by value via default argument:
        funcs = [lambda x=x: x for x in range(5)]
        [f() for f in funcs]
        # [0, 1, 2, 3, 4]  ✅
    ```
</Card>
