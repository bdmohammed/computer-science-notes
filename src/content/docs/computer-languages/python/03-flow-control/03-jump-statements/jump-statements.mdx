## 🎯 Jump Statements Overview

Python provides three primary statements to alter program flow within loops and functions:

| Statement | Purpose | Valid Locations |
|-----------|---------|----------------|
| `break` | Exit nearest enclosing loop | `for`, `while` |
| `continue` | Skip current iteration, proceed to next | `for`, `while` |
| `return` | Exit function immediately | Inside functions |

> ⚠️ **Note**: Python does **NOT** have labeled breaks/continues, nor does it have a `switch` statement (until `match/case` in 3.10, which doesn't use `break`).

<Aside type="caution">
**Syntax Rule**: Using `break` or `continue` outside a loop → **SyntaxError**: `"break/continue not properly in loop"`.
</Aside>

---

## `break`  — Exit Loop Immediately

> **Exits the nearest enclosing loop immediately**, transferring control to the statement following the loop.

```python
// Exits loop immediately — skips remaining iterations
for num in range(1, 5):
    if num == 3:
        break
    print(num)  # 1, 2

// break only exits INNERMOST loop
for i in range(1, 5):
    for j in range(1, 5):
        if (j == 1):
          break;    // exits inner loop only
                    // outer loop continues
```

---

### ⚠️ Invalid Usage — Syntax Error

<Code lang="python" title="❌ break outside loop" code={`
x = 10
if x == 10:
    break  # ❌ SyntaxError: 'break' outside loop

print("hello")
`} />

<Aside type="note">
**Valid Locations Only**: `break` works **only** inside:
1. `for` loops
2. `while` loops

Using it in `if`, `else`, or plain blocks → Syntax Error.
</Aside>

## 🔄 No Labeled Breaks? No Problem!

Java/C++/JS uses `break label;` to exit nested loops. Python doesn't have labels. How do we handle this?

### 🧠 Pythonic Alternatives

<Card title="Option 1: Extract to Function (Recommended)" icon="approve-check">
  Use `return` to exit multiple levels of nesting at once.
  ```python
    def find_value(matrix, target):
        for row in matrix:
            for val in row:
                if val == target:
                    return True  # Exits BOTH loops
        return False

    # Clean, readable, and Pythonic!
  ```
</Card>

<Card title="Option 2: Exception Handling (Rare)" icon="backspace">
  Use a custom exception to break out of deep nesting.
  ```python
    class FoundException(Exception):
        pass

    try:
        for i in range(10):
            for j in range(10):
                if i + j == 15:
                    raise FoundException()
    except FoundException:
        print("Found it!")
  ```
  **Note**: Only use for truly exceptional cases or very deep nesting.
</Card>

<Card title="Option 3: Boolean Flag" icon="information">
  The traditional approach.
  ```python
    found = False
    for i in range(10):
        for j in range(10):
            if condition:
                found = True
                break
        if found:
            break
  ```
  **Verdict**: Works, but less elegant than extracting a function.
</Card>

<Aside type="tip">
**Best Practice**: If you find yourself needing a labeled break, **extract the nested logic into a helper function** and use `return`. It improves modularity and readability.
</Aside>

## `continue` Statement

> **Skips the current iteration** of the nearest enclosing loop and proceeds to the next iteration.

```python
// Skips rest of current iteration — jumps to update/condition
// Skip even numbers:
for i in range(10):
    if i % 2 == 0:
        continue
    print(i)  # 1, 3, 5, 7, 9

// continue in while — condition still checked:
i = 0
while (i < 5):
    i += 1
    if (i === 3):
        continue  // skips rest of body, checks condition
    print(i)  // 1, 2, 4, 5
```

---

### ⚠️ Invalid Usage

<Code lang="python" title="❌ continue outside loop" code={`
if x > 0:
    continue  # ❌ SyntaxError: 'continue' not properly in loop
`} />

<Aside type="note">
**Valid Locations Only**: `break` works **only** inside:
1. `switch` statements
2. Loop constructs (`for`, `while`)
3. Labeled blocks (rare, advanced use)

Using it in `if`, `else`, or plain blocks → compile error.
</Aside>

## `return` Statement

> **Exits the current function immediately**, optionally returning a value to the caller.

---

### 🔑 Syntax Patterns

<Code lang="python" title="return with value" code={`
def max_val(a, b):
    if a > b:
        return a  # ✅ Exit function, return a
    return b      # ✅ Exit function, return b
`} />

<Code lang="python" title="return without value (void-like)" code={`
def process(x):
    if x < 0:
        return    # ✅ Early exit — guard clause pattern
    # Continue processing only if x >= 0
    print(f"Processing: {x}")
`} />

---

### 🛡️ Guard Clause Pattern — Early Return

<Code lang="python" title="Prefer early returns over nested if" code={`
# ❌ Nested if (Arrow Code - hard to read)
def process_user(user):
    if user is not None:
        if user.is_active:
            if user.has_permission:
                perform_action(user)

# ✅ Guard clauses with early return (Clean!)
def process_user(user):
    if user is None:
        return           # Guard 1
    if not user.is_active:
        return           # Guard 2
    if not user.has_permission:
        return           # Guard 3
    
    # Actual logic — no nesting!
    perform_action(user)
`} />

<Aside type="tip">
**Guard Clause Benefits**:
1. ✅ Reduces nesting (Indentation Hell)
2. ✅ Each validation is independent and clear
3. ✅ Fail-fast: invalid inputs exit early
</Aside>

### Pass Statements — Explicit No-Op

```python
// No-op placeholder — body can't be empty
for i in range(5):
    pass  // valid, does nothing

// Busy wait (avoid in production)
while condition:
    pass  // spins until condition false

// Empty class body
class Empty:
    pass  // valid, creates empty class
```

## ✨ The Unique Python `else` Clause

> Python loops can have an `else` block. It executes **only if the loop completes normally** (i.e., did NOT hit a `break`).

<Code lang="python" title="Loop else usage" code={`
# Scenario: Search for a number
numbers = [1, 3, 5, 7]
target = 4

for n in numbers:
    if n == target:
        print(f"Found {target}")
        break
else:
    # Executes ONLY if break was NOT hit
    print(f"{target} not found in list")

# Output: "4 not found in list"
`} />

<Aside type="tip">
**Why use it?** It eliminates the need for boolean flags like `found = False`. It makes search logic cleaner and more readable.
</Aside>

## 🔬 Bytecode

```python
import dis

def f():
    for x in [1, 2, 3]:
        print(x)

dis.dis(f)
# GET_ITER              ← calls __iter__()
# FOR_ITER    →end      ← calls __next__(), jumps to end on StopIteration
# STORE_FAST  x
# LOAD_GLOBAL print
# LOAD_FAST   x
# CALL        1
# JUMP_BACKWARD →FOR_ITER
# end:
```

```python
import dis

def f():
    x = 0
    while x < 5:
        x += 1

dis.dis(f)
# LOAD_CONST   0
# STORE_FAST   x
# LOAD_FAST    x        ← loop starts here
# LOAD_CONST   5
# COMPARE_OP   
# POP_JUMP_IF_FALSE →end  ← condition false → exit
# LOAD_FAST    x
# LOAD_CONST   1
# BINARY_OP    +=
# STORE_FAST   x
# JUMP_BACKWARD →condition ← go back to top
# end:
```
