## 🔌 Interfaces in Python

> **Python has no `interface` keyword.**  
> Instead, it uses two main concepts to achieve interface-like behavior:
> 1. **Duck Typing**: "If it quacks like a duck, it's a duck." (Implicit)
> 2. **Abstract Base Classes (ABCs)**: Explicit contracts using the `abc` module.
> 3. **Protocols**: Structural typing using `typing.Protocol` (Python 3.8+).

```text
Java Interface      → Python Equivalent
│
├── Contract Only   → ABC (Abstract Base Class)
├── Default Methods → Mixins or Standard Inheritance
├── Static Methods  → @staticmethod
├── Constants       → Module-level UPPER_CASE variables
├── Marker Interface→ Empty Protocol or ABC
└── Functional Int. → Callable Type Hints / Lambdas
```

<Aside type="success">
🎯 **Python Philosophy**: *"We're all consenting adults here."*  
Python prefers **implicit** interfaces (Duck Typing) over explicit ones. You don't *declare* that you implement an interface; you just *implement the methods*.
</Aside>

## 🦆 Duck Typing (The Pythonic Way)

In Java, you must say `class Dog implements Animal`. In Python, if `Dog` has a `.speak()` method, it *is* an Animal for any code that calls `.speak()`.

<Code lang="python" title="Duck Typing in Action" code={`
class Duck:
    def speak(self):
        return "Quack!"

class Dog:
    def speak(self):
        return "Woof!"

# No common parent or interface needed!
def make_it_speak(animal):
    print(animal.speak())  # ✅ Works for both

make_it_speak(Duck())  # Quack!
make_it_speak(Dog())   # Woof!
`} />

<Aside type="note">
**Pros**: Flexible, less boilerplate.  
**Cons**: Errors happen at **runtime** if a method is missing.  
**Fix**: Use **ABCs** or **Protocols** to catch errors early with type checkers (like `mypy`).
</Aside>

## 🏛️ Abstract Base Classes (ABCs)

To enforce a contract explicitly (like Java interfaces), use the `abc` module.

<Code lang="python" title="Defining an Interface with ABC" code={`
from abc import ABC, abstractmethod

class Shape(ABC):  # ✅ Inherits from ABC
    @abstractmethod
    def area(self):
        """Subclasses MUST implement this"""
        pass
    
    @abstractmethod
    def perimeter(self):
        pass

    # ✅ Concrete method (like Java default method)
    def describe(self):
        return f"I am a shape with area {self.area()}"

# ❌ Cannot instantiate abstract class
# s = Shape()  # 💥 TypeError: Can't instantiate abstract class

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    
    def area(self):
        return 3.14 * self.radius ** 2
    
    def perimeter(self):
        return 2 * 3.14 * self.radius

# ✅ Concrete subclass works
c = Circle(5)
print(c.describe())  # "I am a shape with area 78.5"
`} />

### 🔑 Key Rules for ABCs
1. **Inherit from `ABC`**: The class must subclass `abc.ABC`.
2. **Use `@abstractmethod`**: Decorate methods that *must* be implemented.
3. **No Instantiation**: You cannot create an instance of an ABC until all abstract methods are implemented.
4. **Concrete Methods Allowed**: ABCs can have regular methods with bodies (similar to Java `default` methods).

## 📜 Protocols (Structural Typing)

Introduced in Python 3.8, `Protocol` allows **static duck typing**. It checks if a class *has* the right methods, without requiring inheritance. This is closer to Go interfaces or TypeScript structural types.

<Code lang="python" title="Using Protocol for Static Checks" code={`
from typing import Protocol

class Flyable(Protocol):
    def fly(self) -> str: ...

class Bird:
    def fly(self) -> str:
        return "Flapping wings"

class Plane:
    def fly(self) -> str:
        return "Using engines"

# ✅ Type checker (mypy) validates this:
def take_off(vehicle: Flyable):
    print(vehicle.fly())

take_off(Bird())  # ✅ Has .fly()
take_off(Plane()) # ✅ Has .fly()
# take_off("Car") # ❌ mypy error: str has no attribute 'fly'
`} />

<Aside type="tip">
**ABC vs Protocol**:
- **ABC**: Requires explicit inheritance (`class Dog(Animal)`). Good for runtime checks (`isinstance`).
- **Protocol**: Implicit structure. Good for decoupling libraries. No inheritance needed.
</Aside>

## 🔄 Multiple "Inheritance"

Python supports multiple inheritance, allowing a class to implement multiple ABCs or Protocols.

<Code lang="python" title="Multiple Interfaces" code={`
from abc import ABC, abstractmethod

class Swimmable(ABC):
    @abstractmethod
    def swim(self): pass

class Flyable(ABC):
    @abstractmethod
    def fly(self): pass

# ✅ Implementing multiple interfaces
class Duck(Swimmable, Flyable):
    def swim(self):
        print("Paddling...")
    
    def fly(self):
        print("Flying...")

d = Duck()
d.swim()
d.fly()
`} />

## 📦 Variables & Constants in Interfaces

Java interfaces have `public static final` variables. Python doesn't have interface fields. Instead, use **Module-Level Constants**.

| Java Interface | Python Equivalent |
|----------------|-------------------|
| `int MAX_SIZE = 100;` | `MAX_SIZE = 100` (in module) |
| `String URL = "api.com";` | `URL = "api.com"` (in module) |

<Code lang="python" title="Constants Pattern" code={`
# config.py
MAX_RETRIES = 3
API_URL = "https://api.example.com"

# main.py
import config

print(config.MAX_RETRIES)  # Access like static final
`} />

<Aside type="caution">
**Convention**: Use `UPPER_CASE` for constants. Python doesn't enforce immutability, but linters will warn if you modify them.
</Aside>

## 🏷️ Marker Interfaces

Java uses empty interfaces like `Serializable`. In Python, use **Empty Protocols** or **ABCs**.

<Code lang="python" title="Marker Protocol" code={`
from typing import Protocol

class Serializable(Protocol):
    """Marker interface for serializable objects"""
    pass

class User:
    def __init__(self, name):
        self.name = name

# Usage in type hints
def save_to_disk(obj: Serializable):
    ...

# Or use isinstance with ABC
from abc import ABC
class SerializableABC(ABC):
    pass

class Data(SerializableABC):
    pass

print(isinstance(Data(), SerializableABC))  # True
`} />

  </Card>

## 🧩 DSA Angle: Comparator Pattern

In Java, you implement `Comparator`. In Python, you use **Key Functions** or **Protocols**.

<Code lang="python" title="Sorting with Custom Logic" code={`
from typing import Protocol

class Comparable(Protocol):
    def __lt__(self, other: 'Comparable') -> bool: ...

# ✅ Python uses rich comparison methods (__lt__, __gt__) instead of Comparator interface
class Student:
    def __init__(self, name, grade):
        self.name = name
        self.grade = grade
    
    def __lt__(self, other):
        return self.grade < other.grade

students = [Student("Alice", 90), Student("Bob", 85)]
students.sort()  # ✅ Uses __lt__ automatically
`} />

| Goal | Python Technique |
|------|------------------|
| **Define Contract** | `class Foo(ABC)` + `@abstractmethod` |
| **Structural Typing** | `class Foo(Protocol)` |
| **Default Method** | Regular method in ABC/Protocol |
| **Static Method** | `@staticmethod` |
| **Constant** | Module-level `CONST_NAME = value` |
| **Marker** | Empty ABC or Protocol |
| **Functional Interface** | `Callable[[Args], Return]` |

<Aside type="caution">
**Final Checklist**:
1. ✅ Use `ABC` for explicit base classes.
2. ✅ Use `Protocol` for decoupled structural typing.
3. ✅ Remember: Errors in ABCs happen at **instantiation**, not definition.
4. ✅ Use `@abstractmethod` to enforce implementation.
5. ✅ Prefer Duck Typing for simple scripts; ABCs/Protocols for large systems.
</Aside>

## 1️⃣ ABC — Abstract Base Class

### Basic Interface

```python
from abc import ABC, abstractmethod
from typing import Iterator

class Repository(ABC):
    """Interface for data access layer."""

    @abstractmethod
    def find_by_id(self, id: int): ...

    @abstractmethod
    def find_all(self) -> list: ...

    @abstractmethod
    def save(self, entity) -> None: ...

    @abstractmethod
    def delete(self, id: int) -> None: ...

    # CONCRETE method — shared behavior across all implementations:
    def exists(self, id: int) -> bool:
        return self.find_by_id(id) is not None
```

```python
# Attempt to instantiate interface → TypeError:
Repository()
# TypeError: Can't instantiate abstract class Repository
# with abstract methods find_by_id, find_all, save, delete

# Must implement ALL abstract methods:
class UserRepository(Repository):
    def __init__(self):
        self._store = {}

    def find_by_id(self, id: int):
        return self._store.get(id)

    def find_all(self) -> list:
        return list(self._store.values())

    def save(self, entity) -> None:
        self._store[entity.id] = entity

    def delete(self, id: int) -> None:
        self._store.pop(id, None)

repo = UserRepository()   # ✅ all abstract methods implemented
repo.exists(1)            # ✅ inherited concrete method works
```

### 🔬 How ABC Enforcement Works

```
ABCMeta is a METACLASS — it overrides __new__ and __call__:

1. At class creation (ABCMeta.__new__):
   Collects all methods decorated with @abstractmethod
   Stores in cls.__abstractmethods__ = frozenset({names})

2. At instantiation (ABCMeta.__call__):
   Checks if cls.__abstractmethods__ is non-empty
   If yes → TypeError (class is abstract, can't instantiate)

3. When subclass defines all methods:
   ABCMeta computes new __abstractmethods__ = base.__abstractmethods__ - implemented
   If empty → subclass is concrete, can be instantiated
```

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...

    @abstractmethod
    def perimeter(self) -> float: ...

Shape.__abstractmethods__             # frozenset({'area', 'perimeter'})

class Circle(Shape):
    def area(self) -> float: ...     # only area implemented

Circle.__abstractmethods__           # frozenset({'perimeter'})  ← still abstract
Circle()                             # TypeError — perimeter missing

class Square(Shape):
    def area(self) -> float: ...
    def perimeter(self) -> float: ...

Square.__abstractmethods__           # frozenset()  ← empty — concrete
Square()                             # ✅
```

### Virtual Subclasses — `register()`

```python
from abc import ABC, abstractmethod

class Drawable(ABC):
    @abstractmethod
    def draw(self): ...

# Third-party class you CAN'T modify:
class ExternalWidget:
    def draw(self):
        print("drawing widget")

# Register it as virtual subclass:
Drawable.register(ExternalWidget)

w = ExternalWidget()
isinstance(w, Drawable)      # True  ← registered
issubclass(ExternalWidget, Drawable)  # True

# BUT: register is UNCHECKED — no verification of methods:
class FakeDrawable:
    pass                     # has no draw() at all

Drawable.register(FakeDrawable)
isinstance(FakeDrawable(), Drawable)  # True  ← LIES
FakeDrawable().draw()                 # AttributeError at runtime
```

## 2️⃣ Protocol — Structural Subtyping (3.8+)

```python
from typing import Protocol

class Drawable(Protocol):
    def draw(self, canvas) -> None: ...
    def resize(self, factor: float) -> None: ...
```

```python
# Any class with these methods satisfies Drawable:
class Circle:
    def draw(self, canvas) -> None:
        canvas.circle(self.x, self.y, self.r)

    def resize(self, factor: float) -> None:
        self.r *= factor

class Rectangle:
    def draw(self, canvas) -> None:
        canvas.rect(self.x, self.y, self.w, self.h)

    def resize(self, factor: float) -> None:
        self.w *= factor
        self.h *= factor

# NEITHER inherits from Drawable — yet both satisfy it!
def render_all(shapes: list[Drawable], canvas) -> None:
    for shape in shapes:
        shape.draw(canvas)

render_all([Circle(), Rectangle()], canvas)   # ✅ mypy accepts this
```

```
Protocol checks at STATIC ANALYSIS TIME (mypy/pyright).
No isinstance check needed.
No inheritance required.
Any class with matching method signatures qualifies.
```

### 🔬 `@runtime_checkable` — Enable `isinstance`

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Sized(Protocol):
    def __len__(self) -> int: ...

@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...

isinstance([1, 2, 3], Sized)        # True   ← list has __len__
isinstance(42,        Sized)        # False  ← int has no __len__
isinstance(open("f"), Closeable)    # True   ← file has close()
```

```
WITHOUT @runtime_checkable:
  isinstance(x, MyProtocol)   → TypeError: not a runtime-checkable Protocol

WITH @runtime_checkable:
  isinstance checks ONLY method PRESENCE (not signatures)
  It's a shallow check — method must exist, signature not verified

class Liar:
    def __len__(self):
        return "not an int"   # wrong return type

isinstance(Liar(), Sized)    # True ← runtime check passes!
                             # mypy would catch this statically
```

## 4️⃣ ABC vs Protocol — When to Use Each

```
┌────────────────────────────────────────────────────────────────┐
│                    DECISION MATRIX                             │
├──────────────────────┬─────────────┬──────────────────────────┤
│                      │    ABC      │       Protocol           │
├──────────────────────┼─────────────┼──────────────────────────┤
│ Explicit inheritance │     ✅      │          ❌              │
│ Duck typing          │     ❌      │          ✅              │
│ Runtime isinstance   │     ✅      │  ✅ (if @runtime_check) │
│ Static type check    │     ✅      │          ✅              │
│ Third-party classes  │  register() │          ✅ (automatic)  │
│ Shared impl (mixin)  │     ✅      │          ❌              │
│ Enforcement          │   Runtime   │       Static only        │
│ Python version       │    2.6+     │          3.8+            │
│ Use case             │ IS-A        │ CAN-DO                   │
└──────────────────────┴─────────────┴──────────────────────────┘

USE ABC when:
  ├── You control the class hierarchy
  ├── You want shared implementation (concrete methods)
  ├── You need runtime isinstance enforcement
  └── Explicit "is-a" relationship matters

USE Protocol when:
  ├── You don't control third-party classes
  ├── You want duck typing with static verification
  ├── Defining function parameter interfaces
  └── "can-do" capability matters, not lineage
```

## 🔬 Mixin Pattern — Interface + Shared Implementation

```python
from abc import ABC, abstractmethod

class JSONMixin:
    """Concrete mixin — provides JSON serialization to any class."""
    def to_json(self) -> str:
        import json
        return json.dumps(self.__dict__)

    @classmethod
    def from_json(cls, data: str):
        import json
        return cls(**json.loads(data))


class TimestampMixin:
    """Adds created_at/updated_at management."""
    def __init__(self, *args, **kwargs):
        import time
        super().__init__(*args, **kwargs)
        self.created_at = time.time()
        self.updated_at = time.time()

    def touch(self):
        import time
        self.updated_at = time.time()


class Persistable(ABC):
    @abstractmethod
    def save(self) -> None: ...

    @abstractmethod
    def load(self, id: int) -> None: ...


class User(JSONMixin, TimestampMixin, Persistable):
    def __init__(self, name: str, email: str):
        self.name  = name
        self.email = email
        super().__init__()     # ← triggers TimestampMixin.__init__ via MRO

    def save(self) -> None:
        db.write(self.to_json())

    def load(self, id: int) -> None:
        data = db.read(id)
        obj = self.from_json(data)
        self.__dict__.update(obj.__dict__)
```

```
MRO for User:
  User → JSONMixin → TimestampMixin → Persistable → ABC → object
  super() chain follows this order.
```

## 🔬 DSA Connection

```python
# Protocol for graph algorithms — any graph structure works:
from typing import Protocol, Iterator

class Graph(Protocol):
    def neighbors(self, node: int) -> Iterator[int]: ...
    def nodes(self) -> Iterator[int]: ...

# BFS works with ANY Graph implementation:
from collections import deque

def bfs(graph: Graph, start: int) -> list[int]:
    visited = {start}
    queue   = deque([start])
    order   = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph.neighbors(node):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

# AdjList, Matrix, EdgeList all work as long as they implement Graph Protocol
class AdjacencyList:
    def __init__(self, edges):
        from collections import defaultdict
        self._g = defaultdict(list)
        for u, v in edges:
            self._g[u].append(v)

    def neighbors(self, node): return iter(self._g[node])
    def nodes(self):           return iter(self._g)

bfs(AdjacencyList([(1,2),(1,3),(2,4)]), 1)   # ✅ satisfies Graph Protocol
```

## 🚀 Real-World Production Patterns

### Pattern 1 — Service Layer Interface

```python
from abc import ABC, abstractmethod
from typing import Protocol

# ABC for service with shared retry logic:
class BasePaymentGateway(ABC):

    MAX_RETRIES = 3

    @abstractmethod
    def charge(self, amount: int, token: str) -> dict: ...

    @abstractmethod
    def refund(self, charge_id: str) -> dict: ...

    def charge_with_retry(self, amount: int, token: str) -> dict:
        for attempt in range(self.MAX_RETRIES):
            try:
                return self.charge(amount, token)
            except TimeoutError:
                if attempt == self.MAX_RETRIES - 1:
                    raise

class StripeGateway(BasePaymentGateway):
    def charge(self, amount: int, token: str) -> dict:
        return stripe.charge(amount, token)

    def refund(self, charge_id: str) -> dict:
        return stripe.refund(charge_id)

class BraintreeGateway(BasePaymentGateway):
    def charge(self, amount: int, token: str) -> dict:
        return braintree.transaction.sale({"amount": amount})

    def refund(self, charge_id: str) -> dict:
        return braintree.transaction.refund(charge_id)
```

### Pattern 2 — Protocol for Dependency Injection

```python
from typing import Protocol

# Define what you NEED — not what it IS:
class Cache(Protocol):
    def get(self, key: str) -> bytes | None: ...
    def set(self, key: str, value: bytes, ttl: int = 0) -> None: ...
    def delete(self, key: str) -> None: ...

class UserService:
    def __init__(self, cache: Cache):    # accepts ANY Cache implementation
        self._cache = cache

    def get_user(self, id: int) -> dict:
        key = f"user:{id}"
        if cached := self._cache.get(key):
            return json.loads(cached)
        user = db.query_user(id)
        self._cache.set(key, json.dumps(user).encode(), ttl=300)
        return user

# Works with Redis, Memcached, in-memory dict — all satisfy Cache protocol
class InMemoryCache:
    def __init__(self):
        self._store = {}

    def get(self, key): return self._store.get(key)
    def set(self, key, value, ttl=0): self._store[key] = value
    def delete(self, key): self._store.pop(key, None)

# Testing — no mock framework needed:
svc = UserService(InMemoryCache())   # ✅ satisfies Cache Protocol
```

## 💀 Interview Trap 5 — Multiple ABCs and Diamond MRO

```python
from abc import ABC, abstractmethod

class A(ABC):
    @abstractmethod
    def method(self): ...

class B(A):
    def method(self): return "B"   # implements A.method

class C(A):
    def method(self): return "C"   # implements A.method

class D(B, C):                     # diamond
    pass                           # which method()?

D()             # ✅ — B.method called (MRO: D→B→C→A)
D().method()    # "B"

# D.__abstractmethods__ = frozenset()  ← empty, because B satisfies A
# MRO: D → B → C → A → ABC → object
```
