## ⚡ Static Control Flow in Java

---

### 🧠 What It Is

When the JVM **loads a class**, it runs static members in a defined, strict order — before any object is created, before `main()` runs, before anything else. This sequence is **Static Control Flow**.

---

### 🔬 Three Phases (JVM Execution Model)

```
CLASS LOADING TRIGGERED
        │
        ▼
┌─────────────────────────────────────────────┐
│  PHASE 1 — IDENTIFICATION                   │
│  JVM scans top-to-bottom                    │
│  All static variables → assigned DEFAULT    │
│  values (0, null, false)                    │
│  No assignments run. No blocks run.         │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│  PHASE 2 — EXECUTION (top → bottom)         │
│  Static variable assignments  ──┐           │
│  Static initializer blocks    ──┤ in order  │
│  (interleaved by position)    ──┘           │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│  PHASE 3 — main() executes                  │
│  (only for the entry-point class)           │
└─────────────────────────────────────────────┘
```

The Execution Order 📜
Interview Critical: Memorize this sequence.
Static Variables (Default values → Explicit values)
Static Blocks (Top to bottom)
Main Method
🏛️ Flow Diagram
```
+---------------------+
|   Class Loading     |
+---------------------+
         |
         v
+---------------------+
| 1. Static Vars      | (Memory Allocation)
+---------------------+
         |
         v
+---------------------+
| 2. Static Blocks    | (Initialization Logic)
+---------------------+
         |
         v
+---------------------+
| 3. Main Method      | (Program Starts)
+---------------------+
```

🧠 Key Rule
Static code runs ONCE when the class is loaded into memory, before the main method executes.

---

### 📋 Execution Order Rules

| Rule | Behavior |
|------|----------|
| Static variables | Get **default** value in Phase 1 (`0`, `null`, `false`) |
| Assignments + blocks | Execute **top-to-bottom** in Phase 2 |
| Multiple static blocks | All run, in order of appearance |
| Class loaded once | Phases run **exactly once** per ClassLoader |
| Inheritance | **Parent** static flow completes **before** child's |

### 💻 Real-World Code — Config Loader Pattern

```java
public class AppConfig {

    // Phase 1: x = 0 (default)
    static int timeout = loadTimeout();    // Phase 2, step 1

    // Phase 2, step 2 — static block
    static {
        System.out.println("Block 1 — timeout so far: " + timeout); // 30
    }

    static int maxRetries = 3;             // Phase 2, step 3

    // Phase 2, step 4
    static {
        System.out.println("Block 2 — maxRetries: " + maxRetries);  // 3
        System.out.println("timeout again: " + timeout);             // 30
    }

    static int loadTimeout() {
        // At this point, maxRetries is still 0 (default — not yet assigned)
        System.out.println("loadTimeout called — maxRetries = " + maxRetries); // 0 ← TRAP
        return 30;
    }
}
```

**Output:**
```
loadTimeout called — maxRetries = 0   ← Phase 1 default, not 3
Block 1 — timeout so far: 30
Block 2 — maxRetries: 3
Block 2 — timeout again: 30
```

🔴 **What breaks if done wrong:** Assuming `maxRetries` is `3` inside `loadTimeout()`. It's `0`. This silently misconfigures retry logic in prod with no exception thrown.

```java
class Base {

    static int i = 10; 
    // (1) Static variable i initialized

    static {
        // (2) First static block starts

        methodOne(); 
        // (3) Calls methodOne()

        System.out.println("first static block"); 
        // (5) Prints: first static block
    }

    public static void main(String[] args) {
        // (8) main() starts after class loading

        methodOne(); 
        // (9) Calls methodOne()

        System.out.println("main method"); 
        // (11) Prints: main method
    }

    public static void methodOne() {
        System.out.println(i); 
        // (4) Prints: 10  (when called from static block)
        // (10) Prints: 10 (when called from main)
    }

    static {
        // (6) Second static block starts

        System.out.println("second static block"); 
        // (7) Prints: second static block
    }

    static int j = 20; 
    // (12) Static variable j initialized
}
```

Read indirectly write only state (or) RIWO :
With in the static block if we are trying to read any variable then that read is
considered as "direct read"
If we are calling a method , and with in the method if we are trying to read a method ,
that read is called Indirect read
If a variable is in RIWO state then we can't perform read operation directly otherwise
we will get compile time error saying " illegal forward reference ".


🧩 Example 1 — System.exit() in static block
class Test {

    static int i = 10; 
    // (1) i initialized

    static {
        // (2) static block runs during class loading

        System.out.println(i); 
        // (3) prints 10

        System.exit(0); 
        // (4) JVM terminates immediately → main() NEVER runs
    }

    public static void main(String[] args) {
        // ❌ This will never execute
        System.out.println("main");
    }
}
✅ Output
10
💡 Key Insight
System.exit(0) kills JVM immediately
Even main() won’t execute

🧩 Example 2 — Illegal Forward Reference
class Test {

    static {
        // (1) static block executes first (top → bottom order)

        System.out.println(i); 
        // ❌ COMPILE ERROR: illegal forward reference
        // because i is declared later
    }

    static int i = 10; 
    // (2) declaration comes AFTER usage → not allowed
}
❌ Output
Compile-time error: illegal forward reference
💡 Key Insight
In static context:
You cannot use a variable before it's declared
Even though JVM assigns default value (0), Java blocks access at compile time

🧩 Example 3 — Method Call Bypasses Forward Reference Rule
class Test {

    static {
        // (1) static block runs first

        methodOne(); 
        // (2) method call is allowed (no direct variable access)
    }

    public static void methodOne() {
        System.out.println(i); 
        // (3) i is accessed here → default value (0)
    }

    static int i = 10; 
    // (4) actual initialization happens AFTER static block
}
❌ Runtime Behavior
0

### 🔁 Inheritance — Parent Before Child
Interview Favorite: When does the parent static block run?
🧠 Rule: Parent static members load BEFORE Child static members.

```java
class Parent {
    static int x = 10;
    static {
        System.out.println("Parent static block — x = " + x); // 10
    }
}

class Child extends Parent {
    static int y = 20;
    static {
        System.out.println("Child static block — y = " + y);  // 20
        System.out.println("Inherited x = " + x);             // 10
    }
}

// Trigger: new Child() or Child.y
// Output:
// Parent static block — x = 10
// Child static block — y = 20
// Inherited x = 10
```

```
Class Loading Order (Inheritance):
  java.lang.Object
       │
    Parent  ←── loads & initializes first
       │
    Child   ←── loads & initializes second
```

```java
class Base {

    static int i = 10; 
    // (1) Base: i initialized → 10

    static {
        // (2) Base: first static block

        methodOne(); 
        // (3) calls methodOne()

        System.out.println("base static block"); 
        // (5)
    }

    public static void main(String[] args) {
        // (Not used — Derived.main runs)

        methodOne();
        System.out.println("base main");
    }

    public static void methodOne() {
        System.out.println(i); 
        // (4) prints 10
    }

    static int j = 20; 
    // (6) Base: j initialized → 20
}


// =============================


class Derived extends Base {

    static int x = 100; 
    // (7) Derived: x initialized → 100

    static {
        // (8) Derived: first static block

        methodTwo(); 
        // (9) calls methodTwo()

        System.out.println("derived first static block"); 
        // (11)
    }

    public static void main(String[] args) {
        // (14) Entry point (JVM starts here)

        methodTwo(); 
        // (15)

        System.out.println("derived main"); 
        // (17)
    }

    public static void methodTwo() {
        System.out.println(y); 
        // (10) prints 0 (default value)
        // (16) prints 200 (after initialization)
    }

    static {
        // (12) Derived: second static block

        System.out.println("derived second static block"); 
        // (13)
    }

    static int y = 200; 
    // (18) Derived: y initialized → 200
}
```

### ⚠️ Forward Reference Rule

```java
class A {
    static {
        x = 10;                        // ✅ WRITE allowed before declaration
        // int z = x;                  // ❌ COMPILE ERROR — illegal forward reference (READ)
    }
    static int x = 20;                 // Phase 2 runs this AFTER block → x = 20, not 10
}
```

| Operation | Before Declaration | Result |
|-----------|-------------------|--------|
| Write (`x = 10`) | ✅ Allowed | Value gets overwritten by later assignment |
| Read (`int z = x`) | ❌ Compile error | `illegal forward reference` |

### 💣 Interview Traps

**🪤 Trap 1 — Compile-Time Constants skip class loading**

```java
class Config {
    static final int PORT = 8080;          // compile-time constant
    static final int TIMEOUT = getVal();   // NOT a constant (method call)

    static {
        System.out.println("Config loaded");
    }

    static int getVal() { return 30; }
}

class Main {
    public static void main(String[] args) {
        System.out.println(Config.PORT);    // "Config loaded" is NEVER printed
        System.out.println(Config.TIMEOUT); // "Config loaded" IS printed
    }
}
```

Why: `static final int PORT = 8080` is **inlined at compile time** (constant folding). The JVM never loads `Config`. `TIMEOUT` requires method call → class loads → static block runs.

This fails senior devs who assume accessing any static field loads the class.

---

**🪤 Trap 2 — Static variable value depends on method call order**

```java
class DB {
    static int poolSize = init();    // calls init() when poolSize is still 0
    static int maxConn = 100;

    static int init() {
        return maxConn / 2;          // maxConn = 0 (default) → returns 0
    }
}
// DB.poolSize = 0, not 50
```

Prod scenario: connection pool silently initializes with 0 connections. App starts fine. First DB call throws "No connections available" under load.

---

**🪤 Trap 3 — Circular Static Initialization**

```java
class A {
    static int val = B.val + 1;  // B loads → B tries to use A.val
}

class B {
    static int val = A.val + 1;  // A not done yet → A.val = 0 (default)
}

// A.val = 0 + 1 = 1? No.
// B loads first → A.val still 0 → B.val = 1 → A.val = 2
// Result depends on which class triggers loading first
// Silent wrong values. No exception.
```

**🪤 Trap 4 — Forward Referencing**
```java
class Test {
    static int x = y; // ❌ Compile Error: Illegal forward reference
    static int y = 10;
}
```
Rule: You cannot use a static variable before it is declared.

Trap 2: Static vs. Instance
class Test {
    static { System.out.println("Static"); }
    { System.out.println("Instance"); } // Instance Block
    
    public static void main(String[] args) {
        new Test(); // Triggers Instance Block
    }
}

Static      (Runs once at class load)
Instance    (Runs every time 'new Test()' is called)


### 🔧 Class Loading Triggers

| Trigger | Class Loaded? |
|---------|--------------|
| `new MyClass()` | ✅ Yes |
| `MyClass.staticMethod()` | ✅ Yes |
| `MyClass.staticField` (non-constant) | ✅ Yes |
| `MyClass.CONSTANT` (`static final` literal) | ❌ No |
| Subclass loaded | ✅ Yes (parent first) |
| `Class.forName("MyClass")` | ✅ Yes |
| Declaring a variable `MyClass obj;` | ❌ No |

### 🔩 DSA / Internals Connection

**Underlying primitive: Single-pass linear scan + flag-based mutual exclusion**

The JVM uses an **initialization lock** (`<clinit>` method in bytecode) per class. This is the compiled form of all static blocks + static variable assignments merged top-to-bottom.

```
javap -c MyClass  →  shows <clinit>() method
```

- Only **one thread** runs `<clinit>`. Others **block** until it completes.
- This is why static initialization is **thread-safe by default**.
- If `<clinit>` throws, class enters **error state** — future access throws `NoClassDefFoundError`, not the original exception.

```
Thread 1: triggers class load → acquires init lock → runs <clinit>
Thread 2: waits on init lock
Thread 3: waits on init lock
              ↓
Thread 1 done → lock released → Threads 2 & 3 see initialized class
```

Real-Life & DSA Context 🏢
🏢 Real-Life: Utility Classes
Scenario: You have a Config class that loads database properties once.
Usage: Put loading logic in a static block.
Benefit: Runs once at startup, not every time you call a method.
class Config {
    static String DB_URL;
    static {
        // Runs once when class loads
        DB_URL = loadFromFiles(); 
    }
}
🧩 DSA: Precomputation
Scenario: You need a lookup table (e.g., Prime numbers) for multiple test cases.
Usage: Compute once in static block, reuse in all test cases.
Benefit: Saves time complexity across multiple queries.
⚠️ Real-Life Problem: Static Initialization Order Fiasco
Bug: Static variable A depends on Static variable B, but B is defined later.
Result: A gets default value (0/null) instead of expected value.
Fix: Order your static variables carefully or avoid complex static dependencies.


### 🐛 `NoClassDefFoundError` — The Silent Killer

```java
class Config {
    static {
        if (true) throw new RuntimeException("env var missing");
    }
}

// First access:
// → RuntimeException thrown, caught somewhere, logged, forgotten

// Every subsequent access to Config:
// → NoClassDefFoundError (not RuntimeException)
// → Stack trace points to random caller, not the real cause
// → Original exception is GONE
```

Prod pattern: service starts, config init fails silently, every request after that crashes with `NoClassDefFoundError` that looks unrelated to the real root cause.
