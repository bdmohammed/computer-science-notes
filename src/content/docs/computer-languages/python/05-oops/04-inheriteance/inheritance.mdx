## 🧬 Inheritance in Python

> **Inheritance** allows a class (child) to derive attributes and methods from another class (parent).  
> Unlike Java, Python supports **Multiple Inheritance** and uses a dynamic **Method Resolution Order (MRO)** to handle conflicts.

```text
Java Inheritance   → Python Equivalent
│
├── extends        → class Child(Parent):
├── implements     → Not needed (Duck Typing / Protocols)
├── super()        → super()
├── @Override      → Not needed (Dynamic Dispatch)
└── Multiple Inh.  → class Child(Parent1, Parent2): ✅
```

<Aside type="success">
🎯 **Key Insight**: Python is more flexible than Java. You don't need interfaces to achieve polymorphism—any object with the right methods works (Duck Typing). However, for strict contracts, use **Abstract Base Classes (ABCs)**.
</Aside>

## 🗂️ Basic Syntax & Single Inheritance

### 🔑 The `class Child(Parent)` Syntax

<Code lang="python" title="Basic Inheritance" code={`
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f"{self.name} makes a sound."

# Dog inherits from Animal
class Dog(Animal):
    def speak(self):
        # Override parent method
        return f"{self.name} says: Woof!"

# Usage
dog = Dog("Buddy")
print(dog.speak())  # "Buddy says: Woof!"
print(isinstance(dog, Animal))  # True ✅
`} />

### 🧭 What is Inherited?
- **Attributes**: `self.name` from `__init__` (if called via `super()`).
- **Methods**: `speak()` (unless overridden).
- **Not Inherited**: Private attributes (`__var`) are name-mangled, making them hard to access but technically present.

## 🔗 Constructor Chaining with `super()`

In Python, `__init__` is not automatically called. You must explicitly call the parent's constructor using `super()`.

<Code lang="python" title="Using super() for Initialization" code={`
class Animal:
    def __init__(self, species):
        self.species = species

class Dog(Animal):
    def __init__(self, name, breed):
        # ✅ Call parent constructor
        super().__init__("Canine") 
        self.name = name
        self.breed = breed

    def info(self):
        return f"{self.name} is a {self.breed} ({self.species})"

dog = Dog("Rex", "Labrador")
print(dog.info())  # "Rex is a Labrador (Canine)"
`} />

<Aside type="caution">
**Java vs Python**:  
- Java: `super()` is implicit if no args are needed.  
- Python: You **must** call `super().__init__()` if the parent has an `__init__` that requires arguments, otherwise the parent's state won't be initialized.
</Aside>

## 🔄 Method Overriding & Polymorphism

Python uses **dynamic dispatch**. If a child defines a method with the same name as the parent, the child's version is used.

<Code lang="python" title="Overriding and Extending" code={`
class Shape:
    def area(self):
        raise NotImplementedError("Subclasses must implement area()")

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        # Override parent method
        return 3.14 * self.radius ** 2

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2

# Polymorphism in action
shapes = [Circle(5), Square(4)]
for shape in shapes:
    print(shape.area())  # Calls correct method for each object
`} />

## 🌐 Multiple Inheritance & MRO

Unlike Java, Python allows a class to inherit from **multiple parents**. Python resolves method conflicts using the **C3 Linearization Algorithm** (MRO).

<Code lang="python" title="Multiple Inheritance" code={`
class Flyer:
    def fly(self):
        return "Flying..."

class Swimmer:
    def swim(self):
        return "Swimming..."

# Duck inherits from BOTH
class Duck(Flyer, Swimmer):
    pass

duck = Duck()
print(duck.fly())   # "Flying..."
print(duck.swim())  # "Swimming..."

# Check MRO (Method Resolution Order)
print(Duck.__mro__) 
# (<class 'Duck'>, <class 'Flyer'>, <class 'Swimmer'>, <class 'object'>)
`} />

### ⚠️ The Diamond Problem
If two parents inherit from the same grandparent, Python's MRO ensures the grandparent is only initialized once.

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

# MRO: D -> B -> C -> A -> object
# A is visited only once!
```

<Aside type="tip">
**Interview Tip**: Use `ClassName.__mro__` or `help(ClassName)` to see the resolution order. Python searches left-to-right, depth-first, but avoids duplicates via C3 linearization.
</Aside>

## 🚫 Restrictions & Differences from Java

| Feature | Java | Python |
|---------|------|--------|
| **Multiple Class Inheritance** | ❌ No (Interfaces only) | ✅ Yes |
| **`final` Class** | `final class Foo` | No keyword (Convention: `_Final`) |
| **`final` Method** | `final void bar()` | No keyword (Convention: Don't override) |
| **Access Modifiers** | `private`, `protected` | `_protected`, `__private` (Conventions) |
| **Method Overloading** | ✅ Yes (Same name, diff params) | ❌ No (Last definition wins) |
| **Abstract Classes** | `abstract class` | `abc.ABC` + `@abstractmethod` |

## 🎯 Interview Cheat Sheet

<CardGrid>
  <Card title="Q: How does Python handle multiple inheritance?" icon="information">
    Python uses the **Method Resolution Order (MRO)** based on the **C3 Linearization** algorithm. It creates a linear list of classes to search for methods, ensuring each class is visited only once.
  </Card>
  
  <Card title="Q: What is `super()`?" icon="approve-check">
    `super()` returns a proxy object that delegates method calls to a parent or sibling class in the MRO. It’s essential for calling parent constructors (`__init__`) and extending parent methods.
  </Card>

  <Card title="Q: Can you override private methods?" icon="backspace">
    Technically, yes. Python’s "private" (`__method`) is just name mangling (`_Class__method`). A subclass can define its own `__method`, but it won’t override the parent’s mangled method. It’s a new method.
  </Card>

  <Card title="Q: Does Python support method overloading?" icon="error">
    **No.** If you define two methods with the same name, the second one overwrites the first. Use default arguments or `*args`/`**kwargs` instead.
  </Card>

  <Card title="Q: How do you prevent a class from being inherited?" icon="shield">
    Python doesn’t have a `final` keyword. You can raise an error in `__init_subclass__` or use a metaclass to prevent inheritance, but it’s rarely done in Pythonic code.
  </Card>
</CardGrid>

## 🧠 Mental Model First

```
Inheritance = one class ACQUIRES attributes and methods of another.

Child class  → inherits FROM
Parent class → inherited BY (also: base class, superclass)

Python inheritance is DIFFERENT from Java/C++:
  ├── Multiple inheritance natively supported
  ├── MRO (C3 linearization) resolves conflicts
  ├── super() is cooperative, not just "call parent"
  ├── Everything inherits from object implicitly
  └── No private inheritance (no access modifiers on extends)

INHERITANCE CHAIN:
  Dog → Animal → object
  Every class you write has this at minimum:
  MyClass → object
```

```
MEMORY MODEL:

class Animal:
    def speak(self): return "..."

class Dog(Animal):
    def fetch(self): return "fetching"

d = Dog()

Attribute lookup on d.speak():
  1. d.__dict__          → not here
  2. Dog.__dict__        → not here
  3. Animal.__dict__     → FOUND speak() → call it
  4. object.__dict__     → would check next
```

## 1️⃣ Single Inheritance

```python
class Animal:
    def __init__(self, name: str, sound: str):
        self.name  = name
        self._sound = sound

    def speak(self) -> str:
        return f"{self.name} says {self._sound}"

    def breathe(self) -> str:
        return f"{self.name} inhales and exhales"

    def __repr__(self) -> str:
        return f"{type(self).__name__}({self.name!r})"


class Dog(Animal):
    def __init__(self, name: str, breed: str):
        super().__init__(name, "Woof")    # delegate to parent __init__
        self.breed = breed                 # child-specific attribute

    def fetch(self, item: str) -> str:     # new method — child only
        return f"{self.name} fetches the {item}"

    def speak(self) -> str:                # OVERRIDE parent method
        return f"{self.name} barks: WOOF WOOF!"
```

```python
d = Dog("Rex", "Labrador")

d.speak()      # "Rex barks: WOOF WOOF!"   ← overridden
d.breathe()    # "Rex inhales and exhales"  ← inherited from Animal
d.fetch("ball")# "Rex fetches the ball"     ← child-only
d.name         # "Rex"   ← inherited attribute
d.breed        # "Labrador" ← child attribute
repr(d)        # "Dog('Rex')"  ← inherited __repr__

isinstance(d, Dog)     # True  ← direct type
isinstance(d, Animal)  # True  ← parent
isinstance(d, object)  # True  ← always
```

## 🔬 MRO — Method Resolution Order

```
MRO defines the ORDER in which Python searches classes
for attributes and methods.

Stored in:  ClassName.__mro__  (tuple of classes)
Algorithm:  C3 Linearization (Python 2.3+)
```

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

D.__mro__
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
```

```
C3 LINEARIZATION:
  L[D] = D + merge(L[B], L[C], [B, C])

  L[B] = [B, A, object]
  L[C] = [C, A, object]

  merge([B,A,object], [C,A,object], [B,C]):
    Step 1: B is head of first list, not in tail of any → take B
    merge([A,object], [C,A,object], [C]):
    Step 2: A is head, but IS in tail of [C,A,object] → skip
            C is head of second list, not in any tail → take C
    merge([A,object], [A,object], []):
    Step 3: A → take A
    merge([object], [object], []):
    Step 4: object → take object

  L[D] = [D, B, C, A, object]
```

```python
# Visualize MRO:
for cls in D.__mro__:
    print(cls)
# <class 'D'>
# <class 'B'>
# <class 'C'>
# <class 'A'>
# <class 'object'>

# Also available as method:
D.mro()     # same as list(D.__mro__)
```

## 2️⃣ `super()` — Cooperative Multiple Inheritance

```python
class Animal:
    def __init__(self, name: str):
        self.name = name
        print(f"Animal.__init__: {name}")

class Dog(Animal):
    def __init__(self, name: str, breed: str):
        super().__init__(name)            # delegates up the MRO
        self.breed = breed
        print(f"Dog.__init__: breed={breed}")

class ServiceDog(Dog):
    def __init__(self, name: str, breed: str, role: str):
        super().__init__(name, breed)     # delegates to Dog
        self.role = role
        print(f"ServiceDog.__init__: role={role}")
```

```python
sd = ServiceDog("Max", "Lab", "Guide")
# Animal.__init__: Max
# Dog.__init__: breed=Lab
# ServiceDog.__init__: role=Guide
```

### 🔬 `super()` Internals

```
super() in Python 3 (no args) automatically knows:
  1. The class it's defined in (via __class__ cell variable)
  2. The instance (via first argument — self)

super().__init__() does NOT mean "call my parent's __init__"
It means "call the NEXT __init__ in the MRO of type(self)"

This is COOPERATIVE — each class in MRO gets a turn.
```

```python
# Explicit super() — equivalent to implicit:
super(Dog, self).__init__(name)   # old style
super().__init__(name)            # new style (Python 3)

# What super() returns:
class Foo(object):
    def method(self):
        s = super()
        print(type(s))         # <class 'super'>
        print(s.__self_class__) # Foo
        print(s.__self__)       # instance
```

## 4️⃣ Diamond Problem — MRO Resolution

```
        object
       /      \
      A        B
       \      /
          C

"Diamond problem": C inherits from both A and B,
 which both inherit from object.
 Which __init__ gets called?
```

```python
class Base:
    def __init__(self):
        print("Base.__init__")
        super().__init__()          # ← cooperative: must call super!

class Left(Base):
    def __init__(self):
        print("Left.__init__")
        super().__init__()          # ← not "call Base" — call NEXT in MRO

class Right(Base):
    def __init__(self):
        print("Right.__init__")
        super().__init__()

class Diamond(Left, Right):
    def __init__(self):
        print("Diamond.__init__")
        super().__init__()


d = Diamond()
# Diamond.__init__
# Left.__init__
# Right.__init__
# Base.__init__

Diamond.__mro__
# (Diamond, Left, Right, Base, object)
```

```
EACH __init__ called EXACTLY ONCE.
super() follows the MRO — not just "my parent".

Without cooperative super():
  If Left.__init__ called Base.__init__() directly:
  Base.__init__ would run TWICE.
  Right.__init__ would be SKIPPED.
```

```python
# BAD — direct parent call breaks diamond:
class Left(Base):
    def __init__(self):
        Base.__init__(self)    # 💀 skips Right in diamond scenario
                               # Base called twice, Right never called

# GOOD — cooperative super():
class Left(Base):
    def __init__(self):
        super().__init__()     # ✅ follows MRO — Right gets its turn
```

## 5️⃣ Method Overriding

```python
class Shape:
    def area(self) -> float:
        raise NotImplementedError("Subclass must implement area()")

    def describe(self) -> str:
        return f"{type(self).__name__} with area {self.area():.2f}"


class Circle(Shape):
    def __init__(self, radius: float):
        self.radius = radius

    def area(self) -> float:           # OVERRIDE
        import math
        return math.pi * self.radius ** 2


class Rectangle(Shape):
    def __init__(self, w: float, h: float):
        self.w, self.h = w, h

    def area(self) -> float:           # OVERRIDE
        return self.w * self.h

    def describe(self) -> str:         # EXTEND parent — call + add
        base = super().describe()      # gets "Rectangle with area 24.00"
        return f"{base} [{self.w}×{self.h}]"
```

```python
shapes = [Circle(5), Rectangle(4, 6)]
for s in shapes:
    print(s.describe())    # polymorphic — right describe() called
# Circle with area 78.54
# Rectangle with area 24.00 [4.0×6.0]
```

## 6️⃣ Mixin Pattern

```
Mixin = class designed to be MIXED IN to other classes.
        Provides reusable behavior — not a standalone class.

Rules for Mixins:
  ├── No __init__ (or minimal __init__ that calls super())
  ├── Doesn't make sense as standalone object
  ├── Provides specific capability
  └── Named with "Mixin" suffix (convention)
```

```python
class LogMixin:
    """Adds structured logging to any class."""
    def log(self, level: str, message: str) -> None:
        import logging
        logger = logging.getLogger(type(self).__name__)
        getattr(logger, level.lower())(message)

    def log_call(self, method_name: str, **kwargs) -> None:
        self.log("debug", f"{method_name} called with {kwargs}")


class ValidationMixin:
    """Adds field validation to any class."""
    def validate_positive(self, name: str, value: float) -> None:
        if value <= 0:
            raise ValueError(f"{name} must be positive, got {value}")

    def validate_not_empty(self, name: str, value: str) -> None:
        if not value or not value.strip():
            raise ValueError(f"{name} cannot be empty")


class SerializeMixin:
    """Adds dict/JSON serialization to any class."""
    def to_dict(self) -> dict:
        return {
            k: v for k, v in self.__dict__.items()
            if not k.startswith('_')
        }

    def to_json(self) -> str:
        import json
        return json.dumps(self.to_dict())

    @classmethod
    def from_dict(cls, data: dict):
        obj = cls.__new__(cls)
        for k, v in data.items():
            setattr(obj, k, v)
        return obj


class Product(LogMixin, ValidationMixin, SerializeMixin):
    def __init__(self, name: str, price: float, stock: int):
        self.validate_not_empty("name", name)
        self.validate_positive("price", price)
        self.validate_positive("stock", stock)
        self.name  = name
        self.price = price
        self.stock = stock
        self.log("info", f"Created product: {name}")

    def sell(self, qty: int) -> None:
        self.log_call("sell", qty=qty)
        self.validate_positive("qty", qty)
        if qty > self.stock:
            raise ValueError("Insufficient stock")
        self.stock -= qty
        self.log("info", f"Sold {qty} of {self.name}")
```

```python
p = Product("Widget", 9.99, 100)
p.sell(10)
p.to_dict()    # {'name': 'Widget', 'price': 9.99, 'stock': 90}
p.to_json()    # '{"name": "Widget", "price": 9.99, "stock": 90}'

p2 = Product.from_dict({"name": "Gadget", "price": 5.0, "stock": 50})
```

## 7️⃣ `__init_subclass__` — Hook on Subclass Creation

```python
class Plugin:
    """Auto-registers all subclasses as plugins."""
    _registry: dict[str, type] = {}

    def __init_subclass__(cls, name: str = "", **kwargs):
        super().__init_subclass__(**kwargs)
        plugin_name = name or cls.__name__.lower()
        Plugin._registry[plugin_name] = cls
        print(f"Registered plugin: {plugin_name}")

class AuthPlugin(Plugin, name="auth"):
    def run(self): return "authenticating"

class CachePlugin(Plugin, name="cache"):
    def run(self): return "caching"

class MonitorPlugin(Plugin):        # uses class name automatically
    def run(self): return "monitoring"
```

```python
# Registered plugin: auth
# Registered plugin: cache
# Registered plugin: monitorplugin

Plugin._registry
# {'auth': AuthPlugin, 'cache': CachePlugin, 'monitorplugin': MonitorPlugin}

Plugin._registry['auth']().run()  # "authenticating"
```

## 8️⃣ `super()` With `*args, **kwargs` — The Right Pattern

```python
class Base:
    def __init__(self, **kwargs):
        print(f"Base: {kwargs}")
        super().__init__(**kwargs)   # pass remaining to object (should be empty)

class Left(Base):
    def __init__(self, left_param=None, **kwargs):
        print(f"Left: left_param={left_param}")
        super().__init__(**kwargs)   # pass remaining up

class Right(Base):
    def __init__(self, right_param=None, **kwargs):
        print(f"Right: right_param={right_param}")
        super().__init__(**kwargs)

class Combined(Left, Right):
    def __init__(self, left_param, right_param, **kwargs):
        super().__init__(
            left_param=left_param,
            right_param=right_param,
            **kwargs
        )
```

```python
c = Combined(left_param="L", right_param="R")
# Left: left_param=L
# Right: right_param=R
# Base: {}
```

```
Pattern for cooperative __init__ with multiple inheritance:
  Each class pops its OWN parameters from **kwargs
  Passes remaining kwargs up with super()
  Base class receives empty kwargs (absorbed by each level)
```

## 🔬 Inheritance Internals — `__dict__` and `__mro__`

```python
class A:
    x = 1
    def foo(self): return "A.foo"

class B(A):
    y = 2
    def foo(self): return "B.foo"   # shadows A.foo

b = B()

# Where attributes live:
A.__dict__   # {'x': 1, 'foo': <function>, ...}
B.__dict__   # {'y': 2, 'foo': <function>, ...}  ← B's foo only
b.__dict__   # {}  (no instance attributes yet)

# Lookup for b.foo:
# 1. b.__dict__    → not found
# 2. B.__dict__    → FOUND B.foo → return it

# Lookup for b.x:
# 1. b.__dict__    → not found
# 2. B.__dict__    → not found
# 3. A.__dict__    → FOUND x=1 → return it
```

```python
# Type introspection:
B.__bases__       # (A,)             ← direct parents only
B.__mro__         # (B, A, object)   ← full resolution order
B.__subclasses__()# []               ← live subclasses (if any)
issubclass(B, A)  # True
issubclass(A, B)  # False
```

## 🔬 DSA Connection

```python
# Inheritance in tree node design:
class TreeNode:
    def __init__(self, val: int):
        self.val   = val
        self.left  = None
        self.right = None

class AVLNode(TreeNode):
    def __init__(self, val: int):
        super().__init__(val)
        self.height = 1          # AVL-specific

class RedBlackNode(TreeNode):
    def __init__(self, val: int):
        super().__init__(val)
        self.color  = "red"      # RB-specific
        self.parent = None

# All tree algorithms work on TreeNode:
def height(node: TreeNode) -> int:
    if node is None: return 0
    return 1 + max(height(node.left), height(node.right))

# Works for AVLNode and RedBlackNode via polymorphism
```

## 💀 Interview Trap 1 — `super()` Without Cooperative Pattern

```python
class Base:
    def setup(self):
        print("Base.setup")

class Mixin:
    def setup(self):
        print("Mixin.setup")
        super().setup()        # ← cooperative

class MyClass(Mixin, Base):
    def setup(self):
        super().setup()

MyClass().setup()
# Mixin.setup
# Base.setup      ← both run ✅

# Without super() in Mixin:
class BadMixin:
    def setup(self):
        print("BadMixin.setup")
        # NO super().setup()

class MyBadClass(BadMixin, Base):
    def setup(self):
        super().setup()

MyBadClass().setup()
# BadMixin.setup  ← Base.setup NEVER runs ❌
```

## 💀 Interview Trap 2 — `isinstance` vs `type()` With Inheritance

```python
class Animal: pass
class Dog(Animal): pass

d = Dog()

type(d) is Dog        # True
type(d) is Animal     # False  ← type() is EXACT, no inheritance

isinstance(d, Dog)    # True
isinstance(d, Animal) # True   ← isinstance follows MRO

# Common bug — checking exact type when isinstance needed:
def process(animal):
    if type(animal) == Animal:      # 💀 rejects Dog, Cat, etc.
        handle(animal)

def process_correct(animal):
    if isinstance(animal, Animal):  # ✅ accepts all subclasses
        handle(animal)
```

## 💀 Interview Trap 3 — Inconsistent MRO Raises `TypeError`

```python
class A: pass
class B(A): pass

class Broken(A, B):    # 💥 TypeError: Cannot create a consistent MRO
    pass

# Why?
# A's MRO: [A, object]
# B's MRO: [B, A, object]
# Broken wants: [Broken, A, B, ...]
# But B inherits A → A must come AFTER B in MRO
# Broken puts A BEFORE B → contradiction → TypeError

# Fix:
class Fixed(B, A):     # ✅  MRO: [Fixed, B, A, object]
    pass
```

```python
class Animal:
```
