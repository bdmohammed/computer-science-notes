## 🎯 Java Main Method — Complete Guide

> The **main method** is the entry point of every Java program. The JVM looks for this exact signature to start execution.
> Whether the class contains main() method or not, and whether it is properly declared or not, these checking's are not responsibilities of the compiler, at runtime JVM is responsible for this. If JVM unable to find the required main() method then we will get runtime exception saying NoSuchMethodError: main.
---

## 📌 The Exact Signature

```java
class Test {}

Output:
> javac Test.java
> java Test R.E: NoSuchMethodError: main

// At runtime JVM always searches for the main() method with the following prototype

public static void main(String[] args)

// If we are performing any changes to the above syntax then the code won\'t run and will get Runtime exception saying NoSuchMethodError. or main method not found in class Test, please declared main method as p s v m(S[] a)
```

### 🏛️ Architecture: JVM Entry Point

```text
+---------------------+
|      JVM Starts     |
+---------------------+
         |
         v
+---------------------+
|   Load Class        |
|   (e.g., Main)      |
+---------------------+
         |
         v
+---------------------+
|   Look for:         |
|   main(String[])    |
+---------------------+
         |
         v
+---------------------+
|   Execute Code      |
+---------------------+
```

```
java MainClass arg1 arg2
       │
       ▼
┌──────────────────────────────────────────┐
│  1. JVM starts                           │
│     → creates JVM process                │
│     → allocates heap, metaspace, etc.    │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  2. Bootstrap ClassLoader loads          │
│     → java.lang.Object                  │
│     → java.lang.String                  │
│     → other core classes                │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  3. Application ClassLoader loads        │
│     MainClass.class from classpath       │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  4. Static initialization of MainClass   │
│     → static fields initialized          │
│     → static blocks executed             │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  5. JVM creates main thread              │
│     → name: "main"                       │
│     → daemon: false                      │
│     → priority: 5 (NORM_PRIORITY)        │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  6. main thread pushes stack frame       │
│     → invokes MainClass.main(args)       │
│     → execution begins                   │
└──────────────────────────────────────────┘
```
> 🔑 Static initializers run **before** `main()`. If a static block throws, `ExceptionInInitializerError` fires and `main()` never runs.

### 🔑 Keyword Breakdown

| Keyword | Meaning | Why? (Interview Answer) |
| :--- | :--- | :--- |
| **`public`** | Access Modifier | JVM is outside the class. It needs **public** access to call it. |
| **`static`** | Memory Type | JVM calls it **without creating an object**. Static belongs to the class, not an instance. |
| **`void`** | Return Type | The method doesn't return data to the JVM (it exits to OS). |
| **`main`** | Method Name | Fixed identifier recognized by JVM. |
| **`String[]`** | Parameter | Stores **command-line arguments** passed to the program. |
| **`args`** | Variable Name | Convention (can be anything, e.g., `xyz`), but `args` is standard. |

<Aside type="note">
**Memory Trick**: "**P**ublic **S**tatic **V**oid **M**ain" → "**P**lease **S**top **V**isiting **M**e" — the JVM's entry password! 🔑
</Aside>

## 🔬 In-Depth — Why Each Keyword?

```text
1. If NOT public → JVM can't access → ❌ runtime error
java MainClass
Error: Main method not found in class MainClass,
please define the main method as:
   public static void main(String[] args)

2. If NOT static → JVM must create object first
               but WHICH constructor? JVM doesn't know → ❌
// If main() were instance method:
public void main(String[] args) { }     // non-static

// JVM would need to do:
MainClass obj = new MainClass();        // which constructor?
obj.main(args);                         // which args to constructor?

// JVM has no way to know — static solves this:
MainClass.main(args);                   // no object needed — clean entry point

3. If NOT void   → return value goes nowhere (JVM ignores) → ❌
// JVM discards any return value from main()
// To signal exit code to OS — use System.exit()
public static void main(String[] args) {
    if (args.length == 0) {
        System.exit(1);     // exit code 1 → OS — signals failure
    }
    // normal completion → exit code 0 automatically
}

4. If NOT main   → JVM doesn't find entry point → ❌

5. If NOT String[] → signature mismatch → ❌
OS command:
  java OrderService --env=prod --port=8080

JVM receives:
  args[0] = "--env=prod"
  args[1] = "--port=8080"

args is never null — may be empty array (String[0])
if no args passed: args.length == 0
```

## 🔄 Valid Variations — Compiler Allows These

### 1. Var-Args Allowed ✅
Since Java 5, you can use var-args instead of an array.

<Code lang="java" title="Var-args syntax" code={`
// ✅ Valid — compiles to array internally
public static void main(String... args) { }
`} />

### 2. Argument Name Change ✅

<Code lang="java" title="Variable name is flexible" code={`
// ✅ Valid — JVM only cares about type, not name
public static void main(String[] myArgs) { }
public static void main(String[] xyz) { }
`} />

### 3. Final Modifier ✅

<Code lang="java" title="Prevent reassignment" code={`
// ✅ Valid — prevents args = new String[...]
public static void main(final String[] args) { }
`} />

### 4. Overloading `main` ✅ (But JVM Ignores Others)

<Code lang="java" title="Overloading is allowed" code={`
public static void main(String[] args) { } // ✅ JVM calls this
public static void main(int[] args) { }    // ✅ Valid method, but JVM ignores it
public static void main(String args, int x) { } // ✅ Valid overload

// Interview Q: "Can you overload main?"  
// Answer: "Yes, but JVM **only calls** the one with String[] args."`} />

### 5. Modifier Order Doesn't Matter

<Code lang="java" title="static public is valid" code={`
// ✅ Valid — order of public/static doesn't matter
static public void main(String[] args) { }`} />

### 6. Additional Modifiers Allowed

<Code lang="java" title="synchronized, strictfp, etc." code={`
// ✅ Valid — extra modifiers don't break signature
public static synchronized void main(String[] args) { }
public static strictfp void main(String[] args) { }`} />

### 7. Array Declaration Styles

<Code lang="java" title="All valid array syntaxes" code={`
public static void main(String[] args) { }  // ✅ Recommended
public static void main(String []args) { }  // ✅ Valid
public static void main(String args[]) { }  // ✅ Valid (C-style)`} />

### 8. Inheritance & Method Hiding

Static methods follow **method hiding**, not overriding. If child class lacks `main()`, parent's `main()` executes.

<Code lang="java" title="Case 1: Child inherits parent's main" code={`
class Parent {
    public static void main(String[] args) {
        System.out.println("parent main");
    }
}
class Child extends Parent {}
//it is method hiding not method overriding
> javac Parent.java
> java Parent.class
o/p: parent main
> java Child.class
o/p: parent main
`} />

<Code lang="java" title="Case 2: Child hides parent's main" code={`
class Parent {
    public static void main(String[] args) {
        System.out.println("parent main");
    }
}
class Child extends Parent {
    public static void main(String[] args) {
        System.out.println("Child main");
    }
}
// java Child → Output: "Child main" ✅
// This is METHOD HIDING, not overriding (static methods can't be overridden)
`} />

<Aside type="caution">
**Key Distinction**: Static methods use **method hiding**, not polymorphic overriding. The method called depends on the **reference type at compile time**, not the runtime object type.
</Aside>

# ☕ Java 1.7 Enhancements — main() Method

## 🔑 The Key Change

> **Before Java 7**: You could run a program **without main()** using static blocks + `System.exit(0)`.  
> **From Java 7**: **main() is mandatory**. Period.

---

## 🔬 Before Java 7 (Java 6 and Earlier)

<Code lang="java" title="Running without main() — Java 6" code={`class Test {
    static {
        System.out.println("Running without main!");
        System.exit(0); // stop JVM before it looks for main()
    }
}`} />

```text
Output (Java 6):
Running without main!

✅ Worked fine! No error at all.
JVM ran static block → System.exit(0) → stopped → never looked for main()
```

---

## 🔬 From Java 7 Onwards

### Case 1: Static block with exit(0), no main()

<Code lang="java" title="Java 7+ behavior" code={`class Test {
    static {
        System.out.println("Running without main!");
        System.exit(0);
    }
}`} />

```text
Output (Java 7+):
Running without main!
Error: Main method not found in class Test, please define 
the main method as:
   public static void main(String[] args)

⚠️ Static block still runs BUT JVM now explicitlychecks for main() and gives clear error if missing!
```

### Case 2: Static block only, no exit(0), no main()

<Code lang="java" title="Static block without exit" code={`class Test {
    static {
        System.out.println("static block");
    }
}`} />

```text
Java 6:
javac Test.java && java Test
Output:
static block
Exception in thread "main" java.lang.NoSuchMethodError: main

Java 7+:
javac Test.java && java Test
Error: Main method not found in class Test, please define 
the main method as:
   public static void main(String[] args)
```

### Case 3: Both static block AND main()

<Code lang="java" title="Static block + main() — works in all versions" code={`class Test {
    static {
        System.out.println("static block");
    }
    public static void main(String[] args) {
        System.out.println("main method");
    }
}`} />

```text
Java 6 & Java 7+ Output:
static block
main method

✅ Static blocks always execute BEFORE main() — this behavior unchanged!
```

## 🔄 Execution Flow: Java 1.6 vs 1.7+

### Java 1.6 Flow

```mermaid
flowchart TD
    A[Identification of static members]
    B[Execute static block & Variable assignment if it is available]
    C["Check whether main() available or not"]
    D["Execute main() method"]
    E["RE: NoSuchMethodError"]

    A --> B
    B --> C
    C -- Yes --> D
    C -- No --> E
```

```mermaid
    E[Raise Error]

    A -- Yes --> B
    A -- No --> E
    B --> C --> D
```

```text
JVM starts
    ↓
Loads .class file (ClassLoader)
    ↓
Static variables initialized
    ↓
Static blocks executed  ← runs BEFORE main!
    ↓main() called
    ↓

    ↓
JVM exits
```

## 🔬 Step 5 — Reading Command-Line Arguments

```java
public static void main(String[] args) {

    // Raw access
    System.out.println(args.length);    // number of args
    System.out.println(args[0]);        // first arg — AIOOBE if empty

    // Safe access
    if (args.length > 0) {
        String first = args[0];
    }

    // Common patterns:
    // java MyApp 8080
    int port = args.length > 0
        ? Integer.parseInt(args[0])
        : 8080;                         // default if not provided

    // java MyApp --port=8080 --env=prod
    Map<String, String> params = new HashMap<>();
    for (String arg : args) {
        if (arg.startsWith("--") && arg.contains("=")) {
            String[] parts = arg.substring(2).split("=", 2);
            params.put(parts[0], parts[1]);
        }
    }
    int port2 = Integer.parseInt(params.getOrDefault("port", "8080"));
}
```

```java
// Command line args — positional or custom format
```

## 🔬 Step 6 — main() and Threads

```java
public static void main(String[] args) throws InterruptedException {

    System.out.println(Thread.currentThread().getName());   // "main"
    System.out.println(Thread.currentThread().isDaemon());  // false

    // Non-daemon threads keep JVM alive
    Thread worker = new Thread(() -> {
        try { Thread.sleep(5000); }
        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        System.out.println("worker done");
    });
    worker.setDaemon(false);    // default — JVM waits for it
    worker.start();

    System.out.println("main done");
    // main thread exits — but JVM stays alive for worker
}
// Output:
// main
// false
// main done
// (5 seconds later)
// worker done
// JVM exits
```

```
JVM exit condition:
  ALL non-daemon threads finished
  ↓
  JVM calls shutdown hooks
  ↓
  JVM exits

main() finishing ≠ JVM exiting
If non-daemon threads still running → JVM stays alive
Daemon threads: killed immediately when JVM exits
```

## 🔬 Step 7 — Java 21 Instance main() (Preview)

```java
// Java 21+ preview — JEP 445: Unnamed Classes and Instance Main Methods
// Removes ceremony for small programs

// Old way — full ceremony
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

// Java 21 preview — instance main, no class declaration needed
void main() {
    System.out.println("Hello");
}

// Also valid in Java 21 preview:
class Hello {
    void main() {                   // instance method — JVM creates instance
        System.out.println("Hello");
    }
}
```

```
Java 21 main method search order:
  1. static void main(String[])    ← traditional — checked first
  2. static void main()            ← no-arg static
  3. void main(String[])           ← instance with args
  4. void main()                   ← instance no-arg

JVM picks first match.
For instance main: JVM calls no-arg constructor, then main().
```

> 🔑 Java 21 instance main is **preview** — needs `--enable-preview` flag. Production code: still use `public static void main(String[] args)`.

**🪤 Trap 2 — Overloaded main() — which one runs?**

```java
public class MyClass {

    public static void main(String[] args) {
        System.out.println("String[] version");     // ← JVM calls THIS
    }

    public static void main(String args) {          // overloaded — different signature
        System.out.println("String version");       // never called by JVM
    }

    public static void main() {                     // overloaded — no param
        System.out.println("no-arg version");       // never called by JVM (pre-Java 21)
    }
}
// Output: String[] version
// JVM strictly requires: public static void main(String[])
// Other overloads are regular methods — JVM ignores them as entry point
```

---

**🪤 Trap 3 — Calling main() explicitly — recursive or re-entrant**

```java
public static void main(String[] args) {
    System.out.println("count: " + args.length);
    if (args.length < 3) {
        main(new String[]{"a", "b", "c"});  // ✅ legal — main is just a static method
    }
}
// Output:
// count: 0
// count: 3
// main() can call itself — it's just a static method
// recursive main → StackOverflowError if unbounded
// No special JVM protection against re-entrant main
```

---

**🪤 Trap 4 — `System.exit()` skips finally blocks in other threads**

```java
public static void main(String[] args) {
    Thread t = new Thread(() -> {
        try {
            Thread.sleep(10000);
        } finally {
            System.out.println("finally in thread");    // may NOT run
        }
    });
    t.start();

    System.exit(0);     // JVM terminates immediately
    // thread t's finally: skipped — JVM doesn't wait
    // shutdown hooks: DO run (registered via addShutdownHook)
    // finally in main thread: also skipped
}
// Output: (nothing from finally)
// System.exit() = hard stop
```

---

**🪤 Trap 5 — `args` is never null but elements can be**

```java
public static void main(String[] args) {
    // args itself — NEVER null — JVM guarantees String[0] if no args
    if (args == null) { }   // dead code — args is never null

    // But if you do:
    String[] custom = {null, "hello", null};
    main(custom);           // calling main explicitly
    // now args[0] = null — elements can be null when called programmatically
    // args[0].length() → NPE

    // Safe pattern:
    for (String arg : args) {
        if (arg == null) continue;      // guard against programmatic nulls
        processArg(arg);
    }
}
```

## 🔩 DSA / Internals Connection

**Underlying primitive: Stack frame creation + method lookup via constant pool**

```
JVM entry point invocation — bytecode level:

java MainClass arg1 arg2

JVM runtime:
  1. Build String[] from OS args:
     String[] args = new String[]{"arg1", "arg2"};

  2. Resolve main method:
     Class  clazz  = Class.forName("MainClass");
     Method method = clazz.getMethod("main", String[].class);
     // lookup: constant pool → method descriptor → match

  3. Create main thread stack frame:
     frame {
       local variable array:
         slot 0: args  (String[] reference)
       operand stack: empty
       return address: JVM_exit
     }

  4. invokestatic MainClass.main([Ljava/lang/String;)V
     // static method — no 'this' slot

  5. After main() returns:
     frame popped
     main thread terminates
     JVM checks: any non-daemon threads alive?
       yes → wait
       no  → run shutdown hooks → exit

Bytecode descriptor of main:
  ([Ljava/lang/String;)V
   │                 │
```

```java
public class PaymentService {

    private static final Logger log = LoggerFactory.getLogger(PaymentService.class);

    public static void main(String[] args) {

        // Step 1: parse and validate args
        ServiceConfig config = parseArgs(args);

        // Step 2: register shutdown hook — cleanup on Ctrl+C or SIGTERM
        Runtime.getRuntime().addShutdownHook(new Thread(() -> {
            log.info("Shutdown signal received — cleaning up");
            config.getServer().stop();
            config.getDb().close();
            log.info("Shutdown complete");
        }, "shutdown-hook"));

        // Step 3: initialize and start
        try {
            Server server = new Server(config);
            server.start();
            log.info("PaymentService started on port {}", config.getPort());

            // Step 4: keep main thread alive — server runs on other threads
            server.awaitTermination();

        } catch (Exception e) {
            log.error("Failed to start PaymentService", e);
            System.exit(1);     // non-zero exit code → signals failure to OS/k8s
        }
    }

    private static ServiceConfig parseArgs(String[] args) {
        ServiceConfig config = new ServiceConfig();

        for (String arg : args) {
            if (arg.startsWith("--port=")) {
                config.setPort(Integer.parseInt(arg.substring(7)));
            } else if (arg.startsWith("--env=")) {
                config.setEnv(arg.substring(6));
            } else {
                System.err.println("Unknown argument: " + arg);
                System.exit(1);
            }
        }

        return config;
    }
}
```

🔴 **What breaks if done wrong:** No shutdown hook → Ctrl+C kills process → in-flight transactions not committed → DB connections not returned to pool → next startup finds leaked connections → connection pool exhausted → service fails to start.


<Aside type="tip">**Production Best Practice**: Always validate `args` early in `main()` and provide clear usage messages. Exit with non-zero code (`System.exit(1)`) on error to signal failure to shell scripts and orchestrators.</Aside>

## 🔑 Quick Reference Summary

| Requirement | Valid? | Notes |
|------------|--------|-------|
| `public static void main(String[] args)` | ✅ | Exact JVM signature |
| `static public void main(String[] args)` | ✅ | Modifier order flexible |
| `public static void main(String... args)` | ✅ | Var-args compiles to array |
| `public static void main(String[] xyz)` | ✅ | Parameter name doesn't matter |
| `public static void main(final String[] args)` | ✅ | `final` allowed |
| `public static synchronized void main(String[] args)` | ✅ | Extra modifiers OK |
| `private static void main(String[] args)` | ❌ Runtime | JVM can't access |
| `public void main(String[] args)` | ❌ Runtime | Must be `static` |
| `public static int main(String[] args)` | ❌ Runtime | Must return `void` |
| `public static void Main(String[] args)` | ❌ Runtime | Case-sensitive: `main` ≠ `Main` |
| `public static void main()` | ❌ Runtime | Must have `String[]` parameter |

<Aside type="caution">
**Final Warning**: Even if your code compiles, an incorrect `main()` signature causes a **runtime** `NoSuchMethodError`, not a compile error. Always double-check the signature before debugging!
</Aside>
