## What is an Identifier?

**Definition:** An identifier is any name you give to something in your program.

| Used For                | Example                            | Identifier                |
| ----------------------- | ---------------------------------- | ------------------------- |
| Variables               | `int age = 25;`                    | `age`                     |
| Methods                 | `void calculateSum()`              | `calculateSum`            |
| Classes                 | `class BankAccount`                | `BankAccount`             |
| Interfaces              | `interface Flyable`                | `Flyable`                 |
| Packages                | `com.company.utils`                | `com`, `company`, `utils` |
| Constants               | `static final int MAX_SIZE = 100;` | `MAX_SIZE`                |
| Enums                   | `enum Color`                       | `Color`                   |
| Enum Constants          | `RED, GREEN`                       | `RED`, `GREEN`            |
| Constructors            | `BankAccount()`                    | `BankAccount`             |
| Labels                  | `loop:`                            | `loop`                    |
| Generic Type Parameters | `<T>`, `<K, V>`                    | `T`, `K`, `V`             |
| Annotations             | `@Override`                        | `Override`                |


### Example Breakdown

```java
class Test {
    public static void main(String[] args) {
        int x = 10;
        System.out.println("Hello, World!");
    }
}
```

| Identifier | Purpose      |
| ---------- | ------------ |
| `Test`     | class        |
| `main`     | method       |
| `String`   | class/type   |
| `args`     | parameter    |
| `x`        | variable     |
| `System`   | class        |
| `out`      | field/object |
| `println`  | method       |

Things That Are NOT Identifiers ❌

| Thing       | Example                 |
| ----------- | ----------------------- |
| Keywords    | `if`, `class`, `return` |
| Operators   | `+`, `*`, `=`           |
| Literals    | `10`, `"hello"`         |
| Punctuation | `;`, `{}`, `()`         |

<Aside type="tip" title="Remember">
**Identifier = Just a NAME**  
But the compiler treats it as a **MEMORY REFERENCE**.
</Aside>

## The 6 Golden Rules ⭐

### Rule 1 — Allowed Characters

Only these types are allowed:
```
Letters     : a–z, A–Z
Digits      : 0–9
Underscore  : _ // ⚠️ valid pre-Java 9, WARNING in Java 9+, ERROR in Java 21+
Dollar Sign : $
```

<Aside type="caution">
Using anything else (`Special Keyword (#, @, %)`, `Contain spaces`, `Contain operators`, `Reserved keyword`, `boolean literal`, `Null literal`) → **Compile Time Error**
</Aside>

```java
✅ total_number
❌ Total#         // C.E.
```

---

### Rule 2 — Starting Character

Cannot start with a digit (`0–9`).

Java identifiers can start with:
- ✅
    - letter
    - _
    - $
    - Unicode letter (e.g. Arabic, Hindi scripts — yes, really)
- ❌
    - digit

```java
✅ ABC123   // Valid → treated as identifier
❌ 123ABC   // Invalid → treated as a number
```

---

### Rule 3 — Case Sensitivity

Java is **case sensitive**.

```java
abc ≠ ABC ≠ Abc

int number = 10;   // different from →
int Number = 20;
```

---

### Rule 4 — Length Limit

Technically **no limit**, but keep it readable.

```java
numberOfStudents                            // ✅ Good
n                                           // ❌ Too vague
numberOfStudentsInEngineeringDepartment2024 // ❌ Too long
```

<Aside type="tip">
Best practice: keep identifiers **under 15 characters**.
</Aside>

---

### Rule 5 — Reserved Words

Cannot use Java **keywords** as identifiers.

```java
❌ int if = 10;  // invalid
```

---

### Rule 6 — Predefined Class Names

You **can** use predefined class names as identifiers — but avoid it.

```java
✅ int String = 10;  // compiles, outputs 10
⚠️  Legal but bad practice — very confusing
```

---

## Special Characters Deep Dive

### `$` Dollar Sign

✅ Allowed in identifiers.

```java
int $price = 100;
int total$amount = 500;
```

<Aside type="caution">
Technically valid but **not recommended** for normal code.  
`$` is mainly used by the **compiler** for compiler-generated names.  
Example:
```
// Inner class: Outer$Inner.class
// Lambda: MyClass$$Lambda$1
// Avoid $ in handwritten code — collides with generated names
```
</Aside>

---

### `_` Underscore

<Aside type="danger">
Since **Java 9**, `_` alone is **not allowed** as an identifier.
</Aside>

```java
/ _ (single underscore)
int _ = 10;         // Java 7/8: valid with warning
                    // Java 9-20: warning "underscore is a keyword"
                    // Java 21+: COMPILE ERROR — reserved for future (unnamed patterns)
int __ = 10;        // ✅ two underscores — always valid

// Java 21+ unnamed variable (the reason _ was reserved):
if (obj instanceof Point(int x, _)) {   // _ = unnamed pattern variable
    use(x);
}
```

## Naming Conventions

> Not enforced by the compiler — but **mandatory in real-world SDE work**.

| Used For                   | Convention           | Example             |
| -------------------------- | -------------------- | ------------------- |
| Variables                  | `camelCase`          | `userAge`           |
| Methods                    | `camelCase`          | `calculateSalary()` |
| Classes                    | `PascalCase`         | `BankAccount`       |
| Interfaces                 | `PascalCase`         | `Flyable`           |
| Enums                      | `PascalCase`         | `Color`             |
| Enum Constants             | `UPPER_CASE`         | `RED`, `MAX_SIZE`   |
| Constants (`static final`) | `UPPER_CASE`         | `MAX_SIZE`          |
| Packages                   | `lowercase`          | `com.company.utils` |
| Generic Type Parameters    | Single Uppercase     | `T`, `K`, `V`, `E`  |
| Records                    | `PascalCase`         | `UserRecord`        |
| Annotations                | `PascalCase`         | `@Override`         |
| Private Fields             | `camelCase`          | `balanceAmount`     |
| Boolean Variables          | `is/has/can` prefix  | `isActive`          |
| Files                      | Same as public class | `BankAccount.java`  |

# 🔬 Under the Hood — What the Compiler Does With Identifiers
## 🗺️ The Full Pipeline

```
YourFile.java
      │
      ▼
┌─────────────────┐
│     Lexer       │  → breaks source into TOKENS
└────────┬────────┘    identifiers first seen here as raw strings
         │
         ▼
┌─────────────────┐
│     Parser      │  → builds AST (Abstract Syntax Tree)
└────────┬────────┘    identifiers get roles: variable, method, type...
         │
         ▼
┌─────────────────┐
│ Symbol Table    │  → maps identifier → type + scope + slot
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Name Resolution │  → every USE linked to its DECLARATION
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Type Checker    │  → verifies types match across assignments/calls
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Code Generator  │  → identifiers → slot numbers / field names
└────────┬────────┘    local variable names DISAPPEAR here
         │
         ▼
      .class file
      (bytecode + constant pool + optional debug tables)
         │
         ▼
┌─────────────────┐
│      JVM        │  → loads .class, executes bytecode using slot numbers
└─────────────────┘    identifier names never seen at runtime
```

---

## 🔤 Step 1 — Lexer: Identifier → Token

The lexer scans source **character by character**.

```
Source: int maxRetries = 3;

Lexer output:
┌──────────────┬──────────────────┐
│  Token       │  Type            │
├──────────────┼──────────────────┤
│  int         │  KEYWORD         │
│  maxRetries  │  IDENTIFIER      │
│  =           │  OPERATOR        │
│  3           │  INTEGER_LITERAL │
│  ;           │  PUNCTUATION     │
└──────────────┴──────────────────┘
```

Lexer rule for IDENTIFIER:

```
if (current_char is letter | $ | _)
    keep reading while (letter | digit | $ | _)
    → emit IDENTIFIER token

then check keyword table (HashMap<String, TokenType>):
    match  → emit KEYWORD instead
    no match → user-defined identifier
```

> 🔑 At the lexer stage, `maxRetries` is just a **string**. No type, no scope, no meaning yet.

---

## 🌳 Step 2 — Parser: Identifier Gets a Role

The parser builds an **Abstract Syntax Tree**.

```java
int maxRetries = 3;
```

```
AST:
        LocalVarDecl
        /           \
     Type           Init
    "int"           /  \
                 Name   Value
            "maxRetries"  3
```

```java
void process(String userId) {
    log(userId);
}
```

```
AST:
        MethodDecl
        /    |     \
     Name  Params  Body
  "process"   |       \
           ParamDecl  MethodCall
           /    \      /      \
        Type   Name  Name    Arg
      "String" "userId" "log" "userId"
```

> 🔑 Same string `"userId"` appears twice — parser links both to the **same declaration node**. This is name resolution beginning.

---

## 🗃️ Step 3 — Symbol Table: The Compiler's Dictionary

Semantic analyzer builds a **scoped symbol table** — a HashMap per scope block.

```
Symbol {
    String  name          // "maxRetries"
    Type    type          // int
    Kind    kind          // LOCAL / FIELD / METHOD / CLASS / PARAM
    int     slot          // position in local variable array
    boolean initialized   // for definite assignment analysis
}
```

```
Symbol Table — scoped structure:

Class scope
│  ├── DEFAULT_TIMEOUT → Symbol{int, FIELD, static}
│  └── process()       → Symbol{void, METHOD}
│
└── process() scope
      ├── slot 0 = this
      ├── slot 1 = userId    → Symbol{String, PARAM}
      └── slot 2 = maxRetries → Symbol{int, LOCAL}
```

Shadowing — inner scope wins:

```java
int x = 10;              // class field → Symbol in class scope

void method() {
    int x = 20;          // local → Symbol in method scope
    // compiler sees 'x' → checks method scope first → finds slot-local x
    // class field x is SHADOWED
}
```

> 🔑 Lookup always goes **inner → outer**. First match wins. If nothing found → `cannot find symbol` compile error.

---

## 🔍 Step 4 — Name Resolution

Every identifier USE is resolved to its DECLARATION.

```java
maxRetries = maxRetries + 1;
```

```
Compiler:
  1. See "maxRetries" on left  → look up scope stack → found: Symbol{int, slot=2}
  2. See "maxRetries" on right → look up scope stack → same Symbol{int, slot=2}
  3. AST node patched: Identifier("maxRetries") → resolved to slot=2

Resolution walk order:
  block scope
      ↓ not found
  method scope
      ↓ not found
  class scope (fields + methods)
      ↓ not found
  superclass scope
      ↓ not found
  import scope
      ↓ not found
  java.lang (auto-imported)
      ↓ not found
  COMPILE ERROR: cannot find symbol
```

> 🔑 `cannot find symbol` = name resolution failed at step 4. The identifier string exists in source but maps to no Symbol in any accessible scope.

---

## ✅ Step 5 — Type Checker

After resolution every identifier has a known Symbol with a Type.

```java
String userId = 99;
// userId → Symbol{String, slot=1}
// 99     → IntLiteral, type=int
// int not assignable to String → COMPILE ERROR: incompatible types

int maxRetries = "three";
// Symbol{int} ← String → COMPILE ERROR: incompatible types
```

> 🔑 Type checking happens **after** name resolution. Compiler needs to know what `userId` IS before it can check if `99` fits.

---

## ⚙️ Step 6 — Code Generator: Identifiers DISAPPEAR

```java
void process(String userId) {
    int maxRetries = 3;
    maxRetries = maxRetries + 1;
    log(userId, maxRetries);
}
```

```
Compiled bytecode (javap -c):

void process(java.lang.String);
  Code:
     0: iconst_3         // push literal 3
     1: istore_2         // store → slot 2  (was: maxRetries)
     2: iload_2          // load  ← slot 2  (was: maxRetries)
     3: iconst_1         // push literal 1
     4: iadd             // add
     5: istore_2         // store → slot 2  (was: maxRetries)
     6: aload_0          // load  ← slot 0  (was: this)
     7: aload_1          // load  ← slot 1  (was: userId)
     8: iload_2          // load  ← slot 2  (was: maxRetries)
     9: invokevirtual log
    12: return
```

```
"maxRetries" → GONE. Replaced by slot 2.
"userId"     → GONE. Replaced by slot 1.
Only slot numbers survive in bytecode.
```

Slot assignment rules:

```
Instance method:
  slot 0 = this          (always — implicit first param)
  slot 1 = first param
  slot 2 = second param
  slot n = first local variable

Static method:
  slot 0 = first param   (no this)
  slot 1 = second param

long / double consume TWO slots (64-bit):
  void method(long x, int y):
    slot 0,1 = x   (64-bit)
    slot 2   = y
```

> 🔑 Local variable names **do not exist** in bytecode. The JVM executes using slot numbers only.

## 📋 Where Identifier Names Survive — Debug Tables

```
.class file structure:
  ├── constant_pool           ← string pool: class names, field names, method names
  ├── methods[]
  │     └── Code attribute
  │           ├── bytecode              ← slot numbers only
  │           ├── LineNumberTable       ← bytecode offset → source line number
  │           └── LocalVariableTable   ← slot → name + type  ← DEBUG ONLY
  └── fields[]                ← field names survive (reflection needs them)
```

```
LocalVariableTable (javap -verbose):
┌───────┬────────┬─────────────┬────────────────────┬───────┐
│ Start │ Length │ Name        │ Descriptor         │ Index │
├───────┼────────┼─────────────┼────────────────────┼───────┤
│   0   │   13   │ userId      │ Ljava/lang/String; │   1   │
│   1   │   12   │ maxRetries  │ I                  │   2   │
└───────┴────────┴─────────────┴────────────────────┴───────┘
```

```bash
# Compile with full debug info (default javac)
javac MyClass.java

# Strip all debug info — names gone, debugger shows arg0, arg1
javac -g:none MyClass.java

# View bytecode + debug tables
javap -c -verbose MyClass
```

> 🔑 Field names survive because **reflection needs them**. Local variable names are optional debug metadata — stripped in prod builds.

## 🔒 Constant Folding — Identifiers Eliminated Entirely

```java
static final int MAX_RETRIES = 3;   // compile-time constant

void check(int attempts) {
    if (attempts > MAX_RETRIES) { }  // MAX_RETRIES referenced here
}
```

```
Compiled bytecode:
  iload_1
  iconst_3          ← 3 inlined directly — no getfield instruction
  if_icmple ...

"MAX_RETRIES" → completely eliminated
Not even a getfield bytecode — value folded to literal at compile time
```

> 🔑 `static final` primitive = compile-time constant = **no runtime reference** to the field at all. Accessing `MyClass.MAX_RETRIES` does NOT trigger class loading.

## 🏭 Production Scenario

You get an `NoSuchFieldException` in prod:

```
java.lang.NoSuchFieldException: retryCount
    at java.lang.Class.getDeclaredField(Class.java:2412)
    at com.payments.ConfigLoader.inject(ConfigLoader.java:88)
```

Diagnosis steps:

```bash
# 1. Check what fields actually exist in the compiled class
javap -p com.payments.PaymentService

# Output:
# private int retries;     ← field was RENAMED from retryCount
# Reflection looks for "retryCount" — bytecode has "retries" — mismatch

# 2. Check if compiled with debug info
javap -verbose com.payments.PaymentService | grep LocalVariableTable
# No output → compiled with -g:none → no local var names in debug

# 3. Check constant pool for field names
javap -verbose com.payments.PaymentService | grep "Field"
# constant pool entry: Field retries:I
```

Root cause: field renamed in source → recompiled → reflection string `"retryCount"` hardcoded → `NoSuchFieldException`. Field names survive compilation — mismatched string = runtime failure.

> 🔑 Reflection bypasses compile-time name resolution. Identifier strings in `getDeclaredField("name")` are **never checked by the compiler** — only at runtime.

## 📊 Summary

```
Stage              │ What happens to your identifier
───────────────────┼──────────────────────────────────────────────────
Lexer              │ Raw string token — no meaning
Parser             │ Role assigned in AST (var, method, type, param)
Symbol Table       │ Mapped to: type + kind + slot + scope
Name Resolution    │ Every USE linked to its DECLARATION symbol
Type Checker       │ Types verified across all usages
Code Generator     │ Local names → slot numbers (GONE)
                   │ Field names → constant pool (SURVIVE)
                   │ Compile-time constants → inlined literals (GONE)
.class file        │ Bytecode uses slots only
                   │ LocalVariableTable = optional name map (debug)
JVM Runtime        │ Slot numbers only — identifier names never seen
Reflection         │ Field/method names looked up from constant pool
```
