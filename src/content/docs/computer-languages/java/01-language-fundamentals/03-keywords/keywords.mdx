In Java, some identifiers are reserved to perform special functions.
These reserved identifiers are called **KEYWORDS** or **RESERVED WORDS**.

<Aside type="caution">
You **CANNOT** use them as identifiers (variable/class names).
</Aside>

**Why?** Because each keyword already has a fixed meaning in the compiler.

```java
int class = 10; // ❌ Compile-time error
```

## 8. Unused Keywords

```java
// const and goto are reserved but do nothing
goto    const

int const = 1;      // ❌ COMPILE ERROR — reserved keyword
int goto  = 1;      // ❌ COMPILE ERROR — reserved keyword
// Neither const nor goto has any functionality in Java
// Reserved to prevent confusion with C/C++ programmers
// and to keep options open for future Java versions
```

## 9. Reserved Literals
🪤 Trap 1 — true, false, null are not keywords — they are literals

```java
true    false    null

int true = 1;       // ❌ COMPILE ERROR — but NOT because true is a keyword
                    // true is a BOOLEAN LITERAL — different category
                    // same effect: cannot be used as identifier
// Keywords: for, while, class...
// Literals: true, false, null
// Both: cannot be identifiers — but for different reasons
```

🪤 Trap 2 — Unicode identifiers are valid — obfuscation attack

```java
// Looks like "false" — IS NOT false
// Using Unicode lookalike characters
int fаlse = 10;     // 'а' is Cyrillic — not ASCII 'a'
System.out.println(fаlse);  // prints 10 — valid identifier
// Used in obfuscated/malicious code to hide logic
// Compiler accepts it — human eye misses it
```
