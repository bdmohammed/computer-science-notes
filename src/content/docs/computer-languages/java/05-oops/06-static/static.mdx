## ⚡ Static Control Flow in Java

> **When the JVM loads a class, it runs static members in a defined, strict order — before any object is created, before `main()` runs. This sequence is Static Control Flow.**

<Aside type="tip">
**🧠 Mental Model**: Think of class loading as a **single-pass linear scan**.  
1. **Identification**: Mark all static members, assign defaults (`0`, `null`).  
2. **Execution**: Run assignments and blocks top-to-bottom.  
3. **Ready**: Class is now usable.  
⚠️ If you read a variable before its assignment line, you get its default value (or a compile error if accessed directly).
</Aside>

---

## 🔬 The Three Phases (JVM Execution Model)

```
CLASS LOADING TRIGGERED
        │
        ▼
┌─────────────────────────────────────────────┐
│  PHASE 1 — IDENTIFICATION                   │
│  JVM scans top-to-bottom                    │
│  All static variables → assigned DEFAULT    │
│  values (0, null, false)                    │
│  No assignments run. No blocks run.         │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│  PHASE 2 — EXECUTION (top → bottom)         │
│  Static variable assignments  ──┐           │
│  Static initializer blocks    ──┤ in order  │
│  (interleaved by position)    ──┘           │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│  PHASE 3 — main() executes                  │
│  (only for the entry-point class)           │
└─────────────────────────────────────────────┘
```


### The Execution Order 📜
```
Interview Critical: Memorize this sequence.
Static Variables (Default values → Explicit values)
Static Blocks (Top to bottom)
Main Method

🏛️ Flow Diagram
+---------------------+
|   Class Loading     |
+---------------------+
         |
         v
+---------------------+
| 1. Static Vars      | (Memory Allocation)
+---------------------+
         |
         v
+---------------------+
| 2. Static Blocks    | (Initialization Logic)
+---------------------+
         |

+---------------------+
| 3. Main Method      | (Program Starts)
+---------------------+
```
🧠 Key Rule
Static code runs ONCE when the class is loaded into memory, before the main method executes.

## 📋 Execution Order Rules

| Rule | Behavior |
|------|----------|
| **Static Variables** | Get **default** value in Phase 1 (`0`, `null`, `false`). |
| **Assignments + Blocks** | Execute **top-to-bottom** in Phase 2. |
| **Multiple Static Blocks** | All run, in order of appearance. |
| **Class Loaded Once** | Phases run **exactly once** per ClassLoader. |
| **Inheritance** | **Parent** static flow completes **before** Child's begins. |

## 💻 Real-World Code — The "Trap" Pattern

<Code lang="java" title="Config Loader — Watch the order!" code={`
public class AppConfig {

    // Phase 1: x = 0 (default)
    static int timeout = loadTimeout();    // Phase 2, step 1

    // Phase 2, step 2 — static block
    static {
        System.out.println("Block 1 — timeout so far: " + timeout); // 30
    }

    static int maxRetries = 3;             // Phase 2, step 3

    // Phase 2, step 4
    static {
        System.out.println("Block 2 — maxRetries: " + maxRetries);  // 3
        System.out.println("timeout again: " + timeout);             // 30
    }

    static int loadTimeout() {
        // At this point, maxRetries is still 0 (default — not yet assigned)
        // ⚠️ TRAP: maxRetries is still 0 (default) because
      // its assignment (Step 3) hasn't happened yet!
        System.out.println("loadTimeout called — maxRetries = " + maxRetries); // 0 ← TRAP
        return 30;
    }
}
`} />

**Output:**
```text
loadTimeout called — maxRetries = 0   ← Phase 1 default, not 3!
Block 1 — timeout so far: 30
Block 2 — maxRetries: 3
Block 2 — timeout again: 30
```

<Aside type="danger">
**🚨 Production Bug**: Assuming `maxRetries` is `3` inside `loadTimeout()`. It's `0`. This silently misconfigures retry logic in prod with no exception thrown. Always be aware of **Read Indirectly Write Only (RIWO)** state.
</Aside>

## 🛑 Forward References & RIWO

Java prevents you from using a static variable **directly** before it is declared. This is called an **Illegal Forward Reference**.

<CardGrid>
  <Card title="❌ Direct Read (Compile Error)" icon="error">
    ```java
    class Test {
        static {
            System.out.println(i); // ❌ C.E: illegal forward reference
        }
        static int i = 10;
    }
    ```
  </Card>
  
  <Card title="✅ Indirect Read (Allowed)" icon="approve-check">
    ```java
    class Test {
        static {
            methodOne(); // ✅ Allowed: Method call bypasses check
        }
        public static void methodOne() {
            System.out.println(i); // Prints 0 (default value)
        }
        static int i = 10;
    }
    ```
  </Card>

  <Card title="✅ Write Before Declaration" icon="information">
    ```java
    class Test {
        static {
            x = 10; // ✅ Allowed: Writing is safe
        }
        static int x = 20; // Overwrites 10 with 20 later
    }
    // Final value of x is 20.
    ```
  </Card>
</CardGrid>

```java
class Base {

    static int i = 10; 
    // (1) Static variable i initialized

    static {
        // (2) First static block starts

        methodOne(); 
        // (3) Calls methodOne()

        System.out.println("first static block"); 
        // (5) Prints: first static block
    }

    public static void main(String[] args) {
        // (8) main() starts after class loading

        methodOne(); 
        // (9) Calls methodOne()

        System.out.println("main method"); 
        // (11) Prints: main method
    }

    public static void methodOne() {
        System.out.println(i); 
        // (4) Prints: 10  (when called from static block)
        // (10) Prints: 10 (when called from main)
    }

    static {
        // (6) Second static block starts

        System.out.println("second static block"); 
        // (7) Prints: second static block
    }

    static int j = 20; 
    // (12) Static variable j initialized
}

Analysis:
i=0 [RIWO]
j=0 [RIWO]
i=10 [R&W]
j=20 [R&W]
l.identification of static members from top to bottom[l to 6]
2.execution of static variable assignments and static blocks from top to bottom[7 to 12]
3.execution of main method[13 to 15]
```

<Aside type="note">
**RIWO State**: When a variable is identified (Phase 1) but not yet executed (Phase 2), it is in **Read Indirectly Write Only** state.  
- **Direct Read**: `System.out.println(x)` → ❌ Compile Error.  
- **Indirect Read**: `method() { println(x); }` → ✅ Returns default value.  
- **Write**: `x = 10` → ✅ Allowed.
</Aside>

## 🔁 Inheritance — Parent Before Child

> **Rule**: Parent static members load and initialize **completely** before Child static members begin.

<Code lang="java" title="Inheritance Execution Order" code={`class Parent {
    static int x = 10;
    static {
        System.out.println("Parent static block — x = " + x);
    }
}

class Child extends Parent {
    static int y = 20;
    static {
        System.out.println("Child static block — y = " + y);
        System.out.println("Inherited x = " + x);
    }
}

// Trigger: new Child() or Child.y
// Output:
// Parent static block — x = 10
// Child static block — y = 20
// Inherited x = 10`} />

```
Class Loading Order (Inheritance):
  java.lang.Object
       │
    Parent  ←── loads & initializes first
       │
    Child   ←── loads & initializes second
```

### Complex Inheritance Example

<Code lang="java" title="Parent & Child Interleaving" code={`

    static int i = 10; 
    // (1) Base: i initialized → 10

    static {
        // (2) Base: first static block

        methodOne(); 
        // (3) calls methodOne()

        // (5)
    }

        // (Not used — Derived.main runs)

        methodOne();
        System.out.println("base main");
    }

    public static void methodOne() {
        System.out.println(i); 
        // (4) prints 10
    }

    static int j = 20; 
    // (6) Base: j initialized → 20
}


// =============================


class Derived extends Base {

    static int x = 100; 
    // (7) Derived: x initialized → 100

    static {
        // (8) Derived: first static block

        methodTwo(); 
        // (9) calls methodTwo()

        System.out.println("derived first static block"); 
        // (11)
    }

    public static void main(String[] args) {
        // (14) Entry point (JVM starts here)

        methodTwo(); 
        // (15)

        System.out.println("derived main"); 
        // (17)
    }

    public static void methodTwo() {
        System.out.println(y); 
        // (10) prints 0 (default value)
        // (16) prints 200 (after initialization)
    }

    static {
        // (12) Derived: second static block

        System.out.println("derived second static block"); 
        // (13)
    }

    static int y = 200; 
    // (18) Derived: y initialized → 200
}

Analysis:

j=0 [RIWO]
x=0 [RIWO]
y=0 [RIWO]
i=10 [R&W]
j=20 [R&W]
x=100 [R&W]
y=200 [R&W]

Output:

0
Derived first static block
Derived second static block
200
Derived main
Output:

E:\scjp>java Base
0

20
Basic main
Whenever we are executing Child class the following sequence of events will be
performed automatically.
1. Identification of static members from Parent to Child. [1 to 11]
2. Execution of static variable assignments and static blocks from Parent to
Child.[12 to 22]
3. Execution of Child class main() method.[23 to 25].
Note : When ever we are loading child class autimatically the parent class will be loaded
but when ever we are loading parent class the child class don't be loaded automatically.


`} />



<Aside type="caution">
**Key Insight**: When `Derived` loads, `Base` loads first.  
1. `Base` initializes completely (`i=10`, block runs, `j=20`).  
2. `Derived` starts initializing. `x=100`.  
3. `Derived` static block calls `methodTwo()`. At this point, `y` is still `0` (default) because `static int y = 200` hasn't been reached yet!
</Aside>

## 🔧 Class Loading Triggers

Not every reference to a class triggers loading.

| Trigger | Class Loaded? | Why? |
|---------|--------------|------|
| `new MyClass()` | ✅ Yes | Instance creation requires class definition. |
| `MyClass.staticMethod()` | ✅ Yes | Must resolve method bytecode. |
| `MyClass.staticField` | ✅ Yes | Unless it's a constant. |
| `MyClass.CONSTANT` (`static final` literal) | ❌ No | **Constant Folding**: Value inlined at compile time. |
| Subclass loaded | ✅ Yes | Parent must load first. |
| `Class.forName("MyClass")` | ✅ Yes | Explicit reflection load. |
| Declaring `MyClass obj;` | ❌ No | Just a reference variable, no object created. |

### 🪤 Trap: Compile-Time Constants

<Code lang="java" title="Constant Folding avoids class load" code={`class Config {
    static final int PORT = 8080;          // Compile-time constant
    static final int TIMEOUT = getVal();   // NOT constant (method call)

    static {
        System.out.println("Config loaded");
    }
    static int getVal() { return 30; }
}

class Main {
    public static void main(String[] args) {
        System.out.println(Config.PORT);    // "Config loaded" is NEVER printed
        System.out.println(Config.TIMEOUT); // "Config loaded" IS printed
    }
}`} />

<Aside type="tip">
**Why?** `PORT` is known at compile time. The compiler replaces `Config.PORT` with `8080` in `Main.class`. The JVM never touches `Config.class` for that line. `TIMEOUT` requires running code, so `Config` must load.
</Aside>

## 🔩 Internals — The `<clinit>` Method

The JVM merges all static variable assignments and static blocks into a single special method called **`<clinit>`** (class initialization).

- **Thread-Safe**: The JVM acquires a lock on the class object before running `<clinit>`. Only one thread can initialize a class at a time.
- **Single Pass**: Runs exactly once.
- **Error State**: If `<clinit>` throws an exception, the class enters an error state. Future attempts to use the class throw `NoClassDefFoundError`.

```bash
javap -c MyClass
# Look for:
# static {};
#   descriptor: ()V
#   flags: ACC_STATIC
```

## 🏭 SDE/SRE Relevance & Patterns

<CardGrid>
  <Card title="Pattern 1: Resource Initialization" icon="rocket">
    ```java
    // Load native libraries or JDBC drivers once at startup
    class DatabaseHelper {
        static {
            System.loadLibrary("native_db_lib");
            // Or register JDBC driver
            // DriverManager.registerDriver(new OracleDriver());
        }
    }
    ```
  </Card>
  
  <Card title="Pattern 2: DSA Precomputation" icon="shield">
    ```java
    // Compute primes once, reuse for all test cases
    class MathUtils {
        static boolean[] isPrime = new boolean[10000];
        static {
            Arrays.fill(isPrime, true);
            // Sieve of Eratosthenes logic here...
        }
    }
    ```
  </Card>

  <Card title="Anti-Pattern: Circular Dependency" icon="error">
    ```java
    class A { static int val = B.val + 1; }
    class B { static int val = A.val + 1; }
    
    // If A loads first:
    // 1. A starts init. Needs B.val.
    // 2. B starts init. Needs A.val.
    // 3. A is still initializing, so A.val = 0 (default).
    // 4. B.val = 0 + 1 = 1.
    // 5. Back to A: A.val = 1 + 1 = 2.
    // Result: A=2, B=1. (Silent logical bug!)
    ```
  </Card>

  <Card title="Anti-Pattern: NoClassDefFoundError" icon="caution">
    ```java
    class Config {
        static {
            if (envMissing) throw new RuntimeException("Fail");
        }
    }
    // First access: RuntimeException caught/logged.
    // Second access: NoClassDefFoundError.
    // Why? Class is marked "erroneous". JVM won't retry init.
    ```
  </Card>
</CardGrid>

## 🧠 Full Mental Model Summary

```text
STATIC CONTROL FLOW CHECKLIST

1. Trigger:
   new X(), X.staticMethod, X.staticField (non-const), Class.forName()

2. Parent First:
   Parent <clinit> completes fully before Child <clinit> starts.

3. Top-to-Bottom:
   Within a class, execute line-by-line.
   - Var declared? Default value assigned.
   - Assignment reached? Update value.
   - Block reached? Execute code.

4. Forward Reference:
   - Direct Read before decl? ❌ Compile Error.
   - Indirect Read (method)? ✅ Returns default.
   - Write? ✅ Allowed.

5. Constants:
   - static final Literal? → Inlined (No class load).
   - static final Method()? → Class loads.

6. Safety:
   - <clinit> is synchronized.
   - Failure marks class as erroneous.
```

<Aside type="tip">
**Next Steps**:
1. ✅ Avoid complex logic in static blocks. Keep them simple.
2. ✅ Never rely on the order of static variables across different classes.
3. ✅ Use `static final` constants for config values to avoid unnecessary class loading.
4. ✅ Handle exceptions in static blocks carefully — they can kill your app startup silently.

Mastering static flow prevents subtle initialization bugs that are nightmares to debug in production. ☕✨
</Aside>
