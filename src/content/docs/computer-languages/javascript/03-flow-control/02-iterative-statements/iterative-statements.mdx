## for Loop

> The most commonly used loop — ideal when the **number of iterations is known in advance**.

> The classic C-style loop — ideal when you need **index access** or **complex control**.

---

### 🔑 Syntax & Execution Flow

```js
for (initialization; condition; update) {
    // body
}

// Classic counted loop
for (let i = 0; i < 5; i++) {
    console.log(i);  // 0 1 2 3 4
}

// Execution order:
// 1. initialization (once)
// 2. condition check
// 3. body (if condition true)
// 4. update
// 5. goto 2
```

```
for flow:
    initialization
            │
            ▼
  ┌───────────────────┐
  │ evaluate condition│◄──────────────────┐
  └────────┬──────────┘                   │
           │                              │
    ┌──────┴──────┐                       │
  false          true                     │
    │              │                      │
    ▼         execute body                │
 exit loop         │                      │
              execute update──────────────┘
```

### 🔬 The Three Sections — Deep Dive

---

#### 1. Initialization Section

- Executed **exactly once** at loop start
- Declare and initialize loop variables
- **Multiple variables allowed** (comma-separated)

<Code lang="js" title="✅ Valid initialization patterns" code={`
// Multiple variables in init and update
for (let i = 0, j = 10; i < j; i++, j--) {
    console.log(i, j);
}
// 0 10, 1 9, 2 8, 3 7, 4 6

// Any valid JavaScript statement allowed (even console.log!)
let i = 0;
for (console.log("Starting..."), i = 0; i < 3; i++) {
    console.log("Loop body", i);
}
//Starting...
//Loop body
//Loop body
//exectution end

// Pre-declared variable
// Empty sections — all three optional
int i = 0;
for (; i < 5; i++) { }  // initialization optional

// Infinite loop
for (;;) {                  // all three empty
    // runs forever
}

// Reverse iteration
for (let i = arr.length - 1; i >= 0; i--) {
    console.log(arr[i]);
}

// Step by 2
for (let i = 0; i < 10; i += 2) {
    console.log(i);  // 0 2 4 6 8
}
`} />

<Code lang="js" title="❌ Invalid initialization" code={`
// Redeclaring with let in same scope
let i = 0;
for (let i = 0; i < 5; i++) { }  // ❌ SyntaxError: Identifier 'i' has already been declared

// Different types in same declaration
for (let i = 0, var/let/const b = true; i < 5; i++) { }   // ❌ Uncaught SyntaxError: Unexpected token

// ✅ Fix: Use different variable name or reuse existing
for (i = 0; i < 5; i++) { }  // ✅ Reuses outer i
`} />

#### 2. Condition Section

- Must evaluate to a value coerced to **boolean**
- **Optional** — if omitted, treated as `true` (infinite loop)
- Checked **before each iteration**

<Code lang="js" title="Condition examples" code={`
// Standard boolean expression
for (let i = 0; i < 10; i++) { }

// Omitted condition = infinite loop
for (let i = 0; ; i++) {  // condition defaults to true
    if (i >= 10) break;   // manual exit required
}

// Truthy/Falsy coercion applies!
let arr = [1, 2, 3];
for (let i = 0; arr[i]; i++) {  // Stops when arr[i] is undefined/falsy
    console.log(arr[i]);
}

// Method call returning boolean
for (let i = 0; hasMoreData(i); i++) { }
`} />

---

#### 3. Update Section
- Executed **after each iteration** (after body)
- **Any valid JS statement** allowed
- Multiple updates allowed with comma operator

<Code lang="js" title="Update section flexibility" code={`
// Standard increment
for (let i = 0; i < 5; i++) { }

// Multiple updates
for (let i = 0, j = 10; i < j; i++, j--) { }

// Update with side effect
for (let i = 0; i < 3; console.log("Update:", i++)) {
    console.log("Body:", i);
}
// Output:
// Body: 0
// Update: 0
// Body: 1
// Update: 1
// Body: 2
// Update: 2
`} />

---

### 🧱 Braces & Body Rules

<Code lang="js" title="Braces are optional for single statement" code={`
// ✅ Valid: single statement, no braces
for (let i = 0; i < 3; i++)
    console.log(i);

// ❌ Invalid: declarative statement without braces
for (int i = 0; i < 3; i++)
    int x = 10;  // ❌ Uncaught SyntaxError: Lexical declaration cannot appear in a single-statement context

// ⚠️ Dangerous: only first line is part of loop
for (let i = 0; i < 3; i++)
    console.log(i);
    console.log("always prints");  // NOT part of loop!

// ✅ Fix: Always use braces
for (let i = 0; i < 3; i++) {
    console.log(i);
    console.log("part of loop");
}
`} />

<Aside type="caution">
**Best Practice**: **Always use braces**, even for single statements. Prevents bugs when adding lines later and improves readability.
</Aside>

## ⚠️ for Loop — No Unreachable Code Errors (JS Difference!)

Unlike Java, JavaScript **does not** perform compile-time flow analysis for unreachable code. Infinite loops are **runtime behaviors**, not compile errors.

<Card title="Case 1: Condition always true → Infinite Loop" icon="caution">
  ```js
    for (let i = 0; true; i++) {
        console.log("hello");
    }
    console.log("hi");  // ✅ Compiles fine! But never runs at runtime.
    // Browser/Node will hang or crash due to infinite loop.
  ```
</Card>

<Card title="Case 2: Condition always false → Body skipped" icon="approve-check">
  ```js
    for (let i = 0; false; i++) {
        console.log("hello");  // Never runs
    }
    console.log("hi");  // ✅ Runs immediately
    // No compile error — JS doesn't optimize this away statically.
  ```
</Card>

<Card title="Case 3: Omitted condition = Infinite Loop" icon="caution">
  ```js
    for (let i = 0; ; i++) {  // condition defaults to true
        console.log("hello");
    }
    console.log("hi");  // ✅ Compiles fine! Never reached at runtime.
  ```
</Card>

<Card title="Case 4: Dynamic variables → Runtime behavior" icon="approve-check">
  ```js
    let a = 10, b = 20;
    for (let i = 0; a < b; i++) {
        console.log("hello");  // Infinite if a/b don't change
    }
    console.log("hi");  // ✅ Compiles fine.
    // JS engines (V8) may optimize hot paths at runtime, but no static error.
  ```
</Card>

<Aside type="tip">
**Linting Tip**: Use ESLint rule `no-constant-condition` to catch likely infinite loops during development:
  ```js
  // ESLint error: Unexpected constant condition
  for (let i = 0; true; i++) { ... }
  ```
</Aside>

## 🔄 for Loop Variations & Traps

<Card title="Variation 1: Multiple variables" icon="rocket">
  ```js
    // Comma-separated declarations
    for (let i = 0, j = 10; i < j; i++, j--) {
        console.log(i, j);
    }
    // Output: 0 10, 1 9, 2 8, 3 7, 4 6
  ```
</Card>

<Card title="Variation 2: Infinite loop pattern" icon="shield">
  ```js
    // Classic infinite loop with break
    for (;;) {
        if (shouldExit()) break;
        process();
    }
    // Equivalent to: while (true) { ... }
  ```
</Card>

<Card title="Trap 1: Modifying loop variable inside body" icon="error">
  ```js
    for (let i = 0; i < 5; i++) {
        console.log(i);  // prints: 0, 2, 4
        i++;  // ⚠️ Extra increment — skips every other value!
    }
    // Flow: i=0 → print 0 → i++(body)→1 → i++(update)→2 → check 2<5 → ...
  ```
  **Fix**: Avoid modifying loop variable inside body unless intentional.
</Card>

<Card title="Trap 2: Loop variable scope (let vs var)" icon="error">
  ```js
    // ✅ let/const: Block scoped — i NOT accessible outside
    for (let i = 0; i < 5; i++) { }
    console.log(i);  // ❌ ReferenceError: i is not defined
    
    // ⚠️ var: Function scoped — i LEAKS outside!
    for (var j = 0; j < 5; j++) { }
    console.log(j);  // ✅ 5 (avoid var in loops!)
  ```

  <Aside type="caution">
    **Fix**: Always use `let` or `const` in loops to prevent scope leakage.
  </Aside>
</Card>

<Card title="Trap 3: Empty body semicolon" icon="caution">
  ```js
    // Semicolon = empty statement as loop body
    for (let i = 0; i < 5; i++);  // ← semicolon ends loop!
    console.log("Done");   // Runs once after loop
    
    // Common bug: accidental semicolon after for()

    // Fix: Remove semicolon or add braces:
    for (let i = 0; i < 5; i++) {
        console.log(i);  // ✅ intended body
    }
  ```
</Card>

## for...of Loop (ES6+)

> Simplified syntax for **traversing iterables** (Arrays, Strings, Maps, Sets) — focuses on **values**.

---

### 🔑 Syntax

```js
// For arrays
for (const element of array) {
    // use element
}
```

<Code lang="js" title="for...of examples" code={`
// Array traversal
const arr = [10, 20, 30, 40];
for (const num of arr) {
    console.log(num);  // 10 20 30 40
}

// For strings
for (const char of "hello") {
    console.log(char);  // h, e, l, l, o
}

// For Maps
const map = new Map([['a', 1], ['b', 2]]);
for (const [key, value] of map) {
    console.log(key, value);  // a 1, b 2
}

// Set traversal
const set = new Set(['Alice', 'Bob', 'Charlie']);
for (const name of set) {
    console.log(name);
}

// Works with any object implementing Symbol.iterator
`} />

### ⚠️ Limitations of for...of

<Card title="Cannot access index directly" icon="error">
  ```js
    const arr = [10, 20, 30];
    for (const num of arr) {
        // ❌ No direct index access
        // console.log("Index: " + ???);
    }
    // ✅ Fix: Use .entries() or traditional for loop
    for (const [index, num] of arr.entries()) {
        console.log(`arr[\${index}] = \${num}`);
    }
  ```
</Card>

<Card title="Cannot modify primitive array elements" icon="error">
  ```js
    const arr = [1, 2, 3];
    for (let x of arr) {
        x = 99;  // ❌ Modifies loop variable copy, NOT original array!
    }
    console.log(arr);  // [1, 2, 3] — unchanged!
    
    // ✅ Fix: Use index-based loop for modification
    for (let i = 0; i < arr.length; i++) {
        arr[i] = 99;  // ✅ Modifies actual array element
    }
  ```
</Card>

<Card title="Cannot traverse plain Objects" icon="error">
  ```js
    const obj = { a: 1, b: 2 };
    // for (const val of obj) { }  // ❌ TypeError: obj is not iterable
    
    // ✅ Fix: Use for...in for keys, or Object.values() for values
    for (const key in obj) { console.log(key); }       // a, b
    for (const val of Object.values(obj)) { console.log(val); } // 1, 2
  ```
</Card>

<Card title="Can remove from Array? (Use with caution)" icon="caution">
  ```js
    const list = [1, 2, 3, 4];
    for (const item of list) {
        if (item === 2) {
            list.splice(list.indexOf(item), 1);  // ⚠️ Skips next element!
        }
    }
    console.log(list);  // [1, 3, 4] — worked, but risky if indices shift
    
    // ✅ Safer: Filter to create new array
    const filtered = list.filter(item => item !== 2);
  ```
</Card>

### 🎯 When to Use for...of

✅ **Use for...of when**:
- Reading/traversing all elements sequentially
- Working with Arrays, Strings, Maps, Sets, NodeLists
- Code clarity is priority

❌ **Use traditional for when**:
- Index access needed (or use `.entries()`)
- Reverse traversal needed
- Modifying array length/structure during iteration
- Skipping elements (step > 1)

## for...in Loop — Object Keys

> Iterates over **enumerable property keys** of an object (including inherited ones).

<Code lang="js" title="for...in examples" code={`
const obj = { a: 1, b: 2, c: 3 };

// Iterates over KEYS
for (const key in obj) {
    console.log(key, obj[key]);  // a 1, b 2, c 3
}

// ⚠️ Warning: Iterates over prototype chain too!
Array.prototype.extra = "oops";
const arr = [10, 20];
for (const index in arr) {
    console.log(index);  // "0", "1", "extra" 😱
}

// ✅ Fix: Use hasOwnProperty check or Object.keys()
for (const key in obj) {
    if (obj.hasOwnProperty(key)) {
        console.log(key, obj[key]);
    }
}

// ✅ Better: Use Object.keys/values/entries for arrays/objects
Object.keys(obj).forEach(key => console.log(key, obj[key]));
`} />

<Aside type="danger">
**Golden Rule**: **Never use `for...in` for Arrays**.  
It iterates over **keys** (strings: "0", "1", "2"), not values, and includes non-index properties.  
✅ Use `for...of` or `.forEach()` for arrays.
</Aside>

## while Loop

> Use when **number of iterations is NOT known in advance** — condition checked **before** each iteration.

---

### 🔑 Syntax & Rules
```js
while (condition) {  // condition coerced to boolean
    // body
}

let i = 0;
while (i < 5) {
    console.log(i);  // 0 1 2 3 4
    i++;  // ⚠️ Must update condition variable to avoid infinite loop
}

// Zero iterations — condition false from start
let x = 10;
while (x < 5) {
    console.log("never");    // never executes
}

// Infinite loop — common server pattern
while (true) {
    Request req = server.accept();
    handle(req);
    // exits only via break, return, or exception
}
```

```
while flow:
  ┌─────────────────────────┐
  │  evaluate condition      │◄────────────────┐
  └────────────┬────────────┘                  │
               │                               │
        ┌──────┴──────┐                        │
      false          true                      │
        │              │                       │
        ▼         execute body─────────────────┘
   exit loop
```

---

### ⚠️ while Loop — Key Rules

1. **Condition coerces to boolean** — truthy/falsy rules apply
2. **Braces optional** for single statement
3. **No unreachable code errors** — infinite loops are runtime issues

<Code lang="js" title="Truthy/Falsy in while" code={`
// ✅ Valid: Non-zero numbers are truthy
let x = 1;
while (x) {  
    console.log("runs");  // Infinite loop! 1 is truthy.
    x = 0;  // Stop condition
}

// ❌ Trap: 0 is falsy
let y = 0;
while (y) {
    console.log("won't run");  // Skipped!
}
`} />

<Code lang="js" title="Braces rules" code={`
// ✅ Valid: single statement, no braces
while (true)
    console.log("hello");  // infinite loop

// ⚠️ Dangerous: only first line is part of loop
while (true)
    console.log("hello");
    console.log("always prints");  // NOT part of loop!

// ❌ Invalid: declarative statement without braces
while (true)
    let x = 10;  // ❌ Error: Lexical declaration cannot appear in a single-statement context

// ✅ Fix: use braces
while (true) {
    console.log("hello");
}
`} />

---

### 🔬 Unreachable Code in while — Same Rules as for

<Card title="Condition always true → infinite loop" icon="error">
    ```js
        while (true) {
            console.log("hello");
        }
        console.log("hi");  // ❌ Error: unreachable statement
    ```
</Card>

<Card title="Condition always false → loop unreachable" icon="error">
    ```js
        while (false) {     // ❌ Error: unreachable statement (entire loop)
            console.log("hello");
        }
        console.log("hi");
    ```
</Card>

<Card title="Infinite loop behavior" icon="error">
    ```js
        const  a = 10, b = 20;
        while (a < b) {     // Infinite loop if a/b don't change
            console.log("hello");
        }
        console.log("hi");  // ✅ Compiles fine! Never reached at runtime.
    ```
</Card>

## do...while Loop

> **Executes body at least once** — condition checked **after** each iteration.

---

### 🔑 Syntax & Key Difference

```js
do {
    // body — runs FIRST
} while (condition);  // condition checked AFTER body (semicolon required!)

// At least one execution guaranteed
let i = 10;
do {
    console.log(i);  // prints 10 — even though condition false
    i++;
} while (i < 5);            // false — loop exits after first iteration

// Classic use — menu driven programs
do {
    printMenu();
    int choice = scanner.nextInt();
    processChoice(choice);
} while (choice != 0);      // keep going until user chooses 0
```

```
do-while flow:
  ┌─────────────┐
  │ execute body │◄────────────────┐
  └──────┬──────┘                  │
         │                         │
  evaluate condition               │
         │                         │
  ┌──────┴──────┐                  │
false          true─────────────────┘
  │
  ▼
exit loop
```

---

### 🔄 while vs do...while Comparison

```text
+----------------------+-----------------------------------+----------------------------------------+
| Feature              | while                             | do-while                               |
+----------------------+-----------------------------------+----------------------------------------+
| Condition check      | Before body (pre-test)            | After body (post-test)                 |
+----------------------+-----------------------------------+----------------------------------------+
| Minimum executions   | 0 (may never run)                 | 1 (always runs once)                   |
+----------------------+-----------------------------------+----------------------------------------+
| Syntax               | while (cond) { }                  | do { } while (cond);                   |
+----------------------+-----------------------------------+----------------------------------------+
| Semicolon required   | ❌ No                             | ✅ Yes (after while)                  |
+----------------------+-----------------------------------+----------------------------------------+
| Best for             | Unknown iterations, may skip      | Must run at least once                 |
|                      |                                   | (e.g., menu)                           |
+----------------------+-----------------------------------+----------------------------------------+
```
> 🔑 `do-while` is the only loop guaranteed to execute **at least once**. The condition is checked **after** the body. The semicolon after `while(condition)` is mandatory — its absence is a compile error.

---

### ⚠️ do...while Rules & Traps

<Card title="Braces optional for single non-declarative statement" icon="approve-check">
    ```js
        // ✅ Valid
        do
            console.log("hello");
        while (true);  // ← semicolon required!
        
        // ❌ Invalid: declarative without braces
        do
            let x = 10;  // ❌ SyntaxError
        while (true);
        
        // ✅ Fix: use braces
        do {
            let x = 10;
        } while (true);
    ```
</Card>

<Card title="Semicolon after while is mandatory" icon="error">
  ```js
    do {
        console.log("hello");
    } while (true)  // ❌ SyntaxError: Missing semicolon
    // ← Missing semicolon after while condition!
  ```
</Card>

<Card title="Infinite loop behavior" icon="caution">
  ```js
    do {
        console.log("hello");
    } while (true);  // Infinite loop
    console.log("hi");  // ✅ Compiles fine! Never reached at runtime.
    
    // But with false condition:
    do {
        console.log("hello");  // ✅ Runs once
    } while (false);
    console.log("hi");  // ✅ Runs after loop
    // Output: hello\nhi
  ```
</Card>

<Card title="Unreachable code detection applies" icon="error">
    ```js
        do {
            console.log("hello");
        } while (true);  // Infinite loop
        console.log("hi");  // ✅ Compiles fine! Never reached at runtime.
        
        // But with false condition:
        do {
            console.log("hello");  // ✅ Runs once
        } while (false);
        console.log("hi");  // ✅ Runs after loop
        // Output: hello\nhi
    ```
</Card>

<Card title="final variables trigger compile-time analysis" icon="caution">
    ```js
        const a = 10, b = 20;
        do {
            console.log("hello");
        } while (a < b);  // Compiler: 10 < 20 = true → infinite
        console.log("hi");  // ✅ Compiles fine! Never reached at runtime.
        
        // But if condition false at compile time:
        const x = 10, y = 5;
        do {
            console.log("hello");  // ✅ Runs once
        } while (x < y);  // 10 < 5 = false → loop exits after one iteration
        console.log("hi");  // ✅ Compiles and runs
        // Output: hello\nhi
    ```
</Card>

### 🎯 Classic do...while Use Case: Menu Systems

<Code lang="js" title="Menu that shows at least once" code={`
let choice;
do {
    console.log("1. Start  2. Settings  3. Exit");
    choice = prompt("Choose: ");  // Browser prompt

`} />

## 🔁 Iterators & Generators — Advanced Iteration

---

### 🔑 Core Concepts

<Card title="Iterable Protocol" icon="information">
  ```js
    // An object is iterable if it implements Symbol.iterator
    const myIterable = {
        [Symbol.iterator]: function* () {
            yield 1;
            yield 2;
            yield 3;
        }
    };
    
    // Can be used with for...of
    for (const num of myIterable) {
        console.log(num);  // 1, 2, 3
    }
    
    // Built-in iterables:
    // • Arrays, Strings, Maps, Sets, Arguments, NodeLists
    // • Plain objects are NOT iterable by default
  ```
</Card>

<Card title="Iterator Protocol" icon="backspace">
  ```js
    // An iterator is an object with next() method
    const myIterator = myIterable[Symbol.iterator]();
    
    console.log(myIterator.next());  // { value: 1, done: false }
    console.log(myIterator.next());  // { value: 2, done: false }
    console.log(myIterator.next());  // { value: 3, done: false }
    console.log(myIterator.next());  // { value: undefined, done: true }
    
    // Used internally by for...of, spread operator, destructuring
  ```
</Card>

### 💻 Practical Usage Comparison

<Code lang="js" title="for...of (uses Iterator internally)" code={`const names = ["Alice", "Bob", "Charlie"];

// for...of syntax — clean, readable
for (const name of names) {
    console.log(name);
}
// Internally uses:
// const it = names[Symbol.iterator]();
// let result = it.next();
// while (!result.done) {
//     const name = result.value;
//     console.log(name);
//     result = it.next();
// }`} />

### 🎯 When to Use Which

✅ **Use for...of (Iterable) when**:
- Simple traversal, read-only access
- Code clarity is priority
- Working with Arrays, Strings, Maps, Sets

✅ **Use Manual Iterator when**:
- Need custom control flow (pause/resume)
- Implementing custom data structures
- Working with Async Iterators (`for await...of`)

    // Classic trap — var is function-scoped:

    for (var i = 0; i <Ca 3; i++) {

    }

## 📊 DSA / Internals Connection

> Every loop is a **control flow graph (CFG)** with a back-edge — an edge that points backward in the graph from a later node to an earlier one. The presence of a back-edge is the formal definition of a loop in compiler theory. V8 detects back-edges to identify hot loops for OSR (On-Stack Replacement) optimization.
>
> `for...of` uses the **Iterator pattern** — a fundamental design pattern (GoF) and the same protocol used by lazy sequences in functional languages like Haskell. The `{ value, done }` object returned by `.next()` is identical to a **generator's yield state** in CS theory — a continuation of computation.
>
> Labeled `break`/`continue` implement **structured jumps** — a restricted form of `goto` that only allows jumping to enclosing scopes. This is the formal distinction between structured and unstructured programming (Dijkstra's "GOTO considered harmful"). V8 compiles labeled breaks to unconditional jump instructions (`JMP` on x86-64) — same as `goto` at the machine level, but lexically constrained at the source level.

### Nested `for` — Complexity Awareness

```js
// O(n²) — be aware of nested loops:
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    // runs n² times
  }
}

// O(n³) — triple nested:
for (let i = 0; i < n; i++) {
  for (let j = i; j < n; j++) {    // j starts at i → optimization
    for (let k = j; k < n; k++) {  // k starts at j → optimization
      // still O(n³) but ~6x fewer iterations than n³
    }
  }
}

// Real use — matrix multiplication:
function matMul(A, B) {
  const n = A.length;
  const C = Array.from({ length: n }, () => new Array(n).fill(0));

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
      for (let k = 0; k < n; k++) {
        C[i][j] += A[i][k] * B[k][j];
      }
    }
  }
  return C;
}
```

## ⚙️ Deep Dive — V8 Loop Optimization (OSR)

```
┌──────────────────────────────────────────────────────────┐
│         V8 ON-STACK REPLACEMENT (OSR)                    │
│                                                          │
│  Problem: A loop runs 100,000 iterations                 │
│  By iteration 10,000 it's "hot"                          │
│  But we're INSIDE the loop — can't restart               │
│                                                          │
│  Solution: ON-STACK REPLACEMENT                          │
│                                                          │
│  While loop runs in Ignition (interpreter):              │
│    iteration 1-9999   → bytecode                         │
│    iteration 10000    → loop is HOT                      │
│    TurboFan compiles  → optimized machine code           │
│    WHILE STILL IN THE LOOP → replaces stack frame        │
│    iteration 10001+   → machine code 🚀                  │
│                                                          │
│  OSR = swap from slow to fast mid-execution              │
│  Only JS engines do this — C++ compiles upfront          │
└──────────────────────────────────────────────────────────┘
```

```js
// What TurboFan does to a hot loop:
for (let i = 0; i < arr.length; i++) {
  sum += arr[i];  // called 100,000 times
}

// TurboFan sees:
// → arr is always PACKED_SMI array (integers, no holes)
// → arr.length never changes in the loop
// → sum is always a number
// Compiles to: direct memory read + integer add loop
// Zero type checks per iteration — same as C
```

### How `for...of` Works Internally — Iterator Protocol

```
┌──────────────────────────────────────────────────────────┐
│         for...of INTERNAL MECHANICS                      │
│                                                          │
│  for (const val of iterable) { body }                   │
│                                                          │
│  Desugared to:                                           │
│    const iterator = iterable[Symbol.iterator]();         │
│    let result = iterator.next();                         │
│                                                          │
│    while (!result.done) {                                │
│      const val = result.value;                           │
│      body;                                               │
│      result = iterator.next();                           │
│    }                                                     │
│                                                          │
│  iterator.next() returns: { value, done }                │
│  done = true → loop exits                                │
│  done = false → value used, loop continues              │
└──────────────────────────────────────────────────────────┘
```

```js
// Custom iterable — implements iterator protocol:
class Range {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }

  [Symbol.iterator]() {         // ← makes it iterable
    let current = this.start;
    const end = this.end;

    return {
      next() {                  // ← iterator object
        if (current <= end) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
}

for (const n of new Range(1, 5)) {
  console.log(n); // 1, 2, 3, 4, 5
}

// Spread works too — uses same protocol:
[...new Range(1, 5)] // [1, 2, 3, 4, 5]
```

### `for...of` on String — Unicode Awareness

```js
// for...of correctly handles multi-byte Unicode:
const emoji = "😀🎉";

// for...of — correct (uses code points):
for (const char of emoji) {
  console.log(char); // "😀", "🎉" ✅ — 2 iterations
}

// Classic for — WRONG (uses UTF-16 code units):
for (let i = 0; i < emoji.length; i++) {
  console.log(emoji[i]); // 4 iterations — broken chars 😱
}

emoji.length  // 4 — two emoji = 4 UTF-16 code units
[...emoji].length // 2 — spread uses iterator → correct ✅
```
