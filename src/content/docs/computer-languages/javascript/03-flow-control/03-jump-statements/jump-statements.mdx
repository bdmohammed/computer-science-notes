## 🎯 Jump Statements Overview

JavaScript provides several statements to alter normal program flow:

| Statement | Purpose | Valid Locations |
|-----------|---------|----------------|
| `break` | Exit nearest enclosing loop or switch | `switch`, `for`, `while`, `do-while`, labeled blocks |
| `continue` | Skip current iteration, proceed to next | `for`, `while`, `do-while`, labeled loops |
| `return` | Exit function immediately, optionally return value | Anywhere inside a function |
| `throw` | Raise an exception | Anywhere (caught by `try...catch`) |

<Aside type="caution">
**Runtime Rule**: Using `break` or `continue` outside their valid locations → **SyntaxError**: `"Illegal break/continue statement"`.  
Unlike Java, this is caught at **parse time** (before execution), not compile time.
</Aside>

<Aside type="tip" title="🎯 MUST KNOW">
**JS Superpowers vs Java**:  
✅ **Labeled statements work on ANY block** — not just loops!  
✅ **No unreachable code errors** — JS engines don't flag dead code statically  
✅ **`throw` statement** — fundamental for error handling (no checked exceptions)  
✅ **Generators (`yield`)** — pause/resume execution (advanced jump)  
✅ **Async/Await** — implicit jumps in asynchronous flow  
</Aside>

## `break`  — Exit Loop Immediately

> **Exits the nearest enclosing `switch` or loop immediately**, transferring control to the statement following it.

```js
// Exits loop immediately — skips remaining iterations
for (let i = 0; i < 10; i++) {
  if (i === 5) break;
  console.log(i); // 0, 1, 2, 3, 4
}

// break only exits INNERMOST loop
for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j == 1) break;    // exits inner loop only
        // outer loop continues
    }
}

// break in switch inside loop — only exits switch:
for (let i = 0; i < 3; i++) {
  switch (i) {
    case 1: break; // breaks switch, NOT the for loop 😱
  }
  console.log(i); // still runs: 0, 1, 2
}
// Output:
// after switch: 0
// one
// after switch: 1
// after switch: 2
```

---

### ⚠️ Invalid Usage — Syntax Error

<Code lang="js" title="❌ break outside switch/loop" code={`
let x = 10;
if (x === 10) {
    break;  // ❌ SyntaxError: Illegal break statement
}
console.log("hello");
`} />

<Aside type="note">
**Valid Locations Only**: `break` works **only** inside:
1. `switch` statements
2. Loop constructs (`for`, `while`, `do-while`, `for...in`, `for...of`)
3. Labeled blocks (advanced use)

Using it in plain `if`, `else`, or functions → SyntaxError.
</Aside>

## 🔁 Labeled statement

> **Labels** allow you to name a loop or block and use `break` or `continue` to control flow at that specific level, enabling more complex flow control across nested loops.

---

### 🧠 How Labels Work in JS

In JavaScript, labels can be applied to **any statement**, not just loops. This allows breaking out of nested blocks.

```js
// Label syntax: labelName: loop
outer:
for (let i = 0; i < 5; i++) {
    for (let j = 0; j < 5; j++) {
        if (i === 2 && j === 2) {
            break outer;        // exits OUTER loop entirely
        }
        console.log(i + "" + j + " ");
    }
}
// Output: 00 01 02 03 04 10 11 12 13 14 20 21
// stops when i=2, j=2

// Labeled continue
outer:
for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j === 1) {
            continue outer;     // skip to next iteration of OUTER loop
        }
        console.log(i + "" + j + " ");
    }
}
// Output: 00 10 20
// j=1 triggers continue outer — j=2 never reached

// ✅ Valid: label before loop
search:
for (let i = 0; i < rows; i++) {
    for (let j = 0; j < cols; j++) {
        if (matrix[i][j] === target) {
            break search;  // Exit both loops at once
        }
    }
}

// ✅ Valid: label on any block (JS specific!)
myBlock: {
    console.log("Start");
    if (condition) break myBlock;  // Exit block early
    console.log("This might be skipped");
}
console.log("After block");  // Execution continues here

// ❌ Invalid: label on expression/statement without block
// wrong: console.log("hi");  // ❌ SyntaxError: Unexpected token
```

```
Label placement:
  label MUST immediately precede the loop statement
  label can be any valid identifier
  break label  → exits labeled loop
  continue label → skips to next iteration of labeled loop
  No goto equivalent — labels only work with break/continue
```

## continue Statement

> **Skips the current iteration** of the nearest enclosing loop and proceeds to the next iteration.

```js
// Skips rest of current iteration — jumps to update/condition
for (let i = 0; i < 10; i++) {
    if (i % 2 == 0) continue;  // skip even numbers
    console.log(i + " "); // 1 3 5 7 9
}

// In while — continue jumps to condition check
let i = 0;
while (i < 10) {
    i++;
    if (i % 2 == 0) continue;  // jumps to condition check (i<10)
    console.log(i + " "); // 1 3 5 7 9
}

// In do-while — continue jumps to condition check
let j = 0;
do {
    j++;
    if (j % 2 == 0) continue;  // jumps to while(j<10) check
    console.log(j + " ");
} while (j < 10);              // 1 3 5 7 9
```

---

### ⚠️ Invalid Usage — Same as break

<Code lang="js" title="❌ continue outside loop" code={`
if (x > 0) {
    continue;  // ❌ SyntaxError: Illegal continue statement
}
// continue only valid inside: for, while, do-while, for...in, for...of, or labeled loops
`} />

## return Statement

> **Exits the current function immediately**, optionally returning a value to the caller.

---

### 🔑 Syntax Patterns

<Code lang="js" title="return with value (non-void function)" code={`
function max(a, b) {
    if (a > b) return a;  // ✅ Exit function, return a
    return b;             // ✅ Exit function, return b
    // Code here would be unreachable (but JS doesn't flag it!)
}
`} />

<Code lang="js" title="return without value (void-like function)" code={`
function process(x) {
    if (x < 0) return;    // ✅ Early exit — guard clause pattern
    // Continue processing only if x >= 0
    console.log("Processing: " + x);
}
`} />

---

### 🛡️ Guard Clause Pattern — Early return for Validation

<Code lang="js" title="Prefer early returns over nested if" code={`
// ❌ Nested if (harder to read)
function process(user) {
    if (user) {
        if (user.isActive) {
            if (user.hasPermission) {
                // Actual logic here...
            }
        }
    }
}

// ✅ Guard clauses with early return (cleaner)
function process(user) {
    if (!user) return;           // Guard 1
    if (!user.isActive) return;  // Guard 2
    if (!user.hasPermission) return;  // Guard 3
    
    // Actual logic — no nesting!
    performAction(user);
}
`} />

<Aside type="tip">
**Guard Clause Benefits**:
1. ✅ Reduces nesting → improves readability
2. ✅ Each validation is independent and clear
3. ✅ Easy to add/remove validations
4. ✅ Fail-fast: invalid inputs exit early, no wasted computation
</Aside>

## ⚠️ The Dangerous Combination: do-while + continue

> This pattern is notoriously tricky — `continue` in `do-while` skips to the **while condition**, not the loop start.

---

### 🔬 Step-by-Step Execution Trace

<Code lang="js" title="Complex do-while + continue example" code={`let x = 0;
do {
    ++x;                          // Step 1: x becomes 1
    console.log(x);               // Step 2: Print 1
    if (++x < 5) continue;        // Step 3: x becomes 2; 2<5=true → continue
    ++x;                          // ❌ SKIPPED due to continue!
    console.log(x);               // ❌ SKIPPED due to continue!
} while (++x < 10);               // Step 4: x becomes 3; 3<10=true → next iteration
// Output so far: 1

// Iteration 2:
// ++x → x=4; print 4; ++x→5; 5<5=false → don't continue
// ++x→6; print 6; while(++x→7; 7<10=true) → next iteration
// Output: 1, 4, 6

// Iteration 3:
// ++x→8; print 8; ++x→9; 9<5=false → don't continue  
// ++x→10; print 10; while(++x→11; 11<10=false) → exit
// Final Output: 1, 4, 6, 8, 10`} />

---

### 🧠 Why This Is Dangerous

<Card title="Trap 1: continue skips to condition, not loop start" icon="error">
  In `do-while`, `continue` jumps directly to the `while (condition)` check — **not** to the top of the loop body.  
  This can skip critical initialization or update code unexpectedly.
</Card>

<Card title="Trap 2: Multiple increments + continue = hard to trace" icon="error">
  When loop variable is modified in multiple places (`++x` in body, condition, and after `continue`), tracking its value becomes extremely difficult.  
  ✅ Prefer: single update location, clear loop structure.
</Card>

<Card title="✅ Safer Alternative: Use for loop with clear structure" icon="approve-check">
  ```js
      for (let x = 1; x < 10; x++) {
          console.log(x);
          if (x < 5) continue;  // Clear: skip to x++ update
          x++;  // Explicit second increment
          console.log(x);
      }
      // Same logic, but for-loop structure makes flow more predictable
  ```
</Card>

<Aside type="danger">
**Rule of Thumb**: Avoid `continue` in `do-while` loops unless the flow is trivial.  
Prefer `if` guards with early `continue` in `for`/`while` loops, or refactor complex logic into helper functions.
</Aside>
