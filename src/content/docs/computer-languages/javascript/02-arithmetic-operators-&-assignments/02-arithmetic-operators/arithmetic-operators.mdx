## 🔢 Rule 1: No Type Promotion — All Numbers Are Equal!

> JavaScript has **only two numeric types**:  
> - `Number` — IEEE 754 double-precision (64-bit float)  
> - `BigInt` — arbitrary precision integers (ES2020+)

**No byte/short/char/int/long/float/double hierarchy** — no promotion rules needed!

### 📊 Type Behavior Comparison

| Operation | Java Result Type | JavaScript Result Type |
|-----------|-----------------|----------------------|
| `10 + 3` | `int` | `Number` |
| `10.5 + 3` | `double` | `Number` |
| `'a' + 'b'` | `int` (195) | `string` ("ab") ⚠️ |
| `true + 1` | ❌ C.E: boolean + int | `Number` (2) ⚠️ |
| `null + 5` | ❌ C.E: null + int | `Number` (5) ⚠️ |
| `[] + []` | ❌ C.E: array + array | `string` ("") ⚠️ |

### 💻 Coercion Examples (Watch Out!)

<Code lang="js" title="Coercion happens automatically — sometimes surprisingly" code={`
// ✅ Expected numeric behavior
console.log(10 + 3);        // 13
console.log(10.5 + 3);      // 13.5
console.log('10' + '3');    // "103" ← string concatenation!
console.log('10' - '3');    // 7 ← minus forces numeric conversion!

// ⚠️ Surprising coercion
console.log(true + 1);      // 2 (true → 1)
console.log(false + 5);     // 5 (false → 0)
console.log(null + 10);     // 10 (null → 0)
console.log(undefined + 5); // NaN (undefined → NaN)
console.log([] + 1);        // "1" ([] → "" → "1")
console.log({} + 1);        // "[object Object]1" or 1 (context-dependent!)

// ✅ Force numeric conversion explicitly:
console.log(Number('10') + 3);  // 13
console.log(+'10' + 3);         // 13 (unary + is concise coercion)
`} />

<Aside type="caution">
**Assignment Trap Avoided**: Because JS has no `byte`/`short`, you never get "possible loss of precision" errors:
```js
// Java: byte a=10, b=20; byte c = a+b; // ❌ C.E
// JS: No such problem!
let a = 10, b = 20;
let c = a + b;  // ✅ Works — c is Number, no cast needed
```
</Aside>

## 🔥 Rule 2: Division by Zero — Never Throws!

### JavaScript Behavior (All Numeric Types)

> IEEE 754 standard defines **infinity** and **NaN** → **No exception**, special values returned.

<Code lang="js" title="Division by zero — always safe, returns special values" code={`
console.log(10 / 0);        // Infinity ✅
console.log(-10 / 0);       // -Infinity ✅
console.log(0 / 0);         // NaN ✅
console.log(-0 / 0);        // NaN ✅

let d = 10 / 0;             // Infinity
let e = -10 / 0;            // -Infinity  
let f = 0 / 0;              // NaN
let g = 10 % 0;             // NaN

// Check special values:
console.log(Number.isFinite(d));    // false
console.log(Number.isNaN(f));       // true
console.log(!Number.isFinite(g));   // true (NaN is not finite)

// Access constants:
console.log(Number.POSITIVE_INFINITY);  // Infinity
console.log(Number.NEGATIVE_INFINITY);  // -Infinity
console.log(Number.NaN);                // NaN
`} />

<Aside type="note">
**Key Difference from Java**:  
| Scenario | Java `int` | Java `double` | JavaScript `Number` |
|----------|-----------|---------------|-------------------|
| `10 / 0` | 💥 `ArithmeticException` | `Infinity` | `Infinity` ✅ |
| `0 / 0`  | 💥 `ArithmeticException` | `NaN` | `NaN` ✅ |

> 🔑 JavaScript **never throws** on division by zero — always returns `Infinity` or `NaN`. This eliminates try-catch for division safety checks!
</Aside>

## 🔬 Division — Always Floating Point (No Integer Truncation!)

```js
// Positive / positive
10 / 3   →  3.3333333333333335  ← always float!

// Negative — no truncation confusion:
-7 / 2   →  -3.5  ← exact float result
 7 / -2  →  -3.5
-7 / -2  →   3.5

// ✅ To get integer division like Java:
Math.floor(10 / 3)   → 3
Math.trunc(-7 / 2)   → -3  (truncates toward zero, like Java)
Math.floor(-7 / 2)   → -4  (floor toward -∞)
```

```
Integer division patterns in JS:
  Math.trunc(x / y)  → truncates toward zero (matches Java /)
  Math.floor(x / y)  → truncates toward -∞ (mathematical floor)
  x / y | 0          → bitwise OR trick for truncation (fast, but only for 32-bit range)
  ~~(x / y)          → double bitwise NOT, same as | 0

Example:
  Math.trunc(-7 / 2)  → -3  (Java: -7 / 2 = -3) ✅
  Math.floor(-7 / 2)  → -4  (Java: different!)
```

> 🔑 JavaScript division **always returns float**. Use `Math.trunc()` to mimic Java's integer division behavior. `Math.floor()` gives mathematical floor (different for negatives).

## 🔬 Modulo (%) Operator — Same Sign Rule as Java

```js
// Basic
10 % 3   →  1
10 % 5   →  0
10 % 10  →  0
10 % 11  →  10  (dividend < divisor → result = dividend)

// Sign rule: result sign matches DIVIDEND (left operand) — SAME AS JAVA!
 7 %  3  →  1   (positive dividend → positive result)
-7 %  3  → -1   (negative dividend → negative result)
 7 % -3  →  1   (positive dividend → positive result — divisor sign ignored)
-7 % -3  → -1   (negative dividend → negative result)

// Floating point modulo works too:
10.5 % 3.0  →  1.5
-10.5 % 3.0 → -1.5
```

```
Formula: a % b = a - Math.trunc(a/b)*b   (where trunc is toward zero)

-7 % 3:
  -7 / 3 = -2.333...
  Math.trunc(-2.333) = -2
  -7 % 3 = -7 - (-2 * 3) = -7 + 6 = -1

Use case: checking even/odd
  n % 2 === 0  → even  (BUT: -4 % 2 === 0 ✅ still works)
  n % 2 === 1  → odd   ❌ WRONG for negatives (-3 % 2 = -1, not 1)
  n % 2 !== 0  → odd   ✅ correct for all integers
```

> 🔑 `n % 2 === 1` fails for negative odd numbers — `-3 % 2 = -1`, not `1`. Always use `n % 2 !== 0` to check odd numbers. **Same rule as Java!**

## 🔬 Compound Assignment Operators — Same, But No Implicit Cast Issues

```js
let x = 10;

x += 5;     // x = x + 5  = 15
x -= 3;     // x = x - 3  = 12
x *= 2;     // x = x * 2  = 24
x /= 4;     // x = x / 4  = 3.75  ← float result!
x %= 4;     // x = x % 4  = 3.75
x **= 2;    // x = x ** 2 = 14.0625  (ES2016+)
```

### ✅ No Hidden Cast — Simpler Than Java

```js
// Java trap: byte b = 10; b = b + 5; // ❌ C.E
// JS: No such problem — no byte/short types!

let num = 10;
num += 5;           // ✅ Works — num is Number, no cast needed
num = num + 5;      // ✅ Also works — same result

// No silent overflow from implicit narrowing:
let big = Number.MAX_SAFE_INTEGER;
big += 1000;        // ✅ Works — may lose precision, but no compile error
console.log(big);   // 9007199254741991 (precision loss, but valid Number)
```

> 🔑 Compound operators in JS are **simpler** — no implicit narrowing cast, no "possible loss of precision" errors. Just be aware of floating-point precision limits!

## 🔬 `+` Operator and String Concatenation — Coercion Rules

```js
// + with String — concatenation, with coercion
let s = "value: " + 10 + 20;    // "value: 1020" ← left to right
let t = "value: " + (10 + 20);  // "value: 30"   ← parens force addition first
let u = 10 + 20 + " value";     // "30 value"    ← left to right, int+int first

// Any type concatenated with String → String (with coercion)
"result: " + true         // "result: true"
"result: " + null         // "result: null"   ← null becomes "null" string
"result: " + 3.14         // "result: 3.14"
"result: " + 'A'          // "result: A"
"result: " + {}           // "result: [object Object]"
"result: " + []           // "result: "        ← empty array → empty string

// Minus forces numeric conversion (no concatenation):
"10" - "3"    // 7  ← both coerced to numbers
"hello" - 5   // NaN ← "hello" can't be numeric
```

```
Left-to-right evaluation with coercion:
  "a" + 1 + 2
    → ("a" + 1) + 2     ← string + number = string
    → "a1" + 2
    → "a12"

  1 + 2 + "a"
    → (1 + 2) + "a"     ← number + number = number
    → 3 + "a"
    → "3a"

  [] + {} 
    → "" + "[object Object]"  ← [] → "", {} → "[object Object]"
    → "[object Object]"
```

<Aside type="tip">
**Pro Pattern**: Use template literals to avoid `+` concatenation confusion:
```js
// ❌ Confusing coercion:
let msg = "User " + name + " has " + count + " items";

// ✅ Clear and safe:
let msg = `User ${name} has ${count} items`;
// No coercion surprises — values converted to string predictably
```
</Aside>

## 🔬 BigInt — Arbitrary Precision Integers (ES2020+)

For integers beyond `Number.MAX_SAFE_INTEGER` (`2⁵³ - 1`), use `BigInt`.

<Code lang="js" title="BigInt arithmetic" code={`
// BigInt literal syntax: append 'n'
let big = 9007199254740991n;  // MAX_SAFE_INTEGER as BigInt
let bigger = 123456789012345678901234567890n;  // Arbitrary size!

// BigInt arithmetic — no precision loss
let result = bigger * 2n;  // ✅ Exact result
console.log(result);  // 246913578024691357802469135780n

// ⚠️ Cannot mix BigInt and Number:
// big + 1  // ❌ TypeError: can't mix BigInt and Number

// ✅ Convert explicitly:
let safe = big + BigInt(1);  // ✅
let alsoSafe = BigInt(1) + big;  // ✅

// BigInt supports all arithmetic operators:
big ** 2n;   // ✅ exponentiation
big % 10n;   // ✅ modulo
-big;        // ✅ unary negation

// But no floating point:
let frac = 10n / 3n;  // ✅ 3n (truncates toward zero, like Java int division)
`} />

<Aside type="caution">
**BigInt Limitations**:  
1. ❌ Cannot use with `Math` methods: `Math.sqrt(4n)` → TypeError  
2. ❌ Cannot use with JSON: `JSON.stringify({val: 1n})` → TypeError  
3. ❌ Cannot compare with `==`/`===` to Number: `1n === 1` → false  
4. ✅ Use `Number.isInteger()` won't work — use `typeof x === "bigint"`  
</Aside>

## 🎯 Common Traps & Solutions

<CardGrid>
  <Card title="Trap 1: Unexpected String Concatenation" icon="error">
    ```js
    let total = "10" + 20 + 30;  // "102030" 😱 not 60!
    
    // ✅ Fix: Force numeric conversion first
    let total = Number("10") + 20 + 30;  // 60 ✅
    let total = +"10" + 20 + 30;         // 60 ✅ (unary + is concise)
    let total = parseInt("10") + 20 + 30; // 60 ✅
    ```
    **Rule**: If any operand is string, `+` does concatenation — coerce numbers first!
  </Card>
  
  <Card title="Trap 2: Modulus Sign Rule (Same as Java)" icon="error">
    ```js
    console.log( 10 %  3);  //  1
    console.log(-10 %  3);  // -1  ← sign follows DIVIDEND (left operand)!
    console.log( 10 % -3);  //  1
    console.log(-10 % -3);  // -1
    
    // ✅ Memory rule: result sign = sign of LEFT operand (same as Java)
    ```
    **Interview Answer**: JavaScript's `%` is **remainder**, not mathematical modulo. Sign matches dividend — identical to Java behavior.
  </Card>

  <Card title="Trap 3: Floating-Point Precision Loss" icon="error">
    ```js
    console.log(0.1 + 0.2);  // 0.30000000000000004 😱
    console.log(0.1 + 0.2 === 0.3);  // false!
    
    // ✅ Fixes:
    // 1. Use integers for money (cents):
    let price = 10 + 20;  // 30 cents
    let dollars = price / 100;  // 0.3
    
    // 2. Use toFixed() for display only:
    console.log((0.1 + 0.2).toFixed(2));  // "0.30"
    
    // 3. Use libraries for precision:
    // import Decimal from 'decimal.js';
    // new Decimal(0.1).plus(0.2).equals(0.3);  // true ✅
    ```
  </Card>

  <Card title="Trap 4: BigInt/Number Mixing" icon="error">
    ```js
    let big = 10n;
    let num = 5;
    
    // ❌ These throw TypeError:
    big + num;      // TypeError
    big > num;      // TypeError
    big == num;     // false (but no error — just always false)
    
    // ✅ Convert explicitly:
    BigInt(num) + big;  // 15n ✅
    big > BigInt(num);  // true ✅
    ```
    **Rule**: BigInt and Number are **incompatible types** — always convert explicitly.
  </Card>
</CardGrid>

## 🧩 DSA Angle: Arithmetic in Algorithms

<CardGrid>
  <Card title="Pattern: Safe Midpoint Calculation" icon="shield">
    Avoid overflow in binary search (same as Java, but JS safer with floats):
    ```js
    // ❌ Risky with very large integers (if using BigInt):
    let mid = (low + high) / 2n;  // May overflow BigInt addition
    
    // ✅ Safe — no overflow risk:
    let mid = low + (high - low) / 2n;  // BigInt division truncates
    
    // ✅ For Number (safe up to MAX_SAFE_INTEGER):
    let mid = Math.trunc((low + high) / 2);  // or just (low+high)/2 if precision OK
    ```
  </Card>
  
  <Card title="Pattern: Modulus for Cyclic Indexing" icon="rocket">
    Use `%` for circular buffer/array access (same as Java):
    ```js
    // Rotate array index safely:
    let next = (current + 1) % arr.length;  // wraps to 0 at end
    let prev = (current - 1 + arr.length) % arr.length;  // handles negative
    
    // Hash table indexing:
    let index = Math.abs(key.hashCode?.() || key) % tableSize;
    ```
  </Card>

  <Card title="Pattern: BigInt for Large Number Problems" icon="backspace">
    When problem constraints exceed `Number.MAX_SAFE_INTEGER`:
    ```js
    // Problem: Compute factorial of 100
    // 100! ≈ 9.3e157 — far beyond Number precision
    
    // ✅ Use BigInt:
    function factorial(n) {
        let result = 1n;
        for (let i = 2n; i <= BigInt(n); i++) {
            result *= i;
        }
        return result;  // Exact arbitrary-precision result
    }
    
    // ✅ Or use string manipulation for display:
    console.log(factorial(100).toString());  // Full number as string
    ```
  </Card>

  <Card title="Underlying primitive: IEEE 754 + JIT compilation">
    ```js
      JavaScript arithmetic:
        All Number operations → IEEE 754 double-precision (64-bit float)
        BigInt operations → arbitrary precision integer arithmetic

      Division behavior:
        a / b always returns Number (float) — no integer division
        CPU FDIV instruction → IEEE 754 result → JS Number
        Special cases (div by zero) → Infinity/NaN per IEEE 754
        No exception thrown — silent special values

      Overflow behavior:
        Number: Beyond ±2⁵³ → precision loss (not wrap like Java int)
        BigInt: No overflow — arbitrary precision (memory-limited)

      Coercion rules:
        ToNumber() abstract operation applied before arithmetic
        String → Number: parseFloat-like conversion
        Boolean → Number: true→1, false→0
        null → 0, undefined → NaN
        Object → primitive via valueOf/toString, then ToNumber

      Performance:
        Modern engines (V8, SpiderMonkey) use inline caches, hidden classes
        Hot arithmetic code JIT-compiled to optimized machine code
        BigInt operations slower than Number — use only when needed
    ```
  </Card>
</CardGrid>

| `byte + byte → int` assignment error | No such error — all arithmetic returns `Number` | ✅ JS simpler, but watch coercion |
| `ArithmeticException` on `/ 0` (int) | Never throws — returns `Infinity`/`NaN` | ✅ JS safer for division, but check for special values |

## 1️⃣ Addition `+` — The Overloaded Operator

`+` does **two completely different things** depending on operand types.

```
┌─────────────────────────────────────────────────────────┐
│              + OPERATOR DECISION TREE                   │
│                                                         │
│  operand1 + operand2                                    │
│          │                                              │
│          ▼                                              │
│  Is EITHER operand a string?                            │
│     │                                                   │
│   YES ──────────────────────→ STRING CONCATENATION      │
│     │                         convert both to string    │
│     │                         join them                 │
│   NO                                                    │
│     │                                                   │
│     ▼                                                   │
│  Is EITHER operand an object?                           │
│     │                                                   │
│   YES ──→ call ToPrimitive() on object                  │
│            → hint: "default" (prefers number)           │
│            → then re-run decision tree                  │
│   NO                                                    │
│     │                                                   │
│     ▼                                                   │
│  Convert both to NUMBER → add                           │
└─────────────────────────────────────────────────────────┘
```

```js
// Pure number addition:
5 + 3          // 8
5 + 3.5        // 8.5
Infinity + 1   // Infinity
-Infinity + Infinity // NaN

// String concatenation:
"hello" + " world"  // "hello world"
"5" + 3             // "53" 😱 — 3 converts to string
3 + "5"             // "35" 😱 — left to right
1 + 2 + "3"         // "33" — 1+2=3 first, then "3"+"3"="33"
"1" + 2 + 3         // "123" — "1"+2="12", "12"+3="123"

// Object coercion:
[] + []             // "" — both → "", "" + "" = ""
[] + {}             // "[object Object]"
{} + []             // 0 in some contexts 😱 (see trap below)

## 6️⃣ Exponentiation `**`

```js

2 ** 0          // 1   — anything to power 0 = 1
0 ** 0          // 1   — by convention

2 ** -1         // 0.5 — negative exponent = fraction

│  2 ** 3 ** 2 = 2 ** (3**2) = 2**9 = 512     │

## ⚙️ Deep Dive — IEEE 754 and Why Math Breaks

```
┌─────────────────────────────────────────────────────────┐
│              IEEE 754 DOUBLE PRECISION                  │
│                                                         │
│  64 bits total:                                         │
│  ┌─┬──────────┬────────────────────────────────────┐   │
│  │S│ Exponent │           Mantissa                 │   │
│  │1│    11    │               52                   │   │
│  └─┴──────────┴────────────────────────────────────┘   │
│                                                         │
│  0.1 in binary = 0.0001100110011... (infinite repeat)  │
│  Stored as approximation → 0.1000000000000000055511...  │
│                                                         │
│  0.1 + 0.2                                              │
│  = 0.1000000000000000055... + 0.2000000000000000111...  │
│  = 0.3000000000000000444...                             │
│  ≠ 0.3                                                  │
└─────────────────────────────────────────────────────────┘
```

```js
// Classic IEEE 754 surprises:
0.1 + 0.2          // 0.30000000000000004
0.1 + 0.2 === 0.3  // false 😱

0.3 - 0.1          // 0.19999999999999998
1.005.toFixed(2)   // "1.00" not "1.01" 😱

// Max safe integer:
Number.MAX_SAFE_INTEGER     // 9007199254740991
9007199254740991 + 1        // 9007199254740992 ✅
9007199254740991 + 2        // 9007199254740992 😱 — same number

// Solutions:
// 1. Epsilon comparison:
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON  // true ✅

// 2. Scale to integers:
(0.1 * 10 + 0.2 * 10) / 10  // 0.3 ✅

// 3. BigInt for integers beyond safe range:
9007199254740991n + 2n       // 9007199254740993n ✅

// 4. toFixed for display (NOT computation):
(0.1 + 0.2).toFixed(1)       // "0.3" ✅ — for display only
```

## 💀 Interview Traps

### Trap 1: `{}` + `[]` vs `[] + {}`

```js
[] + {}   // "[object Object]" — [] → "", {} → "[object Object]"
{} + []   // 0 😱

// Why? In statement position:
// {} is parsed as EMPTY BLOCK — not object literal
// +[] is then a UNARY + on [] → +[] → 0

// In expression position (inside parens or assignment):
({} + []) // "[object Object]" ✅ — {} is object literal here
const x = {} + [] // "[object Object]" ✅

// This is a parsing ambiguity — not a coercion bug
```

### Trap 2: `+` with `null` vs `-` with `null`

// But:
null - 1    // -1  — null → 0, then 0 - 1 = -1
null - "1"  // -1  — "-" forces numeric: "1" → 1

// Senior trap — checking for null with arithmetic:
function add(a, b) {

                // if a=null, b="5" → "null5" 😱
}
```

### Trap 4: Increment vs Addition — subtle expression difference

    page,
    totalPages,

## 📊 DSA / Internals Connection

> Every arithmetic operator maps directly to **IEEE 754 double-precision floating point** CPU instructions. V8 Ignition emits `Add`, `Sub`, `Mul`, `Div` bytecodes. TurboFan compiles hot numeric code to native `ADDSD`, `MULSD`, `DIVSD` (SSE2 instructions) on x86-64. There is **zero overhead** for number arithmetic in hot JIT-compiled JS — it's identical to C++ floating point speed.
>
> Modulo `%` is the foundation of **hash tables** (bucket selection), **ring buffers** (circular indexing), and **cycle detection** (Floyd's algorithm). Every DSA topic that wraps around uses `%`.
