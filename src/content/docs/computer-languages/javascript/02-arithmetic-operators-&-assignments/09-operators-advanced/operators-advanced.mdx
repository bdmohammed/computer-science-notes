## Assignment Operators

```text
Assignment Operators in JS
│
├── 🔵 Basic Assignment
│   └── =
│
├── 🔢 Arithmetic Compound
│   ├── +=   (add-assign)
│   ├── -=   (subtract-assign)
│   ├── *=   (multiply-assign)
│   ├── /=   (divide-assign)
│   ├── %=   (modulo-assign)
│   └── **=  (exponent-assign)
│
├── 🔬 Bitwise Compound
│   ├── &=   (AND-assign)
│   ├── |=   (OR-assign)
│   ├── ^=   (XOR-assign)
│   ├── <<=  (left-shift-assign)
│   ├── >>=  (right-shift-assign)
│   └── >>>= (unsigned-right-shift-assign)
│
├── ⚡ Logical Compound (ES2021)
│   ├── &&=  (AND-assign)
│   ├── ||=  (OR-assign)
│   └── ??=  (nullish-assign)
│
└── 🧩 Destructuring Assignment
    ├── Array destructuring
    ├── Object destructuring
    ├── Default values
    ├── Rest in destructuring
    └── Nested destructuring
```

<Aside type="tip" title="🎯 MUST KNOW">
**JS Superpowers vs Java**:  
✅ **No hidden cast trap** — all numbers are 64-bit floats, no narrowing issues  
✅ **Destructuring assignment** — extract values elegantly: `[a, b] = [1, 2]`  
✅ **Logical assignment operators** (ES2021+): `&&=`, `||=`, `??=` for conditional assignment  
✅ **Exponentiation `**` and `**=`** — cleaner than `Math.pow()`  
✅ **No compound assignment overflow surprises** — but watch floating-point precision!  
</Aside>

### 1. Simple Assignment

<Code lang="js" title="Basic assignment" code={`
let x = 10;  // ✅ Simple assignment
const y = 20; // ✅ const prevents reassignment
var z = 30;   // ⚠️ var is function-scoped — prefer let/const
`} />

<Aside type="note">
**`const` ≠ Immutable**: `const` prevents **reassignment of the binding**, not mutation of contents:
```js
const arr = [1, 2, 3];
arr.push(4);  // ✅ Allowed — mutating contents
arr = [5];    // ❌ TypeError — can't reassign binding
```
</Aside>

### 2. Chained Assignment

<Code lang="js" title="✅ Valid: Chained assignment" code={`
let a, b, c, d;
a = b = c = d = 20;  // ✅ All get 20
console.log(\`\${a}---\${b}---\${c}---\${d}\`);
// Output: 20---20---20---20
`} />

<Code lang="js" title="✅ Also valid: Declare + assign in one" code={`
// JS allows declaration + chained assignment:
let a = b = c = d = 30;  // ✅ But careful: b, c, d become GLOBAL if not declared!

// ✅ Safe pattern: declare all first, or use separate statements:
let a, b, c, d;
a = b = c = d = 30;  // ✅ All local

// ✅ Or modern: destructuring for same value:
const [a, b, c, d] = Array(4).fill(30);  // ✅ Clear and safe
`} />

<Aside type="caution">
**Global Leak Trap**: In non-strict mode, `let a = b = c = 30` makes `b` and `c` **global variables**!  
✅ **Fix**: Always declare variables explicitly, or use `"use strict";` to catch this error.
</Aside>

### 3. Compound Assignment — No Hidden Cast, But Watch Coercion!

<Code lang="js" title="Compound operators work without implicit cast" code={`
let x = 10;
x += 5;   // x = x + 5 → 15
x -= 3;   // x = x - 3 → 12
x *= 2;   // x = x * 2 → 24
x /= 4;   // x = x / 4 → 3 (always float division!)
x %= 4;   // x = x % 4 → 3
x **= 2;  // x = x ** 2 → 9 (ES2016+ exponentiation)
`} />

#### 🔬 Why JS Has No Narrowing Cast Trap

<Code lang="js" title="No byte/short types — no narrowing issues" code={`
// Java trap: byte b = 10; b = b + 1; // ❌ C.E: int → byte needs cast
// JS: No such problem — all numbers are 64-bit floats!

let num = 10;
num = num + 1;  // ✅ Works perfectly
num += 1;       // ✅ Also works — same result

// No implicit cast needed — JS has no byte/short/char types!
// Everything is Number (or BigInt for large integers)
`} />

#### ⚠️ But JS Has Coercion Surprises!

<Code lang="js" title="Compound assignment with coercion" code={`
// String + number: concatenation, not addition!
let s = "10";
s += 5;  // s = "10" + 5 → "105" (string concatenation!)
console.log(s);  // "105"

// Force numeric first:
let n = "10";
n = Number(n) + 5;  // n = 15 ✅
// Or concise:
n = +"10" + 5;      // n = 15 ✅ (unary + coerces to number)

// Boolean coercion:
let flag = true;
flag += 1;  // true → 1, then 1 + 1 = 2
console.log(flag);  // 2 (number!)
console.log(typeof flag);  // "number"

// ✅ Safe pattern: validate types before compound assignment
function safeAdd(a, b) {
    if (typeof a !== "number" || typeof b !== "number") {
        throw new TypeError("Both operands must be numbers");
    }
    return a + b;
}
`} />

<Aside type="danger">
**Golden Rule**: Compound assignment **does not auto-cast types** — it coerces operands first per JS rules.  
`"10" += 5` → `"105"` (string), not `15` (number). Always validate input types!
</Aside>

#### 🧮 Complex Expression Evaluation

<Code lang="js" title="Compound ops with chained assignment" code={`
let a, b, c, d;
a = b = c = d = 20;

// Evaluate right-to-left for assignment, but left-to-right for operands:
a += b -= c *= d /= 2;

// Step-by-step (same as Java):
// 1. d /= 2 → d = 20 / 2 = 10
// 2. c *= d → c = 20 * 10 = 200
// 3. b -= c → b = 20 - 200 = -180
// 4. a += b → a = 20 + (-180) = -160

console.log(\`\${a}--\${b}---\${c}---\${d}\`);
// Output: -160---180---200---10
`} />

<Aside type="caution">
**Avoid Complex Compound Chains**: Expressions like `a += b -= c *= d` are hard to read and debug.  
✅ Prefer separate statements for clarity and maintainability.
</Aside>

### 4. Logical Assignment Operators <Badge text="ES2021+" variant="success" />

<Code lang="js" title="Conditional assignment with &&=, ||=, ??=" code={`
// &&= : assign only if left is truthy
let config = { debug: true };
config.debug &&= false;  // config.debug = false (was truthy)
config.enabled &&= true; // config.enabled unchanged (was undefined/falsy)

// ||= : assign only if left is falsy
let user = { name: "" };
user.name ||= "Guest";  // user.name = "Guest" (was falsy)
user.age ||= 18;        // user.age = 18 (was undefined)

// ??= : assign only if left is nullish (null/undefined)
let settings = { theme: null };
settings.theme ??= "light";  // settings.theme = "light" (was null)
settings.debug ??= false;    // settings.debug = false (was undefined)

// ✅ Practical: Safe defaults without overwriting valid falsy values
const port = process.env.PORT ??= 3000;  // Keep "0" if PORT="0", fallback only if null/undefined
`} />

<Aside type="tip">
**Choose the right logical assignment**:  
- `||=` → fallback on **any falsy** (`0`, `""`, `false`, `null`, `undefined`)  
- `??=` → fallback **only on `null`/`undefined`** (preserves `0`, `""`, `false`)  
✅ Prefer `??=` for configuration defaults where `0` or `""` are valid values.
</Aside>

## Conditional (Ternary) Operator

```text
condition ? valueIfTrue : valueIfFalse
```

<Code lang="js" title="Basic ternary usage" code={`
let a = 10, b = 20;
let max = (a > b) ? a : b;  // 20 ✅

// Nested ternary (works but hard to read — prefer if-else or switch):
let x = 5;
let result = x > 0 ? "positive" : x < 0 ? "negative" : "zero";
console.log(result);  // "positive"

// ✅ Modern: Use template literals for complex formatting:
let status = x > 0 ? \`✅ \${x}\` : \`❌ \${x}\`;
`} />

### ⚠️ No Type Promotion Trap — But Coercion Still Applies!

<Code lang="js" title="Ternary returns operand values, not coerced type" code={`
let a = 10, b = 20;

// Both branches are numbers → result is number
let c1 = (a > b) ? 30 : 40;  // 40 ✅ (no type promotion issues)

// Mixed types → result is whichever branch is taken (no coercion!)
let c2 = (a < b) ? "high" : 40;  // "high" (string)
let c3 = (a > b) ? "high" : 40;  // 40 (number)

console.log(typeof c2, typeof c3);  // "string", "number"

// ✅ Ternary returns the actual operand value — no hidden conversion!
// This is different from Java, where ternary result type follows promotion rules.
`} />

<Aside type="note">
**JS Ternary Rule**: The ternary operator **returns one of the two operand values unchanged** — no type coercion or promotion.  
The result type is whichever branch is taken. This is simpler than Java's binary numeric promotion rules!
</Aside>

## Object Creation — No `new` Required (But Still Useful)

> JavaScript has **multiple ways** to create objects — `new` is just one option.

<Code lang="js" title="Object creation patterns" code={`
// 1. Object literal (most common — no 'new' needed!)
const obj1 = { name: "Alice", age: 30 };

// 2. Constructor function with 'new'
function Person(name) { this.name = name; }
const obj2 = new Person("Bob");

// 3. Class syntax with 'new' (ES6+)
class Student {
    constructor(name) { this.name = name; }
}
const obj3 = new Student("Charlie");

// 4. Object.create() — prototype-based
const proto = { greet() { return \`Hi, \${this.name}\`; } };
const obj4 = Object.create(proto);
obj4.name = "Dana";

// 5. Factory function — no 'new', no class
function createPerson(name) {
    return { name, greet: () => \`Hi, \${name}\` };
}
const obj5 = createPerson("Eve");

// ✅ All create objects — choose based on design needs!
`} />

<Aside type="tip">
**Modern Best Practice**:  
- Use **object literals** `{}` for simple data  
- Use **classes** with `new` for inheritance/polymorphism  
- Use **factory functions** for encapsulation without `this` complexity  
- Avoid `new Object()` — verbose and unnecessary
</Aside>

## Array Access Operator `[]` — More Powerful in JS

> Used for **array access**, **property access**, and **destructuring** in JavaScript.

<Code lang="js" title="Array and property access" code={`
// Array access (0-based, out-of-bounds → undefined, not exception!)
const arr = [10, 20, 30];
console.log(arr[0]);   // 10
console.log(arr[5]);   // undefined (no crash!)
arr[1] = 99;           // Modify element

// Property access with [] — dynamic keys
const obj = { name: "Alice", age: 30 };
const key = "name";
console.log(obj[key]);  // "Alice" (dynamic property access)

// Optional chaining with [] — safe nested access
console.log(obj?.address?.[key]);  // undefined if any step null/undefined

// Destructuring assignment — extract values elegantly
const [first, second, ...rest] = [1, 2, 3, 4];
// first=1, second=2, rest=[3,4]

const { name, age: userAge } = obj;
// name="Alice", userAge=30 (rename during destructuring)
`} />

<Aside type="caution">
**Out-of-Bounds Behavior**:  
- Java: `arr[5]` on length-3 array → 💥 `ArrayIndexOutOfBoundsException`  
- JS: `arr[5]` → `undefined` (no crash, but check with `in` operator if needed)  
✅ Use `Array.isArray()` and length checks for robust code.
</Aside>

+------------+--------------------------------------+-----------------------------------+----------------+
| 5          | +  -                                 | Additive / string concat          | Left-to-right  |
+------------+--------------------------------------+-----------------------------------+----------------+
| 6          | <<  >>  >>>                          | Bitwise shift                     | Left-to-right  |

| 12         | &&                                   | Logical AND (short-circuit)       | Left-to-right  |

<Code lang="js" title="Precedence in action" code={`
// * has higher precedence than +
let result = 2 + 3 * 4;  // 2 + 12 = 14 (NOT 20!)

// Use parentheses to override precedence
let result2 = (2 + 3) * 4;  // 5 * 4 = 20 ✅

// Mixed operators: evaluate by precedence, then associativity
let x = 10;
let y = x++ + ++x * 2;  
// Step 1: x++ → use 10, x becomes 11
// Step 2: ++x → x becomes 12, use 12
// Step 3: 12 * 2 = 24 (* before +)
// Step 4: 10 + 24 = 34
console.log(y);  // 34

// ⚠️ String concatenation trap: + is left-associative!
console.log("Score: " + 10 + 20);  // "Score: 1020" ("Score: "+10="Score: 10", +"20"="Score: 1020")
console.log("Score: " + (10 + 20));  // "Score: 30" ✅ parentheses force arithmetic first
`} />

## Operand Evaluation Order — Left to Right Always!

> **Critical Distinction**: Operator **precedence** determines *which operation happens first*, but operand **evaluation order** is **always left-to-right**.

<Code lang="js" title="Left-to-right operand evaluation" code={`let a = 1;
let result = ++a + a++ + ++a;

// Evaluation (left-to-right for operands):
// 1. ++a (first operand): a becomes 2, value = 2
// 2. a++ (second operand): value = 2, then a becomes 3
// 3. ++a (third operand): a becomes 4, value = 4
// 4. Now compute: 2 + 2 + 4 = 8

console.log(result);  // 8
console.log(a);       // 4`} />

### 🧪 Function Call Evaluation Order
<Code lang="js" title="Functions are called left-to-right, regardless of precedence" code={`function m1(x) {
    console.log(\`m1(\${x}) called\`);
    return x;
}

// Expression: m1(1) + m1(2) * m1(3) / m1(4) * m1(5) + m1(6)
// Precedence: * and / before +, but functions called L→R!

let result = m1(1) + m1(2) * m1(3) / m1(4) * m1(5) + m1(6);

// Output order (function calls):
// m1(1) called
// m1(2) called
// m1(3) called
// m1(4) called
// m1(5) called
// m1(6) called
// ← Always left-to-right!

// Then compute by precedence:
// 1 + 2*3/4*5 + 6
// = 1 + 6/4*5 + 6
// = 1 + 1.5*5 + 6  (JS division is always float!)
// = 1 + 7.5 + 6 = 14.5

console.log("Result:", result);  // 14.5
`} />

<Aside type="tip">
**Interview Gold**: When asked about evaluation order:
1. State: *"Operands are always evaluated left-to-right"*
2. Clarify: *"Precedence determines operation order, not evaluation order"*
3. Example: `a() + b() * c()` calls `a()`, then `b()`, then `c()` — even though `*` happens before `+`
4. JS bonus: Division is always float — `6/4 = 1.5`, not `1` like Java integer division!
</Aside>

## `typeof` vs `instanceof` — Type Checking Comparison

<CardGrid>
  <Card title="`typeof` Operator" icon="information">
```js
    // Compile-time? No — runtime type introspection
    console.log(typeof "Hello");  // "string"
    console.log(typeof 42);       // "number"
    console.log(typeof true);     // "boolean"
    console.log(typeof undefined);// "undefined"
    console.log(typeof null);     // "object" 😱 (legacy bug)
    console.log(typeof []);       // "object" (arrays are objects!)
    console.log(typeof function(){}); // "function" (special case)
    
    // Characteristics:
    // • Returns string describing primitive type or "object"/"function"
    // • Works on any value, including primitives
    // • null → "object" (famous quirk)
    // • No exceptions — safe to use on any value
    // • Cannot distinguish array from plain object
```
  </Card>
  
  <Card title="`instanceof` Operator" icon="backspace">
```js
    // Runtime prototype chain check
    console.log([] instanceof Array);    // true ✅
    console.log([] instanceof Object);   // true ✅ (Array.prototype → Object.prototype)
    console.log("hi" instanceof String); // false ❌ (primitive, not object)
    
    // Custom classes
    class Animal {}
    class Dog extends Animal {}
    const dog = new Dog();
    console.log(dog instanceof Dog);     // true ✅
    console.log(dog instanceof Animal);  // true ✅ (prototype chain)
    
    // Characteristics:
    // • Checks if Constructor.prototype is in object's prototype chain
    // • Only works on objects — primitives always return false
    // • Can be customized via Symbol.hasInstance
    // • May fail across iframes/realms (different constructor references)
    // • Use Array.isArray() for reliable array checks
```
  </Card>
</CardGrid>

### 💻 Dynamic Type Checking Example

<Code lang="js" title="Using instanceof for runtime type checks" code={`
// Check built-in types
function process(value) {
    if (value instanceof Date) {
        console.log("Date:", value.toISOString());
    } else if (Array.isArray(value)) {  // ✅ Cross-realm safe array check
        console.log("Array with", value.length, "items");
    } else if (value instanceof RegExp) {
        console.log("Regex:", value.source);
    } else {
        console.log("Other:", typeof value);
    }
}

// Custom class checks
class APIResponse {
    constructor(data) { this.data = data; }
    isValid() { return this.data != null; }
}

function handleResponse(res) {
    if (res instanceof APIResponse && res.isValid()) {
        console.log("Valid response:", res.data);
    } else {
        console.error("Invalid response");
    }
}
`} />

<Aside type="caution">
**Cross-Realm Trap**: `instanceof` can fail across iframes or Node.js `vm` contexts:
```js
// In parent window:
const iframe = document.createElement("iframe");
document.body.appendChild(iframe);
const OtherArray = iframe.contentWindow.Array;

const arr = new OtherArray(1, 2, 3);
console.log(arr instanceof Array);  // false ❌ (different Array constructor)
console.log(Array.isArray(arr));    // true ✅ (works across realms)
```
✅ **Fix**: Use `Array.isArray()`, `Object.prototype.toString.call()`, or libraries for cross-realm type checks.
</Aside>

## `typeof` vs `instanceof` vs `Object.prototype.toString` — Type Checking Deep Dive

<CardGrid>

    // Best for: primitive types, quick checks
    typeof x === "string"   // ✅ String primitive
    typeof x === "number" && Number.isFinite(x)  // ✅ Valid number (excludes NaN/Infinity)
    typeof x === "boolean"  // ✅ Boolean

    // Best for: custom classes, built-in objects (same realm)

    dog instanceof Animal       // ✅ Inheritance check

    // • Primitives always false: "hi" instanceof String → false

  </Card>
  
  <Card title="`Object.prototype.toString.call()` — Most Reliable" icon="shield">

    Object.prototype.toString.call(null)      // "[object Null]"

## ⚙️ Deep Dive — How Assignment Works in V8

```
┌──────────────────────────────────────────────────────────┐
│            ASSIGNMENT INTERNAL PIPELINE                  │
│                                                          │
│  let x = 5;                                              │
│        │                                                 │
│        ▼                                                 │

│  3. Write value into scope slot                          │
│  4. Return the written value (assignment is expression)  │

│  ┌──────────────────────────────────────────────┐        │

└──────────────────────────────────────────────────────────┘
```

  LdaSmi [5]        ← load small integer 5 into accumulator
  Star r0           ← store accumulator into register r0 (x's slot)

  AddSmi [3]        ← add 3 to accumulator

## 1️⃣ Basic Assignment `=`

### Core Behavior
```js
// Right side evaluated FIRST — always:
let x = 5;
let y = x = 10;   // x = 10 first, then y = 10
console.log(x, y); // 10 10

// Assignment IS an expression — returns the value:
let a;
console.log(a = 5);  // 5 — assignment returns assigned value

// Chain assignment — right to left:
let p, q, r;
p = q = r = 42;
// r = 42 first → 42
// q = 42       → 42

```

## 2️⃣ Arithmetic Compound Assignments

### All Six

```js
let x = 10;

x += 5;    // x = x + 5  → 15
x -= 3;    // x = x - 3  → 12
x *= 2;    // x = x * 2  → 24
x /= 4;    // x = x / 4  → 6
x %= 4;    // x = x % 4  → 2
x **= 3;   // x = x ** 3 → 8
```

### They Are NOT Simple Shorthands — Two Differences

```
┌──────────────────────────────────────────────────────────┐
│         compound op vs manual assignment                 │
│                                                          │
│  Difference 1: getter/setter called ONCE vs TWICE        │
│                                                          │
│  obj.x += 1                                              │
│  → reads obj.x (getter once)                             │
│  → adds 1                                                │
│  → writes result (setter once)                           │
│                                                          │
│  obj.x = obj.x + 1                                       │
│  → reads obj.x (getter TWICE — left and right)           │
│  → adds 1                                                │
│  → writes result (setter once)                           │
│                                                          │
│  Difference 2: left side evaluated ONCE                  │
│  arr[i++] += 1  → i incremented once                     │
│  arr[i++] = arr[i++] + 1 → i incremented TWICE 😱        │
└──────────────────────────────────────────────────────────┘
```

```js
// Proof — getter called different number of times:
const obj = {
  _x: 0,
  get x()  { console.log("GET"); return this._x; },
  set x(v) { console.log("SET"); this._x = v; }
};

obj.x += 1;
// GET (read for operation)
// SET (write result)
// 2 console logs

obj.x = obj.x + 1;
// GET (right side — obj.x)
// GET (left side read... actually no, left is just target)
// SET
// Hmm — actually same here, but for arr[fn()] it matters:

const arr = [0, 1, 2];
let i = 0;
arr[i++] += 10;
// i++ evaluated ONCE → index 0
// arr[0] = arr[0] + 10 = 10
// i is now 1

// vs:
let j = 0;
arr[j++] = arr[j++] + 10; // j++ evaluated TWICE 😱
// First j++ → 0, j=1
// Second j++ → 1, j=2
// arr[0] = arr[1] + 10 = 1 + 10 = 11 — DIFFERENT result
```

### Coercion in Compound Assignment

```js
// += follows + coercion rules:
let s = "hello";
s += " world";   // "hello world" — string concat
s += 5;          // "hello world5" — still string

let n = 5;
n += "3";        // "53" — n becomes STRING 😱
n -= 0;          // 53   — n becomes NUMBER again 😱
typeof n;        // "number"

// -= */ always ToNumber:
let x = "10";
x -= 0;          // 10  — "10" → number ✅ (trick to parse)
x *= "2";        // 20
x /= "4";        // 5
```

## 4️⃣ Logical Compound Assignments (ES2021)

### Three Operators

```js
// &&= — assign only if LEFT is TRUTHY:
let a = "hello";
a &&= "world";        // a was truthy → assigns → "world"

let b = "";
b &&= "world";        // b was falsy → NO assign → ""
b &&= "world";        // still "" — never assigned

// ||= — assign only if LEFT is FALSY:
let c = null;
c ||= "default";      // c was falsy → assigns → "default"

let d = "existing";
d ||= "default";      // d was truthy → NO assign → "existing"

// ??= — assign only if LEFT is NULL or UNDEFINED:
let e = null;
e ??= "value";        // null → assigns → "value"

let f = 0;
f ??= "value";        // 0 is NOT nullish → NO assign → 0 ✅

let g = undefined;
g ??= "value";        // undefined → assigns → "value"
```

### Critical Difference — Assignment Only Happens When Needed

```js
// Regular compound — ALWAYS reads and writes:
obj.count = obj.count || 0;   // reads obj.count, writes ALWAYS

// Logical assignment — writes ONLY when condition met:
obj.count ||= 0;              // reads obj.count
                               // writes ONLY if obj.count is falsy

// WHY it matters — Proxy/reactive objects:
const reactive = new Proxy({}, {
  get(t, k)    { console.log(`GET ${k}`); return t[k]; },
  set(t, k, v) { console.log(`SET ${k}=${v}`); t[k]=v; return true; }
});

reactive.x = 5;
reactive.x ||= 10;   // GET x → 5 (truthy) → NO SET ✅
reactive.x = reactive.x || 10; // GET x → 5, SET x=5 😱 (writes even when not needed)
```

## 5️⃣ Destructuring Assignment — Deep Dive

### Array Destructuring

```js
// Basic:
const [a, b, c] = [1, 2, 3];
// a=1, b=2, c=3

// Skip elements:
const [first, , third] = [1, 2, 3];
// first=1, third=3 — middle skipped

// Rest:
const [head, ...tail] = [1, 2, 3, 4, 5];
// head=1, tail=[2,3,4,5]

// Default values:
const [x = 10, y = 20] = [5];
// x=5 (provided), y=20 (default used)
// Default only used if value is UNDEFINED:
const [p = 10] = [null];
// p=null — null is NOT undefined, default NOT used 😱

// Swap without temp:
let m = 1, n = 2;
[m, n] = [n, m];
// m=2, n=1 ✅

// Nested:
const [[a1, a2], [b1, b2]] = [[1, 2], [3, 4]];
// a1=1, a2=2, b1=3, b2=4

// From function return:
function getCoords() { return [10, 20]; }
const [x, y] = getCoords();
```

### Object Destructuring

```js
// Basic:
const { name, age } = { name: "Ali", age: 20 };

// Rename — colon syntax:
const { name: userName, age: userAge } = { name: "Ali", age: 20 };
// userName="Ali", userAge=20
// 'name' and 'age' are NOT in scope — only userName and userAge

// Default values:
const { role = "user", name } = { name: "Ali" };
// name="Ali", role="user" (default)

// Rename + default:
const { x: myX = 100 } = {};
// myX=100 (renamed with default)

// Rest:
const { a, b, ...rest } = { a:1, b:2, c:3, d:4 };
// a=1, b=2, rest={c:3, d:4}

// Computed property keys:
const key = "name";
const { [key]: value } = { name: "Ali" };
// value="Ali"

// Nested:
const { address: { city, zip } } = {
  address: { city: "Bhopal", zip: "462001" }
};
// city="Bhopal", zip="462001"
```

### Destructuring in Function Parameters

```js
// Array params:
function sum([a, b, c = 0]) {
  return a + b + c;
}
sum([1, 2]);     // 3
sum([1, 2, 3]);  // 6

// Object params:
function createUser({ name, role = "user", age }) {
  return { name, role, age };
}
createUser({ name: "Ali", age: 20 });
// { name: "Ali", role: "user", age: 20 }

// Real prod — Express route handler:
app.get("/users/:id", async ({
  params: { id },
  query: { fields = "*", limit = 10 },
  headers: { authorization }
}, res) => {
  const user = await db.findUser(id, { fields, limit });
  res.json(user);
});
```

### Assignment Destructuring (Without `const`/`let`)

```js
// Object — MUST wrap in parens:
let name, age;
({ name, age } = { name: "Ali", age: 20 }); // ✅ — parens required
{ name, age } = { name: "Ali", age: 20 };    // ❌ SyntaxError
// { is parsed as block statement without parens

// Array — no parens needed:
let x, y;
[x, y] = [1, 2]; // ✅
```

## 🔬 Deep Dive — Destructuring Internals

```
┌──────────────────────────────────────────────────────────┐
│         HOW DESTRUCTURING WORKS INTERNALLY               │
│                                                          │
│  const [a, b] = [1, 2];                                  │
│                                                          │
│  Desugared to:                                           │
│    const _tmp = [1, 2];          ← evaluate RHS once    │
│    const a = _tmp[0];            ← index access         │
│    const b = _tmp[1];                                    │
│                                                          │
│  const { name, age } = obj;                              │
│                                                          │
│  Desugared to:                                           │
│    const _tmp = obj;             ← evaluate RHS once    │
│    const name = _tmp.name;       ← property access      │
│    const age  = _tmp.age;                                │
│                                                          │
│  Works on ANY iterable for array destructuring:          │
│    Calls [Symbol.iterator]() on right side               │
│    Pulls values via .next()                              │
│    This is why [a,b] = Set/Map/generator works           │
└──────────────────────────────────────────────────────────┘
```

```js
// Destructuring works on ANY iterable:
const [a, b, c] = new Set([1, 2, 3]);    // a=1, b=2, c=3
const [x, y]    = new Map([[1,"a"],[2,"b"]]);
// x=[1,"a"], y=[2,"b"]

function* gen() { yield 1; yield 2; yield 3; }
const [p, q] = gen();  // p=1, q=2 — generator consumed

// Object destructuring uses property access — NOT iterator:
// Works on ANY object (arrays, maps, dates, etc.)
const { length } = [1, 2, 3];   // length=3 — array IS an object
const { size }   = new Set([1,2,3]); // size=3
```

## 🏭 Real Production Patterns

### Pattern 1 — API Response Normalization

```js
// Destructure nested API response safely:
async function getUser(id) {
  const response = await fetch(`/api/users/${id}`);
  const {
    data: {
      user: {
        id: userId,
        profile: {
          firstName,
          lastName,
          avatar = "/default-avatar.png"
        },
        settings: {
          theme = "light",
          notifications = true
        } = {}   // ← default entire nested object if missing
      }
    },
    meta: { requestId } = {}
  } = await response.json();

  return {
    userId,
    name: `${firstName} ${lastName}`,
    avatar,
    theme,
    notifications,
    requestId
  };
}
```

### Pattern 2 — Config Merging with Logical Assignment

```js
class ServerConfig {
  #config = {};

  load(env) {
    // ??= — only set if not already configured:
    this.#config.port    ??= parseInt(env.PORT, 10) || 8080;
    this.#config.host    ??= env.HOST || "0.0.0.0";
    this.#config.debug   ??= env.NODE_ENV !== "production";

    // ||= — set if falsy (includes 0):
    this.#config.workers ||= require("os").cpus().length;

    // &&= — only update if already set:
    this.#config.db      &&= {
      ...this.#config.db,
      ssl: env.NODE_ENV === "production"
    };

    return this;
  }
}
```

### Pattern 3 — Swap, Extract, Transform in One Line

```js
// Swap array elements:
const arr = [1, 2, 3, 4, 5];
[arr[0], arr[4]] = [arr[4], arr[0]];
// arr = [5, 2, 3, 4, 1]

// Extract from regex match:
const dateStr = "2024-01-15";
const [, year, month, day] = dateStr.match(/(\d{4})-(\d{2})-(\d{2})/);
// year="2024", month="01", day="15"

// Multiple return values pattern:
function divmod(a, b) {
  return [Math.trunc(a / b), a % b];
}
const [quotient, remainder] = divmod(17, 5);
// quotient=3, remainder=2

// Rotate array destructure:
function rotate([first, ...rest]) {
  return [...rest, first];
}
rotate([1, 2, 3, 4]); // [2, 3, 4, 1]
```

### Pattern 4 — State Updates (React/Redux style)

```js
// Immutable state update with destructuring:
function reducer(state, action) {
  switch (action.type) {
    case "UPDATE_USER": {
      const { id, ...updates } = action.payload;
      return {
        ...state,
        users: {
          ...state.users,
          [id]: {
            ...state.users[id],
            ...updates,
            updatedAt: Date.now()
          }
        }
      };
    }

    case "SET_LOADING": {
      const { key, value } = action;
      return {
        ...state,
        loading: {
          ...state.loading,
          [key]: value
        }
      };
    }

    default:
      return state;
  }
}
```

### Pattern 5 — Batch DB Operations with Compound Assignment

```js
// Accumulate stats with compound assignment:
async function processLogs(logs) {
  const stats = { total: 0, errors: 0, warnings: 0, bytes: 0 };

  for (const log of logs) {
    stats.total   += 1;
    stats.bytes   += log.size;
    stats.errors  += log.level === "error"   ? 1 : 0;
    stats.warnings+= log.level === "warning" ? 1 : 0;
  }

  // Compound assignment on object properties:
  const report = {};
  report.errorRate   = stats.errors   / stats.total;
  report.warnRate    = stats.warnings / stats.total;
  report.avgSize     = stats.bytes    / stats.total;
  report.totalBytes  = stats.bytes;
  report.totalBytes /= 1024;          // KB
  report.totalBytes  = +report.totalBytes.toFixed(2);

  return report;
}
```

## 💀 Interview Traps

### Trap 1: Assignment in conditional — the classic bug

```js
// Single = in if — ALWAYS truthy for non-zero:
let x = 5;

if (x = 10) {         // 😱 assigns 10, then evaluates 10 as truthy
  console.log("runs"); // always runs — x is now 10
}

if (x == 10) { ... }  // ✅ comparison
if (x === 10) { ... } // ✅ strict comparison

// Legitimate use — assign AND check:
let chunk;
while ((chunk = stream.read(1024)) !== null) {
  process(chunk); // ✅ intentional assignment in condition
}
// Idiom: wrapping in extra parens signals intentional assignment
```

---

### Trap 2: Destructuring default only for `undefined` — not `null`

```js
const { a = 10 } = { a: undefined }; // a = 10 ✅ — undefined triggers default
const { b = 10 } = { b: null };      // b = null 😱 — null does NOT trigger default
const { c = 10 } = { c: 0 };        // c = 0  😱 — 0 does NOT trigger default
const { d = 10 } = { d: false };     // d = false — false does NOT trigger default
const { e = 10 } = {};               // e = 10 ✅ — missing property = undefined

// ONLY undefined → default. null, 0, false, "" do NOT.
// Real prod trap — API returns null for "not set"
// but destructuring default doesn't catch it:
const { timeout = 5000 } = apiConfig; // apiConfig.timeout = null → timeout = null 😱
// Fix:
const timeout = apiConfig.timeout ?? 5000; // ✅
```

---

### Trap 3: Chained assignment with `let` — not what you think

```js
// This looks like declaring both:
let a = b = 5;
// ACTUALLY:
// b = 5        ← b is UNDECLARED (implicit global in sloppy mode!)
// let a = 5    ← a is declared

console.log(a); // 5  ✅
console.log(b); // 5  ✅ in sloppy mode 😱
// In strict mode: ReferenceError — b is not defined

// The CORRECT way:
let a, b;
a = b = 5; // ✅ both already declared

// Or:
let a = 5, b = 5; // ✅
```

### Trap 4: Destructuring rest must be last — always

```js
// Rest in array destructuring:
const [a, ...rest, b] = [1, 2, 3]; // ❌ SyntaxError — rest not last

const [a, ...rest] = [1, 2, 3];    // ✅ rest=[2,3]

// Rest in object destructuring:
const { a, ...rest, b } = obj;     // ❌ SyntaxError

const { a, b, ...rest } = obj;     // ✅
```

### Trap 5: `+=` type changes silently

```js
let total = 0;

// Items from API — some are strings:
const items = [1, 2, "3", 4]; // "3" is a string from buggy API

for (const item of items) {
  total += item;
}
// 0 + 1 = 1
// 1 + 2 = 3
// 3 + "3" = "33" 😱 — total is now a STRING
// "33" + 4 = "334" 😱

console.log(total); // "334" — not 10

// Fix — validate/convert before accumulating:
for (const item of items) {
  total += Number(item); // or +item
}
// 0 + 1 + 2 + 3 + 4 = 10 ✅
```

### Trap 6: Object destructuring without `let`/`const` needs parens

let x, y;

// Forgot parens — SyntaxError:

### Trap 7: Logical assignment short circuits — no write if condition fails

```js
// This is the INTENDED behavior — but surprises devs:
const obj = { x: 5 };

let writeCount = 0;
const handler = {
  get(t, k) { return t[k]; },
  set(t, k, v) { writeCount++; t[k] = v; return true; }
};
const proxy = new Proxy(obj, handler);

proxy.x ||= 99;   // x=5 (truthy) → condition false → NO write
console.log(writeCount); // 0 — setter never called ✅

proxy.y ||= 99;   // y=undefined (falsy) → condition true → write
console.log(writeCount); // 1 — setter called once ✅

// vs:
proxy.x = proxy.x || 99; // x=5 → 5 (truthy) → BUT setter still called with 5 😱
console.log(writeCount); // 2 — unnecessary write triggered
```

### Trap 8: Destructuring a non-iterable as array pattern

```js
// Array destructuring calls [Symbol.iterator]:
const [a, b] = null;      // ❌ TypeError: null is not iterable
const [c, d] = undefined; // ❌ TypeError: undefined is not iterable
const [e, f] = 5;         // ❌ TypeError: 5 is not iterable
const [g, h] = "hello";   // ✅ — strings ARE iterable: g="h", h="e"

// Object destructuring accesses properties — less strict:
const { a } = null;       // ❌ TypeError: Cannot destructure null
const { b } = undefined;  // ❌ TypeError
const { c } = 5;          // ✅ — c=undefined (no property 'c' on Number)
const { d } = "hello";    // ✅ — d=undefined

// Safe destructuring with default:
const [x = 0, y = 0] = someArray ?? []; // ✅ fallback to empty array
const { name = "?" } = userObj ?? {};   // ✅ fallback to empty object
```

## 📊 DSA / Internals Connection

> Assignment is the most fundamental operation in a **RAM (Random Access Machine)** model — the theoretical model all algorithms are analyzed under. Every variable is a register, every assignment is a write operation. In V8's bytecode, assignment compiles to `Star` (Store accumulator to Register) — a **direct memory write**. Compound assignment = `Load` + `Operation` + `Store` — three instructions.
>
> Destructuring assignment is syntactic sugar over **iterator protocol** (for arrays) and **property access** (for objects). The V8 optimizer inlines destructuring into direct slot reads when shapes are stable — making `const { x, y } = point` as fast as `const x = point.x; const y = point.y`. This is **shape-based optimization** — same as hidden class fast-path access.
