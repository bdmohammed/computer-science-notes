## 🔀 Type Casting in JavaScript

> **Type casting** converts a value from one type to another. JavaScript has **two mechanisms**:
> - **Implicit coercion** — automatic conversion by the engine (context-dependent)
> - **Explicit conversion** — manual conversion using functions or operators

```mermaid
graph TD
    Start[Type Conversion in JS]
    
    Start --> Implicit["Implicit Coercion<br/>(automatic, context-driven)"]
    Start --> Explicit["Explicit Conversion<br/>(manual, intentional)"]
    
    Implicit --> CoerceNum[ToNumber: +, -, *, /, ==]
    Implicit --> CoerceStr[ToString: + with string, template literals]
    Implicit --> CoerceBool[ToBoolean: if, &&, ||, !]
    
    Explicit --> ConvFunc[Conversion functions:<br/>Number(), String(), Boolean()]
    Explicit --> ConvOp[Unary operators:<br/>+, -, !!]
    Explicit --> ConvParse[Parse methods:<br/>parseInt(), parseFloat()]
    
    style Implicit fill:#22c55e,color:#fff
    style Explicit fill:#6366f1,color:#fff
```

<Aside type="tip" title="🎯 MUST KNOW">
**JS Superpowers vs Java**:  
✅ **No `(Type) value` syntax** — use `Number(x)`, `String(x)`, `Boolean(x)` instead  
✅ **Implicit coercion everywhere** — `+`, `==`, `if`, `!` all trigger conversion  
✅ **Truthy/falsy model** — any value can coerce to boolean, not just `true`/`false`  
✅ **No primitive widening/narrowing** — all numbers are 64-bit floats (or BigInt)  
✅ **`typeof` + `instanceof`** for runtime type introspection, not compile-time casts  
</Aside>

## 🔼 Implicit Coercion — Automatic Conversion

### Key Characteristics

| Feature | Detail |
|---------|--------|
| **Who performs it?** | 🤖 JavaScript engine (automatic) |
| **Triggered by** | Operators (`+`, `==`, `!`), control flow (`if`, `while`), template literals |
| **Direction** | Context-dependent — no fixed hierarchy |
| **Information loss?** | ⚠️ **Possible** — silent coercion can cause bugs |
| **Syntax** | No explicit syntax — happens automatically |

### 🧭 Coercion Contexts Table

| Context | Coercion Target | Example | Result |
|---------|----------------|---------|--------|
| Arithmetic `+` | String OR Number | `"5" + 3` | `"53"` (string concat) |
| Arithmetic `-` `*` `/` | Number | `"5" - 3` | `2` (numeric) |
| Equality `==` | Both operands coerced | `5 == "5"` | `true` |
| Logical `!` `&&` `||` | Boolean | `!"hello"` | `false` |
| Control flow `if` | Boolean | `if ("")` | false branch |
| Template literal | String | `` `Value: ${null}` `` | `"Value: null"` |
| Unary `+` `-` | Number | `+"42"` | `42` |

<Code lang="js" title="Implicit coercion examples" code={`// String + Number → String concatenation
console.log("Score: " + 100);  // "Score: 100"
console.log(100 + " points");  // "100 points"

// String - Number → Numeric subtraction (coerces string to number)
console.log("100" - 20);  // 80 ✅
console.log("abc" - 10);  // NaN ❌ ("abc" can't be numeric)

// Equality with coercion (loose equality)
console.log(0 == false);      // true (0 → false, or false → 0)
console.log("" == false);     // true ("" → 0, false → 0)
console.log(null == undefined); // true (special case)

// Logical operators coerce to boolean
console.log(!"hello");        // false (non-empty string is truthy)
console.log(!0);              // true (0 is falsy)
console.log([] && "yes");     // "yes" ([] is truthy, returns right operand)

// Control flow coercion
if ("") {
    console.log("won't run");  // empty string is falsy
}
if ([0]) {
    console.log("runs!");  // array is truthy, even if empty or contains falsy values
}`} />

<Aside type="caution">
**Coercion Trap**: `[] == false` is `true` 😱  
```js
[] == false  // true! Here's why:
// Step 1: false → 0 (ToNumber)
// Step 2: [] → "" (ToString via [].toString())
// Step 3: "" → 0 (ToNumber)
// Step 4: 0 == 0 → true
```
✅ **Fix**: Use strict equality `===` to avoid coercion surprises!
</Aside>

## 🔽 Explicit Conversion — Manual & Intentional

### Conversion Functions (Preferred)

| Function | Converts To | Example | Result |
|----------|-------------|---------|--------|
| `Number(value)` | Number | `Number("42")` | `42` |
| `String(value)` | String | `String(42)` | `"42"` |
| `Boolean(value)` | Boolean | `Boolean("")` | `false` |
| `BigInt(value)` | BigInt | `BigInt("123")` | `123n` |
| `Symbol(value)` | Symbol | `Symbol("id")` | `Symbol(id)` |

<Code lang="js" title="Explicit conversion with functions" code={`// String → Number
console.log(Number("42"));      // 42 ✅
console.log(Number("42.5"));    // 42.5 ✅
console.log(Number("abc"));     // NaN ❌ (invalid numeric string)
console.log(Number(null));      // 0 ✅
console.log(Number(undefined)); // NaN ❌
console.log(Number(true));      // 1 ✅
console.log(Number(false));     // 0 ✅
console.log(Number([]));        // 0 ✅ ([] → "" → 0)
console.log(Number({}));        // NaN ❌ (object can't be numeric)

// Number → String
console.log(String(42));        // "42"
console.log(String(3.14));      // "3.14"
console.log(String(null));      // "null"
console.log(String(undefined)); // "undefined"
console.log(String(true));      // "true"
console.log(String([1,2]));     // "1,2" (array joins with comma)
console.log(String({x:1}));     // "[object Object]"

// Any → Boolean (truthy/falsy rules)
console.log(Boolean(0));        // false (only 7 falsy values!)
console.log(Boolean(""));       // false
console.log(Boolean(null));     // false
console.log(Boolean(undefined));// false
console.log(Boolean(NaN));      // false
console.log(Boolean(false));    // false
console.log(Boolean(0n));       // false

console.log(Boolean(1));        // true (everything else is truthy)
console.log(Boolean("0"));      // true (non-empty string)
console.log(Boolean([]));       // true (empty array is truthy!)
console.log(Boolean({}));       // true (empty object is truthy!)
console.log(Boolean(function(){})); // true (functions are truthy)

// BigInt conversion
console.log(BigInt("9007199254740991"));  // 9007199254740991n ✅
console.log(BigInt(123));                 // 123n ✅
// BigInt("12.5")  // ❌ RangeError: invalid BigInt string (no decimals)
`} />

### Unary Operators for Conversion (Concise but Less Clear)

<Code lang="js" title="Unary operators for explicit conversion" code={`// Unary + : ToNumber (concise but can be unclear)
console.log(+"42");      // 42 ✅
console.log(+"3.14");    // 3.14 ✅
console.log(+"abc");     // NaN ❌
console.log(+true);      // 1 ✅
console.log(+false);     // 0 ✅
console.log(+null);      // 0 ✅
console.log(+undefined); // NaN ❌

// Unary - : ToNumber + negate
console.log(-"42");      // -42 ✅
console.log(-true);      // -1 ✅

// Unary ! : ToBoolean + invert (double !! for explicit boolean)
console.log(!"hello");   // false (truthy → false)
console.log(!!"hello");  // true (explicit boolean conversion)
console.log(!!0);        // false
console.log(!![]);       // true (array is truthy)

// ⚠️ Readability warning:
const value = +"42";     // Clear to experienced devs
const result = !!input;  // Intent: "convert to boolean" — consider Boolean(input) instead
`} />

<Aside type="tip">
**Pro Pattern**: Prefer **explicit functions** (`Number()`, `Boolean()`) over unary operators for clarity:
```js
// ✅ Clear intent:
const count = Number(userInput);
const isValid = Boolean(checkResult);

// ⚠️ Concise but less clear:
const count = +userInput;
const isValid = !!checkResult;
```
Use unary operators when brevity is critical (e.g., competitive programming), but document intent.
</Aside>

## 🔢 Numeric Conversion — Parsing & Edge Cases

### `parseInt()` vs `Number()` vs Unary `+`

| Method | Behavior | Example | Result |
|--------|----------|---------|--------|
| `Number("42px")` | Strict — entire string must be numeric | `Number("42px")` | `NaN` |
| `parseInt("42px")` | Lenient — parses until invalid char | `parseInt("42px")` | `42` |
| `+"42px"` | Strict (same as `Number()`) | `+"42px"` | `NaN` |
| `parseFloat("3.14px")` | Lenient for floats | `parseFloat("3.14px")` | `3.14` |

<Code lang="js" title="Parsing numeric strings" code={`// Strict conversion (entire string must be valid number)
console.log(Number("42"));      // 42 ✅
console.log(Number("42.5"));    // 42.5 ✅
console.log(Number("42px"));    // NaN ❌ ("px" invalid)
console.log(Number(" 42 "));    // 42 ✅ (whitespace trimmed)
console.log(Number(""));        // 0 ✅ (empty string → 0)

// Lenient parsing (stops at first invalid character)
console.log(parseInt("42px"));     // 42 ✅
console.log(parseInt("42.7px"));   // 42 ✅ (stops at decimal for integer parse)
console.log(parseFloat("42.7px")); // 42.7 ✅ (handles decimals)
console.log(parseInt("0x10"));     // 16 ✅ (hex prefix recognized)
console.log(parseInt("10", 2));    // 2 ✅ (binary: "10" base-2 = 2)

// ⚠️ parseInt pitfalls:
console.log(parseInt("08"));  // 8 in modern JS, but 0 in old engines (octal trap!)
// ✅ Fix: Always specify radix for parseInt:
console.log(parseInt("08", 10));  // 8 ✅ explicit base-10

// ✅ Safe parsing pattern:
function safeInt(str, defaultValue = 0) {
    const parsed = parseInt(str, 10);
    return Number.isFinite(parsed) ? parsed : defaultValue;
}
console.log(safeInt("42px"));  // 42
console.log(safeInt("abc"));   // 0 (default)
`} />

### BigInt Conversion — Arbitrary Precision

<Code lang="js" title="BigInt for large integers" code={`// BigInt literal syntax: append 'n'
const big = 123n;

// Convert from string (no decimals allowed!)
const fromStr = BigInt("9007199254740991");  // ✅ MAX_SAFE_INTEGER as BigInt
// BigInt("12.5")  // ❌ RangeError: invalid BigInt

// Convert from Number (may lose precision if > MAX_SAFE_INTEGER)
const fromNum = BigInt(Number.MAX_SAFE_INTEGER);  // ✅
const risky = BigInt(123.456);  // ❌ RangeError: can't convert non-integer

// Convert back to Number (may lose precision!)
const backToNum = Number(123n);  // 123 ✅ (safe for small values)
const large = BigInt("9007199254740992");  // > MAX_SAFE_INTEGER
console.log(Number(large) === Number(large + 1n));  // true 😱 precision lost!

// ⚠️ Cannot mix BigInt and Number in operations:
// 123n + 456  // ❌ TypeError

// ✅ Convert explicitly:
const result = 123n + BigInt(456);  // 579n ✅
const asNum = Number(123n) + 456;   // 579 ✅ (but may lose precision for large values)
`} />

<Aside type="caution">
**BigInt Limitations**:  
1. ❌ Cannot use with `Math` methods: `Math.sqrt(4n)` → TypeError  
2. ❌ Cannot use with JSON: `JSON.stringify({val: 1n})` → TypeError  
3. ❌ Cannot compare with `==`/`===` to Number: `1n === 1` → false  
4. ✅ Use `typeof x === "bigint"` to check type  
5. ✅ BigInt has **no decimal support** — integers only
</Aside>

## 🔄 Boolean Coercion — Truthy/Falsy Rules

### The 7 Falsy Values (Only These!)

```js
// These 7 values coerce to false — everything else is truthy:
false
0
-0
0n          // BigInt zero
""          // empty string
null
undefined
NaN
```

<Code lang="js" title="Truthy/falsy examples" code={`// Falsy values — coerce to false in boolean context:
console.log(Boolean(false));      // false
console.log(Boolean(0));          // false
console.log(Boolean(-0));         // false
console.log(Boolean(0n));         // false
console.log(Boolean(""));         // false
console.log(Boolean(null));       // false
console.log(Boolean(undefined));  // false
console.log(Boolean(NaN));        // false

// Truthy values — coerce to true (common surprises):
console.log(Boolean("0"));        // true ✅ (non-empty string)
console.log(Boolean("false"));    // true ✅ (non-empty string)
console.log(Boolean([]));         // true ✅ (empty array is truthy!)
console.log(Boolean({}));         // true ✅ (empty object is truthy!)
console.log(Boolean(function(){})); // true ✅ (functions are truthy)
console.log(Boolean(Symbol()));   // true ✅ (symbols are truthy)

// Practical: Conditional checks
if ("0") { console.log("runs"); }      // ✅ Runs — "0" is truthy
if ([]) { console.log("runs"); }       // ✅ Runs — [] is truthy
if (0) { console.log("won't run"); }   // ❌ Skips — 0 is falsy
`} />

### Double Bang `!!` for Explicit Boolean

<Code lang="js" title="Convert any value to boolean explicitly" code={`// !!x = Boolean(x) — explicit boolean conversion
console.log(!!"hello");    // true
console.log(!!"");         // false
console.log(!![]);         // true (array is truthy)
console.log(!!0);          // false
console.log(!!null);       // false
console.log(!!undefined);  // false

// ✅ Use case: Normalize truthy/falsy to strict boolean
function toBoolean(value) {
    return !!value;  // or: return Boolean(value);
}

console.log(toBoolean("yes"));  // true
console.log(toBoolean(0));      // false

// ⚠️ Readability: Boolean(x) is clearer than !!x for most codebases
`} />

<Aside type="tip">
**Interview Gold**: Know the **7 falsy values** by heart — this is a top JS interview question!  
Everything else — including empty collections, `"0"`, and functions — is **truthy**.
</Aside>

## 🧳 Object "Casting" — Prototype Chain, Not Class Hierarchy

### `instanceof` for Prototype Chain Checks

<Code lang="js" title="instanceof checks prototype chain" code={`// Built-in types
console.log([] instanceof Array);    // true ✅
console.log([] instanceof Object);   // true ✅ (Array.prototype → Object.prototype)
console.log(/regex/ instanceof RegExp);  // true ✅
console.log(new Date() instanceof Date); // true ✅

// Custom classes
class Animal {}
class Dog extends Animal {}
const dog = new Dog();

console.log(dog instanceof Dog);     // true ✅
console.log(dog instanceof Animal);  // true ✅ (prototype chain)
console.log(dog instanceof Object);  // true ✅ (all objects inherit from Object)

// ⚠️ Primitives return false — instanceof only works on objects:
console.log("hello" instanceof String);  // false ❌ (primitive, not object)
console.log(42 instanceof Number);       // false ❌

// ✅ Boxed primitives work (but avoid boxing):
console.log(new String("hello") instanceof String);  // true ✅
`} />

### `typeof` for Primitive Type Checks

<Code lang="js" title="typeof for runtime type introspection" code={`// Primitive types
console.log(typeof 42);           // "number"
console.log(typeof 3.14);         // "number"
console.log(typeof "hello");      // "string"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof null);         // "object" 😱 (legacy bug, can't be fixed)
console.log(typeof Symbol("id")); // "symbol"
console.log(typeof 123n);         // "bigint"

// Objects and functions
console.log(typeof {});           // "object"
console.log(typeof []);           // "object" (arrays are objects!)
console.log(typeof function(){}); // "function" (special case)
console.log(typeof null);         // "object" (famous quirk)

// ✅ Safe type check pattern:
function getType(value) {
    if (value === null) return "null";  // Handle null first
    if (Array.isArray(value)) return "array";  // Arrays are objects, check first
    return typeof value;
}

console.log(getType(null));  // "null" ✅
console.log(getType([]));    // "array" ✅
console.log(getType({}));    // "object" ✅
`} />

### No Compile-Time Type Checks — Runtime Only

<Code lang="js" title="JS has no compile-time casting — all checks are runtime" code={`// ❌ No (Type) syntax in JS:
// let x = (int) "42";  // SyntaxError — invalid syntax!

// ✅ Use conversion functions:
let x = Number("42");  // 42 ✅

// ❌ No type compatibility checks at "compile" time:
function process(value) {
    // No way to enforce "value must be string" at parse time
    return value.toUpperCase();  // 💥 TypeError if value is number!
}

// ✅ Runtime validation patterns:
function processSafe(value) {
    if (typeof value !== "string") {
        throw new TypeError("Expected string");
    }
    return value.toUpperCase();  // Safe now
}

// ✅ TypeScript adds compile-time checks (optional):
// function processTS(value: string): string {  // TS: compile-time type check
//     return value.toUpperCase();  // ✅ Safe at compile time
// }
`} />

<Aside type="caution">
**Golden Rule**: JavaScript has **no compile-time type safety** — all type checks happen at runtime.  
✅ Use **TypeScript** if you need compile-time type guarantees.  
✅ Use **runtime validation** (`typeof`, `instanceof`, libraries like Zod) for safety in plain JS.
</Aside>

## 🔬 Coercion in Expressions — Order Matters

### Operator Precedence + Coercion

<Code lang="js" title="Coercion order in mixed expressions" code={`// + operator: string concatenation vs numeric addition
console.log("5" + 3);        // "53" (string + number → string concat)
console.log(5 + "3");        // "53" (same — left-to-right evaluation)
console.log("5" + 3 + 2);    // "532" ("5"+3="53", +"2"="532")
console.log(5 + 3 + "2");    // "82" (5+3=8, +"2"="82")

// Force numeric first with parentheses:
console.log(("5" - 0) + 3);  // 8 ("5"-0=5 numeric, +3=8)
console.log(5 + (3 + "2"));  // "532" (3+"2"="32", 5+"32"="532") — still string!

// ✅ Better: explicit conversion:
console.log(Number("5") + 3 + 2);  // 10 ✅ clear intent

// Template literals always coerce to string:
const val = 42;
console.log(\`Value: ${val}\`);  // "Value: 42" (val → string automatically)
console.log(\`Sum: ${"5" + 3}\`);  // "Sum: 53" (coercion happens inside \${})
`} />

### Loose Equality `==` Coercion Rules

<Code lang="js" title="== coercion algorithm (simplified)" code={`// == performs coercion before comparison — complex rules!
console.log(5 == "5");           // true ("5" → 5)
console.log(true == 1);          // true (true → 1)
console.log(false == 0);         // true (false → 0)
console.log(null == undefined);  // true (special case only for ==)
console.log([] == false);        // true ([] → "" → 0, false → 0)
console.log([1] == 1);           // true ([1] → "1" → 1)

// ⚠️ Avoid == for most comparisons — use === instead:
console.log(5 === "5");          // false ✅ (different types)
console.log([] === false);       // false ✅ (different types)

// ✅ When == is intentional: null/undefined check
function isEmpty(value) {
    return value == null;  // true for both null AND undefined
}
console.log(isEmpty(null));      // true
console.log(isEmpty(undefined)); // true
console.log(isEmpty(""));        // false (empty string is not nullish)
`} />

<Aside type="danger">
**Golden Rule**: **Always use `===` and `!==` unless you specifically need coercion**.  
`==` has 15+ edge cases in the coercion algorithm — `===` is simple: same type AND same value.
</Aside>

    - `==` (loose equality): coerces types before comparing → `5 == "5"` → `true`  
    - `===` (strict equality): no coercion, requires same type AND value → `5 === "5"` → `false`  
    ✅ **Always prefer `===`** unless you specifically need coercion (e.g., `value == null`).
  </Card>

  <Card title="Q: How to convert string to number safely?" icon="shield">

    ```js
    // ✅ Strict conversion (entire string must be numeric):
    const num = Number(str);
    if (Number.isNaN(num)) { /* handle error */ }

    // ✅ Lenient parsing (stops at first invalid char):
    const parsed = parseInt(str, 10);  // Always specify radix!
    if (!Number.isFinite(parsed)) { /* handle error */ }

    // ✅ Safe pattern with default:
    const safeInt = (str, defaultVal = 0) => {
        const n = parseInt(str, 10);
        return Number.isFinite(n) ? n : defaultVal;
    };
    ```
  </Card>

  </Card>

  <Card title="Q: Can you cast primitives with (Type) syntax?" icon="error">
    **NO ❌** — JavaScript has **no `(Type) value` casting syntax** like Java.  
    ✅ Use conversion functions: `Number(x)`, `String(x)`, `Boolean(x)`, or unary operators: `+x`, `!!x`.
  </Card>

  <Card title="Q: What is [] == false?" icon="caution">
    **`true`** 😱 — coercion chain:  
    `[]` → `""` (via toString) → `0` (via ToNumber)  
    `false` → `0` (boolean to number)  
    `0 == 0` → `true`  
    ✅ This is why you should **avoid `==`** — use `===` for predictability!
  </Card>

## 🧩 DSA & Practical Patterns

<CardGrid>
  <Card title="Pattern: Safe Numeric Input Parsing" icon="shield">
    Validate and convert user input robustly:
```js
    function parsePositiveInt(str, { min = 0, max = Infinity, defaultVal = null } = {}) {
        // Trim and validate
        const trimmed = String(str).trim();
        if (!trimmed) return defaultVal;
        
        // Parse with radix
        const parsed = parseInt(trimmed, 10);
        
        // Validate result
        if (!Number.isFinite(parsed) || parsed < min || parsed > max) {
            return defaultVal;
        }
        
        return parsed;
    }

    // Usage:
    const age = parsePositiveInt(userInput, { min: 0, max: 120, defaultVal: 18 });
    const count = parsePositiveInt("42px", { defaultVal: 0 });  // 42
```
  </Card>
  
  <Card title="Pattern: Type Guard Functions" icon="rocket">
    Create reusable type-checking utilities:
```js
    // Primitive type guards
    const isString = (val) => typeof val === "string";
    const isNumber = (val) => typeof val === "number" && Number.isFinite(val);
    const isBoolean = (val) => typeof val === "boolean";
    
    // Nullish check (null OR undefined)
    const isNullish = (val) => val == null;  // Intentional == for both null/undefined
    
    // Object type guards
    const isArray = Array.isArray;  // Built-in, cross-realm safe
    const isPlainObject = (val) => 
        val !== null && typeof val === "object" && val.constructor === Object;
    
    // Usage in validation:
    function processUser(data) {
        if (!isPlainObject(data)) {
            throw new TypeError("Expected plain object");
        }
        if (!isString(data.name)) {
            throw new TypeError("name must be string");
        }
        if (!isNumber(data.age) || data.age < 0) {
            throw new RangeError("age must be positive number");
        }
        // Safe to process...
    }
```
  </Card>

  <Card title="Pattern: Fallback Values with ?? and ||" icon="backspace">
    Choose the right operator for defaults:
```js
    // ✅ Use ?? when 0, "", false are valid values:
    const port = process.env.PORT ?? 3000;      // Keeps 0 if PORT="0"
    const name = userInput ?? "Guest";          // Keeps "" if userInput=""
    
    // ✅ Use || when falsy values should trigger fallback:
    const displayName = nickname || name || "Anonymous";  // Falls back if any falsy
    
    // ✅ Combine for complex defaults:
    const config = {
        retries: options?.retries ?? 3,         // Keep 0 if explicitly set
```

## 🔄 Java Type Casting → JS Type Casting Conversion Summary

| Java Feature | JavaScript Equivalent | Critical Difference |
|-------------|----------------------|-------------------|
| `(Type) value` cast syntax | `Number(value)`, `String(value)`, `Boolean(value)` | ✅ JS uses **functions**, not parentheses cast syntax |
| Implicit widening (byte→int) | Implicit coercion in operators (`+`, `==`, `if`) | ⚠️ JS coercion is **context-dependent**, not type-hierarchy based |
| Explicit narrowing (int→byte) | No primitive narrowing — all Numbers are 64-bit floats | ✅ JS simpler — no overflow from narrowing, but watch precision |
| `char` → `int` implicit | `"A".charCodeAt(0)` or `+"A"` (coerces to NaN) | ⚠️ JS has **no `char` type** — strings handle Unicode |
| Object upcast (implicit) | Prototype chain — no explicit "upcast" needed | ✅ JS: all objects inherit from `Object.prototype` automatically |
| Object downcast with `(Type)` | `instanceof` check + use directly (no cast needed) | ✅ JS: no cast syntax — just check prototype, then use |
| `ClassCastException` at runtime | `TypeError` for invalid operations, no cast exception | ✅ JS: type errors happen when **using** value, not casting |
| Compile-time type compatibility | No compile-time checks — all runtime | ⚠️ JS: errors appear at runtime — test thoroughly |
| `String.valueOf(primitive)` | `String(primitive)` or template literals | ✅ JS: multiple ways to convert, all implicit in templates |
| `Integer.parseInt(String)` | `Number(str)`, `parseInt(str, 10)`, `+str` | ✅ JS: more options, but `parseInt` needs radix specified |
| `instanceof` for type check | `instanceof` + `typeof` + `Array.isArray()` | ✅ JS: multiple type-checking tools for different cases |
| `null` casting rules | `null == undefined` is true; `null === undefined` false | ⚠️ JS: two distinct "empty" values with different coercion |

## 🔰 What Is Type Casting in JS?

Type casting = **deliberately converting a value from one type to another**. JS has no dedicated cast syntax like C/Java — instead it uses **functions, operators, and tricks**.

```js
Number("42")    // 42        — explicit cast
+"42"           // 42        — operator cast
"42" * 1        // 42        — implicit via operator
Boolean(0)      // false     — explicit cast
!!0             // false     — operator cast
String(42)      // "42"      — explicit cast
42 + ""         // "42"      — implicit via +
```

### `ToPrimitive` — Object → Primitive

```
ToPrimitive(obj, hint)

  hint = "number":
    1. Try obj[Symbol.toPrimitive]("number")
    2. Try obj.valueOf()
    3. Try obj.toString()
    4. ❌ TypeError if none return primitive

  hint = "string":
    1. Try obj[Symbol.toPrimitive]("string")
    2. Try obj.toString()
    3. Try obj.valueOf()
    4. ❌ TypeError if none return primitive

  hint = "default" (used by + and ==):
    → same as "number" for most objects
    → same as "string" for Date objects
```

```js
// Custom ToPrimitive:
const obj = {
  value: 42,
  [Symbol.toPrimitive](hint) {
    if (hint === "number")  return this.value;
    if (hint === "string")  return `Value(${this.value})`;
    if (hint === "default") return this.value;
  }
};

+obj          // 42        — hint: "number"
`${obj}`      // "Value(42)" — hint: "string"
obj + ""      // "42"      — hint: "default" → 42 → "42"
obj == 42     // true      — hint: "default" → 42
```

### `parseInt(string, radix)` — Parse Integer

```js
// Reads characters until non-numeric:
parseInt("42")        // 42
parseInt("42.9")      // 42  — stops at decimal point

parseInt("abc42")     // NaN — first char invalid
parseInt("")          // NaN — empty string = NaN (different from Number!)
parseInt("0x1F")      // 31  — auto-detects hex (with 0x prefix)

// ALWAYS provide radix (second argument):

parseInt("1010", 2)   // 10  — binary
parseInt("17", 8)     // 15  — octal
parseInt("z", 36)     // 35  — base-36 (0-9 + a-z)

// Whitespace trimmed:

parseInt("  42abc ")  // 42  — stops at 'a'
```

```js
parseFloat(".5")         // 0.5
```

### Pattern 2 — Reliable Type Conversion Utilities

```js
// Production-grade type converters:
const cast = {
  // ToInt — handles all edge cases:
  toInt(value, fallback = 0) {
    if (value === null || value === undefined) return fallback;
    const n = Math.trunc(Number(value));
    return Number.isFinite(n) ? n : fallback;
  },

  // ToFloat — safe float:
  toFloat(value, decimals = 2, fallback = 0) {
    const n = Number(value);
    if (!Number.isFinite(n)) return fallback;
    return parseFloat(n.toFixed(decimals));
  },

  // ToBool — explicit rules:
  toBool(value) {
    if (typeof value === "string") {
      return !["false", "0", "no", "off", ""].includes(
        value.trim().toLowerCase()
      );
    }
    return Boolean(value);
  },

  // ToString — never crashes:
  toStr(value) {
    if (value === null)      return "null";
    if (value === undefined) return "";
    if (typeof value === "symbol") return value.toString();
    return String(value);
  }
};

cast.toInt("42px")    // 0  — "42px" → NaN → fallback
cast.toInt("42.9")    // 42 — truncated
cast.toBool("false")  // false ← string "false" → false
cast.toBool("true")   // true
cast.toBool(1)        // true
```

### Pattern 4 — Bit-Level Integer Conversion

```js

// Use case — pixel manipulation (canvas):
function blendColors(c1, c2, alpha) {
  const a = (alpha * 255) | 0;        // float → byte (0-255)
  const r = ((c1 >> 16 & 0xFF) * a +
             (c2 >> 16 & 0xFF) * (255 - a)) >> 8 | 0;
  const g = ((c1 >> 8  & 0xFF) * a +
             (c2 >> 8  & 0xFF) * (255 - a)) >> 8 | 0;
  const b = ((c1       & 0xFF) * a +
             (c2       & 0xFF) * (255 - a)) >> 8 | 0;
  return (r << 16) | (g << 8) | b;
}
```

## 📊 DSA / Internals Connection

> Type casting connects directly to **type systems** in programming language theory. JS uses a **dynamic weak type system** — types are checked at runtime (dynamic) and implicit conversions happen automatically (weak). The internal algorithms (`ToNumber`, `ToString`, `ToBoolean`, `ToPrimitive`) form a **type coercion lattice** — a directed graph where edges represent conversion paths and costs.
>
> V8 represents every value as a **tagged union** internally. Type casting = reading the tag, branching on it, and producing a value of the target type. For Smi integers, this is a **single bit operation**. For objects, it requires **prototype chain traversal** + **method calls** — orders of magnitude more expensive. This is why type-stable code (same type throughout) is dramatically faster in hot loops — V8 TurboFan only needs to emit one branch, not the full coercion decision tree.
