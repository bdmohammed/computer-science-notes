## 📦 What is a Variable in JS?

A **Variable** is a named container that stores a value. In JavaScript:
1.  **No type declaration** — engine infers type dynamically
2.  **Three keywords**: `var`, `let`, `const` — each with different scoping rules
3.  **Primitives vs Objects** — stored and copied differently

<Code lang="js" title="Variable structure" code={`
let age = 25;
 ↑   ↑    ↑
kw  name value

// No type annotation needed!
// Type is attached to VALUE, not variable

let score = 100;
//  ↑         ↑
//  binding   value in memory
`} />

<Aside type="tip" title="🎯 MUST KNOW">
**JS Variable Superpowers**:  
✅ Dynamic typing — reassign any type anytime  
✅ Block scope with `let`/`const` (ES6+)  
✅ Closures — functions "remember" their lexical scope  
✅ Destructuring — extract values elegantly  
✅ Temporal Dead Zone — catches use-before-declare bugs  
</Aside>

## The Foundational Divide: Primitive vs Object

The most fundamental categorization in JS is based on what variables store: **primitive values** or **object references**.

### 🔵 Primitive Variables

Store the **actual value directly**. Passed/copied by value.

```js
let age = 25;
let name = "Alice";
let active = true;
let nothing = null;      // ⚠️ null is primitive but typeof === "object" (legacy bug)
let notSet = undefined;  // ⚠️ default for uninitialized
let id = Symbol("id");   // ES6+ unique identifier
let big = 9007199254740991n; // ES2020 BigInt

// Stack (conceptual)
// ┌─────────────────┐
// │ age   │ 25      │  ← value itself stored here
// │ name  │ "Alice" │
// └─────────────────┘
```

### 🟠 Object Variables

Store a **reference (address)** to an object on the heap — not the object itself.

```js
let user = { name: "Alice" };
let arr  = [1, 2, 3];
let fn   = function() { return 42; };

// Stack                      Heap
// ┌──────────────────┐       ┌─────────────────┐
// │ user │ 0x1A3F ──┼──────▶│ { name: "Alice" }│
// │ arr  │ 0x2B4C ──┼──────▶│ [1, 2, 3]        │
// └──────────────────┘       └─────────────────┘
//    (holds reference)         (actual objects)
```

---

| Feature | Primitive | Object (Reference) |
|---------|-----------|-------------------|
| **Stored** | Actual value | Reference (memory address) |
| **Copied** | By value (independent) | By reference (shared) |
| **Mutable** | ❌ Immutable | ✅ Mutable (except frozen) |
| **Methods** | ❌ None (boxed temporarily) | ✅ Yes (`.push()`, `.map()`) |
| **typeof** | `"number"`, `"string"`, `"boolean"`, `"undefined"`, `"symbol"`, `"bigint"` | `"object"`, `"function"` |
| **Default** | `undefined` (if declared, not assigned) | `undefined` (if declared, not assigned) |
| **null** | ✅ `null` is primitive | ✅ Often used with objects |
| **Examples** | `25`, `"hi"`, `true`, `null`, `undefined` | `{}`, `[]`, `function(){}`, `new Date()` |

### Copy Behaviour — The Real Difference

// arr2 ──────────▶ [999, 2, 3]  ← both point here!`} />

## 🗂️ Classification by Scope

Beyond type, variables are classified by **where** they are declared, which determines their **scope** and **lifetime**.

```js
JavaScript Variables
│
├── By Declaration Keyword
│   ├── var    → function-scoped, hoisted, can redeclare
│   ├── let    → block-scoped, TDZ, no redeclare
│   └── const  → block-scoped, TDZ, immutable binding
│
├── By Scope Level
│   ├── Global      → window/globalThis (avoid!)
│   ├── Module      → file-level (ESM default)
│   ├── Function    → entire function body
│   ├── Block       → inside { } (let/const only)
│   └── Closure     → captured from outer scope
│
├── By Mutability
│   ├── mutable     → let/var (reassignable)
│   └── const       → binding immutable, object contents mutable
│
└── Special Patterns
    ├── Destructuring → extract values elegantly
    ├── Rest/Spread   → gather or expand values
    └── Optional Chaining → safe nested access
```
```
Variables in JavaScript
│
├── 🔴 var
│   ├── function-scoped
│   ├── hoisted (initialized to undefined)
│   ├── re-declarable
│   ├── re-assignable
│   └── attaches to global object (window.x)
│
├── 🟡 let
│   ├── block-scoped
│   ├── hoisted (NOT initialized — TDZ)
│   ├── NOT re-declarable
│   ├── re-assignable
│   └── does NOT attach to global object
│
└── 🟢 const
    ├── block-scoped
    ├── hoisted (NOT initialized — TDZ)
    ├── NOT re-declarable
    ├── NOT re-assignable (binding locked)
    ├── does NOT attach to global object
    └── ⚠️ object contents ARE mutable
```

#### 🔤 Four Kinds of Variables (Scope Levels)

```
┌──────────────────┬────────────────────────┬────────────┬──────────────┬────────────────┐
│ Kind             │ Where Declared         │ Default    │ Stored       │ Lifetime       │
├──────────────────┼────────────────────────┼────────────┼──────────────┼────────────────┤
│ Global           │ Top-level (no keyword) │ window.x   │ Global obj   │ Page lifetime  │
│ Module           │ Top-level (ESM)        │ undefined  │ Module scope │ Module loaded  │
│ Function         │ Inside function        │ undefined  │ Stack frame  │ Function call  │
│ Block            │ Inside { } (let/const) │ undefined  │ Stack frame  │ Block execution│
└──────────────────┴────────────────────────┴────────────┴──────────────┴────────────────┘
```

```js
// 📦 Module-level (ESM default — NOT global!)
let moduleCount = 0;           // ✅ Private to this file

export class OrderService {
    // Instance field — one per object
    retryCount = 3;            // ✅ Modern class field syntax

    // Static field — one per class (ES2022)
    static totalOrders = 0;

    // Method parameter — lives only during call
    createOrder(customerId) {   // ← customerId is parameter

        // Block-scoped local — must initialize before use
        const status = "PENDING";  // ✅ const: won't reassign

        return { customerId, status };
    }
}
```

> 🔑 **Key Difference from Java**: JS has **no default values for uninitialized variables** — they're always `undefined`. No compile-time "might not be initialized" check — bugs appear at runtime! 🚨

## 1️⃣ Block-Scoped Variables (`let` / `const`) <Badge text="ES6+" variant="success" />

Declared **inside a block `{}`**, method, or function.

- **Scope:** Limited to the nearest enclosing `{ }` block
- **Hoisting:** Hoisted but in **Temporal Dead Zone (TDZ)** until declaration
- **Redeclaration:** ❌ Cannot redeclare in same scope
- **Best Practice:** Default to `const`, use `let` only when reassignment needed

<Code lang="js" title="Block scope — scoped to the nearest { }" code={`{
    let x = 10;
    const y = 20;
    console.log(x, y);  // ✅ 10, 20
}

console.log(x);  // ❌ ReferenceError: x is not defined
console.log(y);  // ❌ ReferenceError: y is not defined

// Loop variable — block-scoped!
for (let i = 0; i < 3; i++) {
    console.log(i);  // 0, 1, 2
}
console.log(i);  // ❌ ReferenceError: i not defined (unlike var!)`} />

<Aside type="danger" title="⚠️ Temporal Dead Zone (TDZ)">
```js
console.log(myLet);  // ❌ ReferenceError: Cannot access 'myLet' before initialization
let myLet = 10;

// TDZ exists from start of block until let/const declaration
// var does NOT have TDZ (but has other traps!)
```
</Aside>

<Tabs>
  <TabItem label="const ≠ Immutable Object">
    <Code lang="js" title="const prevents reassignment, not mutation" code={`const arr = [1, 2, 3];
arr.push(4);        // ✅ Allowed — mutating contents
arr = [5, 6];       // ❌ TypeError: Assignment to constant variable

const obj = { x: 1 };
obj.x = 99;         // ✅ Allowed
obj = {};           // ❌ TypeError

// ✅ Truly immutable: Object.freeze()
const frozen = Object.freeze({ x: 1 });
frozen.x = 99;      // ❌ Silent fail (or TypeError in strict mode)
console.log(frozen.x);  // Still 1`} />
  </TabItem>

  <TabItem label="TDZ in functions">
    <Code lang="js" title="TDZ applies even in nested scopes" code={`function test() {
    console.log(x);  // ❌ ReferenceError (TDZ)
    let x = 10;
    
    if (true) {
        console.log(y);  // ❌ ReferenceError (TDZ)
        const y = 20;
    }
}`} />

    <Aside type="tip">
      Always declare variables **at the top of their scope** to avoid TDZ surprises. Use ESLint rule `no-use-before-define`.
    </Aside>
  </TabItem>

  <TabItem label="Redeclaration rules">
    <Code lang="js" title="let/const cannot be redeclared in same scope" code={`let x = 10;
let x = 20;  // ❌ SyntaxError: Identifier 'x' has already been declared

// ✅ But different scopes are fine:
{
    let x = 30;  // ✅ New block scope
    console.log(x);  // 30
}
console.log(x);  // 10`} />
  </TabItem>
</Tabs>

## 2️⃣ Function-Scoped Variables (`var`) <Badge text="Legacy" variant="caution" />

**Historical keyword** — function-scoped, hoisted with `undefined`, allows redeclaration.

- **Scope:** Entire enclosing function (ignores blocks!)
- **Hoisting:** Declaration hoisted, initialized with `undefined`
- **Redeclaration:** ✅ Allowed (confusing!)
- **Modern Advice:** Avoid `var` — use `let`/`const` instead

<Code lang="js" title="var ignores block scope" code={`if (true) {
    var x = 10;  // ❌ NOT block-scoped!
}
console.log(x);  // ✅ 10 — x "leaked" out of if-block!

// Function scope example
function demo() {
    if (true) {
        var y = 20;
    }
    console.log(y);  // ✅ 20 — y visible in entire function
}
demo();`} />

<Code lang="js" title="Hoisting with var" code={`console.log(myVar);  // ✅ undefined (not ReferenceError!)
var myVar = 10;

// What actually runs (hoisted):
var myVar;           // ← declaration hoisted, initialized undefined
console.log(myVar);  // undefined
myVar = 10;          // ← assignment stays in place`} />

<Aside type="caution">
**Why `var` is problematic**:  
1. Block-ignorant → variables leak unexpectedly  
2. Hoisted with `undefined` → silent bugs instead of clear errors  
3. Allows redeclaration → accidental overwrites  
4. Confusing with closures in loops (classic interview trap!)  

🎯 **Rule**: Default to `const`, use `let` when needed, **avoid `var`**.
</Aside>

## 3️⃣ Global & Module Variables

### Global Scope (Avoid!)
```js
// ❌ Implicit global (NEVER do this in strict mode!)
x = 10;  // Creates window.x (browser) or globalThis.x

// ✅ Explicit (still avoid!)
var globalX = 10;  // function-scoped but at top-level = global
let globalY = 20;  // NOT added to window, but still global module scope
```

### Module Scope (ESM Default — ✅ Preferred)
```js
// 📦 orderService.js (ES Module)
let modulePrivate = 0;  // ✅ Private to this file

export let publicCount = 0;  // ✅ Exported, importable elsewhere

// 📦 main.js
import { publicCount } from './orderService.js';
console.log(modulePrivate);  // ❌ ReferenceError — not accessible!
```

<Aside type="tip">
**Module scope is the new "safe global"**:  
- Variables are file-private by default  
- Explicit `export`/`import` for sharing  
- No pollution of global namespace  
- Tree-shaking friendly 🌳
</Aside>

## 🔬 Scope & Lifetime Comparison

| Feature | `let`/`const` (Block) | `var` (Function) | Global | Module |
|---------|----------------------|------------------|--------|--------|
| **Scope** | Nearest `{ }` block | Entire function | Entire program | Entire file |
| **Hoisted** | ✅ Yes (TDZ) | ✅ Yes (`undefined`) | ✅ Yes | ✅ Yes |
| **Redeclare** | ❌ Error | ✅ Allowed | ❌ Error | ❌ Error |
| **Default** | `undefined` | `undefined` | `undefined` | `undefined` |
| **Strict Mode** | ✅ Required for best practices | ⚠️ Works but discouraged | ❌ Implicit globals forbidden | ✅ Default |
| **Thread Safe** | ✅ Per-execution context | ✅ Per-execution context | ❌ Shared state | ❌ Shared if exported |

<Aside type="note">
**On "thread safety"**: JS is single-threaded with an event loop. Variables aren't shared across threads like Java, but **async operations** can create race conditions! Use proper sequencing (`async/await`, promises) to avoid bugs.
</Aside>

### Variable Shadowing

<Code lang="js" title="Inner scope variable hides outer — no 'this' needed" code={`let x = 10;       // outer scope

{
    let x = 20;   // shadows the outer x!
    console.log(x);   // 20 (inner wins)
}

console.log(x);   // 10 (outer still exists)

// Function parameters shadow outer vars:
function demo(x) {  // parameter x shadows outer x
    console.log(x); // Uses parameter value
}`} />

<Aside type="tip">
Shadowing is legal but can reduce readability. Use descriptive names and avoid reusing variable names in nested scopes unless intentional.
</Aside>

```mermaid

    Start[Execution Context Created] --> Hoist[Hoist Declarations]
    Hoist --> TDZ[Enter Temporal Dead Zone]
    TDZ --> Decl[let/const Declaration Reached]
    Decl --> ExitTDZ[Exit TDZ — Variable Usable]
    
    style TDZ fill:#fbbf24,color:#000,stroke:#f59e0b
    style ExitTDZ fill:#22c55e,color:#fff
```

<Code lang="js" title="Hoisting behavior comparison" code={`// ===== var =====
console.log(a);  // ✅ undefined
var a = 10;

// ===== let =====
console.log(b);  // ❌ ReferenceError: Cannot access 'b' before initialization
let b = 20;

// ===== const =====
console.log(c);  // ❌ ReferenceError
const c = 30;

// ===== function declarations (fully hoisted!) =====
sayHi();  // ✅ Works! Function declarations are fully hoisted
function sayHi() { console.log("Hi"); }

// ===== function expressions (NOT hoisted like declarations) =====
sayHello();  // ❌ TypeError: sayHello is not a function
const sayHello = function() { console.log("Hello"); };`} />

<Aside type="danger">
**Function declaration vs expression hoisting**:  
```js
// ✅ Declaration — fully hoisted (name AND body)
function foo() { return 1; }
foo();  // Works anywhere in scope

// ❌ Expression — only variable hoisted (body NOT hoisted)
const bar = function() { return 2; };
bar();  // ReferenceError if called before this line
```
</Aside>

## 🧠 Pass-by-Value: Primitives vs Objects

**JavaScript is always pass-by-value**. The confusion comes from what "value" means for objects.

<Tabs>
  <TabItem label="Primitive argument — value copy">
    <Code lang="js" title="Changing the parameter does NOT affect the caller" code={`function change(x) {
    x = 100;       // modifies only the LOCAL copy
}

let n = 10;
change(n);
console.log(n); // 10 — unchanged ✅`} />
  </TabItem>

  <TabItem label="Object argument — reference copy">
    <Code lang="js" title="Modifying the object DOES affect the caller" code={`function modify(arr) {
    arr[0] = 999;  // mutates the actual heap object
}

let arr = [1, 2, 3];
modify(arr);
console.log(arr[0]); // 999 ✅`} />
  </TabItem>

  <TabItem label="Reassigning reference — no effect">
    <Code lang="js" title="Reassigning the reference only changes the local copy" code={`function change(obj) {
    obj = { new: "value" };    // reassigns LOCAL reference copy only
}

let original = { old: "value" };
change(original);
console.log(original.old); // "value" — unchanged ✅`} />

    <Aside type="tip">
      **JS is always pass-by-value.**  
      For objects, the *value* being passed is the **reference** — not the object itself. You can mutate the object, but you cannot reassign the caller's reference.
    </Aside>
  </TabItem>
</Tabs>

## 🎁 Bonus: Destructuring & Pattern Matching

<Code lang="js" title="Extract values elegantly" code={`// Array destructuring
const [first, second, ...rest] = [1, 2, 3, 4];
// first=1, second=2, rest=[3,4]

// Object destructuring
const user = { name: "Alice", age: 25, city: "NYC" };

const { name: userName, city: location } = user;

let a = 1, b = 2;
[a, b] = [b, a];  // a=2, b=1 ✅`} />

createUser({ name: "Alice" });  // { name: "Alice", age: 0, roles: [] }

function drawLine([x1, y1], [x2, y2]) {

}`} />

## 🚨 Common Runtime Behaviors & Traps

<CardGrid>
  <Card title="Trap 1 — var in loops with closures" icon="error">
    ```js
    // ❌ Classic trap: all callbacks capture SAME i
    for (var i = 0; i < 3; i++) {
        setTimeout(() => console.log(i), 100);
    }
    // Output: 3, 3, 3 😱

    // ✅ Fix 1: Use let (block-scoped)
    for (let i = 0; i < 3; i++) {
        setTimeout(() => console.log(i), 100);
    }
    // Output: 0, 1, 2 ✅

    // ✅ Fix 2: IIFE with var
    for (var i = 0; i < 3; i++) {
        ((j) => setTimeout(() => console.log(j), 100))(i);
    }
    ```
  </Card>
  
  <Card title="Trap 2 — const with mutable objects" icon="caution">
    ```js
    const config = { debug: false };
    config.debug = true;   // ✅ Allowed! const only protects binding
    config = {};           // ❌ TypeError: Assignment to constant

    // ✅ Truly immutable:
    const frozen = Object.freeze({ debug: false });
    frozen.debug = true;   // ❌ Silent fail (or TypeError in strict mode)
    ```
  </Card>

    ```js
    function test(x = y, y = 10) {  // ❌ ReferenceError!
        console.log(x);
    }
    test();  // y not initialized when evaluating x's default

    // ✅ Safe order:
    function test(y = 10, x = y) {
        console.log(x);  // 10 ✅
    }
    ```
  </Card>

## 🔥 JavaScript Interview Traps

<CardGrid>
  <Card title="Trap 1 — let vs var in closures" icon="error">
    ```js
    // ❌ var: all functions share same i
    const funcsVar = [];
    for (var i = 0; i < 3; i++) {
        funcsVar.push(() => i);
    }
    funcsVar.map(f => f());  // [3, 3, 3]

    const funcsLet = [];

    }

    const nums = [1, 2, 3];
    nums.push(4);      // ✅ Allowed — mutating contents

    // 🎯 Interview question: "Is this array immutable?"
    // Answer: "No — const only prevents reassignment, not mutation."
    ```
  </Card>
  
  <Card title="Trap 3 — Destructuring with undefined" icon="error">
    ```js
    const { x, y = 10 } = { x: 5 };
    console.log(y);  // 10 ✅ (default applied)

    const { a, b = 20 } = { a: 5, b: undefined };
    console.log(b);  // 20 ✅ (undefined triggers default)

    const { c, d = 30 } = { c: 5, d: null };
    console.log(d);  // null ❌ (null does NOT trigger default!)
    ```
  </Card>
  
  <Card title="Trap 4 — Optional chaining vs nullish coalescing" icon="tip">
    ```js
    const user = { profile: null };

    // ❌ Dangerous:
    const city = user.profile.city;  // TypeError: Cannot read property of null

    // ✅ Safe patterns:
    const city1 = user?.profile?.city;  // undefined (optional chaining)
    const city2 = user?.profile?.city ?? "Unknown";  // "Unknown" (nullish coalescing)

    // ⚠️ Don't confuse ?? with ||:
    const count = 0;
    count || 10    // 10 (0 is falsy)
    count ?? 10    // 0 (0 is not null/undefined) ✅
    ```
  </Card>

  <Card title="Pattern: Block Scope for Loop Safety" icon="code">
    ```js
    // Safe async operations in loops
    async function fetchUsers(ids) {
        const results = [];
        for (const id of ids) {
            // let creates new binding per iteration
            const data = await fetch(\`/api/users/\${id}\`);
            results.push(await data.json());
        }
        return results;
    }
    // 🎯 let/const in loops prevent closure bugs with async!
    ```

    function reverse(arr) {
        let [left, right] = [0, arr.length - 1];

## 🔄 Java → JS Variable Conversion Summary

| Java Feature | JavaScript Equivalent | Critical Difference |
|-------------|----------------------|-------------------|
| `int x = 10;` | `let x = 10;` | ✅ No type declaration; type attached to value |
| Primitive vs Reference | Primitive vs Object | ✅ Same concept, but JS primitives include `null`/`undefined` |
| `final` keyword | `const` | ✅ `const` = immutable binding, not immutable object |
| Block scope | `let`/`const` | ✅ Native in JS; Java added in Java 7+ |
| No block scope for `var` | ❌ Avoid `var` | ✅ Use `let`/`const` for predictable block scope |
| Default values (fields) | Always `undefined` | ❌ JS has no compile-time "uninitialized" check |
| Static class variables | Module-level vars / `static` fields | ✅ ES2022 class fields; modules are default scope |
| Pass-by-value | Pass-by-value | ✅ Same! But JS objects = references, causing confusion |
| `null` for primitives | ❌ Primitives cannot be `null` | ✅ Only reference types can be `null` (but `typeof null === "object"`) |
| Variable shadowing | Same behavior | ✅ Inner scope hides outer; no `this` needed |
| Hoisting | `var` hoisted, `let`/`const` in TDZ | ✅ JS hoisting is more complex; TDZ catches bugs at runtime |
| Closures | ✅ Native language feature | ✅ JS closures are first-class; Java requires anonymous classes |

## 2️⃣ `let` — Block-Scoped Variable

## ⚙️ Deep Dive — Hoisting

### What Hoisting Actually Is

```
Hoisting = The JS engine processes ALL declarations
           BEFORE executing any code in that scope.
           It's done by the scope analyzer at parse time.
```

```
Source Order:
  console.log(x);   ← executed first
  var x = 5;        ← declared here

What Engine Does:
  1. Scan entire scope for declarations
  2. Register 'x' in scope → initialize to undefined
  3. THEN execute line by line

Effective Execution:
  var x = undefined;   ← hoisted
  console.log(x);      → undefined (no error)
  x = 5;               ← assignment stays in place
```

### Hoisting Behavior — All Three

```js
// VAR — hoisted AND initialized to undefined:
console.log(a); // undefined — no error
var a = 5;
console.log(a); // 5

// LET — hoisted but NOT initialized (TDZ):
console.log(b); // ❌ ReferenceError: Cannot access 'b' before initialization
let b = 5;

// CONST — same as let (TDZ):
console.log(c); // ❌ ReferenceError
const c = 5;

// FUNCTION DECLARATION — fully hoisted (name + body):
greet();            // ✅ "hello" — works before declaration
function greet() { console.log("hello"); }

// FUNCTION EXPRESSION — only var hoisted, not body:
sayHi();            // ❌ TypeError: sayHi is not a function
var sayHi = function() { console.log("hi"); };
// var sayHi = undefined at this point → calling undefined() = TypeError
```

## 🔬 Deep Dive — Temporal Dead Zone (TDZ)

```
┌─────────────────────────────────────────────────────────┐
│                  TDZ VISUALIZATION                      │
│                                                         │
│  ┌─ Block/Scope Start ──────────────────────────────┐   │
│  │                                                  │   │
│  │  ████████████████████ TDZ ████████████████████   │   │
│  │  ↑                                           ↑   │   │
│  │  Scope starts              let x = 5 ← init │   │   │
│  │                                              │   │   │
│  │  Any access to 'x' in TDZ zone:             │   │   │
│  │  → ReferenceError                           │   │   │
│  │                                             ↓   │   │
│  │  ░░░░░░░░░░░░░░░ LIVE ZONE ░░░░░░░░░░░░░░░░░    │   │
│  │  x is accessible here ✅                        │   │
│  └──────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

```js
// TDZ exists even if outer scope has same name:
let x = "outer";

{
  console.log(x); // ❌ ReferenceError 😱
  // You'd expect "outer" but inner 'let x' creates TDZ
  // from block START — even before its declaration line
  let x = "inner";
}

// Why? Engine sees 'let x' in this block at parse time
// → creates TDZ from block open to declaration line
// → outer 'x' is shadowed IMMEDIATELY — even before init
```

## ⚙️ Deep Dive — How V8 Stores Variables

```
┌─────────────────────────────────────────────────────────┐
│              V8 VARIABLE STORAGE MODEL                  │
│                                                         │
│  var → stored in FUNCTION SCOPE OBJECT                  │
│  ┌─────────────────────┐                                │
│  │  FunctionContext     │                               │
│  │  ├── x: undefined   │ ← initialized at hoist        │

│  └─────────────────────┘                                │
│                                                         │
│  let/const → stored in BLOCK SCOPE RECORD               │
│  ┌─────────────────────┐                                │
│  │  BlockContext        │                               │
│  │  ├── a: <TDZ>       │ ← uninitialized sentinel      │
│  │  └── b: 10          │ ← set at declaration line     │
│  └─────────────────────┘                                │
│                                                         │
│  Closed-over vars → move to HEAP context object         │
│  (so they survive function return)                      │
└─────────────────────────────────────────────────────────┘
```

### Variable Lifecycle (Internal)

```
  DECLARE      INITIALIZE        ASSIGN
     │               │               │
     ▼               ▼               ▼
┌─────────┐    ┌──────────┐    ┌──────────┐
│ binding │    │  value   │    │ new val  │
│ created │    │  set     │    │ set      │
└─────────┘    └──────────┘    └──────────┘

var:    DECLARE+INITIALIZE (undefined) happen at HOIST
        ASSIGN happens at runtime

let:    DECLARE happens at HOIST (TDZ sentinel placed)
        INITIALIZE+ASSIGN happen at declaration line

const:  Same as let
        ASSIGN only happens ONCE at declaration
```

## 🔄 Scope Chain — How Variable Lookup Works

```
function outer() {
  let a = 1;

  function middle() {
    let b = 2;

    function inner() {
      let c = 3;
      console.log(a, b, c); // needs a, b, c
    }
  }
}

Lookup chain for 'a' inside inner():
  inner scope  → no 'a' → miss
       ↓
  middle scope → no 'a' → miss
       ↓
  outer scope  → 'a' found ✅ → value: 1
       ↓
  (global scope → ReferenceError if not found anywhere)
```

```
┌─────────────────────────────────────────┐
│           SCOPE CHAIN                   │
│                                         │
│  inner  { c:3, [[outer]]→middle }       │
│     ↑                                   │
│  middle { b:2, [[outer]]→outer  }       │
│     ↑                                   │
│  outer  { a:1, [[outer]]→global }       │
│     ↑                                   │
│  global { ... }                         │
│                                         │
│  Each scope has [[outer]] pointer       │
│  Lookup = walk the pointer chain        │
│  O(depth) — deeper = slower             │
└─────────────────────────────────────────┘
```

## 💀 Interview Traps

### Trap 1: `var` in `for` loop — closure captures same binding

```js
// Classic — asked in every JS interview:
const fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => console.log(i));
}
fns[0](); // 3 😱
fns[1](); // 3 😱
fns[2](); // 3 😱
// All closures share the SAME var i — by the time they run, i = 3

// Fix 1 — use let (own binding per iteration):
for (let i = 0; i < 3; i++) {
  fns.push(() => console.log(i));
}
fns[0](); // 0 ✅

// Fix 2 — IIFE to capture value (pre-ES6):
for (var i = 0; i < 3; i++) {
  fns.push(((j) => () => console.log(j))(i));
}
```

### Trap 3: `const` in loops — not what you think

## 🔗 DSA / Internals Connection

> Variables are **symbol table entries**. The scope analyzer builds a **hash map** per scope — key is the identifier name, value is the slot metadata (index, type, initialized flag).
>
> TDZ is implemented as an **uninitialized sentinel** in the slot — V8 checks for this sentinel on every read and throws if found. It's a **guard bit** — same concept as a null pointer check before memory access.
>
> The scope chain is a **linked list of hash maps** — exactly like a layered hash map / prototype chain in DSA. Variable lookup = hash map lookup + linked list traversal.
