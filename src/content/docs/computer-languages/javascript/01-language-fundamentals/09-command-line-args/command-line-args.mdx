## 💻 Command Line Arguments in JavaScript — Complete Guide

> **Command Line Arguments** are values passed to your script **at runtime** from the terminal — before execution begins.

<Aside type="tip" title="🎯 MUST KNOW">
**JS CLI Superpowers vs Java**:  
✅ `process.argv` gives full control — you see node path, script path, AND your args  
✅ Rich ecosystem: `yargs`, `commander`, `cac` for professional CLI apps  
✅ Works with npm scripts, build tools, test runners  
✅ Environment variables via `process.env` complement CLI args  
✅ Deno/Bun have modern alternatives to Node's `process.argv`  
</Aside>

---

## 📌 How It Works: Node.js (Most Common)

```js
// 📦 your-script.js
console.log(process.argv);
```

```text
Terminal:
node your-script.js Alice 25 true

process.argv = [
  "/usr/local/bin/node",      // [0] Node.js executable path
  "/path/to/your-script.js",  // [1] Your script file path  
  "Alice",                    // [2] ← Your first argument
  "25",                       // [3] ← Your second argument
  "true"                      // [4] ← Your third argument
]

// ✅ Your actual CLI args start at index 2!
const cliArgs = process.argv.slice(2);  // ["Alice", "25", "true"]
```

<Aside type="note">
**Key Rule**: Arguments are **space-separated** by default. Use **quotes** to pass values containing spaces as a single argument — same as Java!
</Aside>

## 💻 Basic Example: Node.js

<Code lang="js" title="Iterating through arguments" code={`// 📦 greet.js
const args = process.argv.slice(2);  // Get only user-provided args

console.log('Total args:', args.length);

// Classic for loop
for (let i = 0; i < args.length; i++) {
    console.log(\`args[\${i}] = \${args[i]}\`);
}

// Modern style: for...of with index
for (const [idx, arg] of args.entries()) {
    console.log(\`Arg \${idx}: \${arg}\`);
}

// Functional style
args.forEach((arg, idx) => console.log(\`\${idx}: \${arg}\`));`} />

## 🔄 Type Conversion — Always String First

⚠️ **Same as Java**: All CLI arguments arrive as **strings**. Convert explicitly!

<Code lang="js" title="Parsing different types safely" code={`const args = process.argv.slice(2);

// Always check length before accessing indices!
if (args.length < 4) {
    console.error('Usage: node app.js <name> <age> <salary> <flag>');
    process.exit(1);  // ✅ Exit with error code for scripts
}

const name = args[0];                              // "Alice" → String ✅
const age = Number(args[1]);                       // "25" → 25 number ✅
const salary = parseFloat(args[2]);                // "99.5" → 99.5 ✅
const flag = args[3] === 'true';                   // "true" → boolean ✅

// ✅ Modern validation with fallbacks:
const safeAge = Number(args[1]) || 0;              // NaN → 0
const verified = ['true', '1', 'yes'].includes(args[3].toLowerCase());

console.log(\`\${name}, age \${age}, salary $\${salary.toFixed(2)}, active: \${flag}\`);`} />

<Aside type="danger" title="⚠️ NaN Trap">
```js
const age = Number("abc");  // NaN (Not a Number)
console.log(age + 10);      // NaN — silent failure!

// ✅ Always validate:
if (isNaN(age)) {
    console.error("Age must be a valid number");
    process.exit(1);
}

// ✅ Or use fallback:
const safeAge = Number(args[1]) || 18;  // NaN || 18 → 18
```
</Aside>

<Code lang="js" title="Safe parsing with try-catch (for strict validation)" code={`const args = process.argv.slice(2);

function parsePositiveInt(str, fieldName) {
    const num = Number(str);
    if (!Number.isInteger(num) || num < 0) {
        throw new Error(\`\${fieldName} must be a positive integer, got: \${str}\`);
    }
    return num;
}

try {
    const name = args[0];
    const age = parsePositiveInt(args[1], 'Age');
    console.log(\`\${name} is \${age} years old\`);
} catch (error) {
    console.error('❌ Error:', error.message);
    console.error('Usage: node app.js <name> <age>');
    process.exit(1);
}`} />

## ⚠️ Common Mistakes

<CardGrid>
  <Card title="Mistake 1 — Forgetting to slice process.argv" icon="error">
    ```js
    // ❌ Wrong: includes node path and script path!
    const args = process.argv;
    console.log(args[0]);  // "/usr/bin/node" 😱

    // ✅ Correct: slice off first two elements
    const args = process.argv.slice(2);
    console.log(args[0]);  // Your first actual argument ✅
    ```
  </Card>
  
  <Card title="Mistake 2 — Accessing without length check" icon="error">
    ```js
    const args = process.argv.slice(2);
    console.log(args[0]);  // 💥 undefined if no args passed!

    // ✅ Always check:
    if (args.length === 0) {
        console.error('No arguments provided!');
        process.exit(1);
    }
    // Or use optional chaining / nullish coalescing:
    const name = args[0] ?? 'Guest';  // Default to 'Guest' if missing
    ```
  </Card>
  
  <Card title="Mistake 3 — Spaces in arguments" icon="error">
    ```text
    node greet.js Hello World   
    // args = ["Hello", "World"] → 2 arguments!

    node greet.js "Hello World" 
    // args = ["Hello World"] ✅ → 1 argument with space

    # Linux/Mac alternative with single quotes:
    node greet.js 'Hello World'  # Also ✅
    ```
  </Card>

  <Card title="Mistake 4 — Assuming process.argv is mutable" icon="information">
    ```js
    const args = process.argv.slice(2);
    args[0] = "Modified";  // ✅ Works — you're modifying your copy

    // But modifying process.argv directly is confusing:
    process.argv[2] = "New";  // ⚠️ Technically works but don't do this!
    // It mutates the global process object — can cause subtle bugs
    ```
  </Card>
</CardGrid>

## 🎯 Interview Cheat Sheet

<CardGrid>
  <Card title="Q: What is the type of CLI arguments in JS?" icon="information">
    **Always `string[]`** — even numbers, booleans, or dates arrive as strings.  
    You must explicitly parse them: `Number()`, `parseFloat()`, `Boolean()`, etc.  
  </Card>
  
  <Card title="Q: What if no arguments passed — is process.argv null?" icon="approve-check">
    **NO ❌** — `process.argv` is **never null or undefined**.  
    It always contains at least 2 elements: `[nodePath, scriptPath]`.  
    Your actual args start at index 2 — if none passed, `slice(2)` returns `[]`.
    ```js
    // node script.js (no args)
    console.log(process.argv.length);  // 2 (node + script paths)
    console.log(process.argv.slice(2)); // [] — empty array, not null ✅
    ```
  </Card>

  <Card title="Q: Can we pass spaces in a single argument?" icon="approve-check">
    **YES ✅** — wrap in quotes (same as Java!):
    ```text
    node script.js "Hello World" → args[0] = "Hello World"
    node script.js 'Path/To/File' → args[0] = "Path/To/File"
    ```
  </Card>

  <Card title="Q: How do you access the script name itself?" icon="information">
    ```js
    const scriptPath = process.argv[1];  // Full path to your .js file
    const scriptName = scriptPath.split('/').pop();  // Just filename

    // ✅ Modern alternative (ES modules):
    import { fileURLToPath } from 'url';
    import { dirname } from 'path';
    const __filename = fileURLToPath(import.meta.url);
    const __dirname = dirname(__filename);
    ```
  </Card>

  <Card title="Q: Can we modify process.argv?" icon="caution">
    **Technically YES ✅** — it's a mutable array.  
    **But DON'T ❌** — it's a global object; mutating it can cause confusing bugs.  
    Always work with a copy: `const args = process.argv.slice(2);`
  </Card>

  <Card title="Q: What about environment variables vs CLI args?" icon="information">
    ```js
    // CLI args: node app.js --port 3000
    const port = process.argv[3];  // "3000" (string)

    // Env vars: PORT=3000 node app.js  OR via .env file
    const port = process.env.PORT;   // "3000" (string) or undefined

    // ✅ Best practice: CLI args override env vars for flexibility
    const finalPort = Number(process.argv[3] || process.env.PORT || 8080);
    ```
  </Card>
</CardGrid>

    ```js
        // Kadane's algorithm
        let max = nums[0], current = nums[0];
        for (let i = 1; i < nums.length; i++) {
    ```

<Aside type="tip">
**Competitive Coding Pro Tip**: Most online judges (LeetCode, Codeforces) read from `stdin`, not CLI args. Design your solution to support both:
```js
import * as readline from 'readline';

const args = process.argv.slice(2);
const input = args.length > 0 
    ? args  // Use CLI args for local testing
    : await readFromStdin();  // Fallback for judges

async function readFromStdin() {
    const rl = readline.createInterface({ input: process.stdin });
    const lines = [];
    for await (const line of rl) lines.push(line);
    return lines;
}
```

## 🛠️ Professional CLI Parsing Libraries

For anything beyond simple scripts, use a library — don't parse manually!

<Tabs>
  <TabItem label="yargs ✅ (Most Popular)">
    <Code lang="js" title="yargs — expressive, feature-rich" code={`import yargs from 'yargs';
import { hideBin } from 'yargs/helpers';

const argv = yargs(hideBin(process.argv))
  .option('name', {
    alias: 'n',
    type: 'string',
    description: 'User name',
    demandOption: true  // Required!
  })
  .option('age', {
    alias: 'a',
    type: 'number',
    description: 'User age',
    default: 18
  })
  .option('verbose', {
    alias: 'v',
    type: 'boolean',
    description: 'Enable verbose output'
  })
  .help()
  .argv;

console.log(\`Hello \${argv.name}, age \${argv.age}\`);
if (argv.verbose) console.log('Verbose mode enabled');

// Usage:
// node app.js -n Alice -a 25 -v
// node app.js --name Bob --age 30
// node app.js --help  # Auto-generated help! ✅`} />

    <Aside type="tip">
      **yargs superpowers**:  
      ✅ Auto-generated `--help` and `--version`  
      ✅ Type coercion (string → number/boolean)  
      ✅ Default values, required fields, aliases  
      ✅ Subcommands for complex CLIs (`app.js build`, `app.js deploy`)  
    </Aside>
  </TabItem>

  <TabItem label="commander.js ✅ (Minimalist)">
    <Code lang="js" title="commander — simple, intuitive" code={`import { Command } from 'commander';
const program = new Command();

program
  .name('greet')
  .description('Greet a user')
  .argument('<name>', 'user name')
  .option('-a, --age <number>', 'user age', '18')
  .option('-v, --verbose', 'enable verbose output')
  .action((name, options) => {
    console.log(\`Hello \${name}, age \${options.age}\`);
    if (options.verbose) console.log('Verbose mode');
  });

program.parse();  // Parses process.argv automatically

// Usage:
// node app.js Alice -a 25 -v
// node app.js --help  # Clean auto-generated help ✅`} />
  </TabItem>

  <TabItem label="cac ✅ (Modern, TypeScript-first)">
    <Code lang="ts" title="cac — type-safe, modern" code={`import cac from 'cac';

const cli = cac('myapp');

cli
  .command('greet <name>', 'Greet a user')
  .option('-a, --age <number>', 'User age', { default: 18 })
  .option('-v, --verbose', 'Enable verbose output')
  .action((name, options) => {
    console.log(\`Hello \${name}, age \${options.age}\`);
    if (options.verbose) console.log('Verbose mode');
  });

cli.help();  // Auto-generated help
cli.parse();

// ✅ Full TypeScript support — options are typed!
// Usage: node app.js greet Alice -a 25 -v`} />

    <Aside type="note">
      **cac** is great for TypeScript projects — your CLI options get proper types automatically! 🎯
    </Aside>
  </TabItem>
</Tabs>

<Aside type="caution">
**When to use a library vs manual parsing**:  
✅ Use library when:  
- Your CLI has multiple flags/options  
- You need `--help` auto-generation  
- You want type coercion and validation  
- Building a public CLI tool (npm package)  

✅ Manual parsing OK when:  
- Simple script with 1-2 positional args  
- Learning/experimenting  
- Zero-dependency requirement  
</Aside>

<Code lang="js" title="Advanced: Combining CLI args + env vars + config file" code={`// 📦 config.js — Production-ready config loading pattern
import fs from 'fs';
import path from 'path';

function loadConfig() {
  // Priority order: CLI args > env vars > config file > defaults
  const args = process.argv.slice(2);
  
  // 1. Parse CLI flags (simple manual parser for demo)
  const cli = {};
  for (let i = 0; i < args.length; i++) {
    if (args[i] === '--port' && args[i+1]) {
      cli.port = Number(args[++i]);
    } else if (args[i] === '--env' && args[i+1]) {
      cli.env = args[++i];
    }
  }
  
  // 2. Load env vars
  const env = {
    port: Number(process.env.PORT),
    env: process.env.NODE_ENV
  };
  
  // 3. Load config file (if exists)
  let file = {};
  const configPath = path.join(process.cwd(), 'config.json');
  if (fs.existsSync(configPath)) {
    file = JSON.parse(fs.readFileSync(configPath, 'utf8'));
  }
  
  // 4. Merge with priority: CLI > env > file > defaults
  return {
    port: cli.port ?? env.port ?? file.port ?? 3000,
    env: cli.env ?? env.env ?? file.env ?? 'development',
    // ... other config
  };
}

export const config = loadConfig();
console.log(\`Running in \${config.env} mode on port \${config.port}\`);`} />

## 🔰 What Are Command Line Arguments?

Command line arguments = **values passed to a Node.js program at launch** from the terminal. Node exposes them via the global `process.argv` array.

```bash
node app.js hello 42 --env=prod
```

```js
// Inside app.js:
console.log(process.argv);
// [
//   '/usr/bin/node',   ← process.argv[0] — node binary path
//   '/home/user/app.js', ← process.argv[1] — script path
//   'hello',           ← process.argv[2] — first real arg
//   '42',              ← process.argv[3]
//   '--env=prod'       ← process.argv[4]
// ]
```

### Key=Value Parsing (`--key=value`)
```js
// Launch: node server.js --port=3000 --host=localhost --env=prod

const args = process.argv.slice(2);

function parseArgs(args) {
  return args.reduce((acc, arg) => {
    // Handle --key=value
    if (arg.startsWith("--") && arg.includes("=")) {
      const [key, value] = arg.slice(2).split("=");
      acc[key] = value;
      return acc;
    }
    // Handle --flag (boolean)
    if (arg.startsWith("--")) {
      acc[arg.slice(2)] = true;
      return acc;
    }
    // Handle positional
    acc._ = acc._ || [];
    acc._.push(arg);
    return acc;
  }, {});
}

const parsed = parseArgs(args);
// { port: "3000", host: "localhost", env: "prod" }

const PORT = Number(parsed.port) || 8080;
const HOST = parsed.host || "0.0.0.0";
const ENV  = parsed.env  || "development";
```

### Space-Separated Key Value (`--key value`)
```js
// Launch: node app.js --port 3000 --host localhost

function parseArgs(args) {
  const result = { _: [] };

  for (let i = 0; i < args.length; i++) {
    const arg = args[i];

    if (arg.startsWith("--")) {
      const key = arg.slice(2);
      const next = args[i + 1];

      // If next arg exists and is not a flag:
      if (next && !next.startsWith("-")) {
        result[key] = next;
        i++; // skip next — already consumed
      } else {
        result[key] = true; // boolean flag
      }
    } else {
      result._.push(arg); // positional
    }
  }

  return result;
}

const opts = parseArgs(process.argv.slice(2));
// --port 3000 → { port: "3000" }
// --verbose   → { verbose: true }
// file.txt    → { _: ["file.txt"] }
```

## 🏭 Real Production Pattern — Full CLI Tool

```js
#!/usr/bin/env node
// file: db-migrate.js
// Usage: node db-migrate.js --env=prod --dry-run --steps=5

const args = process.argv.slice(2);

// ── Parse ──────────────────────────────────────────────
function parse(args) {
  return args.reduce((acc, arg) => {
    if (arg.startsWith("--") && arg.includes("=")) {
      const [k, v] = arg.slice(2).split("=");
      acc[k] = v;
    } else if (arg.startsWith("--")) {
      acc[arg.slice(2)] = true;
    } else {
      (acc._ ??= []).push(arg);
    }
    return acc;
  }, {});
}

// ── Validate ────────────────────────────────────────────
const VALID_ENVS = ["dev", "staging", "prod"];
```

## 💀 Interview Traps

### Trap 1: All `process.argv` values are STRINGS

```js
// Launch: node app.js 42 true

const [num, bool] = process.argv.slice(2);

typeof num;   // "string" — NOT number 😱
typeof bool;  // "string" — NOT boolean 😱

num === 42;   // false 😱
bool === true; // false 😱

// In prod — comparison without conversion = silent wrong logic:
if (num > 10) { ... }   // "42" > 10 → true (coercion saves you here)
if (num === 42) { ... } // false 😱 — strict equality fails

// Always convert explicitly:
const port = Number(process.argv[2]);
const debug = process.argv[3] === "true"; // string → boolean
```

---

### Trap 2: `process.argv[1]` changes with different runners

```js
// Direct node:
node app.js
// argv[1] = "/absolute/path/to/app.js"

// npm script (package.json: "start": "node app.js"):
npm start
// argv[1] = same — "/absolute/path/to/app.js"

// npx / global CLI tool:
npx my-tool
// argv[1] = path to npx-installed script — NOT your file 😱

// ts-node:
ts-node app.ts
// argv[1] = path to ts-node, NOT app.ts 😱

// Fix — never rely on argv[1] for logic:
// Use __filename instead:
console.log(__filename); // always your actual file
```

---

### Trap 3: Mutating `process.argv` affects all requires

```js
// process.argv is a SHARED global — mutation visible everywhere:
process.argv.push("--injected");

// Any module that reads process.argv LATER sees this:
require("./someLib"); // reads process.argv → sees your injected arg 😱

// Never mutate process.argv — always work with a copy:
const args = process.argv.slice(2); // your own copy
```

---

### Trap 4: `process.exit()` skips `finally` and `async` cleanup

```js
async function shutdown() {
  try {
    await db.close();
    console.log("DB closed");
  } finally {
    process.exit(0); // ← skips nothing in finally — OK here
  }
}

// BUT:
async function badShutdown() {
  await db.close();    // async — not awaited if exit called elsewhere
  process.exit(0);     // runs BEFORE db.close() resolves 😱
}

// Real prod pattern — graceful shutdown:
process.on("SIGTERM", async () => {
  console.log("SIGTERM received");
  await server.close();    // stop accepting connections
  await db.disconnect();   // close DB pool
  process.exit(0);         // NOW exit
});
```

### Trap 5: `=` inside value breaks naive `split("=")`

```js
// Launch: node app.js --query=SELECT * FROM users WHERE id=1

const arg = "--query=SELECT * FROM users WHERE id=1";

// BAD — splits on FIRST = only:
const [key, value] = arg.slice(2).split("=");
// key   = "query"
// value = "SELECT * FROM users WHERE id" 😱 — rest lost

// FIX — split on first = only:
const eqIndex = arg.indexOf("=");
const key   = arg.slice(2, eqIndex);
const value = arg.slice(eqIndex + 1);
// key   = "query"
// value = "SELECT * FROM users WHERE id=1" ✅
```

## 📊 DSA / Internals Connection

> `process.argv` is built from the OS-level `argv[]` array — a **null-terminated array of C strings** passed to `main()`. Node's bootstrap converts each C string into a V8 `String` object and pushes them into a JS `Array`. This is a direct **array of pointers** at the OS level — same data structure as `char* argv[]` in C. Each pointer points to a string in the process's memory segment. Understanding this explains why all values are strings — OS doesn't know types.
