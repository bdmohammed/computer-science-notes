## 🔷 Primitives vs 🔶 References — The Core Split
```
┌──────────────────────────────────────────────────────────┐
│                     MEMORY MODEL                         │
│                                                          │
│  PRIMITIVE                   REFERENCE                   │
│  ─────────────────           ─────────────────           │
│  Stored by VALUE             Stored by REFERENCE         │
│                                                          │
│  Stack                       Stack        Heap           │
│  ┌────────┐                  ┌────────┐    ┌──────────┐  │
│  │ a = 5  │                  │ a ────────> │{x: 1}    │  │
│  │ b = 5  │                  │ b ────────> │{x: 1}    │  │
│  └────────┘                  └────────┘    └──────────┘  │
│                                                          │
│  b = a → COPY of value       b = a → COPY of address     │
│  change b → a untouched      change b.x → a.x changes    │
└──────────────────────────────────────────────────────────┘
```
```js
// Primitive — copy by value
let a = 5;
let b = a;
b = 99;
console.log(a); // 5 — untouched

// Reference — copy by address
let obj1 = { x: 1 };
let obj2 = obj1;
obj2.x = 99;
console.log(obj1.x); // 99 — MUTATED 😱
```

## 2. Floating Point Types
> IEEE 754 Double Precision (64-bit)

```js
// ⚠️ NEVER use number for precise money calculations!
const price = 0.1 + 0.2;
console.log(price); // 0.30000000000000004 😱

// ✅ Better Approaches for Money
// Option 1 — Store money in smallest unit (recommended)
const amountInPaise = 10 + 20;
console.log(amountInPaise); // 30

// Then format later:
const rupees = amountInPaise / 100;
console.log(rupees); // 0.3

// Option 2 — Use Decimal Libraries
import Decimal from "decimal.js";

const amount =
  new Decimal("0.1")
    .plus(new Decimal("0.2"));

console.log(amount.toString()); // 0.3 ✅
```


<Aside type="tip">
**Why 0.1 + 0.2 ≠ 0.3?**  
Floats use **IEEE 754 binary representation**.  
`0.1` in binary = `0.000110011001100...` (repeating!) → computer truncates → tiny error accumulates.
```
float in memory — IEEE 754 32-bit:
  ┌─┬─────────┬───────────────────────┐
  │S│ Exp(11) │    Mantissa(52)       │
  └─┴─────────┴───────────────────────┘
  S = sign bit
  Exp = biased exponent
  value = (-1)^S × 1.Mantissa × 2^(Exp-1023)
```
</Aside>

## 2️⃣ `bigint`
> Arbitrary Precision Integer
Used for very large integers beyond:

```js
typeof 42n   // "bigint"

// When to use:
// Number.MAX_SAFE_INTEGER = 9007199254740991
// Beyond that → BigInt

const big = 9007199254740991n + 1n;  // ✅ exact
const bad = 9007199254740991  + 1;   // ❌ precision loss

// Cannot mix with regular number:
42n + 1     // ❌ TypeError
42n + 1n    // ✅ 43n
BigInt(42) + 1n // ✅
```

## 3️⃣ `string`

A sequence of characters enclosed in single, double, or backticks.

```js
const message = "Hello, World!";
const quote = 'It\'s a beautiful day!';
const template = `Today is ${new Date().toLocaleDateString()}`;
```

Strings are immutable — every operation creates a new string

```js
let s = "hello";

// Length trap — emoji / unicode
"hello".length    // 5  ✅
"😀".length       // 2  ❌ — emoji = 2 UTF-16 code units
[..."😀"].length  // 1  ✅ — spread uses Unicode code points
```

## 7️⃣ `symbol`

Unique and immutable identifiers.

```js
typeof Symbol()  // "symbol"

const a = Symbol("id");
const b = Symbol("id");
a === b   // false — ALWAYS unique, even same description

// Primary use: non-colliding object keys
const ID = Symbol("id");
const obj = {
  [ID]: 123,
  id: "public"
};

obj[ID]   // 123  — Symbol key
obj.id    // "public" — string key
// They don't collide even though both named "id"

// 💀 Symbol JSON Trap
const key = Symbol("x");
const obj = { [key]: 1, name: "Ali" };

JSON.stringify(obj)  // '{"name":"Ali"}' — Symbol key VANISHES silently
```

Useful for:

* Hidden object properties
* Library internals
* Avoiding key collisions

### ✅ Reliable Type Detection Table

| Value | `typeof` | Real Check |
|---|---|---|
| `42` | `"number"` | `typeof x === "number"` |
| `"hi"` | `"string"` | `typeof x === "string"` |
| `true` | `"boolean"` | `typeof x === "boolean"` |
| `undefined` | `"undefined"` | `x === undefined` |
| `null` | `"object"` ❌ | `x === null` |
| `[]` | `"object"` ❌ | `Array.isArray(x)` |
| `{}` | `"object"` | `typeof x === "object" && x !== null` |
| `function(){}` | `"function"` | `typeof x === "function"` |

| `42n` | `"bigint"` | `typeof x === "bigint"` |
| `new Date()` | `"object"` | `x instanceof Date` |

### 🔬 The Nuclear Option — Reliable for All Types
```js
Object.prototype.toString.call(42)         // "[object Number]"
Object.prototype.toString.call("hi")       // "[object String]"
Object.prototype.toString.call(null)       // "[object Null]"
Object.prototype.toString.call([])         // "[object Array]"
Object.prototype.toString.call(new Date()) // "[object Date]"
Object.prototype.toString.call(/regex/)    // "[object RegExp]"

// Utility:
function typeOf(val) {
  return Object.prototype.toString.call(val).slice(8, -1).toLowerCase();
}
typeOf(null)  // "null"  ✅
typeOf([])    // "array" ✅
typeOf(42n)   // "bigint"✅
```

## ⚙️ Deep Dive — V8 Internal Type Representation

```
V8 stores values as "tagged pointers" (Smi vs HeapObject)

┌─────────────────────────────────────────────────┐
│              V8 Value Representation             │
│                                                 │
│  Small Integer (Smi):                           │
│  ┌──────────────────────────┬─┐                 │
│  │      31-bit integer      │1│  ← tag bit = 1  │
│  └──────────────────────────┴─┘                 │
│  Lives on STACK — zero heap allocation          │
│                                                 │
│  HeapObject (everything else):                  │
│  ┌──────────────────────────┬─┐                 │
│  │    pointer to heap       │0│  ← tag bit = 0  │
│  └──────────────────────────┴─┘                 │
│  Lives on HEAP — GC managed                     │
└─────────────────────────────────────────────────┘
```

```
Type Tags in V8 HeapObject:
  MAP pointer → points to "hidden class" (Shape)
  Shape tells V8 → what type this is, field layout, etc.

  string   → SeqOneByteString / SeqTwoByteString
  number   → HeapNumber (when not Smi)
  object   → JSObject
  array    → JSArray (extends JSObject)
  function → JSFunction (extends JSObject)
```

> Small integers (Smi) — roughly -2^30 to 2^30 — **never allocate on the heap**. They live entirely in the pointer itself. This is why integer arithmetic in JS can be extremely fast.

# 🧠 JavaScript Memory Model

```text
Primitive → copied by value
Objects   → copied by reference
```

Example:

```js
let x = 10;
let y = x;

y = 20;

console.log(x); // 10
```

But:

```js
const obj1 = { value: 10 };
const obj2 = obj1;

obj2.value = 20;

console.log(obj1.value);
// 20
```

### Trap 1: `typeof` before declaration — only safe for `var`/undeclared

```js
typeof x          // "undefined" ✅ — safe, no error
console.log(x)    // ❌ ReferenceError

typeof y          // ❌ ReferenceError — y is in TDZ (let/const)
let y = 5;
```

> `typeof` is normally "safe" for undeclared vars — but **not for `let`/`const`** in TDZ. This breaks feature detection code during module migration.

---

### Trap 2: `NaN` is not equal to itself

```js
NaN === NaN   // false 😱 — only value not equal to itself
NaN == NaN    // false

// Correct checks:
Number.isNaN(NaN)     // true  ✅
Number.isNaN("hello") // false ✅ — doesn't coerce

isNaN("hello")        // true  ❌ — coerces string to NaN first
isNaN(undefined)      // true  ❌ — undefined coerces to NaN
```

---

### Trap 3: `-0` is a real value

```js
-0 === 0          // true  😱
-0 == 0           // true

// Detect -0:
Object.is(-0, 0)  // false ✅
Object.is(-0, -0) // true  ✅

// Why it matters:
(-0).toString()   // "0"  — hides the sign
JSON.stringify(-0) // "0" — loses the sign
1 / -0            // -Infinity ← shows the sign survived
```

> `-0` silently becomes `0` in JSON. If your backend sends direction data as `-0`/`0` — you lose direction on serialization.

---

### Trap 4: Arrays are objects — and sparse ones are dangerous

```js
const arr = [1, 2, 3];
arr.x = "surprise";    // ✅ arrays are objects — you can add props

Object.keys(arr)       // ["0", "1", "2", "x"] 😱
arr.length             // 3 — custom prop not counted

// Sparse array:
const sparse = [1, , , 4];  // holes at index 1, 2
sparse.length          // 4
sparse[1]              // undefined
1 in sparse            // false — hole vs undefined value

sparse.map(x => x * 2) // [2, empty, empty, 8] — holes SKIPPED by map
```

---

### Trap 5: `null` + arithmetic

```js
null + 1       // 1   — null coerces to 0
null + "1"     // "null1" — null coerces to string
null * 5       // 0
undefined + 1  // NaN — undefined coerces to NaN (not 0)
undefined * 5  // NaN
```

> `null` and `undefined` behave completely differently in arithmetic coercion. Mixing them in calculations produces silent NaN bugs in prod.

## 📊 DSA Connection — Type System = Tagged Union

```
JS type system is a runtime TAGGED UNION

  Value = (Tag, Data)
  Tag   = one of { number, string, boolean, null,
                   undefined, symbol, bigint, object }
  Data  = actual value

This is the same as:
  enum Type { Number, String, Bool, ... }
  struct Value { Type tag; union { ... } data; }

V8 uses pointer tagging (Smi trick) as an optimization
to avoid heap allocation for the most common case (integers).
```

## 🏭 Production Relevance

```js
// Real-world API response type guard:
function processUser(user) {
  if (user === null || user === undefined) {
    throw new Error("User is nullish");
  }
  if (typeof user !== "object") {
    throw new TypeError(`Expected object, got ${typeof user}`);
  }
  if (!Array.isArray(user.roles)) {
    throw new TypeError("roles must be an array");
  }
  // safe to proceed
}

// Why typeof isn't enough for arrays:
typeof []  // "object" — would pass object check but fail array logic
```
