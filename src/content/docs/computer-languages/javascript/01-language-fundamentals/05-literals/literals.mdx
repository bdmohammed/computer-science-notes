A **Literal** is a fixed value written directly in source code.

- ✔ Represents constant data
- ✔ Written inline, no computation needed
- ✔ JS engine infers type dynamically (no static typing!)

<Code lang="js" title="What a literal looks like" code={`
let x      = 10;                        // 10    → number literal
let d      = 10.5;                      // 10.5  → number literal (float)
let x      = "hello";                   // "hello" → string literal
let x      = true;                      // true  → boolean literal
let x      = null;                      // null  → null literal
let x      = [1, 2, 3];                 // array literal
let x      = { x: 1 };                  // object literal
let b      = /abc/g;                    // RegExp literal
let b      = \`hi ${name}\`;            // string literal
let big    = 9007199240991n; // → BigInt literal`} />

> Identifiers are **names**. Literals are **values written inline**. This distinction matters at the lexer stage.

## 🗺️ Classification

| Literal | Example | Notes |
|---------|---------|-------|
| Number | `10`, `0x1F`, `0b101`, `1_000_000` | All numbers are `Number` (64-bit float) |
| BigInt | `123n`, `0xFFn` | Arbitrary precision integers |
| Boolean | `true`, `false` | Only two values |
| String | `'A'`, `"Hello"`, \`template\` | Single, double, or backtick quotes |
| null / undefined | `null`, `undefined` | Two distinct "empty" values |
| RegExp | `/\\d+/g` | Literal regex syntax |

<Aside type="tip">
🎯 **JS Superpower**: No type suffixes! `10`, `10.5`, `0xFF` — all just `Number`.  
Need big integers? Add `n`: `9007199254740991n` ✅
</Aside>

## 1️⃣ Number Literals (Integral + Floating)

JS has **one `Number` type** for all numeric literals (IEEE 754 double-precision).

### Number Systems
| System      | Base | Prefix      | Allowed Values | Example  | Value |
| ----------- | ---- | ----------- | -------------- | -------- | ----- |
| Decimal     | 10   | none        | `0-9`          | `10`     | 10    |
| Octal       | 8    | `0o` / `0O` | `0-7`          | `0o10`   | 8     |
| Hexadecimal | 16   | `0x` / `0X` | `0-9`, `A-F`   | `0x10`   | 16    |
| Binary      | 2    | `0b` / `0B` | `0-1`          | `0b1010` | 10    |

### All Notations

```js
// Decimal (base 10)
let a = 42;
let b = 3.14;

// Binary (base 2) — prefix: 0b or 0B
let bin = 0b1010;       // = 10 in decimal
let bin2 = 0B1111;      // = 15

// Octal (base 8) — prefix: 0o or 0O
let oct = 0o52;         // = 42 in decimal
let oct2 = 0O17;        // = 15

// Hexadecimal (base 16) — prefix: 0x or 0X
let hex = 0x2A;         // = 42 in decimal
let hex2 = 0xFF;        // = 255

// Exponential (scientific notation)
let exp1 = 1e3;         // 1000
let exp2 = 2.5e-4;      // 0.00025
let exp3 = 1E6;         // 1000000

// BigInt — suffix: n
let big = 42n;
let bigHex = 0x1fn;     // = 31n
let bigBin = 0b101n;    // = 5n
```

### 💡 Numeric Separator (ES2021)
```js
// Underscore as visual separator — no effect on value
let million  = 1_000_000;      // 1000000
let bytes    = 0xFF_EC_D8_12;  // hex with separators
let rate     = 0.000_001;      // 0.000001
let bigNum   = 1_000n;         // BigInt with separator

// Rules:
1__000    // ❌ SyntaxError — double underscore
_1000     // ✅ valid identifier (not a numeric literal)
1000_     // ❌ SyntaxError — trailing underscore
0x_FF     // ❌ SyntaxError — after prefix
```

### ⚠️ Legacy Octal — The Silent Trap
```js
// OLD octal syntax (ES3) — leading zero
let old = 052;   // = 42 in sloppy mode 😱
let old2 = 09;   // = 9  (8/9 not valid octal → silently decimal)

"use strict";
let x = 052;     // ❌ SyntaxError — legacy octal banned in strict mode
let y = 0o52;    // ✅ modern octal — always use this
```

```
┌──────────────────────────────────────────────┐
│           OCTAL TRAP DIAGRAM                 │
│                                              │
│  Sloppy Mode:                                │
│  052  → starts with 0 → octal → 42          │
│  059  → 9 invalid in octal → decimal → 59   │
│  (engine silently switches bases!)           │
│                                              │
│  Strict Mode:                                │
│  052  → SyntaxError immediately              │
│  0o52 → 42  (always correct)                 │
└──────────────────────────────────────────────┘
```

<Aside type="note">
⚠️ **Legacy Octal Trap**: `010` was octal in old JS (non-strict).  
In **strict mode** or ES6+, use `0o10` explicitly. `010` → `8` in sloppy mode, `10` in strict! 🎭
</Aside>

### 🔢 Mental Math: Base Conversion
```text
Binary:    0b1010 = 1×2³ + 0×2² + 1×2¹ + 0×2⁰ = 8 + 2 = 10
Octal:     0o10   = 1×8¹ + 0×8⁰ = 8
Hex:       0x10   = 1×16¹ + 0×16⁰ = 16
Decimal:   123    = 1×10² + 2×10¹ + 3×10⁰ = 123
```

<Code lang="js" title="Number system examples" code={`
let x = 10;      // Decimal → 10
let y = 0o10;    // Octal   → 8
let z = 0x10;    // Hex     → 16
let w = 0b1010;  // Binary  → 10

console.log(\`\${x}----\${y}----\${z}\`); // "10----8----16"`} />

#### ✅ Valid vs ❌ Invalid
<Code lang="js" title="✅ Valid" code={`
let x = 0o777;       // Octal (digits 0–7)
let x = 0xFACE;      // Hex uppercase
let x = 0xbeef;      // Hex lowercase
let x = 1_000_000;   // Underscores for readability (ES2021+)`} />

<Code lang="js" title="❌ Invalid / Traps" code={`
let x = 0786;   // ⚠️ Strict mode: SyntaxError (invalid octal digit 8)
                // ⚠️ Sloppy mode: treated as decimal 786 (confusing!)
let x = 0xBeer; // ❌ SyntaxError: 'r' not a hex digit
let x = 1_00_;  // ❌ SyntaxError: underscore at end`} />

### 🔢 BigInt Literals <Badge text="ES2020+" variant="success" />

For integers beyond `Number.MAX_SAFE_INTEGER` (`2⁵³ - 1`).

<Code lang="js" title="BigInt basics" code={`
let big = 9007199254740991n;           // ✅ exact integer
let hex = 0xFFn;                        // ✅ hex BigInt
let calc = 10n + 20n;                   // ✅ 30n

// ❌ Can't mix Number and BigInt without explicit conversion
let wrong = 10 + 5n;                    // ❌ TypeError
let right = BigInt(10) + 5n;            // ✅ 15n
let right2 = 10n + BigInt(5);           // ✅ 15n`} />

<Aside type="danger">
```js
// 🚫 Common trap: comparing Number and BigInt
10 === 10n   // false (!) — different types
10 == 10n    // true  — loose equality coerces (avoid this!)

// ✅ Always use explicit conversion:
Number(10n) === 10   // true
BigInt(10) === 10n   // true
```
</Aside>

### Underscore in Numeric Literals <Badge text="ES2021+" variant="success" />

<Code lang="js" title="Underscore for readability" code={`
let million    = 1_000_000;         // ✅ readable!
let phone      = 987_654_3210;      // ✅
let amount     = 1_23_456.78;       // ✅
let binary     = 0b1010_1100;       // ✅
let hex        = 0xFF_FF_FF;        // ✅

// ⚠️ Rules — where underscore is NOT allowed:
let a = _100;           // ❌ can't START with _

let e = 0x_FF;          // ❌ can't appear right after prefix`} />

## 2️⃣ Floating Point Literals

All numeric literals with decimals or exponents are `Number` type (no suffixes needed!).

<Code lang="js" title="✅ Valid number forms" code={`
let d1 = 10.5;          // decimal
let d2 = 10.5e2;        // scientific → 1050
let d3 = 1.5e-3;        // → 0.0015
let d4 = 0x10;          // hex integer → 16 (still Number)
let d5 = 0o10;          // octal integer → 8 (still Number)

// ✅ All are type "number":
typeof 10      // "number"
typeof 10.5    // "number"
typeof 0xFF    // "number"
typeof 1e10    // "number"`} />

<Aside type="tip">
🧠 **Memory trick**: *"JS Numbers are Floaty by Default"*  
No `f`, `d`, or `L` suffixes — just write the number. Need arbitrary precision? Use `BigInt` with `n`.
</Aside>

<Aside type="danger">
**Never use `Number` for money** (same as Java!):
```js
console.log(0.1 + 0.2); // 0.30000000000000004 😱

// ✅ Fixes:
// 1. Use integers (cents): 10 + 20 = 30 cents
// 2. Use libraries: decimal.js, big.js
// 3. Use toFixed() for display (but still float underneath!)
```
</Aside>

## 3️⃣ String & Character Literals

⚠️ **JS has no `char` type** — single quotes `'A'` are just length-1 strings!

### Three Quote Styles
<Code lang="js" title="String literal forms" code={`
let s1 = 'Single quotes';      // ✅
let s2 = "Double quotes";      // ✅
let s3 = \`Template literals\`; // ✅ (ES6+)

// When to use which:
'She said "hello"'  // double quote inside single — no escape needed
"it's fine"         // single quote inside double — no escape needed

// Template literals: interpolation + multiline
let name = "Alice";
let greeting = \`Hello, \${name}!\`;  // "Hello, Alice!"

let html = \`
  <div>
    <p>Multiline without \\n!</p>
  </div>
\`;`} />

### Unicode & Escape Sequences
<Code lang="js" title="Unicode & escapes" code={`
let c1 = 'A';              // literal character
let c2 = '\\u0041';        // Unicode escape → 'A'
let c3 = '\\u{1F680}';     // Code point > U+FFFF → '🚀' (ES6+)
let c4 = '\\n';            // Escape: newline
let c5 = String.fromCodePoint(0x1F680); // Alternative for emojis

// All are strings:
typeof 'A'        // "string"
typeof '\\u0041'  // "string"
'A'.length        // 1`} />

<Code lang="js" title="❌ Common traps" code={`
let ch = 'ab';      // ✅ valid! (string of length 2, not error like Java)
let ch = '';        // ✅ valid! (empty string)
let ch = '\\iface'; // ❌ SyntaxError: invalid escape sequence
let ch = \\u0062;   // ❌ SyntaxError: missing quotes`} />

### Escape Sequences Table
| Escape | Meaning |
|--------|---------|
| `\\n` | New line |
| `\\t` | Tab |
| `\\r` | Carriage return |
| `\\\\` | Backslash |
| `\'` | single quote |
| `\"` | double quote |
| `\0` | null character |
| `\\'` / `\\"` | Quote literals |
| `\\uXXXX` | Unicode (4 hex) |
| `\\u{X...}` | Unicode code point (✅ ES6+) |
| `\\xXX` | Hex byte (0-255) |

```js
"\u0041"      // "A"
"\u{1F600}"   // "😀" — emoji via full code point
"\x41"        // "A" — Latin-1
"\n"          // newline character
```
<Aside type="note">
🎯 **DSA Connection**:  
`'a'.charCodeAt(0)` → `97`, `'z'.charCodeAt(0)` → `122`  
Pattern: `char.charCodeAt(0) - 'a'.charCodeAt(0)` gives 0–25 index — perfect for frequency arrays, sliding window, Trie! 🚀
</Aside>

## 4️⃣ Boolean Literals

Only **two values**: `true` or `false` (case-sensitive!).

<Code lang="js" title="Boolean basics" code={`
true    // Token: BOOLEAN_LITERAL(true)
false   // Token: BOOLEAN_LITERAL(false)


let flag = true;
let done = false;

// ✅ Idiomatic JS
if (isActive) { }      // not: if (isActive === true)
if (!isEmpty) { }

// ⚠️ Truthy/Falsy gotchas (JS-specific!)
if (1) { }      // ✅ runs (1 is truthy)
if (0) { }      // ❌ skips (0 is falsy)
if ("") { }     // ❌ skips (empty string falsy)
if ("0") { }    // ✅ runs (non-empty string truthy)

// These are NOT strings, NOT 1/0:
typeof true  // "boolean"
true === 1   // false
true == 1    // true ← coercion trap
false == 0   // true ← coercion trap
false == ""  // true ← coercion trap
`} />

<Aside type="caution">
`"true"` (with quotes) is a **String**, not boolean!  
`True` or `TRUE` → `ReferenceError` (not defined).  
JS is **case-sensitive** for `true`/`false`. 🔐
</Aside>

## 5️⃣ null and undefined Literals

Two distinct "empty" values in JS:

| Literal | Meaning | Typical Use |
|---------|---------|------------|
| `null` | Intentional absence of object | `let user = null;` |
| `undefined` | Variable declared but not assigned | `let x; console.log(x); // undefined` |

<Code lang="js" title="null vs undefined" code={`
let a = null;           // ✅ explicitly "no object"
let b;                  // ✅ b is undefined
let c = undefined;      // ✅ same as above (explicit)

// ❌ Can't assign null/undefined to... well, you can, but:
let num = null;         // ✅ allowed (dynamic typing!)
console.log(num + 10);  // ❌ NaN (null coerces to 0, but still weird)

// ✅ Safe pattern: nullish coalescing (ES2020)
let name = userInput ?? "Guest";  // use "Guest" if userInput is null/undefined

null  // one of only two values of type "object" (the bug)

// null literal vs undefined:
// null   → intentional absence — YOU set it
// undefined → accidental absence — JS set it
`} />

<Aside type="danger">
**Most common runtime error in JS:**
```js
let user = null;
console.log(user.name);  // 💥 TypeError: Cannot read property 'name' of null

// ✅ Defensive patterns:
// 1. Optional chaining (ES2020)
console.log(user?.name);  // undefined (no crash!)

// 2. Nullish coalescing
const displayName = user?.name ?? "Anonymous";

// 3. Type guards
if (user && user.name) { ... }
```
</Aside>

## 3️⃣ Template Literals — Deep Dive

### Basic Form
```js
const name = "Ali";
const age = 20;

`Hello, ${name}! You are ${age} years old.`
// "Hello, Ali! You are 20 years old."

// Any expression works inside ${}:
`${2 + 2}`            // "4"
`${user.getName()}`   // function call
`${condition ? 'a' : 'b'}` // ternary
```

### Multi-line (no `\n` needed)
```js
const html = `
  <div>
    <p>${content}</p>
  </div>
`;
// preserves actual newlines and indentation
```

### Nested Templates
```js
const items = ['a', 'b', 'c'];
const list = `Items: ${items.map(i => `<li>${i}</li>`).join('')}`;
// "Items: <li>a</li><li>b</li><li>c</li>"
```

---

### 🔬 Tagged Template Literals — The Advanced Form

```
tag`string ${expr} string`
  │
  ├── tag = a function
  ├── receives: (strings_array, ...expressions)
  └── returns: anything you want
```

```js
// Tag function signature:
function tag(strings, ...values) {
  console.log(strings); // ['Hello ', '! You are ', ' old.']
  console.log(values);  // ['Ali', 20]
  return "custom output";
}

tag`Hello ${name}! You are ${age} old.`
// "custom output"
```

### Real Production Use — SQL Injection Prevention
```js
// UNSAFE:
const query = `SELECT * FROM users WHERE id = ${userId}`;
// userId = "1; DROP TABLE users;" → SQL injection 💀

// SAFE — tagged template as sanitizer:
function sql(strings, ...values) {
  return {
    text: strings.reduce((q, s, i) =>
      q + s + (values[i] !== undefined ? `$${i}` : ''), ''),
    values: values
  };
}

const query = sql`SELECT * FROM users WHERE id = ${userId}`;
// { text: "SELECT * FROM users WHERE id = $0", values: [userId] }
// parameterized query — safe ✅
```

### Real Production Use — styled-components (CSS-in-JS)
```js
// This is exactly how styled-components works:
const Button = styled.button`
  background: ${props => props.primary ? 'blue' : 'white'};
  color: ${props => props.primary ? 'white' : 'blue'};
  font-size: 1em;
`;
// styled.button IS a tag function
```

### `String.raw` — Built-in Tag
```js
// Ignores all escape sequences:
String.raw`Hello\nWorld`  // "Hello\\nWorld" — literal backslash-n
String.raw`C:\Users\Ali`  // "C:\\Users\\Ali" — no path escape issues

// Real use: Windows paths, regex strings
const pattern = String.raw`^\d{3}-\d{4}$`; // regex without double-escaping
```

## 6️⃣ Array Literal

```js
// Basic
[1, 2, 3]
["a", "b"]
[true, null, undefined, 42n]

// Mixed types — JS arrays are not typed
[1, "two", { three: 3 }, [4]]

// Sparse array literal — TRAP:
[1, , , 4]   // length = 4, holes at index 1 and 2
```

### Trailing Comma Rule
```js
[1, 2, 3,]   // length = 3 ✅ — trailing comma ignored
[1, 2, , ]   // length = 3 ❌ TRAP — hole at index 2, trailing comma ignored
              // [1, 2, empty] — 3 items with a hole
```

### 🔬 Internals — Array Literal vs Array Constructor
```js
[1, 2, 3]        // literal → ALWAYS creates array with 3 elements

new Array(3)     // constructor → creates EMPTY array of length 3 (hole-filled)
new Array(1,2,3) // constructor → creates [1, 2, 3]

// The literal is ALWAYS safer and faster:
// V8 can predict the shape of an array literal at parse time
// and allocate the exact right memory upfront (PACKED array)
```

## 7️⃣ Object Literal

### All Forms
```js
// Basic
const obj = { name: "Ali", age: 20 };

// Shorthand property (ES6)
const name = "Ali";
const obj = { name };   // same as { name: name }

// Computed property names
const key = "dynamic";
const obj = { [key]: 1, [`${key}_2`]: 2 };
// { dynamic: 1, dynamic_2: 2 }

// Method shorthand
const obj = {
  greet() { return "hello"; },     // shorthand
  greet: function() { ... },       // old form — same behavior
  greet: () => { ... }             // arrow — different 'this'!
};

// Getter / Setter
const obj = {
  _x: 0,
  get x()  { return this._x; },
  set x(v) { this._x = v * 2; }
};
obj.x = 5;
obj.x;      // 10
```

### Spread in Object Literal
```js
const defaults = { color: "red", size: 10 };
const custom   = { size: 20, weight: 5 };

const merged = { ...defaults, ...custom };
// { color: "red", size: 20, weight: 5 }
// later spread WINS on conflict

// TRAP — shallow merge only:
const a = { nested: { x: 1 } };
const b = { ...a };
b.nested.x = 99;
console.log(a.nested.x); // 99 😱 — nested object still shared
```

## 8️⃣ RegExp Literal

```js
/pattern/flags

// Flags:
/abc/g    // global — find ALL matches
/abc/i    // case-insensitive
/abc/m    // multiline — ^ and $ match line boundaries
/abc/s    // dotAll — . matches \n too
/abc/u    // unicode — full unicode support
/abc/y    // sticky — match from lastIndex only
/abc/d    // indices — capture match start/end positions

// Combined:
/hello/gi   // global + case-insensitive
```

### ⚠️ RegExp Literal vs Constructor
```js
// Literal — compiled at PARSE TIME (faster, static):
const re = /hello/gi;

// Constructor — compiled at RUNTIME (needed for dynamic patterns):
const pattern = "hello";
const re = new RegExp(pattern, "gi");  // when pattern is a variable

// TRAP — literal regex with 'g' flag has state:
const re = /abc/g;
re.test("abc123abc"); // true  — lastIndex moves to 3
re.test("abc123abc"); // true  — lastIndex moves to 9
re.test("abc123abc"); // false — lastIndex past end, resets to 0
re.test("abc123abc"); // true  — starts over 😱
```

## ⚙️ Deep Dive — How V8 Handles Literals

```
┌─────────────────────────────────────────────────────────┐
│              LITERAL COMPILATION PIPELINE               │
│                                                         │
│  Source Text                                            │
│      │                                                  │
│      ▼                                                  │
│  [ LEXER ] ─── reads chars ──→ emits literal token      │
│      │         "42" → NUMERIC_LITERAL(42)               │
│      │         '"hi"' → STRING_LITERAL("hi")            │
│      │                                                  │
│      ▼                                                  │
│  [ PARSER ] ──→ AST Node                                │
│      │         NumericLiteral { value: 42 }             │
│      │         StringLiteral  { value: "hi" }           │
│      │                                                  │
│      ▼                                                  │
│  [ IGNITION ] ──→ Bytecode                              │
│      │         LdaSmi [42]      ← small int: no heap    │
│      │         LdaConstant [0]  ← string: from pool     │
│      │                                                  │
│      ▼                                                  │
│  [ CONSTANT POOL ]                                      │
│      Strings interned here — same literal text          │
│      → same memory address (deduplication)              │
└─────────────────────────────────────────────────────────┘
```

### String Interning
```js
// V8 interns (deduplicates) string literals:
const a = "hello";
const b = "hello";
// Both point to SAME memory address in constant pool

// But runtime-created strings are NOT interned:
const c = "hel" + "lo";  // may or may not be same address
// V8 may optimize, but not guaranteed
```

### Array Literal — PACKED vs HOLEY
```js
// PACKED (fast path — V8 knows all slots filled):
const arr = [1, 2, 3];        // PACKED_SMI_ELEMENTS

// HOLEY (slow path — V8 must check each access):
const arr = [1, , 3];         // HOLEY_SMI_ELEMENTS

// Once holey, NEVER goes back to packed:
const arr = [1, 2, 3];        // PACKED
arr[5] = 99;                   // → HOLEY (gap at 3,4)
delete arr[0];                 // → HOLEY

// V8's element kind lattice (most → least optimized):
// PACKED_SMI → PACKED_DOUBLE → PACKED
// HOLEY_SMI  → HOLEY_DOUBLE  → HOLEY
```

## 🔬 Literal Type Behavior in JS

JS is **dynamically typed** — no compile-time type checks! But watch for:

1. **Coercion surprises** (`==` vs `===`)
2. **NaN propagation** (any math with NaN → NaN)
3. **BigInt/Number mixing** (TypeError)
4. **Truthy/falsy conversions** in conditionals

<Code lang="js" title="Type behavior examples" code={`
// ✅ All these assignments work (dynamic typing):
let x = 10;        // number
x = "hello";       // now string
x = true;          // now boolean
x = null;          // now null

// ⚠️ Coercion traps:
10 + "20"    // "1020" (string concatenation)
10 - "20"    // -10 (numeric subtraction, "20" coerced)

"10" === 10  // false (strict equality, no coercion)

10 + 5n      // ❌ TypeError: can't mix Number and BigInt
BigInt(10) + 5n  // ✅ 15n

// ✅ Safe numeric checks:
Number.isInteger(10)      // true
Number.isFinite(1e308)    // true

### Trap 2: RegExp `g` flag + `.test()` stateful trap

### Trap 5: `0.1` + `0.2` in numeric literals
```js
// This is a LITERAL issue — not just runtime:
const price = 0.1 + 0.2;   // 0.30000000000000004
// The number literals 0.1 and 0.2 CANNOT be represented
// exactly in IEEE 754 binary — the imprecision is baked in

// Production fix for money:

const display = (cents / 100).toFixed(2); // "0.30" ✅
```

## 📊 DSA / Internals Connection

> **Literals = Compile-time Constants**
>
> In compiler theory, literals are **immediate values** — embedded directly into instruction operands or the constant pool. No memory lookup needed at runtime for primitives. This is the same principle as **immediate addressing mode** in CPU architecture — `MOV EAX, 42` vs `MOV EAX, [address]`. Numeric literals (especially Smis) map directly to this: they live IN the pointer, not behind it.
