## 🔗 String Concatenation in C++ — Complete Guide

> ⚠️ **Critical Difference from Java**: C++ **does NOT overload `+` for mixing `std::string` with primitives**.  
> - `std::string + std::string` → ✅ Works  
> - `std::string + int` → ❌ **Compile Error!** Must use `std::to_string()` or streams.

```
String Concatenation in C++
│
├── Compile-Time
│   └── String literal concatenation   "hello" " " "world"
│
├── C-Style (manual, unsafe)
│   ├── strcat()
│   └── strncat()
│
├── std::string (runtime, safe)
│   ├── operator+     → new string each time
│   ├── operator+=    → in-place append
│   └── append()      → in-place, more control
│
├── std::string_view  → no concatenation, read-only views
│
├── Building strings efficiently
│   ├── std::ostringstream
│   ├── std::string::reserve() + +=
│   └── std::format (C++20)
│
└── Raw buffer manipulation
    └── sprintf / snprintf
```

```cpp
#include <string>
#include <iostream>

int main() {
    // ✅ std::string + std::string works:
    std::string greeting = "Hello" + std::string(" World");  // "Hello World"
    
    // ❌ std::string + int does NOT work:
    // std::string age = "Age: " + 25;  // ❌ Error: no operator+ matches
    
    // ✅ Fix: use std::to_string (C++11):
    std::string age = "Age: " + std::to_string(25);  // "Age: 25"
    
    // ✅ Or use stream insertion (idiomatic C++):
    std::cout << "Age: " << 25 << '\\n';  // Output: Age: 25
    
    // ✅ C++20: std::format (type-safe, Python-like):
    #if __cplusplus >= 202002L
    #include <format>
    std::string msg = std::format("Age: {}", 25);  // "Age: 25"
    #endif
    
    return 0;
}
```

<Aside type="note">
**🔑 Key Rule**: In C++, `+` for strings **only works when both operands are `std::string` (or string literals that can construct `std::string`)**.  
Primitives (`int`, `double`, `bool`, etc.) must be explicitly converted via:
- `std::to_string()` (C++11) — simple, but limited
- `std::ostringstream` — flexible, verbose
- `std::format()` (C++20) — modern, type-safe, recommended
- Stream insertion `<<` — idiomatic for output, not string building
</Aside>

## ⚠️ Left-to-Right Evaluation — Same as Java, But Different Operators

> C++ evaluates expressions **strictly left-to-right** (same as Java). However, since `std::string + int` doesn't work, you **cannot** write mixed expressions like Java.

### 🔄 Why Java's `"Hello " + 1 + 2` Doesn't Translate Directly

```text
Java: "Hello " + 1 + 2
  → "Hello " + 1 = "Hello 1" (String + int → concat)
  → "Hello 1" + 2 = "Hello 12" (String + int → concat)
  → Result: "Hello 12" ✅

C++: "Hello " + 1 + 2
  → "Hello " + 1 = ❌ Compile Error! (no operator+ for const char* + int)
```

### ✅ C++ Patterns for Mixed Expressions

<Code lang="cpp" title="Safe concatenation patterns in C++" code={`
#include <string>
#include <iostream>

int main() {
    // Pattern 1: Convert each primitive with std::to_string
    std::string result1 = "Hello " + std::to_string(1) + std::to_string(2);
    std::cout << result1 << '\\n';  // "Hello 12"
    
    // Pattern 2: Use parentheses + to_string for arithmetic first
    int a = 1, b = 2;
    std::string result2 = "Sum: " + std::to_string(a + b);
    std::cout << result2 << '\\n';  // "Sum: 3"
    
    // Pattern 3: Stream insertion (idiomatic for output, not string building)
    std::cout << "Hello " << 1 << 2 << '\\n';  // Output: Hello 12
    
    // Pattern 4: C++20 std::format (recommended for complex formatting)
    #if __cplusplus >= 202002L
    #include <format>
    std::string result4 = std::format("Hello {} {}", 1, 2);
    std::cout << result4 << '\\n';  // "Hello 1 2"
    #endif
    
    return 0;
}
`} />

### 📊 Expression Behavior Comparison: Java vs C++

| Expression | Java Result | C++ Equivalent | C++ Notes |
|------------|-------------|---------------|-----------|
| `"Hello" + " World"` | `"Hello World"` | `"Hello" + std::string(" World")` | ✅ Both work |
| `"Age: " + 25` | `"Age: 25"` | `"Age: " + std::to_string(25)` | ❌ Java auto-converts; C++ requires explicit |
| `1 + 2 + " Hello"` | `"3 Hello"` | `std::to_string(1+2) + " Hello"` | ✅ Same logic, different syntax |
| `"Hello " + 1 + 2` | `"Hello 12"` | `"Hello " + std::to_string(1) + std::to_string(2)` | ❌ C++ won't concat string+int directly |
| `'A' + 'B'` | `131` (int) | `131` (int) | ✅ Same: char+char → int (ASCII/Unicode math) |
| `"" + 'A' + 'B'` | `"AB"` | `std::string() + 'A' + 'B'` | ✅ Works: std::string + char is defined |

**Memory Trick for C++**:  
*"In C++, `+` is picky — both sides must match. Use `std::to_string`, `<<`, or `std::format` to bridge the gap!"* 🌉
</Aside>

## 🔬 char + char in C++ — Same Trap as Java!

> `char + char` performs **arithmetic addition** (ASCII/Unicode values), **not** string concatenation — identical to Java!

### Why This Happens (Same as Java)

- `char` is a **numeric integral type** in C++ (typically 1 byte, ASCII/execution charset)
- Per usual arithmetic conversions: `char + char → int`
- Result is the **sum of ASCII/Unicode code points**, not a concatenated string

<Code lang="cpp" title="char arithmetic vs string concatenation in C++" code={`
#include <iostream>
#include <string>

int main() {
    char a = 'A', b = 'B';
    
    // ❌ Trap: char + char = int (ASCII addition)
    std::cout << (a + b) << '\\n';           // 131 (65 + 66) — NOT "AB"!
    std::cout << static_cast<char>(a + b) << '\\n';  // 'ƃ' — Unicode 131
    
    // ✅ Fix: Force std::string context for concatenation
    std::cout << std::string() + a + b << '\\n';      // "AB" ✅
    std::cout << std::string(1, a) + std::string(1, b) << '\\n';  // "AB" ✅
    
    // ✅ Alternative: Stream insertion (simplest for output)
    std::cout << a << b << '\\n';  // Output: AB (no + needed!)
    
    // ✅ C++20: std::format for clean formatting
    #if __cplusplus >= 202002L
    #include <format>
    std::cout << std::format("{}{}", a, b) << '\\n';  // "AB"
    #endif
    
    return 0;
}
`} />

### 📊 char Operation Reference — C++

| Expression | Type Promotion | Result | Explanation |
|------------|---------------|--------|-------------|
| `'A' + 'B'` | `char + char → int` | `131` | ASCII: 65 + 66 |
| `'a' + 1` | `char + int → int` | `98` | 'a'=97, so 97+1=98 ('b') |
| `'a' + 1.0` | `char + double → double` | `98.0` | Promoted to double |
| `std::string() + 'A' + 'B'` | `std::string + char → std::string` | `"AB"` | std::string + char is defined |
| `"" + 'A' + 'B'` | ❌ Error | — | `""` is `const char[1]`, not `std::string` |

<Aside type="caution">
**⚠️ C++ Gotcha**: `"" + 'A'` doesn't work because `""` is `const char[1]`, not `std::string`.  
✅ **Fix**: Use `std::string()` or `std::string("")` to create an empty `std::string` first.

```cpp
// ❌ Doesn't work:
std::string s = "" + 'A';  // Error: no operator+ for const char* + char

// ✅ Works:
std::string s = std::string() + 'A';  // "A"
std::string s2 = std::string("") + 'A';  // "A"
```
</Aside>

<Aside type="tip">
**DSA Connection**: Same as Java — `char - 'a'` gives index 0–25 for lowercase letters!
```cpp
char c = 'd';
int index = c - 'a';  // 100 - 97 = 3 ✅ (ASCII arithmetic)
// Foundation for frequency arrays, sliding window, Trie in C++
```
</Aside>

## 🧩 DSA & Practical Patterns — C++ Edition

<CardGrid>
  <Card title="Pattern: Building Output Strings — Performance Matters" icon="rocket">
    For simple cases, `std::to_string` + `+` is readable:
    ```cpp
    std::string name = "Alice";
    int age = 30;
    std::string msg = name + " is " + std::to_string(age) + " years old";
    // "Alice is 30 years old" ✅
    ```
    
    **But**: For loops or many concatenations, use `reserve()` + `+=` or `std::ostringstream`:
    ```cpp
    // ❌ Inefficient: repeated reallocations
    std::string result;
    for (int i = 0; i < n; ++i) {
        result += std::to_string(i) + ",";  // O(n²) if no reserve!
    }
    
    // ✅ Efficient: pre-allocate with reserve()
    std::string result;
    result.reserve(n * 4);  // Estimate: 4 chars per number + comma
    for (int i = 0; i < n; ++i) {
        result += std::to_string(i) + ",";  // Now O(n)
    }
    
    // ✅ Alternative: std::ostringstream (flexible, no manual reserve)
    #include <sstream>
    std::ostringstream oss;
    for (int i = 0; i < n; ++i) {
        oss << i << ",";
    }
    std::string result = oss.str();
    ```
  </Card>
  
  <Card title="Pattern: Debugging Expressions — Clarity Over Cleverness" icon="shield">
    When building complex strings, break into steps or use `std::format`:
    ```cpp
    // ❌ Hard to read (and won't compile without to_string!):
    // std::string s = "Result: " + a + b * c + d;  // Error!
    
    // ✅ Clear and intentional:
    int product = b * c;
    int sum = a + product + d;
    std::string s = "Result: " + std::to_string(sum);
    
    // ✅ Modern C++20: std::format is self-documenting
    #if __cplusplus >= 202002L
    std::string s = std::format("Result: {}", a + b * c + d);
    #endif
    ```
  </Card>

  <Card title="Pattern: Type-Safe Formatting with std::format (C++20)" icon="backspace">
    Prefer `std::format()` for complex, locale-aware output:
    ```cpp
    #include <format>
    
    // ✅ Clear, type-safe, extensible:
    std::string msg = std::format("User: {}, Score: {}/{} ({:.1%})", 
                                  name, score, max, static_cast<double>(score)/max);
    // → "User: Alice, Score: 85/100 (85.0%)"
    
    // ✅ Named arguments (C++20):
    auto msg2 = std::format("Hello {name}, you have {count} messages", 
                           std::format::arg("name", "Bob"), 
                           std::format::arg("count", 5));
    ```
    **Fallback for pre-C++20**: `std::ostringstream` or third-party `{fmt}` library.
  </Card>

    ```cpp
    std::string build_csv(const std::vector<int>& values) {
        std::string result;
        // Estimate capacity: each int up to 10 digits + comma
        result.reserve(values.size() * 11);  
        
        for (size_t i = 0; i < values.size(); ++i) {
            result += std::to_string(values[i]);
            if (i + 1 < values.size()) result += ',';
        }
        return result;  // RVO/NRVO optimizes return
    }
    ```

## 🔬 Advanced: String Concatenation Performance Deep Dive

### 📊 `std::string` Concatenation Costs

<Code lang="cpp" title="Understanding reallocations" code={`
#include <string>
#include <iostream>

int main() {
    std::string s;
    
    // Without reserve(): each += may reallocate if capacity exceeded
    for (int i = 0; i < 1000; ++i) {
        s += 'x';  // May reallocate ~log₂(1000) ≈ 10 times
    }
    
    // With reserve(): single allocation, O(n) total
    std::string t;
    t.reserve(1000);  // Pre-allocate exact capacity
    for (int i = 0; i < 1000; ++i) {
        t += 'x';  // No reallocations — O(n) guaranteed
    }
    
    // ✅ Modern idiom: use append with iterator range for bulk add
    std::string bulk;
    bulk.append(1000, 'x');  // Single allocation, fill with 'x'
    
    return 0;
}
`} />

### 🆚 Concatenation Methods Performance Comparison

| Method | C++ Version | Speed | Readability | Best For |
|--------|-------------|-------|-------------|----------|
| `s += std::to_string(x)` | C++11 | ⚡ Fast (with `reserve()`) | ✅ Good | Simple cases, known size |
| `std::ostringstream` | C++98 | 🐌 Slower (stream overhead) | ✅ Good | Complex formatting, pre-C++20 |
| `std::format()` | C++20 | ⚡ Fast (compile-time format) | ✅✅ Excellent | Modern code, type-safe formatting |
| `s.append()` + iterators | C++11 | ⚡⚡ Fastest (bulk operations) | ⚠️ Verbose | High-performance bulk building |
| `{fmt}` library | Any | ⚡ Fast | ✅✅ Excellent | Pre-C++20 projects needing `std::format`-like API |

<Aside type="tip">
**Pro Tip**: For performance-critical string building:
1. ✅ Use `reserve()` if you know/approximate final size
2. ✅ Prefer `append(count, char)` or `append(iter, iter)` for bulk adds
3. ✅ Use `std::format` (C++20) or `{fmt}` for complex formatting — compiler optimizes format strings
4. ❌ Avoid repeated `s = s + "x"` — creates temporary, less efficient than `s += "x"`
</Aside>

## 💣 Interview Traps — C++ Specific

**🪤 Trap 1 — `std::string + int` Doesn't Work**

```cpp
// ❌ Compile Error:
std::string s = "Count: " + 42;  // Error: no operator+ matches

// ✅ Fixes:
std::string s1 = "Count: " + std::to_string(42);  // C++11
std::ostringstream oss; oss << "Count: " << 42; std::string s2 = oss.str();  // Any C++
#if __cplusplus >= 202002L
std::string s3 = std::format("Count: {}", 42);  // C++20 (best)
#endif
```

**🪤 Trap 2 — `"" + 'A'` Fails (Literal Isn't std::string)**

```cpp
// ❌ Compile Error:
std::string s = "" + 'A';  // Error: no operator+ for const char* + char

// ✅ Fixes:
std::string s1 = std::string() + 'A';  // Empty std::string first
std::string s2 = std::string("") + 'A';  // Explicit std::string from literal
std::string s3; s3 += 'A';  // Start with empty string, then append
```

---

**🪤 Trap 3 — char + char = int, Not String**

```cpp
char a = '1', b = '2';
std::cout << (a + b) << '\\n';  // 99 (49 + 50 in ASCII), NOT "12"!

// ✅ To concatenate chars as string:
std::cout << std::string() + a + b << '\\n';  // "12"
// Or simpler for output:
std::cout << a << b << '\\n';  // Output: 12 (stream insertion, no +)
```

---

**🪤 Trap 4 — nullptr Handling Differs from Java**

```cpp
// Java: "Value: " + null → "Value: null" (String.valueOf handles it)

// C++: No automatic conversion!
const char* p = nullptr;

// ❌ Won't compile:
// std::string s = "Value: " + p;  // Error: no operator+

// ✅ Stream insertion handles it (implementation-defined output):
std::cout << "Value: " << p << '\\n';  // "Value: (nil)" or "Value: 0"

// ✅ Safe manual check:
std::string safe = "Value: " + std::string(p ? p : "null");
```

---

**🪤 Trap 5 — std::string Is Mutable (Unlike Java String)**

```cpp
std::string s = "Hello";
s[0] = 'h';  // ✅ Modifies in place: "hello"

// Java equivalent would require StringBuilder:
// StringBuilder sb = new StringBuilder("Hello");
// sb.setCharAt(0, 'h');  // Java String itself is immutable

// ⚠️ C++ gotcha: modifying via [] doesn't check bounds!
std::string t = "Hi";
// t[10] = 'x';  // 💥 Undefined Behavior! (no bounds check)

// ✅ Safe access: use .at() for bounds-checked access
try {
    t.at(10) = 'x';  // Throws std::out_of_range
} catch (const std::out_of_range& e) {
    // Handle error
}
```

97        ← '0'=48, '1'=49, 48+49=97
01        ← String concat via std::string()
5 = 23    ← Correct C++ translation of Java expression
Value: (nil)  ← or "Value: 0" (implementation-defined)
hi        ← std::string is mutable
*/
`} />

<Aside type="caution">
**🔥 Final Warning**: String concatenation bugs in C++ are **compile-time errors**, not runtime surprises (unlike Java's subtle logic bugs).  
✅ **Always**:  
- Use `std::to_string()` or `std::format()` for primitives  
- Start with `std::string()` (not `""`) when concatenating chars  
- Use `reserve()` for performance in loops  
- Prefer `std::format` (C++20) for complex formatting — it's type-safe and compiler-optimized  
- Remember: `std::string` is mutable — great for building, but watch bounds with `[]`
</Aside>

## 🔷 1. Compile-Time Literal Concatenation

Adjacent string literals are **merged by the compiler** — zero runtime cost.

```cpp
const char* s = "Hello" ", " "World";   // → "Hello, World"
const char* s = "Line1\n"
                "Line2\n"
                "Line3\n";              // merged at compile time

// Different prefix types CANNOT be concatenated
const char* s = "hello" L"world";      // ❌ compile error
const char* s = u8"hello" "world";     // ❌ compile error (C++20)
const char* s = u8"hello" u8"world";   // ✅
```

```
Preprocessor sees: "Hello" ", " "World"
Compiler merges:   "Hello, World\0"
Binary has:        one string in .rodata
Zero runtime cost — no allocation, no copying
```

## 🔷 2. C-Style — `strcat` / `strncat`

```cpp
#include <cstring>

char dest[50] = "Hello";
strcat(dest, ", World");    // dest = "Hello, World"
```

### `strcat` — Internals

```
strcat(dest, src):
  1. Walk dest until '\0' — O(n) scan
  2. Copy src bytes after the '\0' — O(m) copy
  3. Append new '\0'
  Total: O(n + m) every call

Repeated calls:
  strcat(s, a)   → walks 0 chars, copies a
  strcat(s, b)   → walks len(a) chars, copies b
  strcat(s, c)   → walks len(a+b) chars, copies c
  → O(n²) behavior for n concatenations
```

```cpp
// ❌ Buffer overflow — classic CVE pattern
char buf[10] = "Hello";
strcat(buf, " World!!!");   // 14 chars + \0 into 10-byte buffer
                             // writes beyond buf → UB, stack corruption
                             // no length check — just keeps writing

// ❌ Still dangerous
strncat(buf, " World!!!", 5); // limits APPENDED bytes, not total size
                               // must manually compute remaining space
char buf[10] = "Hello";       // already 5 chars used
strncat(buf, " World", 10-strlen(buf)-1);  // ✅ correct usage
```

### `strcat` vs `strncat`

| | `strcat` | `strncat` |
|---|---|---|
| Signature | `char* strcat(char* dst, const char* src)` | `char* strncat(char* dst, const char* src, size_t n)` |
| Length limit | ❌ none | ✅ limits chars copied from src |
| Buffer overflow safe | ❌ | ❌ (still needs manual size math) |
| Null terminates | ✅ | ✅ |
| Use in new code | ❌ never | ❌ still error-prone |

> 🔴 **Never use `strcat` in production.** It is the source of countless buffer overflow CVEs. Use `std::string` or `snprintf`.

## 🔷 3. `std::string` — The Primary Tool

### `operator+` — Creates New String

```cpp
std::string a = "Hello";
std::string b = ", World";
std::string c = a + b;        // new allocation, copies both
```

```
a + b under the hood:
  1. Allocate new buffer: len(a) + len(b) + 1 bytes
  2. Copy a into buffer
  3. Copy b after a
  4. Return new std::string (owns the buffer)

Cost: 1 heap allocation + 2 copies
```

### Chained `+` — The Hidden Cost

```cpp
std::string result = a + b + c + d + e;
```

```
Evaluation (left-to-right):
  temp1 = a + b        → 1 alloc, copy a, copy b
  temp2 = temp1 + c    → 1 alloc, copy temp1, copy c
  temp3 = temp2 + d    → 1 alloc, copy temp2, copy d
  result= temp3 + e    → 1 alloc, copy temp3, copy e

Total: 4 allocations, O(n²) copies for n strings
temp1, temp2, temp3 are created and destroyed immediately
```

> 🔴 **Chained `operator+` is O(n²) for n strings.** Same problem as `strcat`. For building strings from many pieces, use `+=` with `reserve` or `ostringstream`.

### `operator+=` — In-Place Append

```cpp
std::string result;
result += "Hello";
result += ", ";
result += "World";
```

```
result += s under the hood:
  if (result.capacity() >= result.size() + s.size())
      memcpy(result.end(), s.data(), s.size())  // no allocation!
  else
      reallocate(result.size() + s.size())      // 1 allocation
      copy existing + s
```

```
Amortized analysis (like std::vector growth):
capacity doubles on realloc → O(n) total copies for n appends
vs operator+ chain → O(n²) total copies
```

### `append()` — More Control

```cpp
std::string s = "Hello";

s.append(", World");              // append C-string
s.append(str);                    // append std::string
s.append(str, 2, 5);             // append 5 chars from position 2
s.append(3, '!');                 // append "!!!"
s.append(vec.begin(), vec.end()); // append from iterator range
```

### `push_back` — Single Character

```cpp
std::string s = "Hell";
s.push_back('o');   // → "Hello"
```

## 🔬 `std::string` Internals — SSO

```
Small String Optimization (SSO):

std::string on 64-bit (GCC libstdc++):
┌──────────────────────────────────┐
│  pointer to heap buffer (8 bytes)│  ← used for LONG strings
│  size              (8 bytes)     │
│  capacity          (8 bytes)     │
└──────────────────────────────────┘
24 bytes total

SSO: for strings ≤ 15 chars (GCC) / ≤ 22 chars (MSVC):
┌──────────────────────────────────┐
│  inline buffer[15] (15 bytes)    │  ← string stored HERE, no heap alloc
│  size              (1 byte)      │
│  capacity flag     (8 bytes)     │
└──────────────────────────────────┘

"Hello" → stored in inline buffer → zero heap allocation
"Hello, World!!" → 15 chars → still inline
"Hello, World!!!" → 16 chars → moves to heap
```

```cpp
// SSO means short string concatenation is CHEAP
std::string a = "Hi";      // no heap alloc
std::string b = " there";  // no heap alloc
std::string c = a + b;     // "Hi there" = 8 chars → no heap alloc
```

## 🔷 4. `reserve()` + `+=` — Production Pattern

```cpp
// ❌ Naive — multiple reallocs
std::string result;
for (const auto& s : words) {
    result += s;            // may reallocate every iteration
    result += " ";
}

// ✅ Pre-allocate — zero reallocs
std::string result;
size_t total = words.size(); // space for spaces
for (const auto& s : words)
    total += s.size();
result.reserve(total);       // one allocation upfront

for (const auto& s : words) {
    result += s;
    result += ' ';
}
```

```
Without reserve:  potentially log(n) reallocations, each copies everything
With reserve:     0 reallocations — pure memcpy appends
Difference:       10× faster for large string building
```

## 🔷 7. `snprintf` — C-Style Safe Formatting

```cpp
char buf[256];
int id = 42;
const char* name = "Alice";

int written = snprintf(buf, sizeof(buf), "User %d (%s)", id, name);
// written = number of chars that WOULD be written (excluding \0)

if (written >= (int)sizeof(buf)) {
    // output was truncated — handle this
}
```

> 🔑 `snprintf` always null-terminates (unlike `sprintf`). The return value tells you if truncation occurred — **always check it**.

## 🏭 Real-World Production Scenario

**Log aggregation service — 10M logs/sec:**

```cpp
// ❌ What was in prod — O(n²) string building
std::string build_log(const Event& e) {
    return "[" + e.timestamp + "] " +     // alloc 1
           e.level + ": " +               // alloc 2
           e.service + " - " +            // alloc 3
           e.message + " {" +             // alloc 4
           e.trace_id + "}";              // alloc 5
    // 5 heap allocations per log line

}

// ✅ Fixed — 1 allocation, measured 4× faster
std::string build_log(const Event& e) {
    std::string result;
    result.reserve(128);                   // pre-allocate typical size
    result += '[';
    result += e.timestamp;
    result += "] ";
    result += e.level;
    result += ": ";
    result += e.service;
    result += " - ";
    result += e.message;
    result += " {";
    result += e.trace_id;
    result += '}';
    return result;                         // NRVO — no copy on return
}

// ✅ C++20 — cleanest, similar performance
std::string build_log(const Event& e) {
    return std::format("[{}] {}: {} - {} {{{}}}",
        e.timestamp, e.level, e.service, e.message, e.trace_id);
}
```

## 🎯 Interview Traps

**Trap 1:**
```cpp
std::string s = "Hello";
s = s + s;    // safe?
```
> ✅ Safe. `s + s` creates a temporary new string (reading from `s` twice is fine — no aliasing issue because `+` creates a new object). `s` is then assigned the temporary. But `s += s` is also defined — the standard explicitly makes self-assignment safe for `+=`.

**Trap 2:**
```cpp
const char* a = "Hello";
const char* b = " World";
const char* c = a + b;    // compiles?
```
> ❌ **Compile error.** `a + b` is pointer arithmetic — adds two pointers, which is illegal. `a + 5` would be valid (pointer + integer). You cannot concatenate C-style strings with `+`.

**Trap 3:**
```cpp
std::string result;
for (int i = 0; i < 1000; i++)
    result = result + std::to_string(i);
// vs
for (int i = 0; i < 1000; i++)
    result += std::to_string(i);
```
> First loop: O(n²) — each `+` creates and copies a growing string. Second: O(n) amortized. At n=1000 with average length 3 chars: first = ~1.5M copy operations, second = ~3K copy operations.

**Trap 4:**
```cpp
std::string_view sv = "Hello";
sv + " World";    // valid?
```
> ❌ **Compile error.** `std::string_view` has no `operator+` — it's a non-owning view. It cannot own a new concatenated string. Must convert to `std::string` first: `std::string(sv) + " World"`.

**Trap 5:**
```cpp
char buf[5] = "Hi";
strncat(buf, "!!!!", 4);    // safe?
```
> ❌ **Buffer overflow.** `buf` has 5 bytes, already contains `"Hi\0"` (3 bytes used). `strncat` appends up to 4 chars + null → needs 3 + 4 + 1 = 8 bytes. `buf` only has 5. `strncat`'s `n` parameter limits chars from `src`, not total buffer size.
