## 💻 Command Line Arguments in C++ — Complete Guide

> **Command Line Arguments** are values passed to the program **at runtime** from the terminal — before `main()` starts executing.
> 
> ⚠️ **Critical Difference from Java**: C++ uses **`argc`/`argv`** (count + pointer array of C-strings), **NOT** `String[]`. Everything arrives as `char*` (null-terminated C-strings), not `std::string`!

```bash
$ ./server --host=localhost --port=8080 -v config.json
   │         │               │           │   │
   │         │               │           │   └── positional arg
   │         │               │           └── short flag
   │         │               └── long option with value
   │         └── long flag
   └── argv[0] — program name
```

```cpp
// Standard entry point with arguments:
int main(int argc, char* argv[]) {
    // argc = argument COUNT (including program name)
    // argv = array of C-style string POINTERS (null-terminated char*)
    return 0;
}

int main(int argc, char*  argv[])   // array of char pointers
int main(int argc, char** argv)     // pointer to char pointer — identical
```

## 📌 How It Works — Memory Layout

```text
Terminal command:
$ ./program alpha beta gamma

Memory layout (simplified):
OS sets up on the stack before _start:

Stack (high → low):
┌─────────────────────┐
│      argc = 4       │
├─────────────────────┤
│    argv (pointer) ──┼──►┌──────────┐
│                     │   │ argv[0] ─┼──► "./program\0"
│                     │   ├──────────┤
│                     │   │ argv[1] ─┼──► "alpha\0"
│                     │   ├──────────┤
│                     │   │ argv[2] ─┼──► "beta\0"
│                     │   ├──────────┤
│                     │   │ argv[3] ─┼──► "gamma\0"
│                     │   ├──────────┤
│                     │   │ argv[4] ─┼──► nullptr  ← guaranteed sentinel
│                     │   └──────────┘
└─────────────────────┘

Strings stored in:
┌──────────────────────────────────────────┐
│ . / p r o g r a m \0 a l p h a \0 ...   │  ← process memory (read-write)
└──────────────────────────────────────────┘
  Unlike string literals — argv strings ARE modifiable
```

<Code lang="cpp" title="Visualizing argc/argv reception" code={`
#include <iostream>

int main(int argc, char* argv[]) {
    // Runtime system creates argv BEFORE main() runs
    // argv is array of char* pointers — you CAN modify pointers, but strings are typically const
    
    std::cout << "Program: " << argv[0] << '\\n';  // Always present if argc >= 1
    std::cout << "Arg count (excluding program): " << argc - 1 << '\\n';
    
    // argv itself can be modified (reassign pointers), but don't — it's confusing!
    // argv[1] = const_cast<char*>("Modified");  // ⚠️ Dangerous: modifies read-only memory!
    
    return 0;
}
`} />

<Aside type="note">
**Key Rule**: Arguments are **space-separated** by default (same as Java). Use **quotes** to pass values containing spaces as a single argument. Shell handles quoting — C++ just receives the parsed result.
</Aside>

## 🔬 In-Depth — How Arguments Flow (C++ vs Java)

```text
You type in terminal:
./myapp Hello 99
        ↓ Shell parses & passes to runtime
int argc = 3;  // "./myapp", "Hello", "99"
char* argv[] = {"./myapp", "Hello", "99", nullptr};
        ↓ passed directly to
int main(int argc, char* argv[])

⚠️ Everything is received as C-STRING (char*)
   even if you pass 99 → it's "99" (char*) not int 99!
   → Must convert explicitly: std::stoi, std::from_chars, etc.
```

### 🆚 Java vs C++ Argument Reception

| Feature | Java `String[] args` | C++ `int argc, char* argv[]` |
|---------|---------------------|------------------------------|
| **Type** | Array of `String` objects | Array of `char*` pointers |
| **Program Name** | ❌ Not included | ✅ `argv[0]` = program path |
| **Count** | `args.length` (runtime property) | `argc` (explicit parameter) |
| **Null Sentinel** | ❌ None | ✅ `argv[argc] == nullptr` |
| **String Mutability** | Mutable `String` (but immutable content) | `char*` points to typically **read-only** memory |
| **Empty Args** | `args.length == 0`, `args != null` | `argc == 1` (only program name), `argv[0]` valid |

| Rule | Detail |
|---|---|
| `argc >= 1` | always — `argv[0]` always exists |
| `argv[0]` | program name, or `""` if not available |
| `argv[argc]` | guaranteed `nullptr` |
| `argv[i]` for `0 <= i < argc` | valid null-terminated C-string |
| Strings are modifiable | `argv[i][j] = 'x'` is **legal** (unlike string literals) |
| Order preserved | `argv[1]` = first arg, `argv[2]` = second, etc. |

<Aside type="danger">
**Critical Safety Note**: `argv[i]` points to **read-only memory** in most environments. Modifying `argv[1][0] = 'X'` → **undefined behavior** (may crash).  
✅ **Rule**: Treat `argv` strings as `const char*` — read, don't write.
</Aside>

## 💻 Basic Example — Iterating Arguments

<Code lang="cpp" title="Classic C-style iteration" code={`
#include <iostream>

int main(int argc, char* argv[]) {
    std::cout << "Program: " << argv[0] << '\\n';
    std::cout << "Total user args: " << argc - 1 << "\\n\\n";
    
    // Classic loop — start at 1 to skip program name
    for (int i = 1; i < argc; ++i) {
        std::cout << "argv[" << i << "] = " << argv[i] << '\\n';
    }
    
    return 0;
}
`} />

<Code lang="cpp" title="Modern C++: Convert to std::vector<std::string>" code={`
#include <iostream>
#include <vector>
#include <string>

int main(int argc, char* argv[]) {
    // Convert C-style args to modern C++ container
    // Skip argv[0] (program name) if desired:
    std::vector<std::string> args(argv + 1, argv + argc);
    
    // Now use range-based for, algorithms, etc.
    for (size_t i = 0; i < args.size(); ++i) {
        std::cout << "Arg " << i << ": " << args[i] << '\\n';
    }
    
    // Or enhanced for-loop (loses index):
    for (const auto& arg : args) {
        std::cout << "  • " << arg << '\\n';
    }
    
    return 0;
}
`} />

<Code lang="cpp" title="C++20: Use std::span for zero-copy view" code={`
#include <iostream>
#include <span>  // C++20

int main(int argc, char* argv[]) {
    // Non-owning view over argv — zero allocation!
    std::span<char* const> args(argv, argc);  // const pointers to char
    
    for (size_t i = 0; i < args.size(); ++i) {
        std::cout << "args[" << i << "] = " << args[i] << '\\n';
    }
    
    // Works with arrays, vectors, initializer_list too!
    return 0;
}
`} />

## 🔄 Type Conversion — Always `char*` First

All command line arguments arrive as **C-strings (`char*`)**. Convert explicitly to other types.

<Code lang="cpp" title="Parsing different types — modern C++17/20" code={`
#include <iostream>
#include <string>
#include <charconv>  // C++17: std::from_chars (fast, no exceptions)

int main(int argc, char* argv[]) {
    if (argc < 5) {
        std::cerr << "Usage: ./app <name> <age> <salary> <flag>\\n";
        return 1;
    }

    // argv[1] = name (keep as string)
    std::string name = argv[1];  // ✅ Safe conversion
    
    // argv[2] = age (parse int)
    int age{};
    auto [ptr, ec] = std::from_chars(argv[2], argv[2] + std::strlen(argv[2]), age);
    if (ec != std::errc{}) {
        std::cerr << "Invalid age: " << argv[2] << '\\n';
        return 1;
    }
    
    // argv[3] = salary (parse double)
    double salary = std::stod(argv[3]);  // ✅ Throws on error — wrap in try-catch
    
    // argv[4] = flag (parse bool)
    bool flag = (std::string(argv[4]) == "true" || argv[4] == "1"s);
    
    std::cout << name << ", age " << age 
              << ", salary $" << salary 
              << ", active: " << std::boolalpha << flag << '\\n';
    
    return 0;
}
`} />

### 🔬 Conversion Methods Comparison

| Method | C++ Version | Throws? | Speed | Best For |
|--------|-------------|---------|-------|----------|
| `std::stoi` / `std::stod` | C++11 | ✅ `std::invalid_argument` | Medium | Simple scripts, clarity |
| `std::from_chars` | C++17 | ❌ Returns `std::errc` | ⚡ Fastest | Performance-critical, no exceptions |
| `std::stringstream` | C++98 | ❌ (failbit) | Slow | Complex parsing, locale-aware |
| `atoi` / `atof` | C++98 (C) | ❌ Returns 0 on error | Fast | Legacy code (⚠️ unsafe!) |

<Aside type="danger">
⚠️ **Common Crash**: Using `atoi` on invalid input returns `0` silently — no error indication!
```cpp
int age = atoi("abc");  // Returns 0 — is age really 0 or invalid? ❌ Ambiguous!
// ✅ Prefer std::from_chars or std::stoi with try-catch
```
</Aside>

<Code lang="cpp" title="Safe parsing with std::from_chars (C++17)" code={`
#include <charconv>
#include <cstring>

bool parseInt(const char* str, int& out) {
    auto [ptr, ec] = std::from_chars(str, str + std::strlen(str), out);
    return ec == std::errc{};  // true if success
}

int main(int argc, char* argv[]) {
    if (argc < 2) return 1;
    
    int value;
    if (!parseInt(argv[1], value)) {
        std::cerr << "Failed to parse integer: " << argv[1] << '\\n';
        return 1;
    }
    
    std::cout << "Parsed: " << value << '\\n';
    return 0;
}
`} />

## ⚠️ Common Mistakes — C++ Edition

<CardGrid>
  <Card title="Mistake 1 — Accessing argv[1] without checking argc" icon="error">
```cpp
    int main(int argc, char* argv[]) {
        std::cout << argv[1];  // 💥 Undefined Behavior if argc < 2!
        // If user runs: ./myapp (no args) → argc=1 → argv[1] is out of bounds
    }
    
    // ✅ Fix — always check argc first
    if (argc > 1) {
        std::cout << argv[1];
    } else {
        std::cerr << "Error: expected at least 1 argument\\n";
        return 1;
    }
```
  </Card>
  
  <Card title="Mistake 2 — Comparing C-strings with ==" icon="error">
```cpp
    if (argv[1] == "hello") {  // ❌ Compares POINTERS, not content!
        // Only true if argv[1] points to same address as literal "hello"
    }
    
    // ✅ Correct — compare content:
    if (std::string(argv[1]) == "hello")  // Convert to std::string
    // Or C-style:
    if (std::strcmp(argv[1], "hello") == 0)  // Use strcmp from <cstring>
```
  </Card>
  
  <Card title="Mistake 3 — Modifying argv strings" icon="error">
```cpp
    argv[1][0] = 'X';  // 💥 Undefined Behavior!
    // argv[1] typically points to read-only memory (string literal area)
    // May crash with segmentation fault
    
    // ✅ Safe: copy to mutable buffer if you need to modify
    std::string mutableArg = argv[1];
    mutableArg[0] = 'X';  // ✅ Now safe
```
  </Card>

  <Card title="Mistake 4 — Assuming argv is null-terminated like Java" icon="error">
```cpp
    // Java: args is never null, empty array if no args
    // C++: argc tells you count — argv[argc] is nullptr sentinel
    
    // ❌ Dangerous loop:
    for (int i = 0; argv[i] != nullptr; ++i) {  // Works, but...
        // What if argc is wrong? Trust argc, not sentinel, for safety
    }
    
    // ✅ Preferred: use argc for bounds
    for (int i = 0; i < argc; ++i) {
        // Safe: argv[i] guaranteed valid for i < argc
    }
```
  </Card>
</CardGrid>

## 🎯 Interview Cheat Sheet — C++ CLI

<CardGrid>
  <Card title="Q: What is the type of command line arguments in C++?" icon="information">
    **`char* argv[]`** (or `char** argv`) — array of pointers to null-terminated C-strings.  
    Not `std::string`, not `String[]` — you must convert explicitly: `std::stoi`, `std::from_chars`, etc.  
  </Card>
  
  <Card title="Q: What if no arguments passed — is argv null?" icon="approve-check">
    **NO ❌** — `argv` is **never null** in hosted C++.  
    `argc` will be **at least 1** (program name at `argv[0]`).  
```cpp
    // ./myapp (no user args)
    // Inside main: argc == 1, argv[0] = "./myapp", argv[1] = nullptr
```
  </Card>

  <Card title="Q: Can we pass spaces in a single argument?" icon="approve-check">
    **YES ✅** — shell handles quoting (same as Java):
```text
    ./myapp "Hello World"   → argv[1] = "Hello World" ✅
    ./myapp 'Path/To/File'  → argv[1] = "Path/To/File" ✅
    // Quotes are removed by shell — C++ receives the parsed string
```
  </Card>

  <Card title="Q: What is argc when no user args passed?" icon="information">
    **`1`** — because `argv[0]` (program name) is always present in hosted C++.  
```cpp
    // ./myapp
    // argc = 1, argv[0] = "./myapp", argv[1] = nullptr
    std::cout << argc;  // Prints: 1
```
  </Card>

  <Card title="Q: Can we change argv inside main?" icon="caution">
    **Technically YES, but DANGEROUS** — `argv[i]` points to read-only memory.
```cpp
    argv[1] = const_cast<char*>("new");  // ⚠️ Compiles, but may crash at runtime
    // ✅ Safe: copy to std::string first
    std::string arg = argv[1];
    // Now modify arg freely
```
  </Card>

  <Card title="Q: Can we pass null as an argument?" icon="error">
    **NO ❌** — you cannot pass literal `nullptr` from terminal.  
    However, you can pass the **string** `"null"`:
```text
    ./myapp null
    // argv[1] = "null" (4-character C-string), not C++ nullptr
```
  </Card>
</CardGrid>

<CardGrid>
  <Card title="Pattern: Passing test input via CLI" icon="rocket">
    Quickly test algorithms with different inputs without modifying code:
```cpp
    // ./solution 5 3 → n=5, k=3

        if (argc < 3) {

        std::cout << solve(n, k) << '\\n';
        return 0;
    }
```
  </Card>
  
  <Card title="Pattern: Passing array elements" icon="shield">
    Convert CLI args directly into vectors for algorithm testing:
```cpp
    // ./solution 1 2 3 4 5
    int main(int argc, char* argv[]) {
        std::vector<int> arr;
        arr.reserve(argc - 1);  // Skip program name
        for (int i = 1; i < argc; ++i) {
            arr.push_back(std::stoi(argv[i]));  // Parse each arg
        }
        // arr = {1, 2, 3, 4, 5} ✅
        std::cout << maxSubarraySum(arr) << '\\n';
        return 0;
    }
```
  </Card>

  <Card title="Pattern: Flag-based test selection with std::optional" icon="backspace">
    Use C++17 `std::optional` for clean optional argument handling:
```cpp
    #include <optional>
    #include <string_view>
    
    std::optional<int> findIntArg(int argc, char* argv[], std::string_view flag) {
        for (int i = 1; i < argc; ++i) {
            std::string_view arg = argv[i];
            if (arg.starts_with(flag) && arg[flag.size()] == '=') {
                return std::stoi(std::string(arg.substr(flag.size() + 1)));
            }
        }
        return std::nullopt;  // Flag not found
    }
    
    int main(int argc, char* argv[]) {
        int testId = findIntArg(argc, argv, "--test").value_or(1);  // Default to 1
        bool verbose = findIntArg(argc, argv, "--verbose").has_value();
        runTest(testId, verbose);
        return 0;
    }
    // ./solution --test=3 --verbose  → runs test 3 with verbose output
```
  </Card>
</CardGrid>

## 🏢 Real-Life SDE Usage — Modern C++

<CardGrid>
  <Card title="Pattern: Environment switching via args" icon="shield">
    Simple pattern for deploying to different environments:

```cpp
    int main(int argc, char* argv[]) {
        std::string_view env = (argc > 1) ? argv[1] : "dev";

        }
        return 0;

    // ./app       → defaults to dev (safe fallback)
```
  </Card>

  <Card title="Pattern: File processing CLI tool" icon="information">
    Real-world pattern for batch operations:
```cpp
    #include <filesystem>  // C++17
    namespace fs = std::filesystem;
    
    int main(int argc, char* argv[]) {
        if (argc < 3) {
            std::cout << "Usage: ./importer <input.csv> <output.json> [--dry-run]\\n";
            return 1;
        }
        
        fs::path inputFile = argv[1];
        fs::path outputFile = argv[2];
        bool dryRun = false;
        
        // Check for optional flags
        for (int i = 3; i < argc; ++i) {
            if (std::string(argv[i]) == "--dry-run") dryRun = true;
        }
        
        if (dryRun) {
            std::cout << "[DRY RUN] Would import " << inputFile << " → " << outputFile << '\\n';
        } else {
            importData(inputFile, outputFile);
        }
        return 0;
    }
    // ./importer data.csv result.json --dry-run
```
  </Card>

  <Card title="Pattern: Using a CLI parsing library (Production)" icon="rocket">
    For complex CLIs, use a library — don't hand-roll:
```cpp
    // CLI11: https://github.com/CLIUtils/CLI11 (header-only, C++11)
    #include <CLI/CLI.hpp>
    
    int main(int argc, char* argv[]) {
        CLI::App app("Data Importer Tool");
        
        std::string input, output = "result.json";
        bool verbose{false};
        
        app.add_option("-i,--input", input, "Input file")->required();
        app.add_option("-o,--output", output, "Output file");
        app.add_flag("-v,--verbose", verbose, "Enable verbose logging");
        
        CLI11_PARSE(app, argc, argv);  // Parses and handles --help automatically
        
        if (verbose) std::cout << "Importing " << input << " → " << output << '\\n';
        importData(input, output);
        return 0;
    }
    // ./importer -i data.csv -o out.json -v
    // ./importer --help  → auto-generated usage!
```
  </Card>
</CardGrid>

<Aside type="caution">
**Production Checklist** for C++ CLI apps:
1. ✅ Always validate `argc` before accessing `argv[i]`
2. ✅ Use `std::from_chars` or try-catch around `std::stoi` for safe parsing
3. ✅ Print usage help when arguments are missing/invalid (or use CLI11)
4. ✅ Exit with non-zero code (`return 1;`) on failure for script integration
5. ✅ Document expected arguments in `--help` output
6. ✅ Treat `argv` strings as read-only — copy to `std::string` before modifying
</Aside>

## 🧭 Quick-Revision Cheat Sheet

```text
✅ STANDARD SIGNATURE:
   int main(int argc, char* argv[])    // Most common
   int main(int argc, char** argv)     // Equivalent pointer syntax
   // argc = count (including program name), argv[argc] = nullptr sentinel

✅ KEY RULES:
   • argv[0] = program name/path (always present if argc >= 1)
   • User args start at argv[1] → argv[argc-1]
   • All args are C-strings (char*) — null-terminated, typically read-only
   • Always check: if (argc > N) before accessing argv[N]

✅ CONVERSION METHODS:
   • std::stoi / std::stod          — C++11, throws on error
   • std::from_chars                — C++17, fastest, no exceptions ✅ Preferred
   • std::stringstream              — C++98, flexible but slow
   • atoi / atof                    — C legacy, unsafe (returns 0 on error) ❌ Avoid

✅ MODERN C++ PATTERNS:
   • Convert to std::vector<std::string> for easy iteration
   • Use std::span<char*> (C++20) for zero-copy views
   • Use std::optional<T> for optional arguments (C++17)
   • Use std::format for type-safe usage messages (C++20)
   • Use CLI11/argparse for complex parsing — don't hand-roll!

⚠️ COMMON TRAPS:
   • argv[1] without checking argc >= 2 → undefined behavior 💥
   • if (argv[1] == "hello") → compares pointers, not content! ❌
   • Modifying argv[i][j] → may write to read-only memory → crash 💥
   • Using atoi on invalid input → silent 0 return → logic bugs ❌
   • Assuming argv can be null → it never is in hosted C++ ❌

🎯 DSA BEST PRACTICES:
   • Enable fast I/O: std::ios::sync_with_stdio(false); std::cin.tie(nullptr);
   • Support both CLI args AND stdin for judge compatibility
   • Use std::from_chars for fast, safe integer parsing in tight loops
   • Return explicit exit codes: 0 = success, 1+ = specific errors
   • For benchmarks, use std::chrono + --bench flag pattern
   • Use std::span to pass argument views to helper functions without copying
```

> 🎯 **Interview Pro Tip**: When asked about command line arguments in C++, always mention:  
> 1. The **`argc`/`argv` memory layout** — count + pointer array of null-terminated C-strings  
> 2. **`argv[0]` = program name** — a key difference from Java's `args`  
> 3. **Type conversion methods** — `std::from_chars` (fast, safe) vs `atoi` (unsafe)  
> 4. **Read-only nature of `argv` strings** — modifying causes undefined behavior  
> 5. **Modern alternatives** — `std::span`, `std::optional`, CLI parsing libraries  
> This demonstrates deep understanding of C++'s systems-programming heritage and modern best practices! 🚀

## 🔁 Iteration Patterns

```cpp
// Pattern 1 — index-based (classic)
for (int i = 0; i < argc; i++) {
    std::cout << argv[i] << "\n";
}

// Pattern 2 — sentinel-based (uses argv[argc] == nullptr)
for (char** p = argv; *p != nullptr; ++p) {
    std::cout << *p << "\n";
}

// Pattern 3 — modern C++ (wrap in vector)
#include <vector>
#include <string>
std::vector<std::string> args(argv, argv + argc);
for (const auto& arg : args) {
    std::cout << arg << "\n";
}

// Pattern 4 — string_view (zero copy, C++17)
#include <string_view>
for (int i = 1; i < argc; i++) {
    std::string_view arg = argv[i];
    // no allocation — just a view into argv memory
}
```

## 🔨 Manual Parsing — Production Pattern

```cpp
#include <string_view>
#include <string>
#include <unordered_map>
#include <vector>
#include <stdexcept>
#include <cstdlib>

struct Config {
    std::string host     = "localhost";
    int         port     = 8080;
    bool        verbose  = false;
    std::vector<std::string> files;
};

Config parse_args(int argc, char* argv[]) {
    Config cfg;

    for (int i = 1; i < argc; i++) {
        std::string_view arg = argv[i];

        // Long options: --key=value
        if (arg.starts_with("--")) {
            auto eq = arg.find('=');

            if (eq != std::string_view::npos) {
                auto key = arg.substr(2, eq - 2);
                auto val = arg.substr(eq + 1);

                if      (key == "host") cfg.host = std::string(val);
                else if (key == "port") cfg.port = std::stoi(std::string(val));
                else throw std::runtime_error("Unknown option: " + std::string(arg));
            }
            else {
                // Long flags: --verbose
                if      (arg == "--verbose") cfg.verbose = true;
                else if (arg == "--")        { ++i; break; } // end of options
                else throw std::runtime_error("Unknown flag: " + std::string(arg));
            }
        }
        // Short options: -p 8080
        else if (arg.starts_with("-") && arg.size() == 2) {
            char flag = arg[1];
            if (flag == 'v') { cfg.verbose = true; }
            else if (flag == 'p') {
                if (++i >= argc)
                    throw std::runtime_error("-p requires a value");
                cfg.port = std::stoi(argv[i]);
            }
            else throw std::runtime_error("Unknown flag: -" + std::string(1, flag));
        }
        // Positional arguments
        else {
            cfg.files.push_back(std::string(arg));
        }
    }
    return cfg;
}

int main(int argc, char* argv[]) {
    try {
        Config cfg = parse_args(argc, argv);
        // use cfg.host, cfg.port, cfg.verbose, cfg.files
    }
    catch (const std::exception& e) {
        std::cerr << "Error: " << e.what() << "\n";
        return EXIT_FAILURE;
    }
}
```

## 🔄 Type Conversion from `argv`

Everything in `argv` is a **C-string**. You must convert:

| Target Type | Function | Header | Trap |
|---|---|---|---|
| `int` | `std::stoi(s)` | `<string>` | throws `std::invalid_argument`, `std::out_of_range` |
| `long` | `std::stol(s)` | `<string>` | same |
| `long long` | `std::stoll(s)` | `<string>` | same |
| `float` | `std::stof(s)` | `<string>` | locale-dependent `.` vs `,` |
| `double` | `std::stod(s)` | `<string>` | same |
| `unsigned long` | `std::stoul(s)` | `<string>` | negative input → wraps silently |
| `bool` | manual | — | `"true"/"false"` or `"1"/"0"` |

```cpp
// Safe conversion with error handling
int parse_port(const char* str) {
    try {
        int port = std::stoi(str);
        if (port < 1 || port > 65535)
            throw std::out_of_range("port out of range");
        return port;
    }
    catch (const std::invalid_argument&) {
        throw std::runtime_error(
            std::string("Invalid port: '") + str + "' is not a number");
    }
    catch (const std::out_of_range&) {
        throw std::runtime_error(
            std::string("Port out of range: ") + str);
    }
}
```

> 🔴 **Never use `atoi()` in production:**
> ```cpp
> atoi("abc")  // → 0  silently (no error indication)
> atoi("99999999999") // → UB on overflow
> std::stoi("abc")   // → throws std::invalid_argument ✅
> ```

## 🌍 Wide Character Arguments — `wmain`

On Windows, the OS uses **UTF-16** natively. `argv` gives you UTF-8/ANSI which may mangle Unicode filenames.

```cpp
int main() {
```

## 🔬 Under the Hood — How argv Reaches `main`

```
OS kernel (execve syscall):
  execve("/path/to/prog", argv_array, envp_array)
       │
       ▼
Kernel writes to new process stack:

Stack layout at process startup:
┌──────────────────────┐  high address
│      envp strings    │  "PATH=...\0HOME=...\0..."
├──────────────────────┤
│      argv strings    │  "./prog\0alpha\0beta\0"
├──────────────────────┤
│    envp[] pointers   │  array of char* to env strings
│    envp[n] = nullptr │
├──────────────────────┤
│    argv[] pointers   │  array of char* to arg strings
│    argv[argc]=nullptr│
├──────────────────────┤
│       argc           │  integer count
└──────────────────────┘  low address  ← rsp here

_start reads these directly off the stack
→ passes argc and argv pointer to __libc_start_main
→ which calls main(argc, argv)
```

```bash
# See the actual execve args on Linux
strace ./program foo bar 2>&1 | head -5
# execve("./program", ["./program", "foo", "bar"], 0x... /* env vars */)
```

## ☣️ Modifying `argv` — Legal but Dangerous

```cpp
int main(int argc, char* argv[]) {
    argv[1][0] = 'X';    // ✅ legal — argv strings are writable
    argv[0] = nullptr;   // ✅ legal — but breaks argv[0] assumption

    // Common use: strip a prefix in-place
    // Instead of allocating new string, modify argv[i] directly
    // "Dangerous" because it mutates the caller's data
}
```

> 🔑 **Process name spoofing** on Linux uses `argv[0]` mutation — tools like `nginx` write to `argv[0]` to change what `ps` shows as the process name.

## 🏭 Real-World Production Scenarios

### Scenario 1 — Wrong port crashes server silently

```cpp
// ❌ Old code in prod
int port = atoi(argv[1]);          // "./server abc" → port = 0
server.listen(port);               // listens on port 0 → random OS port
// Server starts, logs nothing wrong, health check fails mysteriously
```

```cpp
// ✅ Fix
int port = std::stoi(argv[1]);     // throws on "abc"
if (port < 1 || port > 65535)
    throw std::runtime_error("Invalid port");
```

### Scenario 2 — Path injection via argv

```cpp
// ❌ Dangerous — argv used directly in shell command
std::string cmd = "rm -rf " + std::string(argv[1]);
std::system(cmd.c_str());
// ./program "$(malicious_command)"  → arbitrary code execution
```

```cpp
// ✅ Never pass argv directly to system() or exec*
// Always validate and sanitize first
// Use execv() family instead of system()
```

### Scenario 3 — argc check missing

```cpp
// ❌ No bounds check
int main(int argc, char* argv[]) {
    std::string host = argv[1];     // crash if ./program run with no args
    int port = std::stoi(argv[2]);  // argc could be 1
}

// ✅ Always validate
int main(int argc, char* argv[]) {
    if (argc < 3) {
        std::cerr << "Usage: " << argv[0] << " <host> <port>\n";
        return EXIT_FAILURE;
    }
}
```

## 📐 `argv[0]` — The Program Name Trap

```bash
$ ./program           → argv[0] = "./program"
$ /full/path/program  → argv[0] = "/full/path/program"
$ program             → argv[0] = "program"  (via PATH)
```

```cpp
// Getting just the filename from argv[0]
#include <filesystem>

int main(int argc, char* argv[]) {
    // ❌ naive
    std::string progname = argv[0];      // might be full path

    // ✅ correct
    std::string progname =
        std::filesystem::path(argv[0]).filename().string();
    // "./build/debug/server" → "server"
}
```

> 🔴 **`argv[0]` can be empty string `""`** if the program is exec'd directly by another process passing an empty argv. Never assume it's non-empty or meaningful.

## 🎯 Interview Traps

**Trap 1:**
```cpp
int main(int argc, char* argv[]) {
    argv[1] = nullptr;    // legal?
    argv[1][0] = 'X';    // legal?
}
```
> First line: ✅ legal — you can modify the pointers in `argv[]`. Second line: ✅ legal — the strings pointed to by `argv` are writable. But after setting `argv[1] = nullptr`, the second line is **UB** — dereferencing nullptr.

**Trap 2:**
```cpp
void foo(char* argv[]) {
    sizeof(argv);    // → ?
}
```
> `sizeof(pointer)` = **8** on 64-bit. `argv` decayed from `char**` — same array decay trap as with arrays. `sizeof` gives pointer size, not array size.

**Trap 3:**
```cpp
int main(int argc, char* argv[]) {
    std::string s = argv[100];   // argc = 3
}
```
> **UB** — `argv[100]` is out of bounds. `argv[argc]` = nullptr is guaranteed, but beyond that is garbage memory. No bounds check, no exception.

**Trap 4:**
```cpp
// Is this valid?
int main(int argc, char* argv[], char* envp[]) { }
```
> **Not standard** — only two signatures are mandated by the standard. But widely supported as a compiler extension (POSIX). In an interview: "implementation-defined, not portable, use `std::getenv` instead."
