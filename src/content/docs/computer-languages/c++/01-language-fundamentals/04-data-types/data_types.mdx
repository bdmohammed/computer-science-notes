# Data Types in C++

**A Data Type tells the compiler:**

➜ What *type* of data a variable can store  
➜ How much *memory* to allocate  
➜ What *operations* are allowed  

---

## 📦 Classification of C++ Data Types

```cpp
C++ Data Types
│
├── 🔵 Built-in Types
│    ├── void                          → "no type" (functions, pointers)
│    ├── std::nullptr_t (C++11)        → type of nullptr
│    ├── std::meta::info (C++26)       → reflection values [GOOD TO KNOW]
│    │
│    ├── INTEGRAL TYPES 🧱
│    │   ├── Boolean: bool            → true/false (size implementation-defined)
│    │   │
│    │   ├── Character Types 🔤
│    │   │   ├── char                 → distinct type, signedness platform-dependent ⚠️
│    │   │   ├── signed/unsigned char → raw memory access, UTF-8 units
│    │   │   ├── wchar_t              → wide chars (UTF-16 on Windows, UTF-32 on Linux)
│    │   │   ├── char16_t (C++11)     → UTF-16 code units
│    │   │   ├── char32_t (C++11)     → UTF-32 code units
│    │   │   └── char8_t (C++20)      → UTF-8 code units (distinct from char)
│    │   │
│    │   └── Standard Integers 🔢
│    │       ├── [signed/unsigned] [short] int [long] [long long]
│    │       │   • short: ≥16 bits
│    │       │   • int: ≥16 bits (usually 32)
│    │       │   • long: ≥32 bits (32 on Windows, 64 on Linux/macOS) ⚠️
│    │       │   • long long: ≥64 bits (C++11)
│    │       │
│    │       └── Key Rule: sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)
│    │
│    └── FLOATING-POINT TYPES 🌊
│        ├── float        → ~7 decimal digits (IEEE-754 binary32)
│        ├── double       → ~15 decimal digits (IEEE-754 binary64) ✅ DEFAULT CHOICE
│        └── long double  → extended precision (platform-dependent: 80-bit x87, 128-bit, or same as double)
│
├── 🟠 Derived Types
│   ├── Pointers                    → int*, char*, void*
│   ├── References                  → int&, int&&
│   ├── Arrays                      → int[10]
│   └── Function Types              → int(int, double)
│
└── 🟢 User-Defined Types
    ├── Class
    ├── Struct
    ├── Union
    ├── Enum / enum class
    └── typedef / using aliases
```

# Data Models

These names describe how a system stores integer types.

| Model | `int` | `long` | `long long` | `Pointer` | Meaning                  |
| ----- | ----- | ------ | ----------- | --------- | ------------------------ |
| LP32  | 16    | 32     | 32          | 32        | Old 16-bit systems       |
| ILP32 | 32    | 32     | 32          | 32        | Classic 32-bit systems   |
| LLP64 | 32    | 32     | 64          | 64        | Windows 64-bit model     |
| LP64  | 32    | 64     | 64          | 64        | Linux/macOS 64-bit model |

---

## Meaning of the Names

A trick:

* **I** = `int`
* **L** = `long`
* **P** = pointer
* Number = bit size

So:

## LP64

Means:

* `long` = 64-bit
* pointer = 64-bit
* `int` remains 32-bit

Used in:

* Linux 64-bit
* macOS

---

## LLP64

Means:

* `long long` = 64-bit
* pointer = 64-bit
* `long` still 32-bit

Used in:

* Windows 64-bit

This is why Windows is weird 😄

#### Signed vs Unsigned
| Signed Type                              | Unsigned Type         |
| ---------------------------------------- | --------------------- |
| `signed int`                             | `unsigned int`        |
| Can store negative values                | Only positive values  |
| Range roughly: `-2^(n-1)` to `2^(n-1)-1` | Range: `0` to `2^n-1` |

Example:

| Type            | Typical Range |
| --------------- | ------------- |
| `signed char`   | -128 to 127   |
| `unsigned char` | 0 to 255      |

```cpp
// 1. Signed
//   Can store:

//   1. positive
//   2. negative
//   3. zero

// 2. Unsigned
//   Can store:

//   1. only positive values
//   2. zero
unsigned int u = 10;
signed int   s = -10;  // 'signed' is default, usually omitted

// Mixing signed/unsigned → implicit conversion → bugs!
int a = -1;
unsigned int b = 1;
if (a < b) { }  // ❌ a converts to huge unsigned! Condition false.
```

#### Signed Integer Representation

Computers store everything in **binary (0 and 1)**.

But:

* positive numbers are easy
* negative numbers need a representation system

Historically, computers used 3 systems:

| Representation   | Example for -5    |
| ---------------- | ----------------- |
| Sign-Magnitude   | separate sign bit |
| One's Complement | invert bits       |
| Two's Complement | invert + add 1    |

---

#### Modern C++ Uses ONLY Two's Complement

Before C++20:

* compiler could use ANY representation

After C++20:

* ONLY two’s complement allowed
So:

* arithmetic becomes simpler
* CPU hardware simpler
* overflow behavior predictable

Modern C++ assumes:

* integers → two’s complement
* floating-point → IEEE-754 (usually)
---

#### What is Two’s Complement?

Example using 8-bit signed integer.
```text
=5
=00000101
=11111010 (invert bits)
=11111011 (add 1)
=-5
```
Two’s complement properties:
* MSB (most significant bit) is sign bit: 0 = positive, 1 = negative
* Range: -128 to 127 for 8-bit
* Addition/subtraction works the same for positive and negative numbers
```cpp
int a = 5;   // 00000101
int b = -5;  // 11111011 (two's complement)
int sum = a + b;  // 00000101 + 11111011 = 00000000 (0)

REPRESENTATION OF NEGATIVE NUMBERS


1) Sign-Magnitude
-----------------
MSB stores sign:
0 = positive
1 = negative

+5
00000101

-5
10000101

Problem:
Two zeros exist:
00000000 = +0
10000000 = -0



2) One's Complement
-------------------
Negative number =
invert all bits

+5
00000101

invert bits
11111010

= -5


Problem:
Two zeros still exist

00000000 = +0
11111111 = -0



3) Two's Complement
-------------------
Negative number =
invert bits + add 1

+5
00000101

invert bits
11111010

add 1
11111011

= -5


Why 11111011 is NOT 251 here?
--------------------------------
Unsigned interpretation:
11111011₂ = 251₁₀

BUT in two's complement:
MSB = 1
=> number is negative

To decode:

11111011

invert bits
00000100

add 1
00000101

= 5

therefore:
11111011₂ = -5


IMPORTANT:
Same bit pattern
Different interpretation

11111011 as unsigned  = 251
11111011 as signed    = -5
```

#### 🎯 Fixed-Width Types — Use These in Production

For exact sizes, prefer fixed-width integers from `<cstdint>`:

| Type | Guaranteed Size | Use When |
|---|---|---|
| `int8_t` | exactly 1 byte signed | byte-level data |
| `uint8_t` | exactly 1 byte unsigned | byte buffers, bitmasks |
| `int16_t` | exactly 2 bytes signed | network protocols, audio |
| `uint16_t` | exactly 2 bytes unsigned | port numbers |
| `int32_t` | exactly 4 bytes signed | most integers |
| `uint32_t` | exactly 4 bytes unsigned | IDs, checksums |
| `int64_t` | exactly 8 bytes signed | timestamps, file sizes |
| `uint64_t` | exactly 8 bytes unsigned | large counts, bitmasks |
| `size_t` | pointer-sized unsigned | sizes, indices, loop counters |
| `ptrdiff_t` | pointer-sized signed | pointer differences |
| `intptr_t` | can hold a pointer value | casting pointers to integers |

```cpp
// ❌ Production bug waiting to happen
long fileSize = getFileSize();     // 4 bytes on Windows — silent truncation

// ✅ Correct
int64_t fileSize = getFileSize();  // guaranteed 8 bytes everywhere
```

#### IEEE 754 Layout (float — 32 bit)

```
31      30    23  22                    0
│        │       │                       │
│  Sign  │  Exp  │       Mantissa        │
│  1 bit │ 8 bit │        23 bit         │
└────────┴───────┴───────────────────────┘

value = (-1)^sign × 2^(exp-127) × 1.mantissa

Example: 5.75

Binary:
Convert 5.75 → Binary


INTEGER PART (5)

2  |   5     → remainder 1
2  |   2     → remainder 0
2  |   1     → remainder 1
       0

Read bottom → top:
101₂


FRACTION PART (0.75)

0.75 × 2 = 1.5   → 1
0.5  × 2 = 1.0   → 1

Read top → bottom:
.11₂

Binary:
5.75₁₀ = 101.11₂

Normalize:
101.11₂ = 1.0111₂ × 2²

Sign bit:
positive number => 0

Exponent:
actual exponent = 2
stored exponent = 2 + 127 = 129
129 in binary = 10000001

Mantissa:
from 1.0111₂
leading 1 is implicit (not stored)
stored mantissa = 01110000000000000000000

Final IEEE 754 bits:

0 10000001 01110000000000000000000

Hexadecimal: 0x40B80000
```

#### IEEE 754 Double Precision (64-bit)

```
63        62........52   51.........................0
| Sign |    Exponent   |          Mantissa          |
| 1bit |    11bit      |           52bit            |

value =
(-1)^sign × 2^(exp - 1023) × 1.mantissa


----------------------------------------------------
FIELDS
----------------------------------------------------

1) Sign Bit (1 bit)
-------------------
0 → positive
1 → negative


2) Exponent (11 bits)
---------------------
Stored using bias = 1023

actual exponent =
stored exponent - 1023


3) Mantissa / Fraction (52 bits)
--------------------------------
Stores fractional binary digits.

Leading 1 is implicit for normalized numbers.

Actual significand:
1.mantissa


----------------------------------------------------
EXAMPLE: 5.75
----------------------------------------------------

5.75₁₀ = 101.11₂

Normalize:
1.0111₂ × 2²


Sign:
0


Exponent:
2 + 1023 = 1025

1025 in binary:
10000000001


Mantissa:
0111000000000000000000000000000000000000000000000000


----------------------------------------------------
FINAL IEEE 754 DOUBLE
----------------------------------------------------

0
10000000001
0111000000000000000000000000000000000000000000000000
```

#### Meaning of IEEE-754

IEEE-754 is the standard for floating-point storage.

Defines:

* NaN
* infinity
* precision
* rounding
* layout in memory

Almost all modern CPUs follow this.

---

#### What is "Subnormal" and "Normal"?

Floating-point numbers have:

| Type      | Meaning                          |
| --------- | -------------------------------- |
| Normal    | regular floating-point numbers   |
| Subnormal | extremely tiny numbers near zero |

Subnormal numbers help avoid sudden underflow to zero.

---

#### Why Floating-Point Has Approximation

Binary cannot perfectly store many decimal values.

Example:

```cpp
0.1 + 0.2 = 0.30000000000000004
```

Because decimals become repeating binary fractions.

---

#### Meaning of These Weird Values

Example:

```text
±0x1p−149
```

This is hexadecimal floating notation.

Means:

```text
1 × 2^-149
```

Used internally for exact binary representation.

---

#### Floating Point Traps

```cpp
// ❌ NEVER compare floats with ==
float a = 0.1f + 0.2f;
if (a == 0.3f) { }      // FALSE — a is 0.30000001192...

// ✅ Use epsilon comparison
if (std::abs(a - 0.3f) < 1e-6f) { }
```

```cpp
// Silent precision loss
double big = 1e16;
double result = big + 1.0;
std::cout << (result - big);    // prints 0, not 1
                                // 1.0 is lost in the noise at 1e16 scale
```

<Aside type="caution">
🔴 Note on data models and floats: LP32 / ILP32 / LLP64 / LP64 models only define integer type sizes. Floating point sizes are governed by IEEE 754, not the data model — which is why float and double are identical across all 4 models. long double is the only exception — it is purely compiler + platform dependent.
</Aside>

This section explains the **special behavior of floating-point numbers** (`float`, `double`, `long double`) in C++.

Floating-point numbers are MUCH more complicated than integers.

---

##### 1. Infinity (`+∞` and `-∞`)

Floating-point types can represent infinity.

```cpp
// Positive Infinity
double x = 1.0 / 0.0; //+infinity

// Negative Infinity
double x = 1.0 / -0.0; //-infinity
```

---

##### 2. Negative Zero (`-0.0`)
This is one of the weirdest floating-point concepts.
C++ floating point has:

```cpp
+0.0
-0.0

0.0 == -0.0 //True

// But They Behave Differently when divided
// Why Negative Zero Exists

// Because floating-point stores:

// * sign
```

##### 12. Implicit Conversions

C++ automatically converts:


```cpp
Integer → Floating

//
// double usually preserves integers exactly up to 2^53

//
// Example:

```

Never compare floating-point numbers directly.

```cpp

if (fabs(a - b) < 1e-9)   // ✅ correct way to compare floats
Because tiny precision errors happen constantly.
```

## 🔬 Under the Hood — How Types Map to Hardware

```
C++ Type        CPU Register / Memory
─────────────────────────────────────────────────────
bool            al  (8-bit register, only bit 0 used)
char            al  (8-bit)
short           ax  (16-bit)
int             eax (32-bit)
long long       rax (64-bit)
float           xmm0 (SSE 32-bit float register)
double          xmm0 (SSE 64-bit float register)
pointer         rax / rdi / rsi (64-bit — same as address bus)
```

```cpp
int x = 5;
// Assembly (x86-64):
// mov eax, 5          ← 'x' → register eax

double d = 3.14;
// Assembly:
// movsd xmm0, [.rodata]   ← 'd' → SSE float register xmm0
```

### Why `int` Is the "Natural" Type

```
CPU's ALU (Arithmetic Logic Unit) is designed around its native word size.
On 32-bit CPUs: native = 32 bits = int
On 64-bit CPUs: native = 64 bits = long long

But int is still 32 bits on 64-bit systems — for ABI compatibility.
Operations on types SMALLER than native size require extra zero/sign extend instructions.

char + char:
  movsx eax, byte [rbp-1]   ← sign-extend char to 32-bit
  movsx ecx, byte [rbp-2]   ← sign-extend char to 32-bit
  add   eax, ecx            ← 32-bit add
  → result is int, not char!  (integer promotion)
```

## Initialization Rules

```cpp
int a;              // uninitialized local variable; reading it is undefined behavior
int b{};            // value-initialized to 0
int c = 0;          // initialized to 0
int d(0);           // initialized to 0

int* p1;            // uninitialized pointer; reading it is undefined behavior
int* p2{};          // nullptr
int* p3 = nullptr;  // nullptr

static int global_like; // zero-initialized
```

| Storage / Form | What Happens |
|---|---|
| Global or `static` object | Zero-initialized before `main()` |
| Local automatic object, `int x;` | Uninitialized; reading before assigning is undefined behavior |
| Local value-initialized object, `int x{};` | Initialized to `0` |
| Dynamic object, `new int` | Uninitialized |
| Dynamic value-initialized object, `new int()` or `new int{}` | Initialized to `0` |

<Aside type="danger">
Declaring an uninitialized local variable is allowed. Reading its value before assigning to it is the bug.
</Aside>
