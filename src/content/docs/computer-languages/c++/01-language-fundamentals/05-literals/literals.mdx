A **Literal** is a fixed value written directly in source code.

- ✔ Represents constant data at compile-time
- ✔ Written directly in code (no runtime computation)
- ✔ Type inferred from syntax + suffixes (C++ is stricter than Java)
{/*  Type inference is a programming language feature where the compiler or runtime automatically deduces the data type of a variable, expression, or function return without requiring the developer to explicitly write it out */}
<Code lang="cpp" title="What a literal looks like" code={`
int x      = 10;         // 10        → integer literal           (type: int)
double d   = 10.5;       // 10.5      → floating-point literal    (type: double)
bool b     = true;       // true      → boolean literal           (type: bool) (C++98+)
char c     = 'A';        // 'A'       → character literal         (type: char)
string s   = "Hello";    // "Hello"   → string literal            (type: string)
int* p     = nullptr;    // nullptr   → pointer literal           (type: std::nullptr_t) (C++11+)
`} />

```
Literals
│
├── Integer Literals
│   ├── Decimal       → 42
│   ├── Octal         → 052
│   ├── Hexadecimal   → 0x2A

│
├── Floating-Point Literals
│   ├── Decimal       → 3.14
│   ├── Scientific    → 3.14e2
│   └── Hex float     → 0x1.8p+1  (C++17)
│
├── Character Literals
│   ├── char          → 'A'
│   ├── wchar_t       → L'A'
│   ├── char16_t      → u'A'
│   ├── char32_t      → U'A'
│   └── char8_t       → u8'A'     (C++20)
│
├── String Literals
│   ├── narrow        → "hello"
│   ├── wide          → L"hello"
│   ├── UTF-8         → u8"hello"
│   ├── UTF-16        → u"hello"
│   ├── UTF-32        → U"hello"
│   └── raw           → R"(hello\n)"
│
├── Boolean Literals  → true, false
├── Pointer Literal   → nullptr
└── User-Defined Literals (C++11) → 42_km, 3.14_kg
```

# 1️⃣ Integral Literals

Integer numbers. Default type is **`int`**.

---

## Number Systems
| System      | Base | Prefix      | Allowed Values | C++ Calculation | Example  | Value |
| ----------- | ---- | ----------- | -------------- | --------------- | -------- | ----- |
| Binary      | 2    | `0b` / `0B` | `0-1`          | powers of 2     | `0b1010` | 10    |
| Octal       | 8    | `0`         | `0-7`          | powers of 8     | `010`    | 8     |
| Decimal     | 10   | none        | `0-9`          | powers of 10    | `10`     | 10    |
| Hexadecimal | 16   | `0x` / `0X` | `0-9`, `A-F`   | powers of 16    | `0x10`   | 16    |


<Aside type="note">
- Hexadecimal A-F => 10-15 in decimal
- All four are identical at runtime — same bits in memory
- C++ is **case-insensitive** for literal prefixes (`0xFF` ≡ `0XFF` ≡ `0xff`).  
- ⚠️ **C++14+** adds binary literals (`0b...`) and **digit separators** using **single quotes**: `1'000'000`.

If you see a prefix, it's not decimal:  
- Starts with `0` → octal (unless `0x`/`0b`)  
- Starts with `0x` → hexadecimal  
- Starts with `0b` → binary (C++14+)
</Aside>

## Base Conversion Examples

```text
123 = 1×10² + 2×10¹ + 3×10⁰ = 123
```

```text
0b1010 = 1×2³ + 0×2² + 1×2¹ + 0×2⁰ = 10
```

```text
010₈ = 1×8¹ + 0×8⁰ = 8
```

```text
0x10 = 1×16¹ + 0×16⁰ = 16
0xFF = 15×16¹ + 15×16⁰ = 240 + 15 = 255
```

<Code lang="cpp" title="Number system examples" code={`
int x = 10;        // Decimal → 10
int y = 010;       // Octal   → 8
int z = 0x10;      // Hex     → 16
int w = 0b10;      // Binary  → 2 (C++14+)

std::cout << x << "----" << y << "----" << z; // Output: 10----8----16`} />

## ✅ Valid vs ❌ Invalid

<Code lang="cpp" title="✅ Valid" code={`
int x = 0777;          // Octal (digits 0–7)
int y = 0xFACE;        // Hex uppercase

long long big = 1'000'000'000LL; // C++14 digit separator + suffix`} />

int z = 1'000_;  // Error: digit separator can't end with '
`} />

## 🔢 Type Suffixes for Integrals

| Suffix | Type    | Example | Resulting Type |
|--------|---------|---------|---------------|
| `u`/`U` | unsigned | `100u` | `unsigned int` |
| `l`/`L` | long | `100L` | `long` |
| `ll`/`LL` | long long | `100LL` | `long long` |
| `ul`/`UL` | unsigned long | `100UL` | `unsigned long` |
| `ull`/`ULL` | unsigned long long | `100ULL` | `unsigned long long` |

```cpp
int a   = 10;       // OK: literal is int
long b  = 10L;      // OK: explicit long
long c  = 10;       // OK: implicit promotion int→long
int d   = 10L;      // ⚠️ Warning: narrowing (long→int), may lose data

// C++17: use brace initialization to prevent narrowing
int e{10L};         // ❌ Error: narrowing conversion not allowed

auto a  = 42;       // int
auto b  = 42u;      // unsigned int
auto c  = 42L;      // long
auto d  = 42LL;     // long long
auto e  = 42ULL;    // unsigned long long
```

> 🔴 **Trap:**
```cpp
long long big = 2147483648;     // ❌ overflow during literal parsing
// literal is int first → already overflowed
long long big = 2147483648LL;   // ✅ suffix makes it long long from the start
```

## Digit Separator (C++14)

```cpp
int million  = 1'000'000;       // ✅ readable
long long big = 9'223'372'036'854'775'807LL;   // INT64_MAX
int hex  = 0xFF'EC'D1'B2;       // ✅ works in all bases
int bin  = 0b1111'0000'1010;    // ✅
```

# 2️⃣ Floating Point Literals

Real numbers. Default type is **`double`**.

---

## Forms Reference

| Form | Example | Notes |
|---|---|---|
| Basic decimal | `3.14` | double by default |
| No integer part | `.14` | valid — same as `0.14` |
| No fractional part | `3.` | valid — same as `3.0` |
| Scientific notation | `3.14e2` | = 314.0 |
| Scientific negative exp | `3.14e-2` | = 0.0314 |
| Hex float (C++17) | `0x1.8p+1` | = 3.0 exactly |

---

## Suffix Reference

| Suffix | Type | Example |
|--------|------|---------|
| (none) | `double` | `3.14` |
| `f`/`F` | `float` | `3.14f` |
| `l`/`L` | `long double` | `3.14L` |

<Code lang="cpp" title="❌ Invalid" code={`
float f = 10.5;   // ❌ Error: narrowing double→float
// FIX: float f = 10.5f;

int i = 10.5;     // ❌ Error: narrowing double→int
// FIX: int i = static_cast<int>(10.5); // or use brace init with caution
`} />

---

## Hex Float Literals (C++17)

```
0x1.8p+1

0x    → hex float prefix
1.8   → hex mantissa (1 + 8/16 = 1.5 in decimal)
p+1   → exponent: × 2¹
= 1.5 × 2 = 3.0
```

> Used in graphics/physics engines where **exact binary representation** matters — avoids rounding that decimal literals introduce.

```cpp
// Integral literals can be assigned to floating types:
double d1 = 123;        // ✅ int → double (promotion)
double d2 = 0123;       // ✅ octal literal → decimal value → double
double d3 = 0x123;      // ✅ hex literal → decimal → double
// ❌ But: 0x123.456 is INVALID — hex floats need 'p' exponent: 0x1.23p+4
```

# 3️⃣ Character Literals

- Single character in **single quotes `' '`**
- `char` is **1 byte** (ASCII/execution character set) by default
- C++ supports multiple character types: `char`, `wchar_t`, `char16_t`, `char32_t`

## Four Valid Forms

<Code lang="cpp" title="All valid char literal forms" code={`
char c1 = 'A';                // 1. Direct ASCII char
char c2 = 97;                 // 2. Integral (ASCII value) → 'a'
char16_t c3 = u'\\u0041';      // 3. Unicode escape (C++11) → 'A'
char c4 = '\\n';               // 4. Escape sequence → newline
`} />

## Encoding Prefixes

| Prefix   | Character Type | Example    | Typical Size  | Encoding / Meaning      |
|----------|----------------|------------|---------------|-------------------------|
| (none)   | char           | 'A'        | 1 byte        | Execution character set |
| u8       | char8_t        | u8'a'      | 1 byte        | UTF-8                   |
| u        | char16_t       | u'α'       | 2 bytes       | UTF-16                  |
| U        | char32_t       | U'α'       | 4 bytes       | UTF-32                  |
| L        | wchar_t        | L'α'       | 2 or 4 bytes  | Platform-dependent      |

| Platform    | `wchar_t` Size | Common Encoding |
| ----------- | -------------- | --------------- |
| Windows     | 2 bytes        | UTF-16          |
| Linux/macOS | 4 bytes        | UTF-32          |

<Code lang="cpp" title="✅ Valid" code={`
char     a = 'A';      // 65
wchar_t  b = L'A';
char16_t c = u'A';
char32_t d = U'A';

char ch1 = 'A';
char ch2 = 65;              // ASCII value → 'A'
char ch3 = '\\n';           // escape sequence
char16_t ch4 = u'\\u0041';  // Unicode escape
char32_t ch5 = U'\\U0001F600'; // 😀 emoji (C++11)
unsigned char ch6 = 0xFF;   // within 0–255 range
`} />

<Code lang="cpp" title="❌ Invalid" code={`
char ch = "A";          // ❌ Error: string literal → const char[2], not char
char ch = 'ab';         // ❌ Warning/Error: multi-character literal (implementation-defined)
char ch = '';           // ❌ Error: empty character literal
char ch = 65536;        // ⚠️ Warning: narrowing (int→char), value truncated
char ch = \\u0062;      // ❌ Error: missing quotes
char ch = '\\iface';    // ❌ Error: invalid escape sequence
`} />

## Escape Sequences (C++ Standard)

| Escape | Meaning | Hex Value |  Value |
|--------|---------|-----------|--------|
| `\n` | New line | 0x0A | 10 |
| `\t` | Horizontal tab | 0x09 | 9 |
| `\r` | Carriage return | 0x0D | 13 |
| `\f` | Form feed | 0x0C | 12 |
| `\b` | Backspace | 0x08 | 8 |
| `\\` | Backslash | 0x5C | 92 |
| `\'` | Single quote | 0x27 | 39 |
| `\"` | Double quote | 0x22 | 34 |
| `\0` | Null character | 0x00 | 0 |
| `\a` | alert/bell | 0x07 | 7 |
| `\f` | form feed | 0x0C | 12 |
| `\v` | vertical tab | 0x0B | 11 |
| `\xNN` | hex value | e.g. `\x41` = 'A' | | 0xNN | varies |
| `\NNN` | octal value | e.g. `\101` = 'A' | | 0NNN | varies |
| `\UNN` | unicode 32-bit (C++11) | `\U00000041` | | 0xUNNNNNNNN | varies |

<Aside type="note">
Every **escape sequence** represents exactly **one character** in the execution character set.

> 🔴 **Trap:** Multi-character literal is **valid but implementation-defined:**
```cpp
int x = 'AB';    // ✅ compiles — but value is implementation-defined
// stored as
// 'A' 'B' '\0'
// Memory
// 0x41 0x42 0x00
// final 
// '\0' null termination
// GCC: 0x4142 = 16706
// Note: multi-character literals are not null-terminated, so they can contain any combination of characters and may not be portable across compilers or platforms.
// This is NOT a string — no null terminator
// GCC warning:  warning: multi-character character constant [-Wmultichar]
      |     int x = 'AB';
      |             ^~~~
```
</Aside>

# 4️⃣ String Literals

Sequence of characters in **double quotes `" "`**.

- Type: `const char[N]` (array of const char), **not** `std::string`
- Stored in read-only memory (often `.rodata` segment)
- **Immutable** — modifying causes undefined behavior

<Code lang="cpp" title="String basics" code={`
const char* s = "C++";  // Type: const char[4]

// Concatenation at compile-time (adjacent literals)
const char* result = "Hello" "World";  // "HelloWorld"

// Runtime concatenation requires std::string
#include <string>
std::string mixed = std::to_string(10) + "20";  // "1020"

// Number + string literal = type error!
// std::string bad = 10 + "20";  // ❌ Error: no operator+ for int + const char*
`} />

---

## Raw String Literals <Badge text="C++11+" variant="success" />

<Code lang="cpp" title="Raw strings — no more escaping" code={`
// Regular string (escaped)
const char* json1 = "{\\n  \\"name\\": \\"Alice\\"\\n}";

// Raw string (C++11) — cleaner!
const char* json2 = R"({
  "name": "Alice",
  "age": 25
})";

// Custom delimiter for nested quotes
const char* regex = R"delim(\w+@\w+\.\w+)delim";
`} />

## Encoding Prefixes for Strings

| Prefix | Type | Example | Use Case |
|--------|------|---------|----------|
| (none) | `const char[]` | `"Hello"` | ASCII/UTF-8 source |
| `u8` | `const char[]` | `u8"Hello"` | Guaranteed UTF-8 (C++20) |
| `u` | `const char16_t[]` | `u"Hello"` | UTF-16 |
| `U` | `const char32_t[]` | `U"Hello"` | UTF-32 |
| `L` | `const wchar_t[]` | `L"Hello"` | Wide strings (platform-dependent) |

```cpp
const char*     a = "hello";      // null-terminated char array
const wchar_t*  b = L"hello";
const char16_t* c = u"hello";
const char32_t* d = U"hello";
const char8_t*  e = u8"hello";    // C++20
```

### String Literal Storage

```
"hello" in memory:

┌───┬───┬───┬───┬───┬───┐
│ h │ e │ l │ l │ o │\0 │
└───┴───┴───┴───┴───┴───┘
  0   1   2   3   4   5     ← 6 bytes total, not 5
                  ↑
            null terminator always appended by compiler
```

### String Literal Concatenation

```cpp
const char* s = "hello " "world";    // ✅ merged at compile time
                                      // = "hello world"

const char* s = "line1\n"
                "line2\n"
                "line3\n";            // ✅ common for long strings
```

### Raw String Literals (C++11)

```cpp
// Normal — need escape sequences
const char* path = "C:\\Users\\name\\file.txt";
const char* regex = "\\d+\\.\\d+";

// Raw — no escape processing
const char* path  = R"(C:\Users\name\file.txt)";
const char* regex = R"(\d+\.\d+)";

// Syntax:  R"delimiter(content)delimiter"
// delimiter can be any string up to 16 chars
const char* tricky = R"xyz(contains)" and R" inside)xyz";
```

> 🔑 Raw strings are **critical** for regex, file paths, JSON/XML embedded in code.

### String Literal Lifetime & Trap

```cpp
const char* foo() {
    return "hello";     // ✅ safe — string literal lives in .rodata
                        //    static storage duration — lives forever
}

const char* bar() {
    char s[] = "hello"; // s is a LOCAL ARRAY — copy of the literal
    return s;           // ❌ dangling pointer — s is on the stack
}
```

```
"hello" literal → .rodata section (read-only, lives entire program)
char s[] = "hello" → stack copy → dies when function returns
```

> 🔴 **Modifying a string literal = UB:**
> ```cpp
> char* s = "hello";   // C++ allows this (deprecated) but modification is UB
> s[0] = 'H';          // ❌ UB — .rodata is read-only memory
>                      // SIGSEGV on most systems
> ```

# 5️⃣ Boolean Literals

Only **`true`** or **`false`** (C++98+).

<Code lang="cpp" title="Boolean literals" code={`
bool a = true;     // stored as 1
bool b = false;    // stored as 0

// ✅ Idiomatic C++
if (isActive) { }      // not: if (isActive == true)
if (!isEmpty) { }

// ⚠️ C++ allows implicit conversion (unlike Java!)
if (1) { }    // ✅ Works: non-zero → true
if (0) { }    // ✅ Works: zero → false
if (ptr) { }  // ✅ Works: non-null → true
`} />

| Expression | Result |
|---|---|
| `true + true` | `2` (int) — bool promoted |
| `!true` | `false` |
| `(bool)42` | `true` |
| `(bool)0` | `false` |
| `(bool)0.0` | `false` |
| `(bool)nullptr` | `false` |
| `(bool)""` | `true` — non-null pointer |

<Aside type="caution">
`"true"` (with quotes) is a **string literal**, not a boolean.  
`True` or `TRUE` → compile error unless you `#define TRUE 1` (not recommended).  
✅ Prefer `#include <cstdbool>` or just use `true`/`false`.
</Aside>

# 6️⃣ Null Pointer Literal

Represents **absence of an object**.

<Code lang="cpp" title="null usage in C++" code={`
const char* s = nullptr;   // ✅ C++11: type-safe null pointer
int* arr = nullptr;        // ✅ preferred

int* old1 = NULL;          // ⚠️ Pre-C++11: macro for 0 or ((void*)0)
int* old2 = 0;             // ⚠️ Works but less clear

int x = nullptr;           // ❌ Error: can't assign nullptr to non-pointer
bool b = nullptr;          // ❌ Error: nullptr only for pointers

// ✅ Modern C++: use std::optional for nullable value semantics
#include <optional>
std::optional<int> maybe;  // empty
if (maybe.has_value()) { /* use *maybe */ }
`} />

<Aside type="danger">
**Most common crash in C++:**
```cpp
const char* s = nullptr;
std::cout << s.length();   // 💥 Undefined Behavior! (nullptr dereference)
// In practice: segfault or access violation
```
✅ Always check pointers before dereferencing, or use `std::optional`/`std::unique_ptr` for safer semantics.
</Aside>

# 🔵 Pointer Literal — `nullptr`

```cpp
int* p = nullptr;     // C++11 — type-safe null pointer
int* p = NULL;        // C — macro, expands to 0 or (void*)0
int* p = 0;           // C++03 style — still works but avoid
```

## Why `nullptr` Over `NULL`

```cpp
void foo(int x);
void foo(int* p);

foo(NULL);      // ❌ ambiguous — NULL is integer 0
                //    calls foo(int), not foo(int*)

foo(nullptr);   // ✅ always calls foo(int*)
                //    nullptr has type std::nullptr_t
```

# 🧩 User-Defined Literals (C++11)

You can define what a suffix **means** for a literal.

```cpp
// Define _km suffix
long double operator"" _km(long double d) {
    return d * 1000.0;   // convert to meters
}

long double operator"" _m(long double d) {
    return d;
}

auto distance = 3.5_km + 200.0_m;   // 3700.0 meters
```

## Standard Library UDLs

| Literal | Type | Header |
|---|---|---|
| `"hello"s` | `std::string` | `<string>` |
| `"hello"sv` | `std::string_view` | `<string_view>` |
| `3i` | `std::complex` imaginary | `<complex>` |
| `100ms` | `std::chrono::milliseconds` | `<chrono>` |
| `2h` | `std::chrono::hours` | `<chrono>` |
| `30s` | `std::chrono::seconds` | `<chrono>` |

```cpp
using namespace std::literals;

auto s  = "hello"s;       // std::string — not const char*
auto sv = "hello"sv;      // std::string_view
auto t  = 100ms;          // chrono duration
auto t2 = 2h + 30min;     // compound duration
```

# 🔬 Under the Hood

```
Integer literal "42"
      │
      ▼
  Lexer tokenizes → INTEGER_LITERAL token, value=42, base=decimal
      │
      ▼
  Type assigned → int (no suffix)
      │
      ▼
  Code generation → immediate value in instruction:
                    mov eax, 42    (x86)
                    ─────────────
                    42 is baked INTO the instruction — no memory load

String literal "hello"
      │
      ▼
  Compiler writes bytes to .rodata section of object file
      │
      ▼
  Replaced in code with → pointer to that .rodata address
                          lea rax, [.rodata+offset]
```

## Where Literals Live in the Binary

```
ELF Binary sections:

.text    → your compiled code (instructions)
.rodata  → string literals, const data  ← "hello" lives here
.data    → initialized global variables
.bss     → zero-initialized globals
stack    → local variables (NOT literals)
```

# 🔬 Literal Type Compatibility in C++

C++ is **stricter** about conversions than Java. Key rules:

1. **Narrowing conversions** (e.g., `double`→`int`, `long`→`int`) require explicit cast or cause errors with `{}` initialization.
2. **Signed/unsigned mismatches** may trigger warnings.
3. **List initialization** (`{}`) forbids narrowing (C++11+).

<Code lang="cpp" title="Compatibility examples" code={`
// ✅ Safe promotions
int i = 10;          // literal int → int
long l = 10;         // int literal → long (promotion)
double d = 10;       // int literal → double (promotion)

// ⚠️ Narrowing: allowed with = but not with {}
int a = 10.5;        // ⚠️ Warning: double→int truncates
int b{10.5};         // ❌ Error: narrowing not allowed in list-init

// ✅ Explicit cast when needed
int c = static_cast<int>(10.5);  // c = 10

// ✅ Suffixes prevent surprises
unsigned int u = 100u;   // explicit unsigned
long long big = 100LL;   // explicit long long
`} />

# 🧭 Quick-Revision Cheat Sheet

```text
✅ INTEGRAL:
   Decimal: 42 | Octal: 052 | Hex: 0x2A | Binary(C++14): 0b101010
   Suffixes: u/U (unsigned), l/L (long), ll/LL (long long)
   Digit separator(C++14): 1'000'000

✅ FLOATING:
   Default: double | Suffixes: f/F (float), l/L (long double)
   Scientific: 1.5e10 | Hex-float(C++17): 0x1.ffffp+127

✅ CHAR:
   'A' (char), u'A' (char16_t), U'A' (char32_t), L'A' (wchar_t)
   Escapes: \n \t \r \\ \' \" \0 \xHH \uXXXX \UXXXXXXXX

✅ STRING:
   "text" (const char[]), u8"text" (UTF-8), R"(raw)" (C++11 raw)
   Adjacent literals auto-concatenate: "Hello" "World" → "HelloWorld"

✅ BOOLEAN:
   true / false (C++98+) | 0 → false, non-zero → true (implicit)

✅ NULL:
   nullptr (C++11, type-safe) | Avoid NULL/0 for pointers

⚠️ COMMON TRAPS:
   • 010 = 8 (octal!), not 10
   • 10.5 is double → needs 'f' for float
   • 'ab' is multi-char literal (implementation-defined)
   • nullptr only for pointers, not primitives
   • Brace init {} forbids narrowing conversions
```

**Trap 1:**
```cpp
auto x = 1 / 2;     // What type? What value?
```
> Type: `int`. Value: `0`. Both operands are `int` literals → integer division. Result is `0`, not `0.5`. Fix: `1.0 / 2` or `1 / 2.0`.

**Trap 2:**
```cpp
int arr[] = {1, 2, 3};
int x = arr[052];        // Which index?
```
> Index `052` is **octal** = 42 decimal. Way out of bounds. UB. No compile error.

**Trap 3:**
```cpp
const char* a = "hello";
const char* b = "hello";
if (a == b) { }          // true or false?
```
> **Implementation-defined.** Most compilers **intern** identical string literals — same `.rodata` address → `true`. But the standard does not guarantee it. Never compare string literals with `==`.

**Trap 4:**
```cpp
auto x = 2147483648;     // What type?
```
> `int` can't hold `2147483648` (= INT_MAX + 1). The compiler picks the **smallest type that fits** — `long` or `long long` depending on platform. Without `LL` suffix, this is platform-dependent behavior. Always write `2147483648LL`.

> 🎯 **Interview Pro Tip**: C++ literals are **compile-time constants**. Use `constexpr` + literals for zero-cost abstractions:  
> `constexpr int buffer_size = 1'024;` → optimized away at compile time.
