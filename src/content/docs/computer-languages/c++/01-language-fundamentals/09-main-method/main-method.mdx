## 🎯 C++ Main Function — Complete Guide

> The **`main` function** is the entry point of every hosted C++ program. The runtime system calls this function to start execution.
> 
> ⚠️ **Critical Difference from Java**: C++ `main` **returns `int`** (exit code to OS), not `void`. The signature is simpler — no `public`/`static` keywords needed.

```cpp
// ❌ No main? Linker error, not runtime!
// class Test {};  // Java: compiles, runtime NoSuchMethodError
// C++: linker error: undefined reference to `main'

// ✅ Standard signature (hosted environment):
int main(int argc, char* argv[]) {
    return 0;  // 0 = success, non-zero = error code to OS
}
```

## 📌 The Exact Signature (Standard C++)

### ✅ Two Standard Forms (C++17 §[basic.start.main])

| Signature | Use Case |
|-----------|----------|
| `int main()` | No command-line arguments needed |
| `int main(int argc, char* argv[])` | Access command-line arguments |

<Code lang="cpp" title="Minimal valid main" code={`
// ✅ Simplest valid entry point
int main() {
    // Your code here
    return 0;  // Success exit code
}
`} />

<Code lang="cpp" title="With command-line arguments" code={`
// ✅ Standard form with argc/argv
int main(int argc, char* argv[]) {
    // argc = argument count (including program name)
    // argv = array of C-style strings (null-terminated char*)
    
    for (int i = 0; i < argc; ++i) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }
    return 0;
}
`} />

### 🔑 Keyword Breakdown — C++ vs Java

| Feature | Java `main` | C++ `main` | Why the Difference? |
|---------|------------|------------|---------------------|
| **Return Type** | `void` | `int` | C++ reports exit status to OS; Java uses `System.exit()` |
| **Access Modifier** | `public` required | None needed | C++ has no class-based access for free functions |
| **Storage Specifier** | `static` required | None needed | `main` is a free function, not a class member |
| **Parameter Type** | `String[] args` | `char* argv[]` or `char** argv` | C++ uses C-style strings; Java uses `String` objects |
| **Argument Count** | `args.length` at runtime | `argc` passed explicitly | C-style convention: count + pointer pair |
| **Program Name** | Not in `args` | `argv[0]` = program name/path | POSIX convention inherited from C |

<Aside type="note">
**Memory Trick**: "**I**nt **M**ain" → "**I**mmediately **M**ain" — C++ jumps straight to `main`, no JVM lookup needed! 🚀
</Aside>

## 🔬 In-Depth — Why `int` Return Type?

```text
int main() {
    // ... program logic ...
    
    return 0;      // ✅ Success (convention: 0 = OK)
    return 1;      // ⚠️ Generic error
    return 2;      // ⚠️ Different error code
    // ... up to 255 (8-bit exit codes on most OS)
}

// OS/shell receives the exit code:
// $ ./myprogram
// $ echo $?          // Prints: 0 (success) or non-zero (error)
// $ ./myprogram || echo "Failed!"  // Runs echo if main() returned non-zero
```

<Aside type="tip">
**C++ Standard Rule**: If `main` reaches the end without `return`, it **implicitly returns 0** (C++98 and later).  
```cpp
int main() {
    std::cout << "Hello";
    // No return statement → implicitly return 0; ✅
}
```
But **explicit `return 0;` is clearer** — always prefer it for readability!
</Aside>

## 🔄 Valid Variations — Standard & Implementation-Defined

### 1. Parameter Declaration Styles ✅

<Code lang="cpp" title="All valid argc/argv forms" code={`
// ✅ Standard forms:
int main(int argc, char* argv[])      // Array syntax (preferred)
int main(int argc, char** argv)       // Pointer-to-pointer (equivalent)
int main(int argc, char* argv[])      // const-correct version:
int main(int argc, const char* argv[]) // ✅ argv strings are read-only

// ✅ C++17 structured bindings style (for iteration, not signature):
int main(int argc, char* argv[]) {
    // Modern iteration:
    for (char* arg : std::span(argv, argc)) {  // C++20 std::span
        std::cout << arg << '\\n';
    }
}
`} />

### 2. `void main()` — Implementation-Defined ⚠️

<Code lang="cpp" title="Non-standard but common extension" code={`
// ⚠️ void main() — NOT standard C++, but allowed by some compilers:
void main() {          // MSVC (Windows), some embedded compilers
    // ... code ...
    // No return needed
}

// ❌ Standard C++ (GCC, Clang, strict mode):
// error: 'main' must return 'int'

// ✅ Portable solution: always use int main()
int main() {
    // ... code ...
    return 0;  // Explicit is better than implicit
}
`} />

<Aside type="danger">
**Never use `void main()` in portable code**. It works on MSVC by default but fails on GCC/Clang with `-pedantic` or `-std=c++20`.  
✅ **Rule**: Always write `int main()` — it's standard, portable, and clear.
</Aside>

### 3. Additional Specifiers Allowed ✅

<Code lang="cpp" title="Valid modifiers on main" code={`
// ✅ noexcept — promise not to throw (C++11)
int main() noexcept {
    // If exception escapes → std::terminate() called
    return 0;
}

// ✅ [[nodiscard]] — warn if return value ignored (C++17, but main's return is handled by runtime)
[[nodiscard]] int main() {
    return 0;
}

// ❌ Invalid specifiers:
// static int main()      // ❌ Error: main cannot be static
// inline int main()      // ❌ Error: main cannot be inline
// virtual int main()     // ❌ Error: main cannot be virtual
// constexpr int main()   // ❌ Error: main cannot be constexpr
`} />

### 4. Wide Character Main (Windows/POSIX Extensions)

<Code lang="cpp" title="Unicode command-line arguments" code={`
// ✅ Windows: wmain with wchar_t (UTF-16)
#ifdef _WIN32
#include <windows.h>
int wmain(int argc, wchar_t* argv[]) {
    // argv contains UTF-16 strings
    // Use wprintf, std::wstring for processing
    return 0;
}
#endif

// ✅ POSIX: main with locale-encoded strings
// (argv is encoded per current locale, often UTF-8 on modern Linux)
int main(int argc, char* argv[]) {
    // Use std::locale, codecvt, or C++20 std::u8string for Unicode
    return 0;
}

// ✅ C++20: char8_t for UTF-8 (but argv is still char*)
// No standard main(char8_t*[]) yet — conversion needed
`} />

### 5. Environment Variable Parameter (POSIX Extension)

<Code lang="cpp" title="Access environment variables directly" code={`
// ✅ POSIX: third parameter for environment (non-standard but widely supported)
int main(int argc, char* argv[], char* envp[]) {
    // envp is null-terminated array of "KEY=value" strings
    for (int i = 0; envp[i] != nullptr; ++i) {
        printf("ENV: %s\n", envp[i]);
    }
    return 0;
}

// ✅ Modern C++ alternative: use std::getenv (standard, but not thread-safe during startup)
#include <cstdlib>
int main() {
    if (const char* home = std::getenv("HOME")) {
        std::cout << "Home: " << home << '\\n';
    }
    return 0;
}
`} />

## 🔄 Execution Order: What Runs Before `main()`?

```text
Program Start
    ↓
Runtime initialization (C++ runtime, not JVM)
    ↓
Static storage duration objects initialized  ← ⚠️ Order is complex!
    ↓
Dynamic initialization of globals (before main)
    ↓
main() is called  ← Your code starts here
    ↓
Program logic executes
    ↓
Stack unwinding: destructors for automatic objects
    ↓
Static objects destroyed (reverse order of construction)
    ↓
Return value passed to OS
```

<Code lang="cpp" title="Static initialization order demo" code={`
#include <iostream>

// Global object — constructor runs BEFORE main()
struct Logger {
    Logger()  { std::cout << "Logger constructed\\n"; }
    ~Logger() { std::cout << "Logger destroyed\\n"; }
};

Logger globalLogger;  // ✅ Static storage duration

int main() {
    std::cout << "main() executing\\n";
    return 0;
}

// Output:
// Logger constructed   ← before main
// main() executing     ← your code
// Logger destroyed     ← after main returns
`} />

<Aside type="danger">
**Static Initialization Order Fiasco**:  
If `file1.cpp` and `file2.cpp` each have global objects that depend on each other, **initialization order is unspecified**.

```cpp
// file1.cpp
extern int x;
int y = x + 1;  // ⚠️ What if x isn't initialized yet?

// file2.cpp
int x = 42;
```

✅ **Fix**: Use "construct on first use" idiom (Meyer's singleton):
```cpp
int& getX() {
    static int x = 42;  // Initialized on first call, thread-safe (C++11)
    return x;
}
```
</Aside>

## 📦 Command Line Arguments — `argc` / `argv` Deep Dive

### 🔬 Memory Layout

```text
Command: ./program hello world

Stack/Heap Layout:
┌─────────────────────────────────┐
│ argv[0] ──▶ "./program"  ──┐    │
│ argv[1] ──▶ "hello"    ──┐ │    │
│ argv[2] ──▶ "world"    ──┐│ │    │
│ argv[3] = nullptr      │││ │    │
└────────────────────────┼┼┼─┼────┘
                         │││ │
                         ▼▼▼ ▼
                    [null-terminated C-strings in read-only memory]
```

<Code lang="cpp" title="Safe argument processing patterns" code={`
#include <iostream>
#include <string>
#include <vector>

int main(int argc, char* argv[]) {
    // ✅ Pattern 1: Classic C-style loop
    std::cout << "Program: " << argv[0] << '\\n';  // Always check argc > 0 first!
    for (int i = 1; i < argc; ++i) {  // Start at 1 to skip program name
        std::cout << "Arg " << i << ": " << argv[i] << '\\n';
    }
    
    // ✅ Pattern 2: Convert to std::vector<std::string> for modern C++
    std::vector<std::string> args(argv + 1, argv + argc);  // Skip argv[0]
    for (const auto& arg : args) {
        std::cout << "Modern: " << arg << '\\n';
    }
    
    // ✅ Pattern 3: C++20 std::span (non-owning view)
    #if __cplusplus >= 202002L
    #include <span>
    std::span<char*> argsSpan(argv, argc);
    for (char* arg : argsSpan) {
        std::cout << "Span: " << arg << '\\n';
    }
    #endif
    
    return 0;
}
`} />

<Aside type="danger">
⚠️ **Common Crash**: Accessing `argv[1]` when `argc == 1` → undefined behavior (dereferencing beyond array).  
✅ **Always check**: `if (argc > 1)` before accessing `argv[1]`.

```cpp
// ❌ Dangerous:
std::string input = argv[1];  // Crash if no args passed!

// ✅ Safe:
if (argc < 2) {
    std::cerr << "Usage: program <input>\\n";
    return 1;  // Error exit code
}
std::string input = argv[1];  // Now safe
```
</Aside>

## 🧠 Advanced: `std::optional` and Argument Parsing

<Code lang="cpp" title="Modern argument handling with C++17" code={`
#include <optional>
#include <string_view>

// Helper: find flag like --verbose in args
std::optional<std::string_view> findFlag(int argc, char* argv[], 
                                        std::string_view flag) {
    for (int i = 1; i < argc; ++i) {
        if (flag == argv[i]) {
            return std::string_view(argv[i]);
        }
        // Handle --key=value style:
        std::string_view arg = argv[i];
        if (arg.starts_with(flag) && arg[flag.size()] == '=') {
            return arg.substr(flag.size() + 1);  // Return value after '='
        }
    }
    return std::nullopt;  // Flag not found
}

int main(int argc, char* argv[]) {
    if (findFlag(argc, argv, "--help")) {
        std::cout << "Usage: program [--verbose] [--output=file]\\n";
        return 0;
    }
    
    bool verbose = findFlag(argc, argv, "--verbose").has_value();
    auto output = findFlag(argc, argv, "--output");  // optional<string_view>
    
    if (output) {
        std::cout << "Output to: " << *output << '\\n';
    }
    
    return 0;
}
`} />

Don't reinvent the wheel for production tools!

<Code lang="cpp" title="Production CLI tool with robust argument parsing" code={`
#include <iostream>
#include <string>
#include <filesystem>  // C++17
#include <optional>

namespace fs = std::filesystem;

struct Config {
    fs::path input;
    fs::path output;
    bool verbose = false;
    int threads = 4;
};

std::optional<Config> parseArgs(int argc, char* argv[]) {
    Config cfg;
    
    for (int i = 1; i < argc; ++i) {
        std::string arg = argv[i];
        
        if (arg == "--help" || arg == "-h") {
            std::cout << "Usage: processor --input=file [--output=file] [--verbose] [--threads=N]\\n";
            return std::nullopt;  // Signal to exit
        }
        else if (arg.starts_with("--input=")) {
            cfg.input = arg.substr(8);
        }
        else if (arg.starts_with("--output=")) {
            cfg.output = arg.substr(9);
        }
        else if (arg == "--verbose" || arg == "-v") {
            cfg.verbose = true;
        }
        else if (arg.starts_with("--threads=")) {
            cfg.threads = std::stoi(arg.substr(10));
        }
        else {
            std::cerr << "Unknown argument: " << arg << "\\n";
            return std::nullopt;
        }
    }
    
    // Validate required args
    if (cfg.input.empty()) {
        std::cerr << "Error: --input is required\\n";
        return std::nullopt;
    }
    
    // Set default output if not specified
    if (cfg.output.empty()) {
        cfg.output = cfg.input.replace_extension(".out");
    }
    
    return cfg;
}

int main(int argc, char* argv[]) {
    auto config = parseArgs(argc, argv);
    if (!config) return 1;  // Error exit code
    
    if (config->verbose) {
        std::cout << "Processing " << config->input << " → " << config->output << "\\n";
        std::cout << "Threads: " << config->threads << "\\n";
    }
    
    // Business logic here...
    processFile(config->input, config->output, config->threads);
    
    return 0;  // Success
}
`} />

// ✅ Freestanding environment (embedded, OS kernel, bootloader)

**Modern C++ Best Practice for `main`**:  
1. Always use `int main()` — portable and standard.

4. Use `return 0;` explicitly for clarity, even though it's implicit.  
5. For complex CLIs, use a parsing library — don't hand-roll production parsers.  
6. In embedded/freestanding targets, know that `main` may not exist — entry point is platform-defined.

## 📌 What Is `main`?

`main` is the **user-defined entry point** of a C++ program. It's where your code starts executing — but **not** where the program actually starts.

```
Program start
      │
      ▼
 [C++ Runtime Startup]   ← before main
      │  → zero-initialize globals
      │  → run static constructors
      │  → set up argc/argv/envp
      │  → initialize standard streams (cin, cout, cerr)
      ▼
   main()               ← your code starts here
      │
      ▼
 [C++ Runtime Teardown]  ← after main returns
      │  → run atexit handlers
      │  → destroy static objects (reverse order)
      │  → flush/close streams
      ▼
  OS process exit
```

## ✅ Valid `main` Signatures

Only **two** signatures are mandated by the C++ standard:

```cpp
// Form 1 — no arguments
int main() { }

// Form 2 — command-line arguments
int main(int argc, char* argv[]) { }

// Equivalent forms of Form 2:
int main(int argc, char** argv) { }        // same — array decays to pointer
int main(int argc, char* argv[], char* envp[]) { }  // non-standard but widely supported
```

> 🔴 Everything else is **implementation-defined or undefined**.

### What Is NOT Valid (but compiles on some compilers)

```cpp
void main() { }            // ❌ non-standard — MSVC allows, standard forbids
                           //    return type MUST be int

main() { }                 // ❌ implicit int — C99 removed it, C++ never had it
int main(void) { }         // ✅ valid in C, valid in C++ (void in parens = no params)
int main(int argc) { }     // ❌ non-standard — argc without argv
```

## 🔢 `argc` and `argv`

```
int main(int argc, char* argv[])
         │           │
         │           └── argument vector — array of C-strings
         └── argument count — number of strings in argv
```

### Memory Layout

```
$ ./program foo bar baz

argc = 4

argv:
┌──────────┐
│ argv[0]  │──► "./program\0"
├──────────┤
│ argv[1]  │──► "foo\0"
├──────────┤
│ argv[2]  │──► "bar\0"
├──────────┤
│ argv[3]  │──► "baz\0"
├──────────┤
│ argv[4]  │──► nullptr   ← guaranteed null terminator
└──────────┘
```

```cpp
int main(int argc, char* argv[]) {
    // argc always >= 1
    // argv[0] = program name (or empty string if not available)
    // argv[argc] = nullptr (guaranteed)

    for (int i = 0; i < argc; i++) {
        std::cout << argv[i] << "\n";
    }

    // Alternatively — iterate to null sentinel
    for (char** p = argv; *p != nullptr; p++) {
        std::cout << *p << "\n";
    }
}
```

### Parsing Real Command-Line Args

```cpp
#include <string>
#include <string_view>
#include <unordered_map>

int main(int argc, char* argv[]) {
    std::unordered_map<std::string, std::string> flags;

    for (int i = 1; i < argc; i++) {
        std::string_view arg = argv[i];

        if (arg.starts_with("--")) {          // C++20
            auto eq = arg.find('=');
            if (eq != std::string_view::npos)
                flags[std::string(arg.substr(2, eq-2))]
                    = std::string(arg.substr(eq+1));
        }
    }
    // ./program --host=localhost --port=8080
    // flags["host"] = "localhost"
    // flags["port"] = "8080"
}
```

## 🌍 `envp` — Environment Variables (Non-Standard)

```cpp
// Supported by MSVC, GCC, Clang — but NOT in the standard
int main(int argc, char* argv[], char* envp[]) {
    for (char** env = envp; *env != nullptr; env++) {
        std::cout << *env << "\n";
        // Prints: PATH=/usr/bin:/bin
        //         HOME=/home/user
        //         ...
    }
}

// Standard-compliant alternative:
#include <cstdlib>
const char* path = std::getenv("PATH");   // ✅ standard
```

## 🔙 Return Value — Exit Codes

```cpp
int main() {
    return 0;      // success — convention
    return 1;      // failure — convention
}
```

### Standard Exit Codes

| Return Value | Meaning |
|---|---|
| `0` | Success |
| `EXIT_SUCCESS` | Success (= 0, from `<cstdlib>`) |
| `EXIT_FAILURE` | Failure (= 1 on most platforms) |
| Any other `int` | Implementation-defined, passed to OS |

```cpp
// Shell reads the exit code:
$ ./program
$ echo $?      // 0 = success, non-zero = failure

// Used in shell scripts:
./program && echo "OK" || echo "FAILED"
```

> 🔑 **Special rule:** if `main` **falls off the end** (no `return`), it implicitly returns `0`. Only for `main` — for any other function this is UB.

```cpp
int main() {
    // no return
}  // ✅ implicit return 0 — only for main
```

## ⚡ Exit Functions — 4 Ways to End a Program

| Function | Runs destructors | Runs `atexit` | Flushes streams | Use When |
|---|---|---|---|---|
| `return` from `main` | ✅ | ✅ | ✅ | Normal exit |
| `std::exit(code)` | ✅ static only | ✅ | ✅ | Exit from non-main |
| `std::quick_exit(code)` | ❌ | ✅ (`at_quick_exit`) | ❌ | Fast exit, no cleanup |
| `std::abort()` | ❌ | ❌ | ❌ | Crash — abnormal termination |
| `std::terminate()` | ❌ | ❌ | ❌ | Unhandled exception |
| `_Exit(code)` | ❌ | ❌ | ❌ | Immediate OS exit |

```cpp
#include <cstdlib>

std::exit(EXIT_FAILURE);      // static destructors run, atexit runs
std::quick_exit(EXIT_FAILURE);// only at_quick_exit handlers run
std::abort();                 // SIGABRT — generates core dump
```

### `atexit` — Register Cleanup Handlers

```cpp
#include <cstdlib>

void cleanup1() { std::cout << "cleanup1\n"; }
void cleanup2() { std::cout << "cleanup2\n"; }

int main() {
    std::atexit(cleanup1);    // registered first
    std::atexit(cleanup2);    // registered second

    return 0;
    // Output: cleanup2   ← LIFO order
    //         cleanup1
}
```

> 🔑 `atexit` handlers run in **LIFO** order. Max guaranteed registrations: **32** (but implementations allow more).

## 🔬 Under the Hood — What Actually Runs Before `main`

```
OS loads ELF/PE binary
      │
      ▼
 Entry point: _start  (NOT main — injected by linker via CRT)
      │
      ▼
 __libc_start_main()  (glibc on Linux)
      │
      ├── Zero-initialize .bss section
      ├── Copy .data section into place
      ├── Run .init_array  ← global constructors run here
      │     └── all global/static object constructors
      │         all __attribute__((constructor)) functions
      ├── Set up argc, argv, envp from OS-provided stack layout
      ├── Initialize C++ runtime (exception tables, etc.)
      ├── Set up __cxa_atexit for static destructors
      │
      ▼
   main(argc, argv)   ← your code
      │
      ▼
   return value
      │
      ▼
 __libc_start_main cleanup
      │
      ├── Run atexit() handlers (LIFO)
      ├── Run .fini_array  ← global destructors (LIFO)
      │     └── all global/static object destructors
      ├── Flush stdio buffers
      │
      ▼
 _exit(return_value)  → system call: exit(2)
      │
      ▼
 OS reclaims process memory, file handles, etc.
```

### Seeing It Yourself

```bash
# Compile and check entry point
g++ -o prog main.cpp
readelf -h prog | grep "Entry point"
# → Entry point address: 0x401040  ← _start, not main

nm prog | grep -E "main|_start|__libc"
# _start         → true entry point
# main           → your function
# __libc_start_main → glibc setup
```

## 🧱 Static Initialization Before `main`

```cpp
#include <iostream>

struct Tracer {
    Tracer()  { std::cout << "BEFORE main\n"; }
    ~Tracer() { std::cout << "AFTER main\n"; }
};

Tracer t;           // global object — runs before main

int main() {
    std::cout << "IN main\n";
}

// Output:
// BEFORE main
// IN main
// AFTER main
```

```
This is how cout/cin/cerr work:
std::ios_base::Init is a global object.
Its constructor initializes the standard streams.
It runs before main — guaranteed.
```

## ☣️ Static Initialization Order Fiasco — The Real Danger

```cpp
// file_a.cpp
int x = 10;             // initialized before main

// file_b.cpp
extern int x;
int y = x * 2;          // ❌ FIASCO
                         // x and y are in different translation units
                         // C++ standard gives NO order guarantee
                         // y might be 0 or garbage
```

```
Within one .cpp file:    order is top-to-bottom ✅ guaranteed
Across .cpp files:       order is UNDEFINED ❌
```

**Fix — Construct On First Use:**

```cpp
int& get_x() {
    static int x = 10;   // initialized on first call, guaranteed
    return x;
}
int y = get_x() * 2;     // ✅ get_x() ensures x is initialized first
```

## 🏭 Real-World Production Scenario

**Crash before `main` in a large server binary:**

```cpp
// database.cpp
DatabasePool db_pool("localhost", 5432);  // global — constructor runs before main

// logger.cpp
Logger logger(db_pool);  // global — depends on db_pool
                         // if logger.cpp initializes before database.cpp
                         // db_pool is uninitialized → crash before main()
                         // stack trace shows _start, not main
                         // impossible to debug without knowing SIOF
```

**Symptom:** Process crashes with SIGSEGV before any of your code in `main` runs. Debugger shows `_start` or `__static_initialization_and_destruction_0`.

**Fix:** Replace global objects with function-local statics.

## 🎯 Interview Traps

**Trap 1:**
```cpp
int main() { }    // return value?
```
> Returns `0` implicitly. This is a **special exception** for `main` only. Any other non-void function with no return = UB.

**Trap 2:**
```cpp
int main() {
    std::exit(0);
}
// Do global destructors run?
```
> **Yes** — `std::exit` runs static destructors and `atexit` handlers. `std::abort()` does NOT.

**Trap 3:**
```cpp
int main(int argc, char* argv[]) {
    std::cout << argv[argc];   // valid?
}
```
> `argv[argc]` is **guaranteed to be `nullptr`** by the standard. Printing it would dereference nullptr — UB. But accessing `argv[argc]` itself (getting the nullptr) is valid.

**Trap 4:**
```cpp
// Can main be called recursively?
int main() {
    static int i = 0;
    if (i++ < 3) main();
}
```
> ❌ **Undefined behavior** in C++. The standard explicitly says `main` **cannot be called** from within the program. It can be defined but not called by user code.

**Trap 5:**
```cpp
int main() {
    return main();   // infinite recursion?
}
```
> UB — calling `main` from itself is explicitly forbidden by the standard. Stack overflow on implementations that allow it.
