In C++, some identifiers are reserved to perform special functions.
These reserved identifiers are called **KEYWORDS** or **RESERVED WORDS**.

<Aside type="caution">
You **CANNOT** use them as identifiers (variable/class/function names).
</Aside>

**Why?** Because each keyword already has a fixed meaning in the compiler.

```c++
int class = 10; // ❌ Compile-time error
```

## 13. Reserved Literals

🪤 Trap 1 — true, false, nullptr are not normal identifiers

```c++
true
false
nullptr

int true = 1;      // ❌ COMPILE ERROR
int false = 1;     // ❌ COMPILE ERROR
int nullptr = 1;   // ❌ COMPILE ERROR
```

These are reserved literals/special keywords.

---

🪤 Trap 2 — Unicode identifiers are valid — obfuscation attack

```c++
// Looks like "false" — IS NOT false
// Cyrillic 'а' instead of ASCII 'a'

int fаlse = 10;

std::cout << fаlse;
```

Compiler accepts it — human eye may miss it.

Used in:
- obfuscated code
- malicious code
- phishing-style attacks

## 15. Important Reserved Identifier Rules ⚠️

### Double underscore is reserved

```c++
int __value = 10; // ❌ Reserved for compiler/library
```

### Underscore + Capital Letter is reserved

```c++
int _Value = 10; // ❌ Reserved
```

### Global underscore identifiers are dangerous

```c++
int _global = 10; // ⚠️ Reserved at global scope
```

Avoid such names in production C++ code.

## 16. Keywords vs Identifiers vs Literals

| Category | Example |
|---|---|
| Keyword | `class`, `while`, `return` |
| Identifier | `age`, `BankAccount` |
| Literal | `10`, `"hello"`, `true` |

Example:

```c++
int age = 10;
```

| Token | Category |
|---|---|
| `int` | keyword |
| `age` | identifier |
| `10` | literal |
