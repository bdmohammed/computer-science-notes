## 🏛️ Class Specifiers in C++ — Complete Guide

> In C++, we control **accessibility** and **behavior** using access specifiers and keywords like `virtual`, `final`, and `friend`. Unlike Java, C++ does not have a single "modifier" list; instead, it uses a combination of access sections, inheritance specifiers, and function qualifiers.

---

## 🗂️ Allowed Specifiers for Classes

### ✅ Access Specifiers

C++ classes have three access levels. Unlike Java, there is **no package-private**. The default access for a `class` is **private**. For a `struct`, it is **public**.

```text
Class Access Specifiers
│
├── public
│   → Accessible from anywhere
│
├── protected
│   → Accessible within the class AND by derived classes (subclasses)
│
└── private (Default for 'class')
    → Accessible ONLY within the class
```

<Code lang="cpp" title="Access Specifier Example" code={`
class MyClass {
public:
    int publicVar;      // Accessible everywhere
    void publicFunc();  // Accessible everywhere

protected:
    int protectedVar;   // Accessible in MyClass and subclasses
    void protectedFunc();

private:
    int privateVar;     // Accessible ONLY in MyClass
    void privateFunc();
};

// ⚠️ Note: If you use 'struct', default is public:
struct MyStruct {
    int x; // Public by default!
};
`} />

<Aside type="note">
**Java vs C++**: 
- Java: Default is **package-private**.
- C++: Default is **private** (for `class`).
- C++ has **no concept of packages**, so `protected` is strictly for inheritance hierarchies.
</Aside>

---

### ✅ Behavior Specifiers

| Keyword | Meaning | Java Equivalent |
|---------|---------|-----------------|
| `virtual` | Enables dynamic dispatch (polymorphism) | Implicit for all non-static/non-final methods |
| `final` (C++11) | Prevents overriding or inheritance | `final` on class/method |
| `override` (C++11) | Ensures method overrides base virtual method | `@Override` annotation |
| `abstract` | N/A (Use pure virtual `= 0`) | `abstract` keyword |
| `friend` | Grants access to private/protected members | N/A (No direct equivalent) |
| `inline` | Hint to embed code (reduce call overhead) | N/A (JIT handles optimization) |
| `constexpr` | Compile-time evaluation | N/A (Limited support) |

## 🌍 public Classes & Headers

In C++, access control is typically managed via **Header Files** (`.h`/`.hpp`) and **Source Files** (`.cpp`). 

- **Public API**: Declared in the header file.
- **Private Implementation**: Hidden in the source file or using the **Pimpl Idiom**.

<Code lang="cpp" title="Header File (MyClass.hpp)" code={`
#ifndef MYCLASS_HPP
#define MYCLASS_HPP

class MyClass {
public:
    MyClass();
    void publicMethod();

private:
    void privateHelper();
    int internalState;
};

#endif
`} />

<Aside type="caution">
**Encapsulation in C++**: To hide a class from other translation units, simply **do not include its header** or place it in an anonymous namespace (`namespace { class Hidden {}; }`) within a `.cpp` file.
</Aside>

## 🔒 final Specifier (C++11)

### final Classes — Cannot Be Extended

Prevents inheritance. Similar to Java's `final class`.

<Code lang="cpp" title="final class prevents inheritance" code={`
class Base final {
public:
    void show() { }
};

// class Derived : public Base { }; // ❌ Compile Error: cannot derive from 'final' base
`} />

#### Why Use `final`?
1. **Performance**: Allows the compiler to **de-virtualize** calls (knows exactly which method to call, no vtable lookup needed).
2. **Design Intent**: Signals that the class is not designed for extension.

### final Methods — Cannot Be Overridden

Prevents overriding in derived classes.

<Code lang="cpp" title="final method prevents overriding" code={`
class Base {
public:
    virtual void display() final {
        // Implementation
    }
};

class Derived : public Base {
    // void display() override; // ❌ Compile Error: overriding final function
};
`} />

<Aside type="note">
**Important**: In C++, you must explicitly mark a method as `virtual` in the base class to enable polymorphism. In Java, all non-static/non-final methods are virtual by default.
</Aside>

## 🎭 abstract Classes (Pure Virtual Functions)

C++ does not have an `abstract` keyword for classes. A class becomes abstract if it contains **at least one pure virtual function**.

Syntax: `virtual ReturnType func() = 0;`

<Code lang="cpp" title="Abstract class with pure virtual methods" code={`
class Shape {
public:
    // Pure virtual function → Makes Shape abstract
    virtual double area() const = 0; 
    
    // Concrete method
    void printArea() {
        std::cout << "Area: " << area() << std::endl;
    }
    
    virtual ~Shape() = default; // Always virtual destructor!
};

// Shape s; // ❌ Compile Error: cannot declare variable of abstract type

class Circle : public Shape {
    double radius;
public:
    Circle(double r) : radius(r) {}
    
    // MUST implement pure virtual function
    double area() const override {
        return 3.14159 * radius * radius;
    }
};

// Usage:
Shape* s = new Circle(5.0); // ✅ Polymorphic pointer
s->printArea();
delete s;
`} />

#### 🔑 Abstract Class Rules

| Rule | Explanation |
|------|-------------|
| **Pure Virtual Syntax** | `virtual void foo() = 0;` |
| **Instantiation** | ❌ Cannot instantiate abstract class directly |
| **Constructor** | ✅ Can have constructors (called by derived classes) |
| **Destructor** | ✅ Should be `virtual` (and often `= default`) |
| **Implementation** | Derived class MUST override all pure virtual functions to become concrete |

<CardGrid>
  <Card title="Cannot Be Instantiated" icon="error">
    ```cpp
    class Abstract {
    public:
        virtual void foo() = 0;
    };
    // Abstract a; // ❌ Error
    ```
  </Card>
  
  <Card title="CAN Have Constructor" icon="approve-check">
    ```cpp
    class Abstract {
    public:
        Abstract(int x) { /* init */ }
        virtual void foo() = 0;
    };
    class Concrete : public Abstract {
    public:
        Concrete(int x) : Abstract(x) { } // Call base ctor
        void foo() override { }
    };
    ```
  </Card>

  <Card title="Pure Virtual Destructor" icon="information">
    ```cpp
    class Abstract {
    public:
        virtual ~Abstract() = 0; // Pure virtual destructor
    };
    // MUST provide definition outside class:
    Abstract::~Abstract() {} 
    
    // Why? Derived destructors call base destructor. 
    // If base is pure virtual without body, link error.
    ```
  </Card>
</CardGrid>

## 🤝 friend Keyword (C++ Specific)

> Java has no equivalent to `friend`. It allows specific functions or classes to access `private` and `protected` members.

<Code lang="cpp" title="friend function and class" code={`
class Box {
private:
    double width;
public:
    Box(double w) : width(w) {}
    
    // Friend function can access private members
    friend void printWidth(Box b);
    
    // Friend class can access all members
    friend class BoxInspector;
};

void printWidth(Box b) {
    // ✅ Allowed: friend function accessing private member
    std::cout << "Width: " << b.width << std::endl;
}

class BoxInspector {
public:
    void inspect(Box b) {
        // ✅ Allowed: friend class accessing private member
        std::cout << "Inspecting width: " << b.width << std::endl;
    }
};
`} />

<Aside type="caution">
**Use `friend` sparingly**. It breaks encapsulation. Prefer public getters/setters or proper interface design unless you are implementing operators (like `<<` for streaming) or tightly coupled helper classes.
</Aside>

## 🧩 DSA Angle: Polymorphism in Containers

> Abstract classes allow storing different types in a single container via pointers.

<Code lang="cpp" title="Polymorphic Container Pattern" code={`
#include <iostream>
#include <vector>
#include <memory>

class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14 * r * r; }
};

class Square : public Shape {
    double s;
public:
    Square(double s) : s(s) {}
    double area() const override { return s * s; }
};

int main() {
    // Store different shapes in one vector
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(5.0));
    shapes.push_back(std::make_unique<Square>(4.0));
    
    for (const auto& shape : shapes) {
        std::cout << "Area: " << shape->area() << std::endl;
    }
    // Output:
    // Area: 78.5
    // Area: 16
    return 0;
}
`} />

<Aside type="tip">
**Why `unique_ptr`?**  
Raw pointers (`Shape*`) require manual `delete`. `unique_ptr` automatically cleans up memory when the vector goes out of scope, preventing leaks.
</Aside>

    class GameUnit {

    // Static polymorphism (compile-time) vs Virtual (runtime)

        void interface() {
            static_cast<Derived*>(this)->implementation();
        }
    };
    
    class Child : public Base<Child> {
    public:
        void implementation() {

        }
    };
    
    // No vtable overhead! Fast!

## 🔑 Quick Reference Summary

### Class Specifiers

| Specifier | Effect |
|-----------|--------|
| `class` | Default member access: **Private** |
| `struct` | Default member access: **Public** |
| `final` | Cannot be inherited |
| `friend` | Grants access to private/protected members |

### Method Specifiers

| Specifier | Effect |
|-----------|--------|
| `virtual` | Enables dynamic dispatch (polymorphism) |
| `override` | Checks if method overrides base virtual method |
| `final` | Prevents further overriding |
| `= 0` | Pure virtual (makes class abstract) |
| `const` | Method cannot modify member variables |
| `static` | Belongs to class, not instance |

### Access Control

| Specifier | Accessible From |
|-----------|-----------------|
| `public` | Everywhere |
| `protected` | Class + Derived Classes |
| `private` | Class Only |

<Aside type="caution">
**Final Checklist**:
1. ✅ Always mark base destructors as `virtual` (or `protected`) if polymorphism is used.
2. ✅ Use `override` in derived classes to catch signature errors.
3. ✅ Use `final` to optimize performance and prevent inheritance when appropriate.
4. ✅ Remember: `struct` defaults to public, `class` defaults to private.
5. ✅ Abstract classes cannot be instantiated directly.
6. ✅ `friend` breaks encapsulation — use with caution.
</Aside>

## 📌 What Are Class Modifiers?

Keywords that **control access, behavior, storage, and inheritance** of class members and classes themselves.

```
Class Modifiers
│
├── Access Modifiers        → who can see/use this member
│   ├── public
│   ├── private
│   └── protected
│
├── Member Modifiers        → how a member behaves
│   ├── static              → belongs to class, not instance
│   ├── virtual             → runtime polymorphic dispatch
│   ├── override            → must override base virtual
│   ├── final               → no further override allowed
│   ├── explicit            → no implicit conversion
│   ├── mutable             → modifiable in const methods
│   ├── inline              → definition in header
│   ├── constexpr           → compile-time evaluation
│   └── friend              → grants access to private
│
└── Class-Level Modifiers
    ├── final               → class cannot be inherited
    └── struct vs class     → default access difference
```

---

## 🔷 1. Access Modifiers

### Rules

```
public:    accessible from ANYWHERE
private:   accessible only within THIS class
           (NOT even derived classes)
protected: accessible within THIS class
           AND derived classes
           NOT from outside
```

```cpp
class Animal {
public:
    std::string name;       // anyone can access
    void breathe();         // anyone can call

protected:
    int heart_rate;         // Animal + derived classes
    void pump_blood();      // Animal + derived classes

private:
    float dna_sequence;     // ONLY Animal itself
    void mutate();          // ONLY Animal
};

class Dog : public Animal {
    void bark() {
        name = "Rex";       // ✅ public
        heart_rate = 80;    // ✅ protected
        dna_sequence = 0;   // ❌ compile error — private
    }
};

Dog d;
d.name = "Rex";             // ✅ public
d.heart_rate = 80;          // ❌ protected — outside class
d.dna_sequence = 0;         // ❌ private
```

### Memory Layout — Modifiers Don't Change It

```
class Foo {
public:
    int a;      // offset 0
private:
    int b;      // offset 4
protected:
    int c;      // offset 8
};

Memory: [a][b][c] — contiguous regardless of access modifier
Access modifiers are COMPILE-TIME ONLY — no runtime overhead
They disappear completely in the binary
```

## 🔷 2. `struct` vs `class` — Default Access

```cpp
struct Foo {
    int x;      // public by default
    int y;      // public by default
};

class Bar {
    int x;      // private by default
    int y;      // private by default
};
```

```
ONLY difference between struct and class in C++:
  struct → default access: PUBLIC
  class  → default access: PRIVATE

Everything else is identical — both can have:
  constructors, destructors, methods, inheritance, virtual functions
```

```cpp
// Inheritance default access also differs:
struct D1 : Base { };      // public inheritance by default
class  D2 : Base { };      // private inheritance by default
```

### Convention

| Use `struct` when | Use `class` when |
|---|---|
| Plain data aggregates (POD) | Complex objects with invariants |
| All members public | Encapsulated with private state |
| No invariants to maintain | Has logic that must protect data |

## 🔷 3. `static` Member

```cpp
class Counter {
public:
    static int count;          // class-level variable — ONE copy for all instances
    static void reset();       // class-level function — no 'this' pointer

    Counter() { ++count; }
    ~Counter() { --count; }
};

// Definition required outside class (pre-C++17)
int Counter::count = 0;

// C++17: inline static — no out-of-class definition needed
class Counter {
    inline static int count = 0;   // ✅ C++17
};
```

### Static Member — Memory Model

```
Instance memory (per object):
┌────────────────┐
│  obj1 members  │
└────────────────┘
┌────────────────┐
│  obj2 members  │
└────────────────┘
┌────────────────┐
│  obj3 members  │
└────────────────┘

Static member (ONE copy in .data section):
┌────────────────┐
│  Counter::count│ ← shared by ALL instances
└────────────────┘
```

```cpp
// Accessing static members
Counter::count;        // ✅ via class name (preferred)
Counter c;
c.count;               // ✅ valid but misleading — looks like instance var

// Static method — no 'this' pointer
class Logger {
    static Logger* instance;
public:
    static Logger& get() {     // ← no 'this'
        if (!instance) instance = new Logger();
        return *instance;
    }
};

// Singleton pattern
Logger::get().log("message");
```

### Static vs Non-Static

| | Non-static | Static |
|---|---|---|
| One per | instance | class |
| Accessed via | `obj.x` | `Class::x` |
| Has `this` | ✅ | ❌ |
| `sizeof(T)` contribution | ✅ | ❌ (not in object) |
| Lifetime | object lifetime | program lifetime |
| Storage | object memory | `.data`/`.bss` |

## 🔷 4. `virtual` — Polymorphic Dispatch

```cpp
class Shape {
public:
    virtual double area() const {    // virtual — runtime dispatch
        return 0.0;
    }
    virtual ~Shape() { }             // virtual destructor — ALWAYS for base classes
};

class Circle : public Shape {
    double r;
public:
    double area() const override {   // overrides Shape::area
        return 3.14159 * r * r;
    }
};

Shape* s = new Circle(5.0);
s->area();    // → calls Circle::area() — runtime dispatch via vtable
              // without virtual: calls Shape::area() — compile-time binding
```

### How `virtual` Works — vtable

```
Each polymorphic class gets a vtable (virtual function table):

Shape vtable:
┌──────────────────┐
│  &Shape::area    │  [0]
│  &Shape::~Shape  │  [1]
└──────────────────┘

Circle vtable:
┌──────────────────┐
│  &Circle::area   │  [0]  ← overrides Shape::area
│  &Circle::~Circle│  [1]
└──────────────────┘

Each object has a hidden vptr (virtual pointer):
Shape obj:  [vptr → Shape vtable ] [data]
Circle obj: [vptr → Circle vtable] [r    ]

Call s->area():
  1. Load vptr from *s
  2. Look up slot [0] in vtable
  3. Call the function pointer found there
  → correct function called regardless of static type
```

```cpp
// Cost of virtual call:
// Non-virtual: call address known at compile time → direct call
// Virtual:     load vptr → load vtable → load slot → indirect call
// ~2-5 ns overhead + prevents inlining + may cause cache miss
```

### Virtual Destructor — Mandatory in Base Classes

```cpp
class Base {
public:
    ~Base() { }             // ❌ non-virtual destructor
};

class Derived : public Base {
    int* data;
public:
    Derived() : data(new int[100]) { }
    ~Derived() { delete[] data; }    // must be called
};

Base* b = new Derived();
delete b;   // ❌ calls ~Base() only — ~Derived() NEVER called
            // data is leaked — memory leak every time
            // undefined behavior — silent in production

// ✅ Fix:
class Base {
public:
    virtual ~Base() { }     // virtual — calls correct destructor
};
```

## 🔷 5. `override` — Explicit Override Marker

```cpp
class Base {
public:
    virtual void process(int x) { }
    virtual void compute() { }
};

class Derived : public Base {
public:
    // ❌ Without override — silent bugs:
    void process(float x) { }    // NOT an override — different signature
                                  // creates NEW function, hides base

    // ✅ With override — compile error if not actually overriding:
    void process(float x) override { }   // ❌ compile error — no match
    void process(int x) override { }     // ✅ correct
    void comute() override { }           // ❌ compile error — typo caught!
    void compute() override { }          // ✅ correct
};
```

> 🔑 **Always use `override`.** It turns silent runtime bugs into compile errors. No performance cost — purely a compile-time annotation.

## 🔷 6. `final` — Prevent Override / Inheritance

```cpp
class Base {
public:
    virtual void process() { }
};

class Middle : public Base {
public:
    void process() override final { }  // final — no more overrides
};

class Derived : public Middle {
    void process() override { }        // ❌ compile error — process is final
};

// Class-level final — cannot be inherited
class Leaf final : public Base {
    void process() override { }        // ✅ can still override base
};

class Child : public Leaf { };         // ❌ compile error — Leaf is final
```

### `final` Performance Benefit

```
virtual call normally:
  vptr → vtable → slot → indirect call  (cannot inline)

With final class or final method:
  compiler KNOWS exactly which function will be called
  → devirtualizes → direct call → can inline
  → eliminates vtable overhead entirely
```

## 🔷 7. `explicit` — Prevent Implicit Conversion

```cpp
class MyString {
    const char* data;
public:
    MyString(const char* s) : data(s) { }  // implicit constructor
};

void print(MyString s) { }

print("hello");    // ✅ implicit: const char* → MyString
                   // may be unintentional
```

```cpp
class MyString {
public:
    explicit MyString(const char* s) : data(s) { }  // explicit
};

print("hello");              // ❌ compile error — no implicit conversion
print(MyString("hello"));   // ✅ explicit construction required
```

### `explicit` on Conversion Operators

```cpp
class SmartBool {
    bool value;
public:
    // ❌ Without explicit — dangerous implicit conversion
    operator bool() { return value; }

    // ✅ With explicit — must be explicitly converted
    explicit operator bool() { return value; }
};

SmartBool sb;
bool b = sb;         // ❌ if explicit — compile error
bool b = (bool)sb;   // ✅ explicit cast required
if (sb) { }          // ✅ contextual conversion — works even with explicit
                     // if/while/for conditions use contextual bool conversion
```

### `explicit` Multi-Parameter Constructor (C++11)

```cpp
class Pair {
public:
    explicit Pair(int a, int b) { }
};

Pair p = {1, 2};    // ❌ compile error with explicit (brace-init implicit)
Pair p{1, 2};       // ✅ direct-list-initialization — works even with explicit
Pair p(1, 2);       // ✅ direct initialization — always works
```

## 🔷 8. `mutable` — Modify in `const` Method

```cpp
class Cache {
    mutable std::unordered_map<int, int> cache_;  // mutable
    mutable std::mutex mtx_;                       // mutable

public:
    // const method — promises not to change logical state
    int compute(int key) const {
        std::lock_guard lock(mtx_);    // ✅ mutable — can lock in const
        auto it = cache_.find(key);
        if (it != cache_.end())
            return it->second;
        int result = expensive(key);
        cache_[key] = result;          // ✅ mutable — can modify cache
        return result;
    }
};
```

```
mutable = "this member is not part of logical state"
          "even though it changes physically, the object is logically const"

Use cases:
  - caches / lazy initialization
  - mutexes (must lock in const methods)
  - reference counts
  - debug counters
```

## 🔷 9. `friend` — Grant Access to Private Members

```cpp
class BankAccount {
    double balance;    // private

    // friend function — can access private members
    friend void audit(const BankAccount& acc);

    // friend class — all members of Auditor can access
    friend class Auditor;
};

void audit(const BankAccount& acc) {
    std::cout << acc.balance;    // ✅ friend — can access private
}

class Auditor {
    void inspect(const BankAccount& acc) {
        std::cout << acc.balance;  // ✅ friend class
    }
};
```

### Friend — Key Properties

```
friend is NOT:
  → inherited (Derived of friend class doesn't inherit friendship)
  → transitive (friend of friend is NOT a friend)
  → symmetric (A friend of B doesn't make B friend of A)
  → a member — declared inside class, defined/used outside

friend IS:
  → a one-way relationship: "I grant you access to MY private members"
  → useful for operator overloading (<<, >>)
  → useful for tightly coupled helper classes
```

```cpp
// Classic friend — stream operator overloading
class Point {
    int x, y;
public:
    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        return os << "(" << p.x << ", " << p.y << ")";  // accesses private x, y
    }
};

Point p{1, 2};
std::cout << p;   // → (1, 2)
```

## 🔷 Access in Inheritance

```cpp
class Base {
public:    int pub;
protected: int prot;
private:   int priv;
};

class D1 : public Base {     // public inheritance
    void f() {
        pub = 1;   // ✅ public in Base  → public in D1
        prot = 1;  // ✅ protected in Base → protected in D1
        priv = 1;  // ❌ private — never accessible
    }
};

class D2 : protected Base {  // protected inheritance
    void f() {
        pub = 1;   // ✅ public in Base  → protected in D2
        prot = 1;  // ✅ protected in Base → protected in D2
    }
};

class D3 : private Base {    // private inheritance
    void f() {
        pub = 1;   // ✅ public in Base  → private in D3
        prot = 1;  // ✅ protected in Base → private in D3
    }
};

D1 d1;
d1.pub = 1;   // ✅ public
D2 d2;
d2.pub = 1;   // ❌ protected — not accessible from outside
D3 d3;
d3.pub = 1;   // ❌ private — not accessible from outside
```

### Inheritance Access Transformation Table

| Base member | `public` inherit | `protected` inherit | `private` inherit |
|---|---|---|---|
| `public` | public | protected | private |
| `protected` | protected | protected | private |
| `private` | inaccessible | inaccessible | inaccessible |

## 🔬 Under the Hood — Memory Layout

```cpp
class Foo {
public:
    int a;                    // +0
protected:
    int b;                    // +4
private:
    int c;                    // +8
    virtual void f() { }     // vptr at +0 (before all members!)
};
```

```
Foo object in memory (with virtual):
┌──────────────────┐
│  vptr (8 bytes)  │  +0   hidden vtable pointer
├──────────────────┤
│  a    (4 bytes)  │  +8   public
├──────────────────┤
│  b    (4 bytes)  │  +12  protected
├──────────────────┤
│  c    (4 bytes)  │  +16  private
└──────────────────┘
Total: 24 bytes

Without virtual: no vptr → 12 bytes
Access modifiers: zero effect on layout — compile-time only
```

## 🎯 Interview Traps

**Trap 1:**
```cpp
class Base {
    virtual void foo() { }    // private virtual
};
class Derived : public Base {
public:
    void foo() override { }   // public override of private virtual
};
Base* b = new Derived();
b->foo();   // accessible?
```
> `b->foo()` → **compile error** — `foo` is `private` in `Base`. Accessibility is checked on the **static type** (`Base*`). But if accessible, the **virtual dispatch** would call `Derived::foo`. Access and dispatch are independent mechanisms. Fix: make `Base::foo` at least `protected` or `public`.

**Trap 2:**
```cpp
class Foo {
    static int x;
    int y;
};
std::cout << sizeof(Foo);   // → ?
```
> `sizeof(Foo) = sizeof(int) = 4`. Static members are **NOT part of the object** — they live in `.data`. Only `y` contributes to `sizeof`. `x` is not counted.

**Trap 3:**
```cpp
class Base {
public:
    virtual void f() final { }
};
class D1 : public Base {
    void f() override { }    // ❌ compile error — f is final
};
class D2 final : public Base {
    void f() override { }    // ✅ — D2 is final class, can still override f
};
class D3 : public D2 { };   // ❌ compile error — D2 is final
```
> `final` on a **method** prevents further overrides of that method. `final` on a **class** prevents inheritance of the class. Both can coexist independently.

**Trap 4:**
```cpp
struct Foo {
    explicit Foo(int x) { }
};
Foo a = 5;     // compiles?
Foo b(5);      // compiles?
Foo c = {5};   // compiles?
Foo d{5};      // compiles?
```
> `a = 5` → ❌ copy-init with `explicit` — compile error. `b(5)` → ✅ direct-init. `c = {5}` → ❌ copy-list-init with `explicit` — compile error. `d{5}` → ✅ direct-list-init — works even with `explicit`.

**Trap 5:**
```cpp
class A {
    friend class B;
};
class B {
    friend class C;
};
class C {
    void f(A& a) { a.x = 1; }  // can C access A's private?
};
```
> ❌ **No.** Friendship is **not transitive**. C is a friend of B, B is a friend of A — but C is NOT a friend of A. `a.x` is inaccessible.
